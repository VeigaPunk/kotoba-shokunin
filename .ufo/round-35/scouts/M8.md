# Scout M8

## Task
Red probe: harness zero/positive baseline-pin corruption after round 29 (`verify_harness_claims.py`). Does a corrupted zero/positive `expect` still pass at HEAD `48a0720`?

## Commands
- `git archive HEAD verifiers | tar -x -C /dev/shm/m8/base` (all probes on `/dev/shm`; `/tmp` at 80%).
- 11-pin corruption matrix: one altered `expect` per copy, `python3 verify_harness_claims.py --baseline <copy>.json --json --cwd <repo>`, run concurrently.
- Positive control: same matrix over all 17 `equal`/`at_least` pins.
- Schema probes: zero row deleted, `expect: null`, `expect: false`, `checks` removed, `checks` as list, baseline `mode` field flipped, extra stale pin.
- Missing baseline: `--json` and plain; malformed JSON; list-shaped baseline.
- Patched `/dev/shm` copy: `if baseline is None and mode in ("zero","positive")` guard, then live `cmp` and the 11-pin matrix again.
- Live byte control: `python3 verifiers/verify_harness_claims.py` (orig vs patched), `--self-test`, `check_assertion_floors.py`.

## Findings
**The round-29 fix landed but is dead code.** `b0b0410` added `if mode == "zero" or mode == "equal"` to the *baseline* arm, but the chain above it captures both modes first: `verify_harness_claims.py:560` `if mode == "zero"` and `:563` `elif mode == "positive"` return before `:566 elif baseline is None` / `:569` the baseline branch. Lines 571-575 are unreachable for zero/positive.

- 11/11 zero/positive corruptions: **exit 0, no DRIFT**. `expected` prints the literal `"0 / empty"` / `"> 0"`, never the pin. This is the exact r29 H1 table, unchanged.
- Positive control 17/17 `equal`/`at_least` corruptions flip exit 1 naming the id — the gate is live for the other modes.
- Row deleted, `expect: null` on a zero pin: exit 0 silent. `expect: false` vs observed `0`: exit 0 (`0 == False`).
- `--json` with a missing baseline: **exit 0**, 11 PASS + 17 OBSERVE (plain mode correctly exits 3). A JSON consumer reads 11 green pins from an absent baseline.
- Malformed JSON and list-shaped baseline: exit 1 with a raw traceback, not the documented 2/3 ladder.
- Patched copy: 11/11 flip, deleted-row/null flip, live stdout md5-identical to orig (`1239f387…`), self-test 0/10 unchanged.
- r29 report (`:11`, LOG `:1292`) claims "all-28 matrix flipped every pin" and "zero==expect exact" — falsified at HEAD; SCORECARD `:32` repeats it.

## Defects
1. **Dead-code fix (H1 class reopens):** 11 zero/positive pins still never compare `expect`; corruption exits 0. `verify_harness_claims.py:560-575`.
2. **`--json` missing baseline exits 0** with 11 PASS rows; plain mode exits 3 — a JSON-only caller sees green.
3. **Baseline `mode` field is decorative:** `oc.permission.skill_{lines,allow}` declare `at_least` in baseline, `equal` in `CHECKS`; the baseline copy is never consulted, so a baseline edit of `mode` is invisible.
4. **Uncaught baseline shape errors** (`checks` absent / list) surface as tracebacks at exit 1, not the 2/3 ladder.
5. **False verification record:** r29 report + LOG + SCORECARD assert the class closed; the landed bytes do not.
6. Same class in `verify_corpus_integrity.py:599` (6 zero pins, 6/6 corruptions exit 0; equal control flips).

## Limits
`/dev/shm` copies only; no repo edit beyond this fragment. Live runs read the host's omp/opencode state; `verify_corpus_integrity` live needs a git worktree, so it ran on a `/dev/shm` clone. Zero/positive matrix re-run once (not repeated for flake); `--self-test` covers neither mode's baseline arm.
