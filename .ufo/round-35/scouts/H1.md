# Scout H1

## Task

Reproduce the r32-named residual (`<<EOF~~` under-catch) on a /dev/shm copy, compare the checker's command parsing against bash, and locate the capture site.

## Commands

- `cp -a verifiers /dev/shm/h1/` + `cp -a <repo> /dev/shm/h1/fresh` (HEAD 48a0720; repo untouched, `git status` clean apart from `.ufo/round-35/`)
- `python3 -c "import verify_skill_checklist; command_subjects([...])"` — 17 opener/terminator pairs, fenced block `cat <<OP / BODY / TERM / cat corpus/absent-round17.md`
- bash 5.3.15 control: same block with `cat /nonexistent/dead` tail; "tail ran" = stderr carries `No such file`
- Patch sketch on the copy only: `sed 's/~?/.../` at `:311`, i.e. `~?` -> `~*` on both delimiter sides
- Preservation: `--self-test`, `check_assertion_floors.py`, `verify_corpus_integrity.py`, 5 heredoc/fence fixtures, full live run diffed against HEAD

## Findings

- **Residual confirmed.** `cat <<EOF~~` / body / `EOF~~` / dead tail -> **1 subject, 1 segment** (only the opener), exit 0; bash closes at `EOF~~` and the dead tail fails (rc 1). Same for `<<EOF~~~`, `<<EOF~~~~`, `<<-EOF~~`, `<<'EOF~~'`, `<<"EOF~~"`. HEAD mismatches bash on **7 of 17** forms; the sketch on **0 of 17**.
- **Site.** `verifiers/verify_skill_checklist.py:311` `HEREDOC_RE` captures at most one tilde per side (`(~?[A-Za-z_][A-Za-z0-9_]*~?)`), so `heredoc_delimiter()` (`:1172`, `HEREDOC_RE.match` at `:1206`) returns `EOF~`; the terminator compare `stripped == heredoc_end` at `:796` never matches `EOF~~` and every later line is `continue`d at `:798`.
- **Fix sketch (validated).** `HEREDOC_RE = re.compile(r"<<-?\s*['\"]?(~*[A-Za-z_][A-Za-z0-9_]*~*)['\"]?")` — one line, no call-site change. sha256 `ea414760…` (HEAD `e26f1939…`). Two purpose-built fixtures (mirrors of `command-heredoc-tilde-dead` with `~~`/`~~~`) flip rc0 -> rc1 naming `corpus/absent-round17.md`; body stays opaque; the `EOF~`-misterm case still leaves the block open (bash warns "delimited by end-of-file").
- **Preservation.** self-test 0/1504; floors 10/108/52/87/1504/62 PASS; corpus integrity 9/9; `command-heredoc-tilde`, `-dead`, `-misterm`, `-cd`, `command-fence-filter` byte-identical output and rc; full live run byte-identical (13 subjects / 9 segments, 41 boxes).
- **Landing debt.** `corpus/knowledge/sibling-citation-routing-round16.json:9` pins the file sha `e26f1939…` (no reader found in `verifiers/*.py`; it is a replay guard), so landing needs a re-pin + `sha_superseded_from` note.

## Defects

1. `:311` multi-tilde under-catch — the claim's target (HIGH, false PASS; closed by the sketch).
2. `:311` delimiter charset `[A-Za-z0-9_]` rejects `-`, `.`, `/`: `<<EOF-x` (and `a-b`) opens no heredoc in checker, bash closes on `EOF-x` -> body lines become subjects (safe-direction noise, pre-existing, **not** closed by the sketch).
3. `<<\EOF` yields `None` (backslash escapes the operator for the walk), so the body is scanned as commands (`nonexistent-binary-xyz` becomes a subject); bash treats it as a real heredoc. Safe direction, noisy; pre-existing.
4. `:796` uses `line.strip()`, so an indented / tab-indented / trailing-space terminator closes the heredoc in the checker while bash keeps it open (over-catch, pre-existing; `<<-` semantics are not distinguished).

## Limits

- bash control used `bash -c` with the tail as the last line; a heredoc left open by bash makes the *tail itself* the body, so "tail ran" is the discriminator, not rc alone.
- Only fenced-block parsing was exercised (`command_subjects`); inline-span and `fenced-arg` paths were not re-derived. The sketch was not applied to the repo — patch lives at `/dev/shm/h1/patched.py`.
