## Findings
- **Identity is clean on the lane, fragile by construction.** 32/32 ahead commits are author==committer `kotoba-shokunin <kotoba@shokunin.local>` with identical timestamps. The identity exists only as a repo-local override; a clone or any unconfigured shell resolves to global `ci <ci@local>` (already 2 such commits in history: `2193667`, `1fbf02b`). No script exports `GIT_AUTHOR_*`/`GIT_COMMITTER_*`.
- **Divergence is exactly as round 34 recorded, and the repair is proven.** 32 ahead / 2 behind; live remote has no loop commit on any branch. The merge rehearsal is deterministic: one `LOG.md` conflict (keep-both), README added, pyc dropped, every gate green afterwards. The behind-2 payload is additive (`README.md` +14, `LOG.md` +7).
- **The rebase trap is quantified.** Global `pull.rebase=true` + `rerere.enabled=true`; 31 of the 32 unpushed SHAs are cited in tracked files and 9 ahead subjects embed a SHA. A bare `git pull` rewrites exactly the commits the corpus cites.
- **Pycache is clean locally, stale on the remote.** Master tracks 0 pyc and both ignore rules match nested dirs; the 2 pyc survive on all 11 remote refs until the divergence merge lands. `.gitignore` history: rules dropped by `c8b53ac` in the same commit that added the 2 pycs, restored by `2ca8d01`.

## Defects
1. **S4-1 (medium, identity)** — lane identity is a `.git/config`-only override; clone/global = `ci <ci@local>`. Fix belongs in the lane wrapper (`GIT_AUTHOR_*`/`GIT_COMMITTER_*`), not in history.
2. **S4-2 (high, carried)** — ahead 32 / behind 2, push non-fast-forward, 0 remote branches carry the loop's work. Rehearsed repair: `git merge --no-rebase origin/master`, resolve `LOG.md` keep-both, commit; all gates green on the result.
3. **S4-3 (medium)** — `pull.rebase=true` (global) + 31/32 cited SHAs: an unattended `git pull` invalidates corpus citations. Requires `--no-rebase` or a `pull.ff`/`pull.rebase=false` lane setting.
4. **S4-4 (low)** — 2 pyc remain tracked on every remote ref (`origin/master` incl.); the merge drops them, but until then a fresh clone carries bytecode.
5. **S4-5 (low)** — stale `packed-refs` entry `fad752b5` (round 17) for `origin/master`, shadowed by the loose `74fc0f1`; harmless now, misleading to any tool reading `packed-refs` directly.
6. **S4-6 (low, concurrency)** — at 07:00:49 another process ran `reset` + `merge origin/master` on the live repo (`MERGE_HEAD 74fc0f1`, `UU LOG.md`, `A README.md`), then reset back at 07:02; it left `.git/rr-cache/4c73aef…/preimage` (127,610 B) with **no postimage**. Stale rerere state, not this lane's mutation.
7. **S4-7 (low, garbage)** — 2 dangling stash/WIP commits (`2ae3af5`, `aa796d8`) reachable from no ref; their trees are fully contained in master, so a `gc` is safe.
