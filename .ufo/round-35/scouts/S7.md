## Findings
- The live claim holds numerically: 0 unindexed, 0 stale, 0 missing, every pointer shape resolving. Two instruments agree.
- Claim wording is off by one: README cannot index itself, so "53 tracked indexed" is really **53 tracked / 52 indexable / 0 unindexed**. The baseline `corpus.index.tracked_files` pins 53 (`equal`), not an indexed count; no check pins the number of *named* rows.
- Coverage is satisfiable without naming a file: replacing all 49 rows with `knowledge/*.md` + `lessons/*.md` yields `9/9 checks pass` (3 patterns). `index_patterns` is observed and baseline-pinned as context, never asserted with a floor.
- Fence blindness: `file_column_tokens` accepts any `|`-leading line inside `## Coverage map` and has no `fenced_regions` call (that helper exists only in `verifiers/verify_skill_checklist.py:596`). A real row swapped for a fenced copy keeps 0 unindexed at exit 0 — the index analogue of claim D's M1, in a different instrument, so the round-35 D fix does not close it.
- Correct non-escapes: a non-table fenced line is not harvested; blockquoted and indented rows are not harvested (they fail closed); the backtick requirement is load-bearing.
- Duplicate rows are invisible to the index family (set semantics); only the baseline `equal` counters on `report_total`/`commit_total` catch them, and `--no-baseline` (the mode used for red probes) does not.
