## Findings
- The slice claim holds: 179 files, all tracked, pins tracked with modes intact, all six floors green, worktree == HEAD.
- Fixture content is genuinely load-bearing for the gating paths: every must-fail case tested flips the self-test when neutralized, including the whole `drop-oc*` family.
- `pins/` is read by no code (r26/r28 S7 debt, re-confirmed): `grep -rn "fixtures/pins\|mini\.bin\|mini2\.bin\|tripwire\.bin" verifiers/*.py` -> only an inline literal site. M3/M7/M8 all pass, so the committed pin fixtures are evidence-only as documented, and `tripwire.bin`'s `EXECUTED` sentinel has no reader.
- `surfaces/inventory-kind-drift.md` is a genuine orphan and a *dead* probe: run directly it FAILs `table_parity` (7 extra/missing ids) and `kind_parity` — but that is id drift, not the kind drift it is named for; `--self-test` never runs it, so replacing it with `inventory-clean.md` yields 87/87 exit 0 (M11). Added r14, untouched since.
- Add-only fixture drift is invisible: a new `checklist/zz-extra/` case leaves 1504/1504 green (M15). There is no fixture-count floor, and `179` is pinned nowhere in `verifiers/`.
- No `.gitattributes`: binary fixtures rely on git's NUL heuristic. `tripwire.bin` has no NUL and is pure ASCII, so a CRLF checkout rewrites it (sha change) — content survives (`/bin/sh` + `EXECUTED`), but the file is no longer byte-identical to HEAD.
