# Scout M9

## Task
Red probe of the r32 padded-key closure (claim W) at HEAD 48a0720: try to falsify
`check_substrate_pins.py`'s "pin keys are exact bytes" promise. Read-only on the
repo; all baselines and the pre-r32 control on /dev/shm (`TMPDIR=/dev/shm/m9`).

## Commands
- `python3 verifiers/check_substrate_pins.py` -> exit 0, `OK 3/3 pins hold`; `--json` twice -> identical sha256 `890de993…` (deterministic).
- `python3 verifiers/check_substrate_pins.py --self-test` -> `0 failure(s) over 62 assertions`; `check_assertion_floors.py` -> `PASS pins observed=62 floor=62`, exit 0.
- Category-hole sweep over all 0x110000 codepoints: `chr(c).isspace() and category not in (Zs,Zl,Zp,Cc,Cf)` -> **0 holes**.
- Trailing-pad sweep: every Zs/Zl/Zp/Cf + ASCII-Cc codepoint appended to `omp_binary_sha256` -> **221/221 exit 2**.
- 80-shape matrix (lead/trail/mid/separator positions x 20 pad chars) -> every whitespace/control/format shape exit 2 naming the key.
- Pre-r32 control (`git show e8a81ac:verifiers/check_substrate_pins.py`): padded key -> exit 0; HEAD -> exit 2. Closure reproduced.

## Findings
- **Claim W holds; no regression.** The r32 fix is category-based, not `str.strip()`-based, and it is complete for the whitespace class: 170 Cf chars that `str.strip()` leaves untouched are all caught (`canonical_pin_key` strips them; `hygiene_offenders` names them by codepoint).
- **Denominator fixed too**: a padded key now enters the count (`UNSUPPORTED 1/4 pins failed:  omp_binary_sha256`), so the r32 W2 "absent from the denominator, summary reads 3/3" concern is closed.
- **Neighbours intact**: r28 six case variants all exit 2; sha drift 1; deleted pin 1 `PIN_ABSENT`; unpadded stray 2; clean 0; `--json` `exit_code` agrees (2/2, pass 3, fail 1).
- **Padded twin + real pin deleted** -> both `PIN_ABSENT` and `UNSUPPORTED` fire, exit 2: the padded value cannot shadow a deletion.
- A *correctly valued* padded key still exits 2 — the exact-bytes contract is stricter than value-checking, matching the r28 precedent.

## Defects
1. **Mn/Mc/Me combining marks still silent at exit 0** (same never-silent-skip class, one category out). `omp_binary_sha256` + U+0301 / U+0308 / U+20D0 / U+0338, at trail and mid positions, and Greek Omicron `Οmp_…` (U+039F) and fullwidth `ｏｍｐ_…` all pass `OK 3/3`. Sharper than the r32-named Cyrillic debt: a combining mark can be appended to the *correct* ASCII key and renders nearly invisibly, so it is a one-keystroke laundering of a legitimate pin. Fix shape: extend `HYGIENE_CATEGORIES` to include `Mn`, or normalise (NFKC) before the exact-bytes test.
2. **Over-broad hygiene arm rejects prose keys.** `{"round 21 note": "x"}` -> exit 2 `pin key is not exact bytes: U+0020 Zs`; pre-r32 it was exit 0. Live `measured_against` free-text keys (`omp_round21_note`, `command`, `round18_move`) contain no spaces today so live is unaffected, but any future note key with a space hard-fails the guard with a pin-shaped error. Documented in the docstring but not scoped to pin-shaped keys.
3. **`--self-test` is not ENOSPC-safe.** Under `/tmp` inode exhaustion (86%, 896k/1M) `tempfile.TemporaryDirectory` raised an uncaught `OSError: [Errno 122]` traceback, exit 1, instead of a named failure. Environmental trigger, code-level robustness gap; `TMPDIR=/dev/shm/m9` made it green.
