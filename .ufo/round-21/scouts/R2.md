## Findings

### 1. Derivation vs script — what I got right

Committed blind model (`/tmp/r2-derivation.md`, written before the script was
opened) matched on: all 9 check ids and their modes; the exit-code contract
(0/1/2/3); the `{"observed","results"}` envelope; the `--self-test` scope
groups; the exclusion taxonomy (`<lane>` placeholders, `..`-segment ellipsis,
quoted meta-findings, globs, out-of-corpus prose); the commit regex semantics
(backticked token, `(?<![A-Za-z0-9_-])` lookbehind keeping `pre-commit` out);
hex = 7–40 chars; `report_pointer_shapes` as the readable surface for pointer
form; the `git ls-files` scope gap.

### 2. Derivation vs script — what I got wrong (diff items)

1. **Envelope shape.** I predicted `observed.pointers` as a sibling of
   `observed.corpus`; the script emits a single `observed.corpus` with every key
   flat (`:986`). The round-11 artifact's `json.load(...)["observed"]["corpus"]`
   example is the accurate one.
2. **`--baseline <path>`** exists (`:955`) and I did not derive it.
3. **The pointer scanner is not backtick-gated** (`UFO_POINTER_RE`, `:134`),
   unlike the INDEX family which explicitly harvests backticked File-cell
   tokens (`BACKTICK_RE`, `:292`). Live consequence: 7 of the 40 harvested
   tokens sit in bare prose (`corpus/knowledge/cold-run-round11.md:65,66,85,100,
   141,142,280`), 3 of them in the *checked* population.
4. **`PLACEHOLDER_MARKS`** (`:120`) is wider than my `<`/`>` prediction: `…`,
   `$`, `\` too.
5. **Naming.** I predicted a `commit_quoted` counter; actual keys are
   `commit_quoted_excluded` + `commit_quoted_detail` (`:397`), and the report
   analogue is `report_pointers_quoted` (`:388`).
6. **Ordering.** `is_excluded_pointer` is tested *before* `inside_quotes`
   (`:362`–`:367`), so a quoted placeholder is counted as excluded, never as
   quoted context.
7. **`evaluate` asymmetry** (`:552`): a baseline missing one check *id* is
   tolerated (`expected=None` → DRIFT), a baseline missing the `checks` object
   is not (KeyError, see D1).
8. `corpus_md_files` appears only in the human line, not in `CHECKS` (`:507`).

### 3. Live state at HEAD — all nine baseline expectations hold

### 4. Before-state numbers: 8 of 9 reproduce, `report_dead` does not

`index_patterns=32`, `report_total=19`, `excluded=1`, shapes `[relative=9,

`/home/vgpnk/projects` no longer exists on this host (`/home/vgpnk/Projects`

capital `Projects` + 4 lowercase occurrences that are all prose about the dead
paths (`checklist-execution-round17.md:263`, `corpus-integrity-round11.md:110`
and `:131`, `claim-census-round12.md:40`) and correctly outside the checked

## Defects named (each: path:line + evidence)

**D1 — an unreadable/malformed baseline exits 1 with a traceback, colliding
with the documented "drift" code.** `verifiers/verify_corpus_integrity.py:990`
(`baseline = json.loads(baseline_path.read_text())`, outside any `try`) and
`:552` (`baseline["checks"].get(...)`, no guard on `checks` itself). Evidence:
`--baseline /tmp/r2-probe/corrupt.json` → `json.decoder.JSONDecodeError …
line 1 column 2` traceback, exit **1**; `--baseline /tmp/r2-probe/no-checks.json`
→ `KeyError: 'checks'` traceback, exit **1**. The script's own contract
(`:82`–`:87`) reserves 1 for drift, 2 for "environment unreadable", 3 for "no
baseline"; a corrupt baseline is none of these, and CI reading the exit code
alone reports a corrupt baseline as corpus drift. Contrast the graceful paths
that do exist: absent baseline → exit 3; missing repo/corpus/index → exit 2.

**D2 — the human summary conflates the commit-quoted counter with the pointer
family's.** `verifiers/verify_corpus_integrity.py:1011`–`:1012` prints
`quoted-excluded={obs['commit_quoted_excluded']}` inside the *pointers*
parenthetical, next to `pointer-excluded={obs['report_pointers_excluded']}`;
`report_pointers_quoted` is never printed in text mode. Evidence: live line reads
`quoted-excluded=2, pointer-excluded=8` while `--json` shows
`commit_quoted_excluded=2` and `report_pointers_quoted=0`. The round-11
artifact quotes this same line (`corpus-integrity-round11.md:171`, `:176`), so
the ambiguity propagates into the record: a reader cannot tell from the line
whether the quoted-context rule fired for pointers at all.

**D3 — the round-11 red-before block is not reproducible at HEAD's host; its
`report_dead` value is host-path-dependent.** `corpus/knowledge/corpus-integrity-round11.md:122`
("8 × host-absolute and 1 × `~`-anchored: all resolving") and the before-block
at `:168`–`:173` (`report_dead=10/19`, `7/9 checks pass`). Evidence: the same
tree (`d49dfa5`, archive + `git init` + `git add -A` + history import) yields
`report_dead=19/19` with identical shapes `[relative=9, absolute=8, tilde=1,
bare=1]`; `test -d /home/vgpnk/projects` → absent, `test -d /home/vgpnk/Projects`
→ exists; the tree's 8 absolute + 1 tilde pointers are lowercase `projects`.
The summary line's *count* (`7/9`, DRIFT ids `report_dead` + `commit_nonhash`,
exit 1) still reproduces — only the value moved. This is the artifact's own
named "machine-local convention" gap made concrete: 9 of 19 checked pointers
flipped dead when the host root changed case, and nothing in the artifact
records that dependency at the point of the claim.

**D4 — latent: the coverage-map parser is not markdown-aware.**
`verifiers/verify_corpus_integrity.py:286` (`cells = line.split("|")`). An
escaped `\|` (or a `|` inside a code span) *upstream* of column 2 shifts
`cells[2]`, so the wrong text would be harvested as the File token. Evidence it
does **not** fire today: `corpus/README.md:18` contains the corpus's only
escaped pipe, but it lands in `cells[3]`/`cells[4]` (split gives 6 cells;
`cells[2]` is still `` `knowledge/claude-md-surface.md` `` and that token is
harvested). Zero live impact; named because the round-11 artifact documents the
escaped-pipe failure mode for a *different* command (`:59`–`:69`) and this is
the same hazard one layer down.
