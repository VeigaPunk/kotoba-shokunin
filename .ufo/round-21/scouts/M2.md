## Findings
- **Non-vacuity confirmed.** Every mutation flavor of the catalogue-cache anchor flips the gate to non-zero: missing file → exit 2 naming the path; content corruption → exit 2 (sqlite error, path unnamed); row-level corruption → exit 1 with six named DRIFT checks. The 28/28 pass at HEAD is a live measurement, not a vacuous pass.
- **Copy fidelity established first.** Copied script/baseline/db are byte-identical to live (shas above) and the intact-anchor control run reproduces the live verdict exactly (`28/28`, exit 0), so the FAILs are caused by the mutations, not by the copy setup.
- **The catalogue check measures the cache, not the sessions**: gutting the cache dropped `omp.catalogue.matched` 7→0 and `missing_names` to all seven names while the session scan stayed identical (763 files, same `2026-10-15T05:02:56.169Z` block). The one-row probe names the exact skill (`godspeed`) that lost its cache entry.
- **Exit-code contract matches the module docstring** (`verify_harness_claims.py:28-30`): 2 = environment unreadable (v1–v3), 1 = drift (v4–v5), 0 = agree (controls). `--self-test` 0 failures / 10 assertions.
- Side-effect note (environment, not repo): the db is WAL-mode — opening the *copy* read-only created `db_intact.db-shm`/`-wal` beside it in `/tmp`; a `-shm` beside the live db was refreshed during the probe window (my live control run and/or concurrent lane runs; attribution not established). Live db **main-file** sha is unchanged before/after (`b62dfed8…`).
