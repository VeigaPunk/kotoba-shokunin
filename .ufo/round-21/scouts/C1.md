## Findings

### Claim F — verdict: **unsound as written**

1. **The after-clause's first conjunct is already false at HEAD.** "All six instruments
   exit 0 at 4e92f36" cannot hold: `verify_skill_checklist.py` exits 1 (`trigger.line_budget`,
   SKILL.md 601 > 600, #3) and `verify_surfaces.py` exits 1 (8 omp loader literals, #4).
   Four of six are green (#14–#17; surfaces' opencode half passes, the omp half does not).
   The falsifier ("any gate exit != 0 at HEAD") is therefore satisfied *before the round starts*,
   while the after-clause's escape ("repaired in-round or recorded as named debt") is the only
   path to satisfaction. Claim and falsifier contradict each other; a round can self-grade either
   way. This is the central F defect.
2. **The substrate moved and nothing in the sweep can see it.** Live omp sha
   `bf1e86a9…` (#5, mtime 2026-10-16, version 18.11.1) ≠ round-18 pin `ff59fc1b…`
   (`verifiers/baseline.json` `measured_against.omp_binary_sha256`). No LOG.md or corpus line
   records `bf1e86a9` (grep over `*.md`/`*.json`: only another scout's fragment). The pins are
   **inert**: no script consumes `omp_binary_sha256`/`opencode_binary_sha256` (grep over
   `verifiers/*.py *.sh` → no match; harness `checks` list has no binary-sha key), and the harness
   passes 28/28 while the binary has moved (#16). So "substrate versions re-measured" needs an
   explicit sha256 command in the counting command — the existing gates cannot supply it.
3. **The 601>600 red is a standing instruction not to rerun.** `SCORECARD.md:60-61`:
   "Do not rerun that unchanged failure merely to confirm it or raise the budget";
   `corpus/lessons/round-19-recensus.md:27-28` records it as pre-existing. F's counting command
   ("expect all 0") would either rerun it (against instruction) or force an unclaimed SKILL.md
   repair (operability surface) inside a freshness round.
4. **Pinning to 4e92f36 leaves the shipped tree uncertified.** Any repair the round lands
   (omp re-anchor, baseline re-record after A's corpus entry) moves HEAD; the Gate standard says a
   verdict names the revision it was measured against. F's observable must require a sweep at the
   **landing commit**, not only at the dispatch HEAD.
5. **Minor — "before" imprecision.** "round-20 was dispatch-blocked with zero fresh sweep"
   (`claims.json:34`) overstates: `.ufo/round-20/acceptance-results.json` records corpus integrity
   9/9, independent exit 0, corpus self-test, and frozen smoke at `292bbf8`
   (also `SCORECARD.md:104-108`). Accurate wording: no sweep at HEAD; a corpus-only partial sweep
   at 292bbf8.

### Claim A — verdict: **sound-with-conditions**

1. **The measurement is executable live — I executed it.** Live per-sibling unresolved:
   kagi 2, kake 1, kasegi 5, kengaku 1, kumitate 5 (14 total, 245 subjects) (#11/#12). All five
   siblings exist and are readable. No sibling repaired itself: kasegi/kagi/kumitate bytes are
   unchanged, and kake/kengaku changed bytes without clearing their cited sites (kake line 78
   same; kengaku's brace-set token persists, moved 578 → 640).
2. **But the committed counting command cannot do it.** The count-code's live mode exits 1
   `source_drift` (#10) because kake and kengaku digests changed (#13) — its own message says
   "reclassify changed inputs before comparing"; frozen mode deliberately never re-probes live
   sources (#9). So A's counting command as written ("extract repo-rooted tokens … compare to
   round-16 counts") is not the committed predicate's live path; the round must produce a **new
   observation**, which is a different evidence class than "delta vs round-16".
3. **The baseline row itself is unreproducible.** `SCORECARD.md:34` records "kasegi 1"; the
   committed evidence file's frozen replay at HEAD returns **kasegi 5** (#9), and the same
   instrument sha (`02ccf1b3…`, matches HEAD and 292bbf8) run live against kasegi's *unchanged*
   SKILL.md returns 5 (#11). Round-16's own packet already says the "10 dead" row "is not a
   semantic defect census" (`corpus/knowledge/sibling-citation-routing-round16.md`, Claim and
   boundary). A delta computed against `SCORECARD.md:34` therefore contains a spurious
   kasegi +4 that is a denominator artifact, not sibling drift.
4. Conditions for soundness: (a) declare the predicate/denominator (gate check
   `trigger.citation_resolves` vs the packet's occurrence units) and record that the SCORECARD
   row's kasegi 1 is not reproducible by the committed instrument; (b) record subject movement
   (226 → 245) alongside unresolved; (c) do not present a kasegi delta as sibling change.

- The two claims measure different surfaces, but neither is cleanly separable at the landing
  commit. A's "corpus knowledge entry lands" changes `corpus.index.tracked_files`, pinned
  `equal 51` (`verifiers/corpus-baseline.json`); without a re-record the corpus gate reddens at
  A's landing commit — A would harm F's axis. Round-16's precedent (`e80f5f5`) is exactly this
  re-record. Conversely F's own LOG/SCORECARD appends grow the governance population (154 at
  HEAD, #3) and can redden `governance.citation_resolves` at the landing commit (round-16's
  "check reads the file under construction"). Neither claim's falsifier covers a red landing
  commit; `claims.json`'s separability sentence ("neither claim's verification depends on the
  other landing") is true only for the pre-landing HEAD, which is the uncertified revision

  (`../.ufo/reports/round-7/kotoba.md`) and the LOG/SCORECARD governance cites resolve against
  the **fleet root outside this repo**; the /tmp copy proves layout sensitivity (copy run #18 red
  on exactly those checks, live green).
