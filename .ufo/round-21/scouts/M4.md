## Findings

### M4 verdict — the box-map predicate is live, and it fails in both directions

Core probe `reword` (one word swapped at SKILL.md:292):

```
FAIL checklist.box_map_complete: evaluated 41 — map entry trigger.06 has no live box
(section 'Trigger-fidelity checklist'); unmapped box at line 292 (section
'Trigger-fidelity checklist', sha256 d6428e6e1694…)      EXIT 1
```

The `--json` payload is the same single FAIL with `"exit_code": 1`. The predicate is
non-vacuous: it evaluates 41 live boxes, names the orphaned map entry (`trigger.06`) *and*
the newly unmapped live box with its sha.

Hash chain, re-derived independently of the instrument's own report:

```
pristine SKILL.md:292 sha256 = 60705f4fa4a2553774a63a9e2df780317ed521379fa1d5c62ddd5c85748403b5
map entry trigger.06 sha256  = 60705f4fa4a2553774a63a9e2df780317ed521379fa1d5c62ddd5c85748403b5  (equal)
mutant   SKILL.md:292 sha256 = d6428e6e169437f5e5c2d427c22ef4df04597e774abe52323ce1174eeac29851  (≠ map)
mutant text = 'Body opens with a single-line role statement, not a restatement of triggers.'
```

So the FAIL is exactly the box's normalised text leaving the map — not an artefact of
line numbering, sections, or the copy's path.

Controls, which bound the claim:

- `rewrap` — identical words, different line breaks — **PASS, exit 0**, 41 boxes mapped.
  Confirms the documented normalisation (continuation lines are joined before hashing), so
  the `reword` FAIL comes from the text change and not from formatting churn.
- `addbox` — **FAIL, exit 1**, `evaluated 42 — unmapped box at line 292 (sha256
  47ece225b3de…)`. One direction only (the live box has no map entry).
- `dropsection` — **FAIL, exit 1**, all 15 `Trigger-fidelity checklist` entries orphaned
  (`map entry trigger.01…06 has no live box` … `(+32 more)`). Shows `section` is part of
  the parity key, so a heading rename invalidates a whole section's worth of map rows.

## Defects named

**D1 — `verifiers/fixtures/checklist/delegated-directory/map.json:15` delegates to a target
that has never existed in the repository, so the `--self-test` case is unreachable from a
clean checkout.**

```json
"disposition": "delegated:delegated-directory/probe-dir"
```

Evidence that the target is absent from the repository, not merely from this worktree:

- `git ls-tree -r 57f9e38 -- verifiers/fixtures/checklist/delegated-directory` → only
  `SKILL.md` and `map.json`.
- `git log --all --diff-filter=A --name-only -- '*probe-dir*'` → no output (never added in
  any commit).
- a walk of every commit's tree for that path → nothing found.
- live `ls -d verifiers/fixtures/checklist/delegated-directory/probe-dir` → *No such file or
  directory*; `find verifiers -type d -empty` → no output.
- `cp -a` of the repo reproduces the failure, so it is not a `git clean` artefact.

Consequence: the case is asserted twice — as the needle `["not an instrument"]` on the
`("delegated-directory", 1, …)` row at `verify_skill_checklist.py:1469`, and as the targeted
`rec(...)` at `verify_skill_checklist.py:1613-1614` requiring
`("not an instrument" in out) and ("Traceback" not in out)` — but the run takes the earlier
`does not exist` branch at `verify_skill_checklist.py:929-932` and both assertions fail. A bare empty directory cannot be committed to git, so this case can only ever pass in a
worktree where someone recreated `probe-dir` by hand. Minimal repair candidate (not applied —
out of this lane's write scope): point the disposition at a directory that *is* tracked, e.g.
`delegated:delegated-directory`, which exists and is a directory, so `is_instrument()` still
returns False; alternatively commit a placeholder file inside `probe-dir`.

**D2 — `LOG.md:848` and `SCORECARD.md:33` record a green `--self-test` that is false at HEAD
on byte-identical inputs.**

`LOG.md:848`: *"`--self-test` → **0 failure(s) over 1504 assertions**"*. `SCORECARD.md:33`
(round-17 calibration row): *"`--self-test` is 0/1504 over 71 fixture dirs"*. At HEAD the same
command reports **2 failures over 1504 assertions**. The inputs are provably the same
revision:

- `sha256sum verifiers/verify_skill_checklist.py` →
  `02ccf1b310f7910502f7938d24eb1cfcabe2c521ec42b7ce6420f1869af8df27`, character-for-character
  the hash `LOG.md:849-850` pins for the round-17 instrument.
- `git diff fad752b HEAD -- verifiers/verify_skill_checklist.py` → empty;
  `git diff fad752b HEAD -- verifiers/fixtures/checklist/delegated-directory/` → empty;
  `git diff 57f9e38 HEAD --` the same fixture dir → empty (unmodified since it landed in
  round 16).

The assertion total (1504) matching exactly rules out a revision difference: the two round-17
records were true only in a worktree carrying the untracked empty `probe-dir`. The correct
record is `2 failures over 1504 assertions`.

  retarget) — those classes already carry fixtures (`map-missing-entry`, `map-dup-box`,
  `map-annotation-mismatch`, `map-dead-delegated`) whose self-test assertions are exercised by

- **I did not verify the repair for D1.** `delegated:delegated-directory` is a reading of
  `verify_skill_checklist.py:917-939`, not a tested fix; no fixture was edited.
- **The live tree was never mutated.** Every tamper, run and capture lives under
