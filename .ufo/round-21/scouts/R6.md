## Findings

1. **The harness runs clean at HEAD, live tree included.** `--self-test` 4/4 PASS exit 0; the full
   run prints `verdict: ALL PASS` exit 0 both on a `cp -a` copy and against the live repo
   (10 worlds: `fault-0-control` + a,b,c,d1,d2,e,f,g,h). It reported
   `instrument_sha256=a32da4a4224e9810549016ec3000583f3068bf552d7a92b0666114c32476dd56`, byte-identical
   to the round-12 doc's pinned final author-instrument sha (doc line 16) — a freshness data point
   for claim F.
2. **Implementation ↔ doc, class for class (the diff):** all nine doc rows have a matching planter
   and a matching gating call (`plant_a` 169 / `plant_b` 176 / `plant_c` 181 / `plant_d1` 189 /
   `plant_d2` 194 / `plant_e` 203 / `plant_f` 211 / `plant_g` 220 / `plant_h` 228; calls at
   400–408). Class names match the doc exactly, including (h)'s `report_pointers_quoted` +1 with
   the checked population unchanged (live row: `PASS(context: quoted=1, checked=32 unchanged)`).
   The divergence is in **assertion strength**, not in class identity: D1, D2, D5, D6 below.
3. **All nine planter anchors are live and non-vacuous at HEAD**; each planter self-verifies its
   plant (grep of the file plus git state for d2/e/f), and `plant_f`'s host precondition holds
   (old path exists, new path absent) — so the green run is not an artefact of no-op planters.
4. **Doc numbers are round-12-era, as the doc's own per-round rule intends** (doc §3 lines
   161–163): live `report_total` is 32 (doc says 24); fault-f's live move is 32→31, fault-a's is
   33 with 1 dead. Not a defect — recorded so nobody reads the stale figures as a live drift.
5. **Round-17 changed only two characters of behaviour**: `plant_f`'s host path case
   (`projects` → `Projects`). Before that commit the (f) planter was `INVALID-PLANT` on this host.

## Defects named (each: path:line + evidence)

**D1 — `verifiers/fault_injection_corpus.sh:290-296`: the (f) verdict's "count detector" half is
vacuous; the row passes on any world whose baseline-mode exit is non-zero, for any class.**
`blind_total` is read from `$w/out.json` (line 290, the `--no-baseline --json` run); the
baseline-mode run writes `$w/out-baseline.txt` (line 291, no `--json`); `base_total` is then read
from `$w/out.json` again (line 293) — the same file, so `[ "$blind_total" = "$base_total" ]`
(line 296) compares a value to itself and cannot fail. Worse, `observed.corpus.report_total` is
mode-independent: in the clean run's fault-f world `out.json` says `report_total = 31` and
`out-baseline.txt` says `DRIFT corpus.pointers.report_total: observed=31 expected=32` — the
detector's signal is the *comparison* against the baseline's stored 32, which the harness never
parses. The comment at lines 11–14 and the doc row at line 134 both claim this half is what PASS
means. **Falsification (mutC):** `plant_f` replaced by "add a tracked+indexed corpus file; move no
pointer at all" → `fault-f | integrity | 0 | - | PASS(blind-spot documented: --no-baseline exit 0;
baseline-mode exit 1)` and `verdict: ALL PASS`, while that world's `out.json` `report_total = 32`
(identical to the control) and `out-baseline.txt` drifts on an unrelated equal-only class:
`corpus.index.tracked_files: observed=52 expected=51`. A correct assertion would pin the DRIFT id
to `corpus.pointers.report_total` (or compare the observed count against the baseline's stored
value).

**D2 — `verifiers/fault_injection_corpus.sh:262-270` (also 339, 343) vs doc line 123: "each
asserted against both instruments" is not implemented — the independent instrument is gated by
exit code alone, and exit 2 counts as agreement.** `fault_must_fire` treats any `indep != 0` and
`!= skip` as PASS (line 266-270); no class is ever read from the independent (it has a `--json`
mode, `verifiers/verify_corpus_independent.py:759`, so this is a choice, not a capability limit).
**Falsification (mutB):** the copy's `verifiers/verify_corpus_independent.py` replaced by a stub
`sys.exit(2)` that never reads the corpus → `fault-a | integrity | 1 | corpus.pointers.report_dead
| PASS` with `fault-a | independent | 2 | - | INFO(gating)`, and the same for b,c,d1,d2,e,f,h; the
run's only failures are `fault-0-control … FAIL-control-dirty` and `fault-g … FALSE-POSITIVE`. So
six must-fire rows report PASS while the second instrument is a stub. (The harness's own header,
lines 8–9, says only "must exit non-zero too" — the implementation matches that comment; it is the
doc's class-level claim and the round's evidence value that overreach. The overall exit code still
catches the stub through the control world, so this is a per-row false-pass, not a silent one.)

**D3 — `corpus/knowledge/independent-verification-round12.md:120`: the pinned sha256
`9bc80ae61cea…` is not a reachable object in this repo.** `git rev-parse --disambiguate=9bc80ae61cea`
→ empty; `git cat-file -t 9bc80ae61cea` → `fatal: Not a valid object name`; no object in
`git rev-list --objects --all` carries that prefix. The harness's only committed blobs are
`7026e73687692f98…` at 633859f (the round-12 landing) and `9db6c692c752f0fd…` at fad752b/HEAD
(round-17) — the pin matches neither, and the round-12 landing sha contradicts it directly. This is
the same defect class the same doc's §5 claims to have repaired elsewhere ("the cold-run record
claimed the shipped script was byte-identical to a pre-commit sha → replaced by the reachability
qualifier"), left standing in §3b.

**D4 — `corpus/knowledge/independent-verification-round12.md:123`: "Ten fault classes" is
unsupported by the doc's own table (nine rows, lines 128–136) and by the harness (nine planters +
one pristine control world, `verifiers/fault_injection_corpus.sh:399-408`).** The count is only
recoverable by silently counting `fault-0-control` as a class. The slice brief for this scout
inherited "10", which is how the ambiguity propagates.

**D5 — doc lines 131–132 vs `verifiers/fault_injection_corpus.sh:403-404`: the class sets are
asserted only positively, so the doc's parentheticals and "only" are descriptive, never enforced.**
(d1) doc: `stale_patterns` (+`missing_paths`); the harness gates d1 on `corpus.index.missing_paths`
alone (the live run does fire both — `fault-d1 | integrity | 1 |
corpus.index.stale_patterns,corpus.index.missing_paths | PASS` — but nothing requires
`stale_patterns`). (d2) doc: `stale_patterns` **only**; the harness asserts presence of
`stale_patterns` with no negative assertion. **Falsification (mutD):** `plant_d2` extended with a
second index row naming an absent file → `fault-d2 | integrity | 1 |
corpus.index.stale_patterns,corpus.index.missing_paths | PASS`, `verdict: ALL PASS` — the world
violates the doc's "only" and still passes.

**D6 — doc line 128 ("(baseline mode also `report_total`)") is never exercised:** `fault_must_fire`
(lines 247–273) runs only `--no-baseline`. I verified the parenthetical is true today (fault-a
world: no-baseline `report_total=33`, `report_dead=1`; baseline mode exits 1 with DRIFT
`corpus.pointers.report_total` observed=33 expected=32 **and** `corpus.pointers.report_dead`), so
this is an unasserted-but-true doc claim, not a false one — named so the round does not read the
green (a) row as covering it.

**Probe-design note (not a defect, kept so the record is honest):** mutA first tried a bare
backticked `round-99` token and nothing fired (baseline also 9/9). The `commit `…`` idiom is what
makes a token a citation; mutA2 used it and the harness correctly read
`corpus.pointers.commit_nonhash` with exit 1 — which also shows `--no-baseline` still DRIFTs
intrinsic classes (only baseline-relative `equal` checks are suppressed), the precondition that
makes (f)'s `--no-baseline exit 0` requirement a real constraint and forced D1's probe to use an
equal-only class.

## Limits (what I did NOT verify)

- **The derivation is not epistemically blind** (doc and harness read in one batch, see disclosure
  above). A lane given only the doc text would settle whether the "ten" reconciliation (control
  world as the tenth) is what a cold reader infers; I inferred it, I did not measure it.
- I did not re-run the harness under a host without the `/home/vgpnk/.../.ufo` tree, so the
  host-anchored resolution property (round-12 §3, `unshare -rm` world) is untested here; plant_f in
  particular is host-dependent by construction (`verifiers/fault_injection_corpus.sh:212-214`).
- I did not test the harness's `--repo` failure paths (unreadable repo, non-git dir, missing
  instrument/corpus → exit 2 guards, lines 59–63) nor `--keep-worlds` cleanup semantics beyond
  observing that worlds persist and `/tmp/round12-faults.*` are the only paths it writes.
- I did not verify the round-12 doc's §3b table against the round-12-era harness blob
  (`7026e736…`) beyond the round-17 diff (path-case only); the doc's numbers (24/23) were not
  re-measured at 633859f.
- Claim F (freshness) and claim A (adjacency) belong to other scouts; this fragment contributes
  only the harness row (ALL PASS at HEAD, instrument sha matching the round-12 pin) and the
  live-tree `__pycache__` observation (Finding 6).
