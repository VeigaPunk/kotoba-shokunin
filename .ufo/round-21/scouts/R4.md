## Findings

### 1. Blind-derived expected check set (derivation, before reading the script)
Enumerated from the two documents only:

1. `surfaces.table_parity` — inventory class-id set ↔ baseline id set, both ways (census:67, 272, 310).

3. `surfaces.no_uncovered_class` — omp `.md` call-shape extraction vs declared ids; described as
   "parity both ways", empty baseline → "extra row" findings (census:27, 37, 285, 292).
4. An unnamed 4th round-13 check implied by census:298-299 ("Reason truth … the checker only proves
   one exists") — an exclusion-reason check.
5. `surfaces.literal_parity` (census:31, 313-315).

7. `surfaces.opencode_extract` (census:28, 286-291).

### 2. Diff vs the script
Actual `CHECK_IDS` (`verifiers/verify_surfaces.py:160-168`): literal_present, no_uncovered_class,
opencode_extract, table_parity, literal_parity, kind_parity, excluded_reason → **7 = 7, one-to-one**.
Items 1,2,3,5,6,7 match by name; item 4 is `surfaces.excluded_reason`, whose code
(`:677-696`: non-empty reason AND the id occurs as an inventory table-row id) matches the derived
capability. **No missing check, no extra check.** Exit codes and the non-vacuity guards for
table_parity/literal_parity/kind_parity/opencode_extract match the census's description
(reproduced in probes #4/#5/#6/#3). Two checks are less guarded than the census's "never passes
vacuously" standard: `no_uncovered_class` and `literal_present` (defects D2, D3).

### 3. Live gate is RED at HEAD (claim F evidence)
`verify_surfaces.py` exits 1: `surfaces.literal_present` FAILs all 8 omp loader-group rows because
the extractor finds **0** pairs. Cause: the live omp binary moved (bf1e86a9…, omp/18.11.1, mtime
2026-10-16) past the round-18 pin (ff59fc1b…, 2026-10-14) and its registration callees renamed
again: `Id|Cl|jD[ef]|Tl|dr|GW` → `Dl|Co|Hj`. The shapes and literals are intact; only the callee
allowlist is stale. `surfaces.no_uncovered_class` reports **PASS** ("all 0 extracted … declared")
on that dead extraction — the gate is red only because `literal_present` independently requires
the call shape. opencode is unaffected: hash matches the pin, `opencode_extract` PASSes 6/6 rules /
5/5 declared ids, and every rule anchor is present in the live bytes (#16).

### 4. The inventory itself re-derives correctly
Raw-byte derivation finds exactly the 8 declared (group, file) pairs and nothing undeclared; an
in-memory allowlist re-pin makes the full gate exit 0 with `no_uncovered_class: all 8 extracted
loader class(es) declared`. So the census tables/baseline are right at HEAD; the extractor's
allowlist is the sole blocking defect.
