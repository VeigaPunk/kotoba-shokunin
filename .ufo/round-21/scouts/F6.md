## Findings

**F1 — the live gate is RED at HEAD, on exactly one check.** `SKILL.md` is 601
lines; the checklist box at `SKILL.md:329` reads `File ≤ 600 lines`, and
`trigger.line_budget` reads its threshold from that box (`from box at line
329`). Everything else is green and non-vacuous (41 boxes, 552 scanned lines, 15
command segments / 19 subjects, 42 + 154 citation tokens). Exit code 1.

**F2 — the red is round-18's, and the round-18 record claims green.**
`git show <c>:SKILL.md | wc -l` per commit: `0089974` (r15) 599, `57f9e38` (r16)
599, `fad752b` (r17) 599, **`02302c5` (r18) 601**, `4e92f36` (HEAD) 601; the
parent of `02302c5` is 599 and probe 10 runs that file with
`line_budget … PASS … 599 lines within budget 600 (from box at line 327)`.
`LOG.md:952` records round 18 as "`verify_skill_checklist.py` — unchanged, `exit
0`". That verdict is false at round 18's own landing commit `02302c5` and at
HEAD: exit is 1. Round 15's LOG entry (`LOG.md:560-562`) shows the intended
discipline ("Landed: 599 lines, live run `exit 0`") — the r18 edit added 2 lines
and no re-run was recorded.

**F3 — `--self-test` is RED: 2 failures / 1504, root-caused and closed by
mutation.** Both failures are the single fixture `delegated-directory`, whose map
(`verifiers/fixtures/checklist/delegated-directory/map.json:15`) delegates
`fixture.02` to `delegated-directory/probe-dir`. That directory does not exist on
disk: `git ls-files verifiers/fixtures/checklist/delegated-directory/` returns
only `SKILL.md` and `map.json`, and `git log --all --diff-filter=A --name-only`
over that path shows the same two files — `probe-dir` was never tracked (git
cannot store an empty directory, so the author's local empty dir never survived
the commit). The run therefore takes the `candidate.exists()` branch
(`verify_skill_checklist.py:929-932`) and reports "does not exist" where both
assertions require "not an instrument" (`:1469-1470` and `:1612-1614`). Probe 9
is decisive: creating that one empty directory in a `/tmp` copy turns the
self-test green — `0 failure(s) over 1504 assertions`, exit 0. Consequence: the
directory branch of `is_instrument` (`:704`, `if not path.is_file()`) is
exercised by no fixture at all; the other delegated fixtures cover the
suffix/shebang/ELF paths (`delegated-py-suffix`, `delegated-elf`), the
non-suffixed file path (`delegated-noninstrument`), the escape rule
(`delegated-escape`) and the missing-target rule (`map-dead-delegated`) — I
checked every `"delegated:` disposition in the fixture tree, and
`delegated-directory/probe-dir` is the only target missing by accident. The
live map has `0 delegated` entries, so this fixture was the only coverage of
that branch.

**F4 — `--self-test` is not hermetic: its verdict depends on whether a `.git`
ancestor exists.** Exporting the same HEAD with `git archive HEAD` (no `.git`)
and running `--self-test` there yields **110 failures over 1504 assertions**
(exit 1) against 2 failures in the `cp -a` copy. Mechanism:
`find_repo_root()` (`:386-392`) falls back to the *skill file's own directory*
when no ancestor carries `.git`; for each fixture that makes `repo` == the
fixture dir, so `governance_enabled` (`:1755-1756`) becomes true and
`governance.citation_resolves` runs against `…/fixtures/checklist/<case>/LOG.md`
and `SCORECARD.md`, which do not exist → `FAIL … unreadable governance file(s)`,
one per case, plus the `clean` case's exit flipping 0 → 1. The `--self-test`
rc is documented (`:249-250`) as not comparable to a live run's, but nothing
documents the checkout-form dependency. Practical effect: any future "self-test
0 failures" claim must state the checkout form; a source export, tarball or
container `COPY` of this repo self-tests red for a reason that has nothing to do
with the code.
