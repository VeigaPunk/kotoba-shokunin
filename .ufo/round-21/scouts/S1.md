Two structural notes on "commit":

  `omp_binary_sha256`. There is no omp source checkout on this host, so no upstream

## Defects named (each: path:line + evidence)

**D1 — stale callee allowlist; the live surfaces gate FAILs.**
`verifiers/verify_surfaces.py:144-148` (`CALL_RE`, callee alternation
`(?:Id|Cl|jD[ef]|Tl|dr|GW)`). Evidence: command 9 returns 0 hits; command 11 reports
`surfaces.literal_present` FAIL naming all 8 loader-group ids; command 10 shows all 8
`(group, file)` pairs present as `Co`/`Dl`/`Hj` calls in the same dump. Fix is a one-line
allowlist re-pin plus a fixture (D3), not a loader re-derivation.

**D2 — `no_uncovered_class` passes vacuously on an empty extraction.**
`verifiers/verify_surfaces.py:521-531`: `check_no_uncovered_class` computes
`uncovered = found - declared` and `return True, "all %d extracted loader class(es)
declared" % len(found)`; with `found == ∅` it returns PASS. The module docstring
(`verify_surfaces.py:95-107`) already names this exact vacuity for the *opencode* half and
installs a floor there — "an extraction producing 0 classes while the baseline declares
opencode classes is a FAIL (the vacuity the check exists to kill)" — but no equivalent
floor guards the omp half, even though the omp baseline declares 8 loader-group classes.
Evidence: command 11, `surfaces.no_uncovered_class` → `status: PASS`,
`detail: "all 0 extracted loader class(es) declared"`. This is what let D1 ship silently.

**D3 — fixture gap: the round-18 callee re-pin was never fixture-covered.**
`verifiers/fixtures/surfaces/` (no file contains a `Tl(`/`dr(`/`GW(` call).
Evidence: command 14 → no match; `strings-omp-clean.txt` still uses `jDe`/`Id`/`Cl`
(`verifiers/fixtures/surfaces/strings-omp-clean.txt:4,7,9`). Consequence: command 12
reports `0 failure(s) over 70 assertions` on the same tree where command 11 exits 1 — the
self-test is structurally blind to the failure mode it most needs to catch (minified

**D4 — census errata claim falsified at the live binary.**
`corpus/knowledge/instruction-surface-census-round13.md:11-14`: "omp `55016ef531…` →
`ff59fc1b48…` (2026-10-14) … **§ A stays live** — the same `.md` registration shapes

## Limits (what you did NOT verify)

- **No omp source or upstream commit.** Only the version string, binary sha256 and ELF
  BuildID are nameable. The intermediate `ff59fc1b` build's *version* is unrecoverable
  from this host (no prior `~/.omp/natives/` dir, no pre-2026-10-16 logs, no version
  string in the repo) — so "18.4.2 → ? → 18.11.1" has a hole in the middle.
- **The old binaries are gone.** `ff59fc1b` was overwritten in place, so I could not
  re-run the round-18 allowlist against it to confirm `Tl|dr|GW` was correct *then*. I
  infer it from `LOG.md` round 18's "7/7 surface checks pass" and from the census errata's
  explicit re-pin note; I did not re-derive it.
- **Registry descriptions are not proof of loading.** F-2a proves the census's quoted
  strings are still present in the binary. It says nothing about whether those loaders
  fire at runtime or reach a prompt — the census's own § Honest ceiling applies unchanged,
  and § A3's wire-level probe was not re-run.
- **§ C exclusions not re-adjudicated.** The 15 extra `Load …` descriptions I saw in the
  live stream were not checked against the census's § C excluded list. If any of them is
  *not* declared excluded, that is a `no_uncovered_class`-class finding that **D2 would
  currently hide** — worth an explicit pass next round.
- **`no_uncovered_class` was not mutation-tested.** D2 is argued from the code path and
  the live `detail` string (`all 0 extracted …` → PASS), not from a mutated copy. I did
  not `cp -a` the repo into `/tmp` to prove a 0-extraction tree passes; the live run
  already *is* the 0-extraction case, which is why I judged the mutation probe redundant.
- **`surfaces.literal_present` fix not attempted.** This slice is read-only; no allowlist
  re-pin, no fixture, no census errata was written. D1/D2/D3/D4 are named for the round's
  owner, not repaired.
- **Only 25 of the 41 census classes spot-checked** (the ≥8 floor exceeded; 8 loader-group
  + 17 loader-literal, biased toward § A's two tables). The § A2 provider-priority table
  and § A3 wire findings were **not** re-measured at all.
- **`omp --version` is the only runtime probe run.** No live omp session was started for
  this slice; the version string was not cross-checked against a session banner.
