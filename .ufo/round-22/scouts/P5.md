## Findings

- **Prototype works end to end, both directions.** Exit 0 on the live baseline (3/3 pins hold);
  exit 1 with the exact failing pin named on the `FAIL` line and the `DRIFT` summary for both a
  wrong sha and a drifted mtime; exit 2 for unreadable baseline and for a vacuous pin set.
- **Live substrate matches the round-21 re-pins exactly at round 22 start**: omp sha
  `bf1e86a9…4974` and mtime `2026-10-16T05:15:11.226207850-03:00` (delta 850 ns), opencode sha
  `d9123b9b…18c9`. (Side-finding for the freshness lanes: nothing moved between round 21 and now.)
- **P5 design choices** (the slice asked for independent choices):
  - pins discovered generically by key regex `^(omp|opencode)_binary_(sha256|mtime)$` against a
    fixed prefix→binary map (`omp` → `~/.local/bin/omp`, `opencode` → `~/.opencode/bin/opencode`,
    same constants as `verify_harness_claims.py:63-66`); unknown/documented keys are ignored;
  - sha256 compare is exact; mtime compare is exact at µs resolution with 2000 ns tolerance —
    justified by a measured fact: `datetime.fromisoformat` truncates the 9-digit fraction to µs,
    dropping the pin's trailing 850 ns, so a 0 ns tolerance would false-positive on the
    correctly-pinned value;
  - zero recognized pins is exit 2 (`VACUOUS`), never a vacuous pass — the round-21 vacuity-guard
    lesson applied preemptively;
  - `--baseline` default is `Path(__file__).resolve().parent / "baseline.json"` (house idiom,
    cf. `verify_harness_claims.py:69`) so the landed copy resolves next to itself; the /tmp
    prototype is run with an explicit `--baseline`;
  - exit-code table mirrors the house convention: 0 hold / 1 drift / 2 unreadable environment;
  - one deliberate omission vs the other guards: no `--self-test` mode (the six /tmp probes above
    are the behavioural evidence; a self-test is the obvious landing hardening).
- **This is prototype-only, /tmp-only.** Nothing was added under `verifiers/`; landing it (plus a
  checklist/surfaces wiring decision) is a future round's capability claim.
