### 2. Design notes for the prototype→landing handoff

**(a) Check set (v1; prototype state).** The prototype wave already specified
and built this — the landing round should land that spec, not re-derive it:
spec `P1.md` (inputs/outputs, 19 probes), live prototype
`/tmp/check_substrate_pins.py` sha256
`9262771020da1b7bb6b50e0598409ded61c5d455594eab7c508d0221fc4e341f` (built by
P5, green control in P6), fixture design `P4.md` (`--self-test` → `0
failure(s) over 23 assertions`), path discovery `P2.md`. Check set:
`pins.present` (PIN_ABSENT → exit 1 — "deleting a pin must be as loud as
drift", `P1.md` F3-probe; round-21's vacuity lesson is the same rule);
`omp_binary_sha256`; `omp_binary_mtime` (**nanosecond-exact parse required** —
`P1.md` cmds 5–6: a naive float parse is 874 ns off and fabricates a DRIFT on
a faithful pin); `opencode_binary_sha256`; optional `pins.versions` once
version keys are added to `measured_against` — today neither version is
pinned (only prose `round18_move` says v2.0.26; `F1.md` limits: "no round-18
version string is recorded"), and `verify_harness_claims.py:478`'s
degenerated builtin probe (R1 defect 6, `customize-opencode` 0× in v2.0.26)
is the blind class a version pin would close. Prototype flag names:
`--baseline`, `--omp-binary`, `--opencode-binary` — keep them or record an
explicit rename (the harness idiom is `--omp-bin`/`--oc-bin`,
`verify_harness_claims.py:626,629`).

**(b) Exit table (prototype contract, `P1.md`).** 0 all pins equal; 1 DRIFT
naming each moved pin (and PIN_ABSENT) plus the remedy (re-record + mechanism
note); 2 environment unreadable (binary absent / stat fails — fail-closed;
kake precedent `../kake-shokunin/scripts/freshness-sweep.mjs:1323-1324`
"malformed pins JSON -> exit 2 (never silent defaults)", `:102`); 3 baseline
absent/unparseable/no `measured_against` object; precedence 3 > 2 > 1 > 0.
**Do not replicate** the harness's `--json --no-baseline` → exit 0 defect
(`F1.md:186-199` D2; `R1.md:153-159` item 8) — the prototype's JSON path
already returns the same code as its text path (`P1.md` cmd 18); keep that.

**(c) Fixtures must be committed files.** `P4.md`'s design is the model: a
93-byte `mini.bin` (`sha256 d3b4640ed5eb408197d7922ca1f2984d93fe7d7cbeb60c831f43f65c3952705c`)
plus per-case pins files — match → 0, sha drift (bytes appended, mtime
restored) → 1 naming the pin, mtime-only drift → 1, missing binary → 2.
Round-21's lesson applies directly: an *empty directory* cannot survive git
(`probe-dir` made `0/1504` false in any clone), so every fixture artifact
lands as a non-empty tracked file under `verifiers/fixtures/pins/`.

**(d) opencode mtime is not a witness.** Live `stat` gives
`1985-10-26 05:15:00.000000000 -0300` — a build-epoch constant, not a build
time (measured this slice). The guard pins opencode by sha only; mtime
equality is meaningful for omp alone (its mtime is a real 2026-10-16
timestamp).

**(e) Red-before is replayable live.** `/tmp` copy of `baseline.json` with
`measured_against.omp_binary_sha256` set to the round-18 pin
`ff59fc1b484c1308a7247ad208305005627b3fac62b440737c2b1835ac32074e`
(`F1.md:57`) → the guard must exit 1 `DRIFT omp_binary_sha256`. That is the
exact state the 2026-10-16 rebuild created while `verify_harness_claims.py`

already demonstrated all these red classes (`P6.md`: sha mismatch → exit 1
naming the pin; missing binary → exit 2; schema-less baseline → non-zero,
no traceback; P5 cites the mutated-copy DRIFT), and the green control is
`P1.md` cmd 7 / `P6.md` cmd 1 — **the landing round must reproduce them
in-round from the landed script, not cite the /tmp prototype**.

**(f) Host-anchoring disclosure.** Defaults are absolute host paths
(`verify_harness_claims.py:52,55`); a clone's green is not hermetic — the
corpus instruments record this same residue
(`corpus/README.md:37`, "pointer resolution is host-anchored"). The guard's
docstring must say so, and its fixture overrides (`--baseline`,
`--omp-binary`, `--opencode-binary`) are what the self-test rides on.
