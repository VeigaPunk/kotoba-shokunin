## Defects named (each: path:line + evidence)
- **D1 — `/tmp/check_substrate_pins.py:78-80`:** `pins = baseline.get("measured_against", {})` (line 78) defaults only when the key is *absent*; a present-but-non-mapping value flows into `for key in sorted(pins):` (line 80) -> uncaught `TypeError: 'NoneType' object is not iterable` (c3-baseline.json, `{ "measured_against": null }`) and `TypeError: 'int' object is not iterable` (c4-baseline.json, `{ "measured_against": 5 }`). Evidence: commands 12-13 above — traceback on stderr, exit **1**. This both contradicts the script's own docstring contract (lines 21-23: "2 environment unreadable (… missing/unparseable baseline …)") and collides with the documented `1 = drift` code, so a schema-corrupt baseline is indistinguishable from pin drift by exit code alone. Hardening for the landing round: guard `isinstance(pins, dict)` at the top of `check_pins` and emit the `UNREADABLE`/`VACUOUS`-style stderr + exit 2 (and reject non-string pin values the same way).
- Not a defect, recorded as a silent-coverage boundary: `/tmp/check_substrate_pins.py:37-44` hardcodes `BINARIES={omp,opencode}` and `PIN_RE ^(omp|opencode)_binary_(sha256|mtime)$`; a future third substrate pin (e.g. `cursor_binary_sha256`) would be skipped silently while the script exits 0, as long as >=1 recognizable pin remains. Documented ("pins are discovered generically": any key matching the regex) but runtime-silent; a future landing should either extend the registry or fail on unmatched `_binary_sha256`-looking keys.
