## Defects named

- **D1 — `SKILL.md:93`** (in-range craft cell): `All craft below (frontmatter, tables,
  gates)` is a forward reference into `SKILL.md`; it is the only byte of the 92 that
  cannot move verbatim (diff shows exactly 1 changed line). Evidence: § 2, command #17.
- **D2 — `SKILL.md:50` and `SKILL.md:266`**: two in-file pointers name the section by
  title; after the move they point at a heading that no longer exists in the file. No
  instrument checks section-name pointers (only path tokens), so this is manual.
- **D3 — `corpus/knowledge/claim-census-round12.md:102`**: the recorded re-derivation
  command uses the section heading as an `awk` range end-marker; post-move the same
  command returns 20 instead of 9 (live 9 / post-move 20, #10). A recorded command that
  changes meaning without failing is the round-12 claim-scope class again.
- **D4 — `corpus/knowledge/instruction-surface-census-round13.md`** (10 `§ Instruction
  surfaces → …` cells, e.g. line 73–80): the `governed by` column is census cell 3 and
  is **not** compared by `verify_surfaces.py` (cells 1 and 2 are), so post-move these
  10 pointers drift silently and the instrument stays green. Evidence: § 4, run #14.
- **D5 — coverage loss, not a defect but must be recorded**: 8 resolvable citations
  leave `trigger.citation_resolves`'s population (42 → 34) and the corpus verifier does
  not check body citations in `corpus/knowledge/*.md` (`corpus.index.*` covers README
  FILE-column patterns; `corpus.pointers.*` covers report/commit pointers only).
  Evidence: run #16 + `verifiers/verify_corpus_integrity.py:6-29`.
- **D6 — sequencing hazard**: `corpus.index.stale_patterns` is "present on disk but
  untracked" (`verifiers/verify_corpus_integrity.py:607`), so splitting the corpus file
  and its README row across commits leaves the gate red. Evidence: run #15.
