## Findings

### F1 — CLI contract (the deliverable)

`verifiers/check_substrate_pins.py` — argparse surface (verbatim from the prototype
`build_parser()`):

```
--repo PATH             default: script's grandparent (same as verify_surfaces.py:7)
--baseline PATH         default: <repo>/verifiers/baseline.json
--omp-binary PATH       default: /home/vgpnk/.local/bin/omp   (override for fixture testing)
--opencode-binary PATH  default: /home/vgpnk/.opencode/bin/opencode
--check ID              append/choices pins.declared|pins.binary_sha256|pins.binary_mtime; default all
--self-test             fixtures only; scratch under /tmp
--json                  machine-readable output
```

Exit codes follow the model exactly (`verify_surfaces.py` docstring, lines 99-103):
**0** all checks PASS | **1** any FAIL (drift or vacuity) | **2** environment
unreadable (a pinned path missing/unreadable, an OS-level baseline read error —
never a pass) | **3** baseline missing/unparseable (bad JSON, no
`measured_against`, pin-shaped key that is not a pin, unknown subject, malformed
sha256/mtime value). Read-only, deterministic, runs no subprocesses. Text output
`"%s %s: %s" % (status, id, detail)` per check; JSON via the shared
`emit_json` shape. Text goes to stdout, `ERROR …` to stderr, for both exit 2 and
3 — matching the model.

Pin grammar (fail-closed): a key of `measured_against` is pin-shaped when it ends
in `sha<N>` / `hash` / `digest` / `mtime` / `binary`. A pin-shaped key must match
`<subject>_binary_sha256` (64 lowercase hex) or `<subject>_binary_mtime`
(ISO-8601 with offset, fraction up to ns), with a subject resolvable to a path
(omp, opencode). Anything else is rejected at load (exit 3) — a mistyped pin key
must never degrade to free text. Non-pin-shaped keys (`command`, `note`,
`round18_move`, `omp_round21_note`) are counted and reported, never interpreted.
`measured_against.command` is never executed (read-only guarantee).

Check semantics:
- `pins.declared` — at least one declared pin exists; detail reports pin count,
  subjects, and ignored free-text keys. Zero pins = FAIL (vacuity: a baseline
  that pins nothing is not a pass).
- `pins.binary_sha256` — per pin: sha256 of the subject's live file == pin; on
  drift the detail carries both full 64-hex values. 0 sha pins = FAIL (vacuity).
- `pins.binary_mtime` — per pin: `os.stat().st_mtime_ns` == pin's integer ns; on
  drift the detail carries pin string, both integer ns, and delta.

Design decisions recorded for the claim round to settle:
1. mtime is compared EXACTLY at ns (see F3). Strictness has a cry-wolf edge: a
   byte-identical rebuild changes mtime only. Prototype keeps it strict (the
   round-18/21 re-pin workflow is the remedy); an advisory variant is a one-line
   change if the claim round prefers sha-only enforcement.
2. `--check` is kept for model parity (`verify_surfaces.py:920-922`); per-check
   emptiness is a FAIL so a selected run cannot pass vacuously.
3. `--repo` exists for default-path parity even though explicit `--baseline`
   makes it unused in the self-test.

### F2 — `--self-test` design (fixtures + fake binaries under /tmp, no real binaries)

Committed fixtures under `verifiers/fixtures/pins/` (design; staged at
`/tmp/p3/fixtures/pins/` in the prototype):

| fixture | role | key content |
|---|---|---|
| `fake-omp.bin` | fake binary, bytes `fake-omp v1\n` | sha256 `fb0a69ae…babc28` |
| `fake-opencode.bin` | fake binary, bytes `fake-opencode v1\n` | sha256 `cccbae2b…813219` |
| `baseline-pins-clean.json` | all pins match | both shas above; both mtimes `2026-01-02T03:04:05.123456789-03:00` = **1767333845123456789 ns**; plus free-text `command`, `note` |
| `baseline-pins-sha-drift.json` | omp sha zeroed | sha check FAIL, mtime stays PASS |
| `baseline-pins-mtime-drift.json` | omp mtime pinned +1 s | mtime FAIL, sha stays PASS |
| `baseline-pins-empty.json` | free text only | `pins.declared` vacuity FAIL |
| `baseline-pins-badkey.json` | `omp_sha256` | pin-shaped, not a pin → exit 3 |
| `baseline-pins-badsubject.json` | `grok_binary_sha256` | unknown subject → exit 3 |
| `baseline-pins-badsha.json` | `"XY…"` value | not 64 hex → exit 3 |
| `baseline-pins-badjson.json` | truncated JSON | exit 3 |

Self-test mechanism: `run_capture(argv)` with `contextlib.redirect_stdout` calling
`main(argv)` in-process (exact `verify_surfaces.py:697-702` idiom); a
`tempfile.TemporaryDirectory(prefix="pins-selftest-")` under /tmp holds copies of
the two fake binaries, `os.utime(p, ns=(CLEAN_NS, CLEAN_NS))` stages the pinned
mtime. Fixtures never carry real binaries; nothing executable is run. Negative
scenarios deliberately do not reference real substrate paths.

Assertion matrix (34 assertions, all green): (a) clean → exit 0 + 3 PASS + free
text reported; (b) sha drift → exit 1, FAIL names `omp` + both hashes, mtime
still PASS; (c) mtime drift → exit 1, sha still PASS; (d) **1 ns drift**
(utime `CLEAN_NS+1`) → exit 1 with `delta +1 ns` — proves ns-exactness; (e)
missing pinned path → exit 2; (f) missing baseline → exit 3; (g) bad JSON → 3;
(h) bad key → 3; (i) bad subject → 3; (j) bad sha value → 3; (k) empty pins →
exit 1 vacuity; (l) `--json` parses, 3 checks all PASS, `exit_code` 0; (m)
`--check` runs one check. Plus three unit assertions on `parse_iso_ns` against
baked integers. Each check id has at least one negative fixture — the lesson of
D2 (an existing check with no committed assertion) applied to the new surface.

### F3 — the nanosecond traps (must-avoid defect classes for the future implementation)

The pin `…05:15:11.226207850-03:00` equals live `st_mtime_ns` …226207850 exactly,
but two obvious implementations produce false FAILs:

- `datetime.fromisoformat` silently truncates the 9-digit fraction to
  microseconds: parsed `microsecond = 226207`, the `850` dropped (measured).
- `datetime.timestamp()` float round-trip: `int(d.timestamp()*10**9)` =
  `…226206976`, 874 ns low (measured).
- Correct: textual fraction parse + `calendar.timegm` integer arithmetic →
  `1792138511226207850`, exact (measured; prototype `parse_iso_ns`).

The self-test encodes this: scenario (a) uses a `.123456789`-fraction pin with a
zero sub-µs digit only in the last place, and (d) off-by-one-ns drift — an
implementation using either trap cannot pass both.

### F4 — live state and grammar geometry

- Live `verifiers/baseline.json.measured_against` (lines 4-9) = 3 declared pins
  (omp sha+mtime, opencode sha only — asymmetric pin sets are normal) + 3
  free-text keys (`command`, `omp_round21_note`, `round18_move`); guard exits 0.
- Fail-closed grammar catches the realistic typo families: `omp_sha256` (missing
  `binary`), `omp_binary_sha25` (truncated kind), `omp_binary` (no kind) — all
  rejected at load with exit 3, none silently ignored.
- Cost: a live full run hashes 463 MB (253.6 MB omp + 210.1 MB opencode); the two
  live runs (2 and 3) completed inside 0.36 s wall total — wiring it into a gate
  adds no perceptible time.
- `corpus-baseline.json`'s `head`/`head_subject` keys are non-pin-shaped here and
  reported as free text; that file yields 0 pins → vacuity FAIL exit 1 (run 6),
  which is the designed behaviour: a repo-head pin needs ancestry semantics and
  is deliberately not half-enforced (see Limits).

## Limits

- The prototype lives at `/tmp/p3/` (outside the repo, per lane rules) and is
  ephemeral; the contract + fixture literals in this fragment are the durable
  artifact. The claim round must re-author the script into `verifiers/` (exact
  path: `verifiers/check_substrate_pins.py`, fixtures
  `verifiers/fixtures/pins/`), re-run the 34-assertion self-test, the live run
  (expect exit 0 at pins as of round 21), and decide whether the guard joins
  `verify_skill_checklist.py`'s check table or stands alone.
- mtime enforcement is ns-exact by design; not tested on filesystems with coarse
  (1 s) timestamp granularity, and the strict-vs-advisory choice is left to the
  claim round (F1 decision 1). Symlinks are followed: a retarget to
  byte-identical content is invisible to sha and mtime, by construction.
- Repo-head pins (`corpus-baseline.json` `head`) and the D2-of-round-21
  `--no-baseline --json` exit-code contradiction are NOT covered — the former
  needs ancestry semantics (a `pins.repo_head` kind is named future work), the
  latter belongs to `verify_harness_claims.py` itself.
- No integration wiring was attempted (checklist/LOG/report); no large-binary
  concurrency or TOCTOU analysis; guard was not run under a sandboxed/read-only
  filesystem.
