## Findings
**F1 — both subjects exist at the pinned paths as regular, non-symlink ELF
executables.** Mode 755, owner `vgpnk:vgpnk`; `readlink -f` = the path itself;
`PATH` resolves `omp` and `opencode` to exactly these two files (command 8).
Caveat: a same-name npx shim is shadowed second on PATH for `opencode`
(`/home/vgpnk/.local/bin/opencode`) — a guard must stat the absolute pinned
path, never `which` (see D2).

**F2 — shas match the baseline exactly, no drift.** `shasum -a 256` and
`sha256sum` agree: omp `bf1e86a9…` = `baseline.json:5`; opencode `d9123b9b…` =
`baseline.json:8`. The round-21 re-pin (omp `ff59fc1b…`→`bf1e86a9…`, note at
`baseline.json:7`) holds; opencode is unchanged since round 18 (`v2.0.26`).

**F3 — `stat` matches for omp; opencode mtime is unpinned and fake.** omp
`st_mtime_ns` = `1792138511226207850` equals the pin
`2026-10-16T05:15:11.226207850-03:00` (`baseline.json:6`) to the nanosecond —
`stat -c %y` renders the same instant as `2026-10-16 05:15:11.226207850 -0300`
(only a format difference: ISO `T` + `-03:00` vs display ` ` + `-0300`).
opencode carries **no mtime pin** (only the sha key exists) and its live mtime
is fake/back-dated: `499162500` s epoch = `1985-10-26 05:15:00 -0300`
(`st_mtime_ns 499162500000000000`). A future guard must not re-pin opencode
mtime as if it were a real build time, and its presence proves mtime alone
cannot attest provenance for opencode.

**F4 — a missing binary should exit 2, naming the path, on stderr.** This is
the repo-wide contract, documented at `verify_harness_claims.py:28-30`
("Exit codes: … 2 the environment is unreadable (missing binary / db / log);
3 no baseline found") and implemented via the `Inconclusive` class
(`verify_harness_claims.py:518-519`, raising site `:281`
`omp binary not found: {binary}`; printing site `:640`
`INCONCLUSIVE: {exc}` → stderr, exit 2). Reproduced live (command 10):
exit 2 with exactly `INCONCLUSIVE: omp binary not found: <path>`. The same
convention is in the other verifiers: `verify_surfaces.py:188` (+ self-tests
asserting missing dump/inventory → exit 2 at `:880,885,925,930`),
`verify_skill_checklist.py:368`, `verify_corpus_integrity.py:406`. Baseline
absent/unreadable is exit 3, not 2 (`verify_harness_claims.py:29-30`;
`verify_surfaces.py` self-test "missing baseline → exit 3"). The /tmp prototype
implements the same ladder and passes all four cases (command 11).

**F5 — prototype iteration found a ns-precision trap.** First prototype
version parsed the pin with `datetime.timestamp()*1e9` (float) and reported
`FAIL omp.mtime` against a matching pin (float can hold ~15-16 significant
digits; the value needs 19). Parsing the fractional digits as an integer fixes
it. Any future in-repo guard must compare `st_mtime_ns` against an
integer-parsed pin fraction, never float seconds.

## Defects named (each: path:line + evidence)
1. **D-P2-1 — no path fields in the pin store; path constants are duplicated
   across instruments.** `verifiers/baseline.json:5-8` pins only
   sha/mtime — the guard must obtain paths elsewhere, and today there are two
   independent copies: `verifiers/verify_harness_claims.py:52,55`
   (`OMP_BIN = HOME / ".local/bin/omp"`, `OC_BIN = HOME / ".opencode/bin/opencode"`)
   and `verifiers/verify_surfaces.py:127-128` (absolute-string dict).
   Evidence: `grep -n "\.local/bin/omp\|\.opencode/bin/opencode" verifiers/*.py`
   → 6 hits across the two files. A third copy in a future
   `check_substrate_pins.py` would be drift surface; the guard should import or
   single-source the paths. (Related named debt — nothing reads these pins —
   persists: round-21 LOG line "no check enforces measured_against".)
2. **D-P2-2 — PATH shadowing hazard for any `which`-based resolution.**
   `/home/vgpnk/.local/bin/opencode` (a `mise`/`npx` wrapper script, 1460 B,
   exec target computed at runtime via `npx --package opencode-ai -- which`) is
   the second PATH resolution of `opencode` (`type -a opencode`, command 8).
   A guard that resolves via `which opencode`/PATH order instead of the
   absolute pinned path could attest a *different* binary on hosts where
   `.local/bin` precedes `.opencode/bin`. Evidence: `file` + `grep
   package_bin_path= ` on the shim; `type -a opencode` ordering at command 8.
3. **D-P2-3 — opencode mtime is un-pinnable as provenance.** Live mtime is the
   back-dated `1985-10-26 05:15:00 -0300` (epoch-class constant), and
   `baseline.json` correctly omits an `opencode_binary_mtime` key (grep, line
   8 is sha-only). Recorded so a future guard does not "fix" the asymmetry by
   pinning a meaningless value. (Observation, not a gate failure.)
