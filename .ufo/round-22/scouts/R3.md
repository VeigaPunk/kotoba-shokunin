## Findings

### 1. Derivation result — the two authorities disagree with each other by one
Doc-derived set (round-10 doc, claim by claim): 27 ids, matching the doc's own
"**27 checks**" (`:15`) and "exit 0, 27/27" (`:186`).
`baseline.json`-derived set: 28 ids (28 `checks` keys). Implementation: 28 ids,
and the 28-id sets are **identical** — every one of the 28 extractor keys
resolves in the flattened observation dict (`evaluate` would `KeyError` otherwise),
and the live run prints `28/28 checks pass`.
Delta vs the doc = exactly `oc.log.skills_rescan_max`, added by round 18
(`02302c5`, referenced at `LOG.md:932`). The round-10 doc, which self-describes as
"the human-readable half of `verifiers/verify_harness_claims.py`" (`:3-4`), never
names it and no successor doc does either (command 13).

### 2. Independent recomputation agrees with the implementation, value for value
`/tmp/r22-r3/recompute.py` recomputes a subset from raw host bytes with its own
code (no import of the verifier): `tmpl_bytes 273`, `tmpl_sha256 c1f03c8e248eb40ec7735baab67f686fc2f254e00d2a0241ff220628461bdb51`,
`anchor_occurrences 1`, both `{{…}}` placeholders present, `db_rows 14`,
`db_rows_wellformed 14` (own `accepts()`), `offered_skills 7`, `dangling []`,
`name_mismatches []`, `over_cliff 7`, `desc_le_100 []`, `init_count_max 0`,
`skills_rescan_max 3`, `perm_skill_lines/allow 0/0`, `dup_lines 0`,
`plugins_cache_present false`, `builtin_customize_opencode false`,
`oc_names_plus_builtin 7`.
Compared against `--json` (`observed`): every value equal. The verifier's
extractors reproduce the host as an independent implementation sees it — no
extractor-fidelity defect found. (One false alarm in my own probe: float-µs
mtime comparison printed `baseline_omp_mtime_match=false`; the ns digits match
exactly — see Limits.)

### 3. Falsifiability census — 6 of 11 opencode checks are vacuous on this substrate
The oc log no longer emits `init count`, `duplicate skill name`,
`evaluated permission=skill`, or `<available_skills>` (command 9, all counts 0;
only `skills rescanned` survives, 13 lines). Therefore `oc.log.init_count_max`,
`oc.log.init_count_monotone`, `oc.dup.roots_both_sided`, `oc.dup.onesided_roots`,
`oc.permission.skill_lines`, `oc.permission.skill_allow` **can only pass** —
they parse a surface that is gone. Round 18 recorded this in `baseline.json:10`
("all expected 0"), so the state is known; what is missing is that `28/28 PASS`
now certifies 22 falsifiable checks while the round-10 doc still presents the
rationale of all 27/28 as live evidence. All four exit-code claims in the doc's
falsification table (`:182-185`, except the 17→16 magnitudes) reproduced exactly
(commands 5–7).

## Defects named (each: path:line + evidence)

count is stale.** Doc says 27 checks / `27/27`; implementation and baseline both

**D2 — `harness-verifier-round10.md:126`: the claimed invariant is dead while
both its checks pass.** Row: `` `oc.log.init_count_max` == `oc.roots.names_plus_builtin` | 18 == 17+1 ``.

**D3 — `harness-verifier-round10.md:202` vs `verifiers/verify_harness_claims.py:522-552,557,569`

## Exploratory note (not a claim): `measured_against` pins are live but unenforced

sha256 pins match live bytes (`bf1e86a9…`, `d9123b9b…`) and the omp mtime pin
