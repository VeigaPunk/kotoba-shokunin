## Findings
- **Non-vacuity of the vacuity guard confirmed, with the specified message.** A dump that is non-empty (515 B, 10 registration calls through the real callee allowlist, 0 `.md` substrings) extracts zero `(group, file.md)` pairs and the gate returns **exit 1 with `FAIL surfaces.no_uncovered_class: vacuity: …` — both in the full gate (R1) and in single-check isolation (R1b)**. The isolation run means the failure is intrinsic to `no_uncovered_class` (`:556` `if loader_group_declared and not pairs`), not a side effect of `literal_present` going red.
- **The guard keys on EXTRACTION, not on dump emptiness.** No emptiness branch exists anywhere in the loaders (`load_dump`/`read_text` `:199-232` have no zero-length special case; grep for `len(dump)`/`dump.strip`/`not dump` finds nothing). The contrast (R4) shows the same check on the same dump + one `.md` call flips to the separate undeclared branch (`not pairs` false), so the vacuity wording is reachable only through the 0-extraction condition.
- **The dead dump is "dead" only for `.md` extraction, not for literals or machinery**: it contains `"cursor/rules"` — the literal of the declared `loader-literal` entry `omp:cursor/rules` — yet it is `.md`-inert, so R1's `literal_present` red rows are exactly the two loader-group rows whose pairs are missing. This is the sharp form of the parent's probe: a dump can carry live registration machinery and satisfiable literals and still be `no_uncovered_class`-red by vacuity alone.
- **Per-harness scoping is real** (R5): opencode with a 0-CALL_RE extraction stays PASS (`all 2 extracted loader class(es) declared` from the omp side; opencode declares no loader-group rows in either baseline), matching the docstring note `:544-547` — opencode's zero-extraction is its documented steady state, not drift.
- **Partial vanish stays red** (R4b): with 1-of-8-style extraction the gate is still exit 1 via the undeclared branch + `literal_present` loader-group pair failures; only the full 0-extraction case takes the vacuity branch.
- Live control at HEAD is 7/7 PASS (exit 0); `--self-test` 75 assertions, 0 failures. Copy fidelity was diff-verified before probes, so the FAILs are caused by the crafted dump, not the copy.
