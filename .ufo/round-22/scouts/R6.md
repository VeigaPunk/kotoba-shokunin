## Findings

1. **The harness is green and its documented class table holds — for all nine rows.** §3b's
   claims re-derived independently (my own instrument invocations, not the harness's rows):
   (a) fires `report_dead`, and in default mode *also* `report_total` exactly as §3b:128
   says; (b) `commit_nonhash`; (c) `commit_unresolvable`; (d1) both `stale_patterns` and
   `missing_paths`; (d2) `stale_patterns` only; (e) `unindexed`; (f) no class in either
   instrument under `--no-baseline`, `report_total` `33 vs expected 34` in default mode;
   (g) clean in both; (h) author `quoted 0→1` (control vs fault world) with
   `report_total 34` unchanged, independent identical (`quoted=1`, `report_total=34`,
   `dead=0`) → §3b:136's counters and its "no false positive in either instrument" both
   reproduce at HEAD. §3b's literal numbers (24→23, "stays 24") are round-12 live values;
   the mechanism is unchanged (`report_total` 34→33 today).
2. **Undocumented extra fires in default mode**: (b) and (c) also DRIFT `commit_total`,
   (e) also DRIFT `tracked_files`. §3b annotates a baseline-mode extra only for (a).
3. **The harness's (f) gate is a tautology, though (f)'s verdict is right.** `json_field`
   always reads `$w/out.json` (`verifiers/fault_injection_corpus.sh:125`) while the baseline
   run is redirected to `out-baseline.txt` (line 291), so `base_total` (line 293) re-reads
   the *no-baseline* JSON: `blind_total = base_total` cannot fail. Evidence: `out.json`
   sha256 `9d1f25797a80…` identical before and after a baseline-mode run in the same world;
   baseline-mode JSON `observed.corpus.report_total = 33` = `blind_total`. The class's real
   detector (`DRIFT corpus.pointers.report_total: observed=33 expected=34`, from
   `out-baseline.txt`) is never parsed; the gate is "baseline mode exited non-zero", with no
   class attribution.
4. **The independent instrument's class attribution is computed, correct, and thrown away.**
   Its `--json` results carry DRIFT ids that agree with the author's on every fault world,
   yet `run_independent` (lines 145–150) writes combined output to `indep.out`, which nothing
   reads, and the rows grade exit codes only (lines 271–272, 300, 337–343). Consequently
   §3b's column "fired class (**both** instruments)" (line 126) is not re-derivable from
   harness output — I had to rebuild it (table above). A non-zero exit for any unrelated
   reason would also be graded as a pass.
5. **`--self-test` reaches no verdict function.** `self_test()` (lines 365–389) only uses
   `new_world`, `plant_a`, `run_integrity`, `drift_ids`; it never calls `fault_must_fire`,
   `fault_known_blind_f`, `fault_h_context`, `fault_must_not_fire` or `control_clean`. So
   MISS, INVALID-PLANT, WRONG-CLASS, FALSE-POSITIVE, (f)'s blind-spot predicate and (h)'s
   count predicate are unproven by any in-repo probe. I forced two of them (MUT1, MUT2): both
   *work* (rows above) — the branches are sound, just untested. Note also that the comment at
   lines 361–364 promises T2 proves "the machinery MUST answer MISS", but the code asserts
   the opposite direction (an unmutated world reads clean, exit 0, line 376): the MISS path
   is unreachable in the self-test.
6. **Exit-code contract re-derived live and correct**: 0 (command 1/2), 1 (7/8/10/11), 2 ×5
   distinct causes (6), 3 absent baseline (9) — matching the docstring (lines 28–29) and
   §3b:121. Flag support `--repo`, `--repo=`, `--keep-worlds`, `--self-test`, unknown → 2.
7. **Round 11's ten fault shapes vs round 12's harness** (`corpus-integrity-round11.md:198-206`):
   six map onto harness classes (deleted index target→d1, unindexed tracked file→e, pointer to
   a non-existent round→a, plausible-but-absent commit hash→c, non-hash token→b, deleted report
   target→a). Four have **no planted world**: renamed baseline, non-git directory, broken brace
   row, blanked FILE-column token. I probed all four by hand (9–11): both guards still work
   (exit 3; exit 2) and both index shapes still fire (three DRIFTs; `unindexed=1`). So the
   round-11 detections survive at HEAD, but only through ad-hoc `/tmp` worlds — no re-runnable
   class covers them, which is the exact failure mode this harness was built to end.
8. **Pin inert (re-confirms round-21 debt).** §3b:120 pins `sha256 9bc80ae61cea…`; the file
   ever had two revisions — `7026e7368769…` (`633859f`, round 12) and `9db6c692c752…`
   (HEAD, after `fad752b`'s host-path case fix in round 17). The pin matches neither, and the
   harness prints only the *instrument*'s sha at runtime, never its own, so a re-run cannot
   bind its output to script bytes. `grep -rn measured_against verifiers/*.py` → no consumer.
   Same finding as `.ufo/round-21/scouts/R6.md:154` and `K07.md:83` — still open.
9. **"10 fault classes" is 9 planters + 1 clean control** (doc:123, `LOG.md:364`,
   `corpus/lessons/round-12.md:45`, `corpus/README.md:46`, `SCORECARD.md:29`, `SCORECARD.md:74`).
   §3b's table has 9 fault rows (126–136); `main()` (lines 399–408) calls 9 fault functions
   plus `control_clean`, and `fault-0-control` is a must-stay-clean world, not a fault class.
10. **"JSON-only assertions" (doc:121) is inaccurate for (f)**, whose decisive gate is a bare
    exit code plus the self-read in finding 3; every other class asserts on JSON.
11. **`SKILL.md:580-582` is false**: it says `--self-test` exercises the machinery "without
    cloning the repo"; it clones it three times (`new_world` per fixture, lines 369/374/383) —
    I measured three worlds at HEAD `b16300f`, 13 MB (command 12). The default path's

    (control + h's control + 9).
