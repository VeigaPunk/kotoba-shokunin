## Findings

### F1 — check ids: 10/10, exact order

Derived from the round-16 landed-verification block (nine ids) + round-17's
tenth (`governance.citation_resolves`) + the baseline map's eight
`executed:<id>` dispositions: `checklist.box_map_complete`,

extra, none missing. The map's 41 boxes (15 trigger + 9 agentdef + 9 dispatch +
8 alwayson) resolve to 8 executed boxes → 8 checks, plus the map check itself
and round 17's addition = 10.

### F2 — semantics diff: 7 matched, 1 over-specified, 3 under-specified

Matched as derived (code agrees with the docs): `name_directory`;
`line_budget` (threshold read from the box, `--max-lines` fallback);
`anti_trigger_clause` (bilingual marker vocabulary, quoted spans stripped);
`no_placeholder` (population = lines non-empty after backtick-span removal; the
same-line negation heuristic); `command_binary_resolves` (heads + path-like
args, skip-list vs `source`/`.`/`exec`, output-vs-input redirects,
output-flag carve-out, `sh -c` unwrapping, `<<~EOF`, segments>0 ∧ subjects==0 →
FAIL); `citation_resolves` (closed root set, ≤3 hops, `./` normalization);
`governance.citation_resolves` (gated on the target being that repo's own
`SKILL.md`, same-line quotes, ellipsis/`round-N` schematics, zero-subject FAIL,
counting exclusions).

Divergences:

- **Derived over-specified by the sources — `checklist.box_map_complete`.**
  The docs describe dispositions + the `delegated:` instrument rule. The code
  also enforces: box annotation ↔ map agreement in both directions
  (`:957-976`), `[x]` marker FAIL (`:977-981`), near-miss checkbox FAIL
  (`:982-984`), unknown `executed:<id>` FAIL (`:910-914`), duplicate `box_id`
  FAIL (`:901-904`), `map["file"] == target name` (`:894`), and a `..`-free
  `delegated:` target (`:925-928`). None of the three sources states these; a
  reader of round 16/17 alone cannot predict six of them.
- **`trigger.literal_trigger_string` over-promises** (see R1-D2).
- **`trigger.frontmatter_parses` reports a constant** (see R1-D3).
- **`trigger.line_budget`'s threshold rule is not the rule it reads as** (see
  R1-D1).

Two derivation traps the code resolves asymmetrically and the docs state
explicitly, so they are not defects: `trigger.citation_resolves` returns **N/A**
at zero subjects (`:1217-1221`) while `governance.citation_resolves` returns
**FAIL** at zero subjects (`:1261-1262`); and `citation_subjects`'
quoted/schematic exclusions are enabled only for governance
(`:1200-1207`, `:1248-1250`), so SKILL.md's own quoted tokens stay checked.

Exit-code contract (not derivable from the docs): `rc = 1` iff any FAIL **or**
every check's `evaluated == 0` (`:1844-1846`), so `box_map_complete`'s 41
evaluated is itself a vacuity guard.

## Defects named (each: path:line + evidence)

**R1-D1 — `trigger.line_budget` takes the box's *first* integer, not the number
the bound names; a verdict flip is reachable.**
`verifiers/verify_skill_checklist.py:1073-1081`: `LINE_BOUND_BOX_RE` locates a
box matching `file … <int> … line(s)`, then `INT_RE.search(b["text"])` returns
the first integer anywhere in that box's normalized text. The module docstring
states the same rule (`:97-102`, "'the first integer in the checklist box whose
text matches…'"), so this is a design gap, not a code/doc divergence. Witness
(commands 13/14): two otherwise identical 18-line `/tmp` fixtures, boxes
`File ≤ 20 lines` vs `Round 16 errata: File ≤ 20 lines` → PASS budget 20 vs
**FAIL budget 16**. The live box (`SKILL.md:329`, `File ≤ 600 lines`) has 600 as
its first integer, so the live threshold is correct today; no committed fixture
covers the earlier-integer case (the only box-binding fixture,
`verifiers/fixtures/checklist/line-budget-box-binding/SKILL.md:46` (48-line file,
box binds 20), has the single self-test row
`("line-budget-box-binding", 1, ["trigger.line_budget"], …)` at
`verifiers/verify_skill_checklist.py:1398`, which pins the FAIL direction
only).

**R1-D2 — `trigger.literal_trigger_string` enforces less than the box recorded
as executed.**
`SKILL.md:281-282` reads "`description` contains ≥1 literal trigger string in
quotes or an explicit `Triggers:` list. (executed: `trigger.literal_trigger_string`)",
but the code's third branch (`:1043-1049`) accepts **any** quoted/backticked
span ≥2 chars — the script's own docstring says so at `:85-86` ("a shape test,
not semantics — quoted jargon like 'deterministic' satisfies it"). The
divergence is the disclosure idiom: the neighbouring box
(`SKILL.md:286-289`, `trigger.anti_trigger_clause`) carries its limit inline
("vocabulary test, not semantics: …"), and this one does not, while the map
records it as `executed:` (`verifiers/checklist-baseline.json:20-23`). Live, the
strong branch is the one hit ("description carries literal 'Triggers:'",
command 3), so the live PASS is not evidence for the weak branch.

**R1-D3 — `trigger.frontmatter_parses` reports a hard-coded `evaluated = 4`.**
`verifiers/verify_skill_checklist.py:1000`. Every other check's `evaluated` is a
population size (boxes, lines, subjects, segments); this one is a constant that
does not vary with the frontmatter's actual field count, and it is returned as 4
even when `fields is None` (parse failure, `:1001-1002`). The `evaluated` column
therefore cannot be read uniformly across the ten checks.

**R1-D4 — carried red: `SKILL.md` is 601 lines against its own box.**
`SKILL.md:329` binds `File ≤ 600 lines`; `wc -l SKILL.md` = 601; command 3 rc 1.
Introduced by round-18 commit `02302c5` (+2 errata lines in the omp-cache
paragraph, `SKILL.md:27-41`; `git show --stat 02302c5` = `SKILL.md | 12 +-`).
`LOG.md:953` (inside the Round 18 section, heading at `LOG.md:891`) records the
instrument as `exit 0` — false at its own landing commit; `SCORECARD.md:32` and
`LOG.md:1211` record the falsification. This is the only red row on the live
gate and the number lane B must retire.

**R1-D5 — a falsified record still stands verbatim.**
`LOG.md:848`: "`--self-test` → **0 failure(s) over 1504 assertions**; fixture
directories **68 → 71**" (round 17). It was false at its own commit — the
`delegated-directory` fixture delegated to an untracked empty directory, so the
record read 2/1504 in any clone until round 21's `.gitkeep`. Round 21 recorded
the falsification (`LOG.md:1214`) but did not rewrite the record; the claim is
now accidentally true at HEAD. Historical-truth gap of exactly the class the
round-17 governance check names as its ceiling ("HEAD existence only"). No
repair attempted here (out of lane scope).

**R1-D6 — governance enablement degrades to "any file named `SKILL.md`" in a
`.git`-less tree.**
`verifiers/verify_skill_checklist.py:1756`: `governance_enabled = skill_path.resolve() == (repo / "SKILL.md").resolve()`,
where `repo` comes from `find_repo_root` (`:386-392`), which falls back to the
file's own directory when no `.git` ancestor exists. Consequence: in a `.git`-less
tree every fixture `…/<case>/SKILL.md` enables the check, which then reads
`<case>/LOG.md` and `<case>/SCORECARD.md` and FAILs with a message naming a file
that was never meant to exist. Witness: command 11/12 — 108 failures, 79 of them
this class. Also the cause of the `command_binary_resolves` FAILs in the same
run (base = fixture dir, `corpus/knowledge/anatomy-and-compression.md` "does not
resolve"). Round-21 `R5-D3` named the non-hermeticity and its `find_repo_root`
cause; this fragment adds the sub-class split (79/108) and the exact message
shape.
