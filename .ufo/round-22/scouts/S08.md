## Findings

- **F1 — boundary is inclusive; the target is `n <= 600`.** 601 → FAIL,
   exactly 600 → PASS, 599 → PASS (commands 1/3/5/7). Implementation:
   `check_line_budget` at verifiers/verify_skill_checklist.py:1084-1094
   (`if n > limit: FAIL`); `n = len(lines)` where `lines =
   text.splitlines()` at :1805 — the count is every physical line of the whole
   file (frontmatter, blanks, all sections included).
- **F2 — threshold source is the live box, not the flag.** `box_line_budget`
   (:1073-1082) takes the first integer of the first box whose text matches
   `LINE_BOUND_BOX_RE` (:362). The trigger checklist box at SKILL.md:329-331
   reads `- [ ] File ≤ 600 lines; overflow already moved to referenced depth
   files.` → limit 600 "from box at line 329". `--max-lines 500`/`700` changed
   nothing (command 9).
- **F3 — one deleted Sources line is exactly the whole delta to green.** At
   601→600 only two numbers moved: `line_budget` 601→600 and
   `no_placeholder` scanned 552→551 (the deleted prose line; not a
   placeholder). All other evaluated counts unchanged (`box_map_complete` 41
   boxes, `citation_resolves` 42, `governance.citation_resolves` 171) and the
   full gate exits 0. Deleting two lines (599) is also green. So claim B's
   "checklist gate fully green" needs exactly the one-line reduction; there is
   zero slack above 600 and one line of slack below.
- **F4 — hazard for whoever lands claim B: count with `splitlines()`, not
   `wc -l`.** The gate counts logical lines; without a trailing newline `wc -l`
   undercounts by 1 (P1/P2). A 601-logical-line file with no trailing newline
   reads `wc -l = 600` yet still FAILs (`evaluated 601`). The live file
   currently ends with `\n`, so both counts agree at 601; claim B's edit must
   not drop the trailing newline or must leave ≥1 line of margin.
- A status-only confirm: `## Sources` cannot be reduced via the checklist
  boxes — the box at :329-331 is inside `## Trigger-fidelity checklist` and
  the four checklist sections are excluded from "non-checklist section"; no
  interaction with the box map was observed (41/41 boxes still mapped after
  the trims).
