## Findings

- The move is mechanically sound: 601 -> 592 lines, gate 10/10 exit 0, boxes 41/41,
  indices/pointers unchanged (`report_dead=0/34`, `commit_total=27`).
- **Claim B's falsifier ("any moved byte altered") is enforced by no instrument.**
  A single word corrupted in the moved block leaves all five instruments at exit 0
  (checklist, corpus-integrity, corpus-independent, surfaces, harness). Only a
  git-pinned byte diff catches it. Without adding that gate the falsifier is
  decorative — and round 15 itself already drifted under this exact hole (defect 3).
- **Landing surface understated.** Claim B (`/.ufo/round-22/claims.json`
  `separability`) lists SKILL.md + corpus/knowledge/ + corpus/README.md, but the
  sim proves `verifiers/corpus-baseline.json` MUST also be re-recorded
  (tracked_files 52 -> 53), else `corpus.index.tracked_files` drifts red after the
  landing commit. Every prior file-adding round did this re-record
  (`git log --oneline -- verifiers/corpus-baseline.json`: rounds 15, 16, 17, 19, 21).
- **Pre-commit ordering trap.** In the working tree a new corpus file is red for
  two reasons regardless of content: `stale_patterns=1` before `git add` and
  `tracked_files 53≠52` after it. "corpus still exits 0" can only be evaluated
  after commit + baseline re-record.
- Green-gate demos require faithful paths: `name_directory` and two citation
  checks are path-sensitive; a bare `/tmp/<x>` clone can never go green.

Proposed integrator command for claim B's landing (exact argv, at the landed tree):

```
# 1) byte identity of the moved body (section pinned at dispatch HEAD b16300f;
#    tuple = commit, body-range, corpus path, anchor line, body line count)
git show b16300f:SKILL.md | sed -n '238,251p' > /tmp/b_body_orig.txt
S=$(grep -n -F -x '| Situation | Table? | Evidence |' corpus/knowledge/decision-tables-round22.md | cut -d: -f1)
diff /tmp/b_body_orig.txt <(sed -n "${S},$((S+13))p" corpus/knowledge/decision-tables-round22.md) && echo B-BYTES-OK
# 2) shape-independent contiguity (survives any heading/note shape the mover picks)
python3 -c 'import subprocess,sys;b="\n".join(subprocess.run(["git","show","b16300f:SKILL.md"],capture_output=True,text=True).stdout.split("\n")[237:251]);sys.exit(0 if b in open("corpus/knowledge/decision-tables-round22.md").read() else 1)'
# 3) no duplication left in the pointer file
python3 -c 'import sys;sys.exit(1 if open("/tmp/b_body_orig.txt").read() in open("SKILL.md").read() else 0)'
# 4) zero-pin refresh (mandatory before the corpus gate can be green)
git add corpus/knowledge/decision-tables-round22.md && python3 verifiers/verify_corpus_integrity.py --no-baseline   # observe tracked_files
# edit verifiers/corpus-baseline.json checks."corpus.index.tracked_files".expect += 1 + a notes entry
# 5) full gate set
python3 verifiers/verify_skill_checklist.py && python3 verifiers/verify_corpus_integrity.py \
 && python3 verifiers/verify_corpus_independent.py && python3 verifiers/verify_surfaces.py \
 && python3 verifiers/verify_harness_claims.py && bash verifiers/fault_injection_corpus.sh
```

If the integrator moves a different section, every step parameterizes on
(commit, body line range, corpus path, anchor first body line, body line count);
`diff` step 1 fails loudly on any word, order, or whitespace change inside the block.
