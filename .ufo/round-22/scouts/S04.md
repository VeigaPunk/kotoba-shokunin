## Findings

1. **The move clears the carried red with wide margin.** 601 → **520** lines
   (`wc -l`; the gate's own counter agrees: `evaluated 520`), gate rc **1 → 0**,
   10/10 PASS. Headroom after the move: 80 lines (rank-3 Router model would fit
   too, 520−44 ≈ 476; rank-4+ would not be needed).
2. **Verbatim is provable byte-for-byte.** Body region = `SKILL.md` lines 77–166,
   10239 bytes, 90 lines, sha256
   `1f6263f8863d81554406390a0489b005609314a455928f356430e1a858ae79ce`; occurs
   **exactly once** in each variant's home file; re-extracted from the home file
   it recomputes to the same digest. The section heading line 75
   (`5e893dd930a1f809cced3cbdaac65d6e86e8db8c70d30b6da59ab0cdb777691a`, 57 B) is
   replaced in SKILL.md by the 12-line summary block (heading kept, wording
   shortened).
3. **Boxes and the box map are line-insensitive.** `checklist-baseline.json`
   carries only `box_id`, `section`, `text_sha256`, `disposition` — no line
   fields — and is byte-identical (`68831bb35f28f8dd…`) in both trees;
   `box_map_complete` PASS with `41 boxes mapped` on both sides. The box's own
   line moves 329 → 248 with no map edit.
4. **Zero baseline churn for the absorb home.** All four committed baselines are
   byte-identical between live and sim (row 21), and the moved body creates **no
   new pointer obligations**: it contains 0 `ufo/reports` pointers and no
   `commit` tokens (only the md5 prefix `c91c0d66`), so `report_total`,
   `report_dead`, `commit_total`, `commit_nonhash` all hold at 34/0/27/0.
5. **Surfaces is structurally immune to this append.** `verify_surfaces.py`
   parses the census only inside `## Class inventory` up to the next `^## `
   heading (`verifiers/verify_surfaces.py:43,451-462`); the new `## Craft table`
   section is appended after `## Honest ceiling`, i.e. out of scope — all seven
   checks return identical details and identical evaluated counts (38/8/5-of-6/
   38/38/38/9) before and after.
6. **Home choice is the only decision with a measurable cost.** Absorb into the
   existing census file (variant A): tracked_files stays 52, `ci` rc 0 with the
   committed baseline, nothing to re-record. New corpus file
   `corpus/knowledge/instruction-surfaces-craft.md` + README row (variant B,
   `git add`ed in the copy): `tracked_files 53`, `ci --json` **rc 1**
   (`corpus.index.tracked_files 53 vs 52`) → the landing must refresh

   refresh, not a fitted denominator"). Variant B's new file is 96 lines

7. **No existing citation is invalidated by the −81-line shift.** In-repo

   sekhmet-l3), never kotoba's own; every live-file line citation to SKILL.md

## Limits (what I did NOT verify)

- Nothing was landed. The only file written is this fragment; the live tree is
  untouched (row 24: `git status` unchanged, `SKILL.md` sha unchanged). All
  mutations happened under `/tmp/s04-fleet*` copies.
- The **full** fault harness was not run against the moved tree: it `git
  clone`s the committed repo, so an uncommitted simulation is invisible to it.
  Only `--self-test` was run (OK). The full run belongs to the integration step
  on the landed tree.
- The sim is a working-tree copy, not a fresh clone; variant B's committed-state
  counts were exposed with `git add` inside the throwaway copy (`git commit` is
  out of this lane's scope), so a real landing's clone-view numbers are inferred
  from the tracked-file count, not measured from a commit.
- Section ranking uses the plain reading (any `##` except the four `*checklist*`
  sections). If the planner intends to exclude reference/roster sections like
  `§ Sources`, then `§ Instruction surfaces` is the **largest** and this
  simulation would be the rank-1 move, with `§ Router model` as the second — the
  measurement here is unaffected either way, but S02's target would be.
- The home-file choice (existing census file vs a new `instruction-surfaces-craft.md`)
  is mine; both arms were measured, and the planner may prefer the other.
- I did not human-review the appended section's rendering, and no reader test
  was done; the appended heading's em-dash was initially double-encoded by my
  script and fixed in the sim (a sim artifact, not a repo defect) — the moved
  body bytes were never affected.
- Carried text I did not re-measure: that "no harness loads" the dispatch-prompt
  directory (kept in the summary; not re-probed this round), and the census
  file's own round-18 errata about binary drift.
