## Findings

1. **The move itself is green on the checklist axis** exactly as claim B needs:
   601 → 519 lines, `verify_skill_checklist.py` 10/10 PASS exit 0 (including
   `trigger.line_budget`), 41 boxes and 41 map entries untouched, one hunk in
   `SKILL.md`, moved bytes verbatim.
2. **New-file cost — the A3 headline for claim B.** A new tracked file under
   `corpus/` moves `corpus.index.tracked_files`, which is an **equal-mode**
   baseline check (52 → 53): the corpus verifier exits **1 even with a correct
   README row**. Green corpus 9/9 additionally requires a one-line
   `verifiers/corpus-baseline.json` expectation refresh — precedent for that
   edit: `corpus-baseline.json` notes `round19_recensus` / `round21_refresh`
   ("Expectation refresh, not a fitted denominator"). Without it, B's "no other
   check is harmed (… corpus … exit 0)" is false.
3. **README row is necessary but only works on a tracked file.**
   Row missing → `unindexed=1` (plus the tracked_files DRIFT); row present but
   file unstaged → `stale_patterns=1` (the pattern matches no `git ls-files
   corpus/` entry). Staging precedes the measurement.
4. **`--no-baseline` observation (the slice's question):** with row + staged
   file, `unindexed=0` and `stale_patterns=0` — they do **not** drift; both are
   zero-mode (baseline-independent) checks that report PASS in no-baseline mode
   while `tracked_files` / `report_total` / `commit_total` report OBSERVE. A
   non-zero unindexed/stale still exits 1 under `--no-baseline` (A3x/A3y).
5. **Cheaper path for the B owner: the append idiom (A3b).** Appending the block
   to the topic's existing corpus file reaches the identical `SKILL.md` state
   (519 lines, same gate result) with corpus 9/9 exit 0, `tracked_files` still
   52, no baseline edit and no new README row — at the cost of a *row update*
   rather than a new row ("one authoritative home per fact", the rule that
   governed the round-15 moves).
6. **Coverage deltas created by the move** (same instrument, live → A3):
   `trigger.citation_resolves` evaluated 42 → **35**;
   `trigger.command_binary_resolves` 19 / 15 segments → **13 / 9**;
   `trigger.no_placeholder` 552 → 477 scanned lines. The moved block's own
   repo-rooted tokens (11 occurrences: `corpus/knowledge/*` ×7, `verifiers/*` ×2,
   `opencode/agents|command` ×2) and its 6 command subjects leave the only
   instrument that checked them; the corpus verifier audits only
   `.ufo/reports/round-N/*.md` pointers and `commit \`<hex>\``, and the new file
   has 0 of each (`corpus.index missing_paths=0` confirms the tokens are not
   scored there at all).
7. **Host-anchoring is an operational trap for any /tmp simulation.** A `cp -a`
   into a differently-named directory fails `trigger.name_directory`; without a
   fleet-like parent (symlinks to `.ufo`, `PROTOCOL.md`, …) both
   `trigger.citation_resolves` and `governance.citation_resolves` fail with dead
   `../` tokens. Both artefacts are environment-only: with the corrected copy,
   the same bytes give 10/10 exit 0.

   about HEAD only.
