## Findings

1. **The move is achievable and the gate goes fully green.** 601 → **523** lines
   (variant A) / **532** (variant B, table retained), 41 boxes intact, all six
   instruments exit 0 including the fault harness. The red carried since round 19
   (`trigger.line_budget`) clears with ~68–77 lines of slack.
2. **The existing census file is a usable corpus home with no baseline churn.**
   Absorbing the section into `corpus/knowledge/instruction-surface-census-round13.md`
   (the file `SKILL.md:79` already points at) adds no new tracked corpus file:
   `corpus.index.tracked_files` observed **52** live and **52** moved, `unindexed=0
   stale=0 missing=0` in both, and `surfaces.literal_parity` / `surfaces.kind_parity`
   stay PASS even after the 10 craft-cell repairs, because the parity check reads only
   cells 1–3 (class_id, literal, kind) — the `governed by` column is prose.
3. **Keeping the H2 heading text is load-bearing.** The heading survives inside the
   summary, so `SKILL.md`'s own cross-references (`SKILL.md:50`, `SKILL.md:188`-ish in
   the moved file: "see \"Instruction surfaces\"" / "use the per-surface rows in
   \"Instruction surfaces\"") stay valid and the round-12 counting claim's awk range
   still terminates (9 → 9). Dropping the heading is still 10/10 green but changes that
   claim's count to 20 — see D4.
4. **Variant choice is free.** Both variants pass; variant B costs 9 lines and preserves
   the nine crop-rule sentences in the always-loaded body, which is what the section's
   own prose argues matters ("The body is the only part the executing agent always
   sees"). Recommended if the landing wants to keep rule availability.
5. **The claim's core property is not machine-checked** (D1) and the move shrinks the
   checked population (D6). A landing can satisfy every instrument while the moved bytes
   are absent or altered.

## Limits

- **New-file corpus home not probed.** Absorbing into an existing indexed file was chosen
  because a new `corpus/knowledge/*.md` would move `corpus.index.tracked_files` (52) and
  require a baseline re-record inside the landing commit; that variant was not measured.
- **Fleet-root resolution is by symlink.** The copies reach `../.ufo`, `../PROTOCOL.md`
  etc. through read-only symlinks to the live fleet root, so `trigger.citation_resolves`
  and `governance.citation_resolves` in the copies resolve against host state, not a
  hermetic world. Nothing outside `/tmp` was written (verified by `git status` and the
  three live hashes above); the same symlink route is what let me avoid a 19-site
  host-path artifact FAIL.
- **No `--self-test` runs** on the checklist/surfaces/corpus instruments inside the
  copies (only their default live modes), and the fault harness ran once, unpinned by
  repetition.
- **No behavioral measurement.** Whether moving the craft rows out of the always-loaded
  body degrades use is unmeasured — no live session was captured; this is a file-level
  simulation only.
- **"No stub" interpretation.** Read as: no stubbed duplicate of the table left behind,
  `SKILL.md` keeps a pointer sentence; the H2 heading text is retained. The
  heading-dropped variant is measured (D4) rather than silently assumed equivalent.
- **S01's exact recipe was not available** (no fragment present at writing time); S05
  mirrors the round-15 idiom as documented in `corpus/README.md` rows 9/10/11 and
  `.ufo/round-22/claims.json` claim B.
