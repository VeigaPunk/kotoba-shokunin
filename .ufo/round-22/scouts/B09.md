# Scout B09

## Task

Checklist-interaction critic for the five round-22 lane-B candidates (nine
non-checklist `##` sections of `SKILL.md`, HEAD `b16300f`, 601 lines). For each
candidate: (a) confirm ZERO `- [ ]` boxes inside it; (b) confirm no checklist
box's TEXT mentions the section (so box hashes are untouched by a move);
(c) confirm the trigger/command vocabulary is unaffected. Interactions found are
reported as defects. All mutation probes ran on `/tmp` worlds; the repo and the
fleet were never written (final `git status --porcelain` shows only the
pre-existing untracked `.ufo/reports/round-22/` and `.ufo/round-22/`; SKILL.md
md5 `666325a12b84746e0cc65b04cb503075` unchanged).

## Limits (what I did NOT verify)

- The corpus re-home scenario (D5/F6) was measured with the corpus verifier's
  own pure `citation_findings`/`resolve_pointer` functions, not by running that
  verifier on a re-homed tree: its file census is `git ls-files corpus/`, and
  registering a new tracked corpus file needs a commit, which the round forbids.
- `corpus.index.unindexed` / `corpus.index.missing_paths` behaviour for the new
  corpus file and its README row is therefore unmeasured (integration-round
  scope; needs the tracked file).
- Worlds were symlink mirrors of the fleet on `/tmp`; the live repo and siblings
  were read-only throughout. I did not re-run the harness/surfaces verifiers —
  they do not read SKILL.md body sections (their inputs are `SKILL.md`
  frontmatter + other artifacts), so no interaction is possible from a body move;
  that is reasoning, not a measurement.
- Nothing here evaluates which candidate is *best* for claim B beyond the
  interaction accounting above; the choice and the band-range-to-verbatim-bytes
  mapping are the integrator's.
