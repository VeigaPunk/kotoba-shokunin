## Defects named (each: path:line + evidence)

**D1 — `verifiers/verify_skill_checklist.py:1751` (with `:269`, `:1752`, `:1756`): `--repo`
does not redirect the checked file; it produces a mixed-target run.**
`skill_path = Path(args.skill) if args.skill else DEFAULT_REPO / "SKILL.md"` where
`DEFAULT_REPO = Path(__file__).resolve().parent.parent` (`:269`); `--repo` only sets `repo`
(`:1752`). Evidence: `--repo /tmp/r22-s01/arms/move/kotoba-shokunin` (a 450-line SKILL.md)
reports `trigger.line_budget: evaluated 601` and `citation_resolves: evaluated 42` — the
live file's numbers — while `governance.citation_resolves` flips to `N/A` because
`governance_enabled` compares the live skill path to the copy root (`:1756`). Consequence
for this round: the slice's own prescribed command cannot measure a copy; a lane that
reports "the move did not clear `line_budget`" from that command is reporting the live
file. Use `cd <copy> && python3 verifiers/verify_skill_checklist.py`, or `--skill` (D2).

**D2 — `verifiers/verify_skill_checklist.py:1769`: a foreign `--skill` silently drops the
box map.** With the default map path `<skill-dir>/map.json` for a foreign target, the run
prints `N/A checklist.box_map_complete: evaluated 0 — no map pinned …` and exits 0 with 9
checks — the 41-box map, the strongest check in the instrument, is absent from a green
verdict rather than red. Evidence: `--skill /tmp/r22-s01/arms/move/kotoba-shokunin/SKILL.md
--repo <same>` → `N/A … map.json`; 9 PASS; exit 0. Mitigation for measurement: pass
`--map <copy>/verifiers/checklist-baseline.json`, or run the copy's own script (which is
what the arm runs above did — they report `evaluated 41`).

**D3 — `SKILL.md:591` (moved bytes line 140): the one pointer in the moved section that
dies on relocation.** `` `../.ufo/reports/round-7/kotoba.md` `` resolves from the repo root
(`/home/vgpnk/Projects/shokunin/.ufo/reports/round-7/kotoba.md` exists) but from
`corpus/knowledge/` resolves to `<repo>/.ufo/reports/round-7/kotoba.md`, and the repo's
`.ufo/reports/` holds `round-20`, `round-21`, `round-22` only. Evidence, both witnesses on

`report_dead=0/35`, `absolute=34`, **9/9 pass exit 0**.

## Limits (what I did NOT verify)

  `/tmp` arms whose sibling repos and fleet `.ufo` are **symlinks** to the real read-only
  paths. Path resolution cannot distinguish a symlink from a real directory, but I did not
  test a copy whose neighbours are real directories.
- The arms live under `/tmp`; their `.git` is a copy, so `git ls-files`/`cat-file` ran
  against copied objects, not the live repository. `corpus.index.tracked_files` and
  `report_total` pin bumps exist only in the arms; the live baseline is untouched.
- The fault harness was run only in its default all-pass mode on the move arm; I did not
  run it against the idiom variant, nor re-check its red paths.
- D1/D6 are characterized from `main()` + two runs per mode, not from a full read of the
  1857-line instrument.
