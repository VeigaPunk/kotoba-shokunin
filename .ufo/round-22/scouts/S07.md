## Findings

1. **The gate goes fully green and nothing else moves.** `line_budget` was the
   only red; on the moved copy all 10 checks PASS, and every other instrument
   returns the identical verdict and identical detail counts as its
   pre-move baseline. `SKILL.md` ends at **523** lines — 77 lines of headroom,
   so a smaller move (e.g. only the evidence paragraphs, file lines 103–166 =
   64 lines) would also clear the bar if the integrator prefers to keep the
   9-row table inline; the full-section move is the one measured here.
2. **The census/inventory checks are not affected** (the slice's explicit
   question). `verify_surfaces.py --repo <copy>` is 7/7 with detail counts
   byte-identical to the pre-move run, and the census's `## Class inventory`
   section is bounded by the next `^## ` heading, so an append at EOF is
   outside every id/literal/kind scan. Variant D/D′ shows the boundary is
   load-bearing and that appending *inside* the section would FAIL
   `table_parity`. Appended content is mass-free for surfaces **only** while
   it carries no `|`-led row with a backticked `harness:group/literal` token
   inside that section.
3. **Absorbing into the existing census file keeps `corpus-baseline.json`
   valid.** `corpus.index.tracked_files` stays 52 (no new tracked file), and
   `report_total 34` / `commit_total 27` are unchanged because the moved bytes
   carry no `.ufo/reports/round-N/` pointer and no `commit <hex>` citation.
4. **The move relocates checks, it does not merely relocate text** (D1, below):
   the executed citation population falls 42 → 36 and the command-subject
   population 19 → 13/15 → 9 segments. Those six commands and the moved
   citations' 11 raw repo-rooted occurrences have **no checker at the new
   home**.
5. **Collateral staleness is 2 lines, and fixing it is free** (Variant A):
   `SKILL.md:50` and `SKILL.md:188` still say `see "Instruction surfaces"`,
   which is now a stub; repointing both to
   `corpus/knowledge/instruction-surface-census-round13.md` keeps the gate
   green and raises the checked citation population to 38.

## Defects named (each: path:line + evidence)

- **D1 (medium — coverage loss).** The moved region loses its machine checks
  without gaining a replacement. Evidence: Variant C′ → `FAIL
  trigger.citation_resolves … line 127: 'corpus/knowledge/agent-def-audit-round6X.md'
  does not resolve` (rc 1) with the token at `SKILL.md:127` at HEAD; Variant C →
  the same token at `corpus/knowledge/instruction-surface-census-round13.md:379`
  (verbatim region lines 327–418) is invisible, all four instruments rc 0. The
  11 raw repo-rooted backticked occurrences leaving the checked population are
  at `SKILL.md:79, 80, 84, 85, 94, 96, 100, 111, 121, 127, 154`; the corpus
  instrument's scope is index rows + `.ufo/reports/round-N/` pointers + commit
  citations only, so nothing checks backticked path citations *inside*
  `corpus/*.md`. Integration should record this as a named, uncured debt (or
  extend an instrument) — do not report the move as check-neutral.
- **D2 (medium — placement constraint).** The append must land outside
  `## Class inventory`: `corpus/knowledge/instruction-surface-census-round13.md:64`
  → next `^## ` heading at line 240 (pre-move numbering). Evidence: Variant D
  (EOF append) → surfaces rc 0; Variant D′ (row inside the section) → `FAIL
  surfaces.table_parity: extra row(s) not in baseline: omp:fake/thing`.
- **D3 (low — verbatim carries a dead cite).** Four of the round-19 dead-path
  cites are inside the moved region: `/home/vgpnk/projects/shokunin/.ufo/prompts/*-L1.md`
  and friends at `SKILL.md:88, 97, 144, 153` (round-19 roll-call: 14 live
  lowercase cites in `SKILL.md`). They now sit at
  `corpus/knowledge/instruction-surface-census-round13.md:340, 349, 396, 405`;
  `test -e /home/vgpnk/projects` → **ABSENT**. A verbatim move preserves the
  defect and moves 4/14 of the repair target list into the corpus; case-
  correcting during the move would break "verbatim bytes". Integrator's call —
  but it must be recorded either way (a green corpus gate cannot see this
  class, per round 19).
- **D4 (low — stale cross-references).** `SKILL.md:50` and `SKILL.md:188` (post-move
  numbering; `:266` / `:50` at HEAD) point readers at `"Instruction surfaces"`
  for the per-surface rows, which are now in the corpus file. Gate-neutral to
  fix (Variant A: rc 0, citations 36 → 38).
- **D5 (low — append recipe trap).** 16 corpus files end without a trailing
  newline, including the target: `corpus/knowledge/instruction-surface-census-round13.md`
  (323rd line unterminated; same for `claim-census-round12.md`,
  `harness-verifier-round10.md`, `lessons/round-{6,8,9,10,11,12}.md`, …). A
  naive append welds the moved heading onto line 323; the recipe writes one
  `"\n"` first, which is why the diff shows a change on the previously last
  line. Verification command:
  `for f in corpus/knowledge/*.md corpus/lessons/*.md; do [ "$(tail -c1 "$f" | xxd -p)" = "0a" ] || echo "$f"; done`
- **D6 (info — simulation trap).** Any scout simulating on a naive
  `cp -a <repo> /tmp/x/copy` copy will report **three phantom FAILs**
  (`trigger.name_directory`, `trigger.citation_resolves`,
  `governance.citation_resolves`) that vanish in a faithful layout (dir named
  `kotoba-shokunin`, sibling symlinks to the fleet root). Use the faithful
  layout or the red-before/after pair is unreadable.
- **D7 (info — the alternative path costs more).** Creating a *new* corpus
  file instead of absorbing into the census would make
  `corpus.index.tracked_files` 52 → 53 against
  `verifiers/corpus-baseline.json` (`"expect": 52`), forcing a baseline
  re-record plus a README row (round-19 precedent). Absorption avoids it.
