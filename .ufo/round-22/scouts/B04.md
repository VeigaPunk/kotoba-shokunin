## Findings

**F1 — the box map cannot be harmed by this move (the charge).** § Sources is
the last section (only `## Refusals` precedes it), it contains zero `- [ ]`
lines (measured: 0), and no box follows its heading — so no box's *section*
attribution can shift. The 41 hashed box texts are unmodified by the move:
`checklist.box_map_complete` passes with `evaluated 41` in EA and EB, and the
match key is `(section, text_sha256)`, so a section shift or a one-character
edit would FAIL. No box text mentions § Sources (only `SKILL.md:311` /
`trigger.11` and `SKILL.md:327` use the word "source", as a *rule*), and
`SKILL.md` contains no `§ Sources` / "Sources below" cross-reference at all.
Consequence for the landing: **box texts must stay byte-identical** — do not
add a "moved to …" note inside e.g. the line-budget box (`SKILL.md:329`); that
edit is exactly what the hash pin is there to catch.

**F2 — the move lands the checklist fully green with 143 lines of headroom.**
601 → 458 lines; all 10 checks PASS (EA/EB). A 5-line stub is enough
(heading + summary + pointer).

**F3 — the stub's pointer is itself machine-checked.** The token
`corpus/knowledge/evidence-base-sources.md` in the stub is counted and
resolved by `trigger.citation_resolves` (EA: `evaluated 26 PASS`), so the
pointer cannot rot silently — the property the round-15 idiom wants.

**F4 — the corpus-side cost is bounded and mechanical.** A new *tracked*
corpus file moves `corpus.index.tracked_files` 52→53; the moved pointer moves
`corpus.pointers.report_total` 34→35. Both are equal-mode pins in
`verifiers/corpus-baseline.json`, so a re-record is mandatory (round-17
precedent: same file, "tracked_files moves 46 -> 47"). ED shows absorption
into an existing corpus file avoids only the `tracked_files` half; the
`report_total` re-record is unavoidable either way.

**F5 — "verbatim" must be read as bytes-minus-one-path-token.** The block's
`../.ufo/reports/round-7/kotoba.md` (`SKILL.md:591`) is one hop from the repo
root; from `corpus/knowledge/` the same bytes mean `corpus/.ufo/…`. The corpus
pointer base is the *file's own directory* (`verifiers/verify_corpus_integrity.py:349`
— `base = Path(rel).parent`), so the naive verbatim copy is red (EA) and the
re-based copy is green (EB). Every other byte is preserved (sha256 `a49d10fd…`).

**F6 — the move exports 17 citation tokens and 3 command subjects out of the
only instrument that resolves them.** `trigger.citation_resolves` 42 → 26
(17 moved out, 1 stub pointer added) and `trigger.command_binary_resolves`
19 subjects / 15 segments → 16 / 12. At the new home nothing checks them: the
EC probe planted `verifiers/b04_does_not_exist.py` and
`corpus/knowledge/b04-nope.md` as dead tokens inside a tracked corpus file and
**both corpus instruments plus the checklist exited without naming them**
(only the `.ufo/reports/round-99/…` token was caught). The corpus instrument's
scope is index coverage + `.ufo/reports/` pointers + `` commit `hash` ``
citations only. This is a verifiability regression, not a check failure.

**F7 — deictic rot inside the verbatim bytes (prose, unchecked).**
`SKILL.md:547` "the authority for every harness number **in this file**" — at
the new home "this file" is the corpus file, and the harness numbers are not
there. `SKILL.md:595` "§ Dispatch-prompt fidelity checklist **below**" — that
section exists only in `SKILL.md`. Both survive grep and every instrument
(no check reads prose reference direction).

**F8 — § Sources is the only section big enough for the job.**
Non-checklist section spans at HEAD: Skill-file anatomy 20 (55–74),
Instruction surfaces 93 (75–167), Router model 46 (168–213, incl. the
verifier-recipe subsection), Frontmatter craft 22 (214–235), Decision tables
