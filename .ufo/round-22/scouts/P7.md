## Findings

1. **Canonical guard is real, non-vacuous, read-only, deterministic.** Live
   run 3/3 exit 0; a one-hex-char sha mutation drives exit 1 with the failing
   pin named and in the DRIFT summary; the ±2000 ns mtime tolerance is
   load-bearing (1850 ns pass / 2850 ns fail, probed both sides); zero-pin and
   zero-`measured_against` baselines exit 2 `VACUOUS`, never a pass (round-21
   lesson honoured). Static grep shows no write call; baseline hash unchanged;
   no files created. It honestly declares its own biggest gap: docstring lines
   18–19 — "no --self-test in this prototype; the mutated-baseline probe is the
   behavioural test" — and that behavioural-test claim checks out (my
   independent mutations reproduce red; P5 scratch `/tmp/round22-p5/baseline-*.json`
   exists). So `--self-test` honesty: **no fabrication**, but also no
   packaged self-test.
2. **Exit-code contract diverges from the repo family.** Canonical missing/
   unparseable baseline → exit 2, while the baseline-consuming family reserves
   `3 = baseline missing/unparseable`: `verifiers/verify_harness_claims.py:28-30`,
   `verifiers/verify_surfaces.py:107-109` ("3 baseline missing or unparseable
   (bad JSON, missing keys…)"), `verifiers/verify_corpus_integrity.py:82-85`.
   The prototype's docstring self-declares 2, so it is internally honest —
   externally a fourth convention. (P2 chose 3 — convention-correct.)
3. **Malformed pin value crashes** (canonical): `iso_to_epoch_us` (line 59
   `re.match`) raises `TypeError` for a non-string pin; the caller catches only
   `ValueError` (lines 94–97), so the process dies with a traceback and exit 1
   — mislabelling a baseline-config error as drift, contradicting its own
   docstring's 0/1/2 contract. Permission failure while hashing (probe 15)
   likewise escapes as a traceback (only the baseline `read_text` is guarded).
4. **P2 variant is strictly worse where they differ, better where noted.**
   Vacuous pass on absent pins (exit 0), three uncaught-exception classes,
   strict ns-equality mtime compare that false-positives on any
   6-digit-precision pin (would have gone red on the pre-repair round-18
   baseline even though nothing moved); positives: exit 3 matches the family,
   and `--omp`/`--opencode` overrides exist (canonical lacks them).
5. **Neither variant is landable as-is; the merge is obviously specified:**
   canonical core + exit 3 for baseline errors + JSON error envelope
   (`"error"`/`"exit_code"`, cf. `verifiers/verify_skill_checklist.py:1739-1742`,
   `verifiers/verify_surfaces.py:980-983`) + `--self-test` over committed
   fixtures + (optionally) P2's binary overrides.
6. **Residual scope fact (not a prototype defect):** pins `command`,
   `round18_move`, `omp_round21_note` are silently skipped (canonical lines
   78–83); the guard enforces pin *content* but cannot detect a
   re-pin-without-note. Today's green is entirely due to round 21's re-pin;
   only mutated copies prove the guard bites.

## Limits (what I did NOT verify)

- **Only the four artifacts hashed here** (canonical P5, P2, P1, P4). P3 has no
  fragment under `.ufo/round-22/scouts/` at review time; P6 and P8 cover the
  same canonical artifact from other angles (adversarial probes, landing plan)
  — any conflict between those fragments is theirs to reconcile, not resolved
  here. Any later edit invalidates the cited hashes (P2 file mtime 01:28:33,
  P1 01:28:03, P4 01:29:13).
- **No Python <3.11 test** of the canonical docstring's compatibility claim
  (host is 3.14.7); no exotic-baseline fuzzing beyond the listed mutations
  (e.g. sha pin of wrong type, huge files, EIO mid-hash, symlinked binaries,
  `st_mtime_ns` races).
- **No integration review**: I did not check how any guard would wire into
  the checklist gate, SCORECARD capabilities table, or fixtures layout
  (`verifiers/fixtures/*` conventions unexamined beyond citing existing
  self-tests).
- **No live-tree mutation happened**: drift evidence is from mutated *copies*;
  the claim "guard catches a real rebuild" is proven only for baseline-content
  mutations, not for re-running after an actual binary swap (which would
  require replacing `~/.local/bin/omp` — out of slice and destructive).
- I did not execute P5's scratch baselines through the canonical guard
  independently of my own equivalents; P4's `run_cases.sh` and P1's spec
  exercises in `/tmp/P1/work/` were not re-run — only each artifact's own
  `--self-test` and my probes.
