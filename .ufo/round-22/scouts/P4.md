## Findings

### F1. Fixture layout (future landing)
```
verifiers/fixtures/pins/
  mini.bin        # committed fixture payload, 93 bytes:
                  #   b"#!kotoba-pin-fixture-mini-v1\n" + bytes(range(64))
                  # sha256 d3b4640ed5eb408197d7922ca1f2984d93fe7d7cbeb60c831f43f65c3952705c
```
No pin JSON is committed: `mtime_ns` is not checkout-stable, so each case **generates** its pin file into its own `tempfile.mkdtemp(prefix="pins-selftest-")` scratch (idiom: `verify_corpus_independent.py:599`), copying `mini.bin` to `bin/mini` first (`shutil.copyfile`). Generated pin file schema (list-shaped; a future live pin = `baseline.json:5-7` re-expressed):
```json
{"pins": [{"id": "fixture.mini", "path": "bin/mini", "sha256": "<64 hex>", "mtime_ns": 1792384172646278621}]}
```
`path` resolves relative to the pin file's directory. `mtime_ns` is an integer from `Path.stat().st_mtime_ns` — deliberately NOT the ISO string form of `baseline.json:6` ("2026-10-16T05:15:11.226207850-03:00"): string→ns parsing is a lossy landmine; the live adapter should emit ns ints.

### F2. The 4 cases, exact setup + assertions
Harness shape = repo self-test idiom: `--self-test` flag, in-process `run_capture(argv)` → `(code, stdout, stderr)` (`verify_surfaces.py:741-745`), `rec(what, ok, got)` collector (`verify_surfaces.py:752-756`), closing `N failure(s) over M assertions` (`verify_surfaces.py:941`), exit `1 if failures else 0`. All pin/JSON mutations act on the tmp copy only.

Shared setup per case: `tmp = mkdtemp(prefix="pins-selftest-<tag>-")`; `mkdir tmp/bin`; `copyfile(mini.bin, tmp/bin/mini)`; `pin(tmp)` writes `tmp/pins.json` with sha256 of the payload and `st_mtime_ns` as observed.

- **(a) match → exit 0.** argv `["--pins", <tmp>/pins.json]`. Assertions (5): exit == 0; stdout contains `PASS pin.fixture.mini:`; `FAIL` not in stdout; stderr == ""; no `Traceback`.
- **(b) sha drift → exit 1, naming the pin.** Mutation: append `b"\x00"`, then `os.utime(target, ns=(pinned_ns, pinned_ns))` to restore mtime (isolates sha; also exercises precedence, below). Reality-check assertion first: `st_mtime_ns == pinned_ns and sha256 != pinned_sha`. Assertions (6): exit == 1; `FAIL pin.fixture.mini:` in stdout; `sha256 drift` in stdout; both the pinned and the observed 64-hex hashes appear; `mtime drift` NOT in stdout (no double-report).
- **(c) mtime drift only → exit 1, distinct reason.** Mutation: `os.utime(target, ns=(pinned_ns - 10**9, ...))`, content untouched; reality-check: ns differs AND sha == pinned_sha (fails loudly if a filesystem truncates ns — the anti-flake guard). Assertions (7): exit == 1; `FAIL pin.fixture.mini:` in stdout; `mtime drift` in stdout; `sha256 unchanged` in stdout; both ns integers appear; `sha256 drift` NOT in stdout.
- **(d) missing binary → exit 2 (never 0/1).** Mutation: `os.remove(target)`. Assertions (5): exit == 2; stderr contains `missing`; stderr contains the path string; stdout has no `PASS`; no `Traceback`.

Total 23 assertions — exactly what the prototype ran green (command 2 above). Message grammar: `PASS pin.<id>: sha256 + mtime match` / `FAIL pin.<id>: sha256 drift: expect=<hex> got=<hex>` / `FAIL pin.<id>: mtime drift (sha256 unchanged): pinned_ns=<n> observed_ns=<n>` / stderr `ERROR pin.<id>: missing binary <path>` — matches `verify_surfaces.py:1054` `PASS/FAIL <id>: <detail>` and `1028` `ERROR …` stderr shape.

### F3. Decisions and justifications
- **mtime-only drift = exit 1 (strict), distinct reason `mtime drift (sha256 unchanged)`.** Justification: (i) the pin exists as a *change detector* — the repo's own recorded semantics are "a move means 're-record deliberately, naming the mechanism', not 'the live catalogue changed'" (`verifiers/baseline.json:127`), and the pinned artifact is a live install binary, so any rewrite at that path is a real event; (ii) sha256 alone cannot see content-identical rebuilds/reinstalls/restores — that whole event class would be invisible; (iii) exit 0 must mean "exactly as recorded"; a rewritten but byte-identical binary is not. Counterargument (touch/restore without content change → noise) is answered by the distinct reason string: re-pin deliberately once, no alert fatigue. Case (c) is deliberately the regression guard against the round-21 debt's shape — a recorded-but-unread field.
- **sha takes precedence** when both drift (code order: sha compare, then `elif` mtime). Case (b) proves it (mtime restored ensures sha is the only mover; assert `mtime drift` absent tests no-double-report).
- **missing binary = exit 2**, per the repo's EnvError convention: `"""Environment cannot answer the question (exit 2)."""` (`verify_corpus_integrity.py:406`, `verify_harness_claims.py:519`); precedent `verify_surfaces.py:925-930` (missing inventory → exit 2). 2 ≠ 1 keeps "cannot verify" apart from "verified drift". Zero-pin file → EnvError → exit 2 (anti-vacuity, mirrors surfaces' never-pass-on-empty stance).
- **Open integration decision (flagged, not decided):** malformed/unreadable pin JSON. The stub catches `OSError` only; `json.JSONDecodeError` would escape as a traceback. Recommend mapping to exit 2 (EnvError) or 3 if the integrator wants symmetry with `verify_surfaces.py:932-937` (missing baseline → exit 3).
