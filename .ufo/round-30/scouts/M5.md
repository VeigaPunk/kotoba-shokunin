# Scout M5

## Task
Floors guard `verifiers/check_assertion_floors.py`: confirm live green, then run one deletion probe (plus cheap side probes) on /tmp copies. Repo tree never mutated; HEAD b761cd6.

## Commands
- live: `python3 verifiers/check_assertion_floors.py` → exit 0, 6 × PASS.
- control: `tar --exclude=.git -cf - . | (cd /tmp/m5/pristine && tar xf -)` → exit 0 (byte-equal verdicts, 0.35 s).
- deletion probe: strip `verify_surfaces.py` self_test block (a) `# (a) clean fixture set` → `# (b) extra undeclared loader class` (6 lines) → `FAIL surfaces observed=74 floor=82`, exit 1.
- unparseable: replace the `%d failure(s) over %d assertions` print → `observed=0 summary=missing`, exit 1.
- whole-file: `rm verifiers/verify_surfaces.py` → exit 1 (no traceback).
- nonzero-exit spoof: self_test prints `0 failure(s) over 82 assertions` then `sys.exit(7)` → `FAIL surfaces`, exit 1 (returncode gate holds).
- count-preserving spoof: every `rec(..., True)` → PASS exit 0 (docstring trust boundary, expected).
- masked swap: replace block (a)'s 5 real assertions with 5 vacuous `rec("vacuous filler %d", True, None)` → **observed=82 floor=82, exit 0**.
- hang: inject `time.sleep(30)` at top of surfaces' self_test → guard blocks; killed only by external `timeout 20` (exit 124).
- override/arg paths: `--script surfaces=<path>` works; unknown name and `NAME` without `=` both → exit 2 usage error.

## Findings
- Deletion detection is real and clean: it names the instrument, prints observed-vs-floor, exits 1, and never crashes on a missing file. Counts match floors exactly (10/88/52/82/1504/51), i.e. zero headroom — any dropped assertion flips it.
- The guard is location-independent: correct from a foreign cwd and from any extracted copy (default `--repo` = parent of the script).
- Three gates combine (`match is not None and assertions >= floor and failures == 0 and returncode == 0`), so both the count and the self-test's own exit code are checked.

## Defects
- D-M5-1 (real, unguarded class): a self-test that **hangs** hangs the guard forever. `subprocess.run` at `check_assertion_floors.py:64-65` has no `timeout=`; probe survived 20 s externally, exit 124. A blocked instrument is indistinguishable from a slow box.
- D-M5-2 (claim overreach): the docstring's "a self-test that silently loses assertions must never still read green" is not true for count-preserving swaps. Swapping 5 real assertions for 5 vacuous `True` ones left `0 failure(s) over 82 assertions` → guard exit 0. The documented boundary covers *spoofed counts*; this is a same-count substitution of vacuous assertions, which the guard structurally cannot see (it reads only the printed total).
- D-M5-3 (operability): the guard is invoked by nothing. No `.sh` runner, no CI, no SKILL.md reference — only its own docstring; the sole live mention is the round-29 SCORECARD capability row. It is a manual capability, so silent regressions stay silent unless a human runs it.

## Limits
- A `verifiers/`-only copy is **not** a valid test bed: `verify_skill_checklist.py` reads repo-rooted fixtures, so a verifiers-only copy reports `self_test_failures=18` for checklist. All probes above used full-tree `/tmp` copies (`.git` excluded).
- Not probed: per-instrument floor correctness (whether 82/1504/… are the right numbers), and whether any instrument's `--self-test` can be reached without `--repo` pinning (round-24 Fix A territory).
- Scratch dirs `/tmp/m5/{pristine,full,spoof,unparse,gone,hang,masked,failing,sig}`; repo left untouched (`git status --porcelain` → only untracked `.ufo/round-30/`).
