## Findings
- **Repro (a), quoted text.** `ls /tmp >/dev/null` + `echo "write <<EOF to open a heredoc"` + dead `cat corpus/absent-round17.md` → checker **exit 0**, `PASS evaluated 1 — 2 segments`; `bash` → **exit 1**. The quoted line opens `heredoc_end="EOF"`; the dead tail is never segmented.
- **Repro (a'), trailing comment.** `ls /tmp` + `ls /tmp # <<EOF here` + dead `cat` → checker **0** (`evaluated 2 — 2 segments`); `bash` **1**. Same site, same swallow.
- **Repro (b), `<<EOF~`.** `python3 - <<EOF~` / `print(1)` / `EOF~` / dead `cat` → checker **0** (`evaluated 1 — 1 segments`); `bash` **1**. `HEREDOC_RE` captures `EOF` from `<<EOF~`, so the real terminator line `EOF~` never matches (`stripped == heredoc_end` at `:788` is false) and the body runs to end of block.
- **Causality controls (not coincidence).** Same dead `cat` with the phantom removed (`echo write EOF to open a heredoc`) → checker **FAIL exit 1** (3 segments); dead line placed *before* the phantom → **FAIL exit 1**. Only the presence/position of the phantom operator flips the verdict.

- **Controls green.** `-tilde` → 0 (3/2); `-tilde-dead` → **1** with the dead tail named; `-tilde-misterm` → 0 (1/1); `--self-test` → `0 failure(s) over 1504 assertions`; live gate → exit 0, no FAIL. ## Defects
1. `verifiers/verify_skill_checklist.py:311` — `HEREDOC_RE` delimiter group `(~?[A-Za-z_][A-Za-z0-9_]*)` stops at `~`'s left neighbour, so `<<EOF~` yields `EOF`; the terminator `EOF~` never closes the body (under-catch, false PASS).
2. `verifiers/verify_skill_checklist.py:784-795` — `HEREDOC_RE.search(line)` at `:793` is applied to the whole raw line with no quote/comment masking, so a `<<EOF` in `"…"` or after `#` opens a phantom heredoc that `continue`s every following line (`:787-790`), hiding all later subjects (under-catch, false PASS).
3. `corpus/knowledge/checklist-execution-round17.md:317` — the ceiling row states the wrong direction for delimiters ending in `~` (documentation only).
