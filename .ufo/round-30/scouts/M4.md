# Scout M4

## Task
Red probe: pins sha drift. Does `verifiers/check_substrate_pins.py` actually
catch a moved substrate pin, and does anything run it in live mode? Read-only
repo; all probes on `/tmp` copies.

## Commands
- `python3 verifiers/check_substrate_pins.py` / `--json` / `--self-test`; `sha256sum` of both binaries.
- Pin-side drift: `/tmp` baseline copies — real round-18 omp sha (`02302c5`: `ff59fc1b…`, mtime `2026-10-14T08:39:28.350702-03:00`), r1; 1-ns-early mtime, r4; opencode `f9dab322…`, r5; swapped shas, p4.
- Binary-side drift: byte-flip and touch of `omp`; 256-byte fixture pinned to itself (F0) then byte-flipped (F1).
- Edge pins: renamed key `omp_binary_sha256_v2` (p1); block deleted (p2); notes-only block (p3); sha + trailing `\n` (w1), leading/trailing space (w2/w3); `measured_against` as a JSON string (r8).
- Caller hunt: `grep -rn check_substrate_pins` across `*.py`/`*.sh`, `.git/hooks`, `SKILL.md`, `SCORECARD.md`; `check_assertion_floors.py --repo <drifted /tmp tree>`.
- Seven-gate sweep at HEAD `b761cd6`; live determinism ×3.

## Findings
- **Drift IS caught, on both sides.** r1 (pin side, real historical sha) → exit 1 `FAIL omp_binary_sha256: sha256 drift … DRIFT 1/3`; r4 (mtime 1 ns early) → exit 1 naming `omp_binary_mtime` `delta_ns=1`; r5/p4 → exit 1. F0 (fixture pinned to itself) → `OK 3/3`, then F1 (same fixture, one byte flipped) → exit 1 — so the comparison is **not** a tautology; the real hash is taken. `--json` agrees (`exit_code 1`, 2 PASS / 1 DRIFT).
- **All documented verdicts hold**: p2/r8 → `VACUOUS` 1; p3 → three `PIN_ABSENT` 1; p1 (canonical pin renamed) → `PIN_ABSENT` 1; unknown kind `omp_binary_sha512` → `UNSUPPORTED` 2; leading/trailing-space sha → `BAD_PIN` 3. Live `exit 0`, `OK 3/3 pins hold`, mtime `delta 0 ns`; 3 runs byte-identical (`890de993…` json, `82468d25…` text). All seven gates green; floors 6/6.
- **No automated caller runs the live mode** (D1). `grep -rn check_substrate_pins` → one hit, `check_assertion_floors.py:34`, which invokes `--self-test`. On a tree whose baseline is fully drifted the floor guard prints `PASS pins observed=51 floor=51` and exits 0 while live mode on the same tree reads `DRIFT 3/3` exit 1 — proven on `/tmp/m4iso2` with an all-bogus baseline. No CI, no git hook, no sweep recipe names the guard (`SKILL.md:463` documents it; `SCORECARD.md:140` says "six red probes per the round-23 claim", i.e. by hand).
- `SHA_RE` is `$`-anchored, not `\Z` (D2): w1 (trailing `\n`) passes the regex and lands as `DRIFT` (tier 1) with the two shas printed identical-looking, while w2/w3 (trailing space) are `BAD_PIN` (tier 3) — one malformation class, two tiers.
- `DISCOVER_RE`'s kind group is `[A-Za-z0-9]+`, so an underscore-bearing kind is invisible (D3): `omp_binary_sha256_v2` is neither compared nor reported — 3 checks evaluated, key absent from output, `exit 0` — against the docstring's "never a silent skip" (`:65`).
- Host has two opencode installs (`~/.opencode/bin` = the pin; `~/.local/bin` = `b240efa9…`); the pin names an absolute path, so the guard is blind to which binary is active. Documented host-anchoring (`:35-38`), not a defect.

## Defects
1. **Caller gap (freshness).** `verifiers/check_assertion_floors.py:34` is the guard's only caller and exercises `--self-test` only; that mode builds inline tempdir fixtures and never reads the repo baseline, so a drifted `measured_against` is invisible to every automated path. The round-21/23 class (a silent rebuild passing all gates) can still pass quietly — the guard exists but nothing runs it.
2. **`SHA_RE` `$` vs `\Z` (`check_substrate_pins.py:88`).** A trailing newline in a sha pin (a plausible heredoc/awk re-pin artefact) is accepted by the regex and mis-tiered as `DRIFT` (1) instead of `BAD_PIN` (3); a trailing space in the same position is `BAD_PIN`. Same malformation, two exit tiers.
3. **Silent skip of underscore-bearing pin kinds (`:83`).** `omp_binary_sha256_v2` matches the `_binary_` shape but not `DISCOVER_RE`'s `[A-Za-z0-9]+` kind, so it is skipped with `exit 0` and no row — the docstring's "a pin the guard cannot resolve is UNSUPPORTED, never a silent skip" is false for this shape, and a re-pin that renames a key this way reads green.

## Limits
- Big binary copies hit the `/tmp` tmpfs quota (4.4 G free vs 254 MB omp), so binary-side drift used byte-flip on a partially written copy plus the 256-byte fixture; both flip correctly, but the 254 MB omp was never hashed in full at a flipped state.
- No patch was written; all probes ran against the unmodified HEAD instrument on `/tmp` copies. Whether the caller gap should be closed by a floor-guard arm or a sweep recipe is the lander's call.
- `check_assertion_floors.py` on `/tmp/m4floors` also reported `FAIL surfaces … self_test_failures=81` and `FAIL checklist … summary=missing` — artefacts of copying a partial tree, not evidence about those gates.
