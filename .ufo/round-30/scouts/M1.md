# Scout M1

## Task
Red probe: tamper the fault harness inside a /tmp copy of the box; test whether the two
inert gates of claims F (freshness) / D (operability) are really inert. Box never mutated —
only `/tmp/m1*` copies and `/tmp/round12-faults.*` worlds were written.

## Commands
- live unpatched: `bash verifiers/fault_injection_corpus.sh` → `ALL PASS`; `--self-test` → `OK`
- `/tmp/m1c`: tamper — after `plant_f`, revert the plant in-world (no-op plant) → `fault-f FAIL`
- `/tmp/m1d`: decoy "planter" planting **nothing** (appends a *resolvable* `commit b761cd6`, drifting `commit_total`, `report_total` untouched) driving `fault_known_blind_f f` → `PASS`, `ALL PASS`
- `/tmp/m1e`: claim-F's proposed fix (planted total vs a **pristine** world's total)
- `/tmp/m1f` / `/tmp/m1g`: m1d decoy and m1c tamper against the fixed harness → both `fault-f FAIL`
- `/tmp/m1h` stub `sys.exit(2)`; `/tmp/m1i` stub `sys.exit(0)`; `/tmp/m1j` exit-code-only stub mis-attributing every dirty world to `report_dead`

## Findings
1. **(f) is inert — confirmed red.** `/tmp/m1d` plants nothing yet prints `PASS(blind-spot documented)` / `ALL PASS`. The gate reduces to `blind exit 0 AND baseline exit != 0`; the count detector never runs.
2. Root cause: `json_field` parses `out.json`, but the baseline run (`:292`) writes `out-baseline.txt`, so `base_total` (`:294`) re-reads the *same* `--no-baseline` number. On the real fault-f world `report_total=35` in both modes; `[ "$blind_total" = "$base_total" ]` (`:297`) is a tautology.
3. The claim's `counting_command` ("both M7 probes FAIL") is not what a naive tamper shows — `/tmp/m1c` FAILs, but only via the exit-code clause. A true (f) probe needs the m1d no-plant construction. The claim's *falsifier* ("either probe still passing") does hold against m1d.
4. Claim-F's fix is **verified sufficient**: m1e passes real `f` (`total 36 -> 35`), FAILs m1d and m1g, `--self-test` stays `OK`, rest of harness unchanged.
5. **(h) never consults the independent at all.** `fault_h_context` has no `run_independent` call and emits no independent row (call sites `:256,:289,:337,:351`; 337/351 are control/must-not-fire). The claim's "a stub independent FAILs (h)" is **not achievable as written**.
6. The claim's stub description ("always exiting 2") is itself off: `/tmp/m1h` yields six `MISS(independent-verdict)` rows for a–e and `fault-0-control` → `FAIL-control-dirty` — that stub is *detected*.
7. **(h) is inert in a narrower, real sense**: `/tmp/m1i` (stub always exit 0) leaves `fault-h` and `fault-f` `PASS`. Neither gate's content check runs, so a non-performing independent is invisible to f/h.
8. `/tmp/m1j` shows the content gap is narrow: six must-fire rows (a,c,d1,d2,e,control) stayed `PASS`, so (h)'s exit-code-only check is inert only when the independent exits non-zero.

## Defects
- D1: `fault_known_blind_f` count detector is a tautology (same `out.json` read twice) — (f) cannot notice a no-op plant; reproduced red via m1d.
- D2: `fault_h_context` never runs the independent — claim F's "(h) verifies the independent's verdict content" is unimplementable as stated.
- D3: claim F's `before`/`counting_command` mis-state the (h) hole: an exit-2 stub is already caught (6 MISS rows); the exit-0 stub is what slips through.

## Limits
- All probes on `/tmp` copies; box written only by this fragment.
- m1d's decoy is a harness-side construction (synthetic planter), not a harness bug — it exists only to exercise `fault_known_blind_f`'s verdict logic.
- No minimal one-line patch built for (h); D2/D3 report the gap. The (f) fix is verified end to end.
- Live invariance: harness sha256 `9db6c692…5d34`, independent `6d3a760e…eb902`, HEAD `b761cd6`, live `ALL PASS` before and after.
