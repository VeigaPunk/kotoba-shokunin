## Findings

**F1 — control is green in a /tmp copy, both instruments.** Run 0/0c: `9/9 checks
pass` exit 0 at `tracked=52, report_dead=0/34, commit_total=27`; the independent
re-derivation agrees class-for-class. No harness-fidelity trap: the corpus verifier
carries no directory-name or HOME-relative claim, so a `cp -a` copy named `repo`
reproduces the live verdicts. Scratch runs therefore start from a true green.

**F2 — the probe hypothesis is confirmed: one in-grammar dead pointer → exit 1, and
the site is named exactly.** Run 1 (a single appended line in a tracked, indexed
corpus file) moves `report_dead` 0→1 and `report_total` 34→35; the text output prints
`corpus/lessons/round-19-recensus.md:41: ../.ufo/reports/round-99/kotoba.md` in the
detail block (`verify_corpus_integrity.py:1014-1016`) and in `--json`
`report_dead_detail` verbatim — repo-relative path, 1-based line number, the offending
token. Site naming is not degraded by `--json` (run 3).

**F3 — the zero class is baseline-free, so the detector cannot be disarmed by editing
the baseline.** Run 2 (`--no-baseline`) still exits 1 with the same site line; only
the two `equal` rows degrade to OBSERVE. This matches the docstring contract ("a `zero`
violation is baseline-independent and still exits 1") and means the round-23
re-record of `corpus-baseline.json` cannot mask a dead pointer.

**F4 — both corpus instruments agree on the dead pointer.** Run 4: the independent
instrument reports `dead=1` with the identical site string and its own DRIFT row.
Agreement here is evidence rather than restatement, since the independent tokenizer
was written from the class spec.

**F5 — delivery form decides detectability; three shapes are structurally invisible.**
(a) A dead pointer fully inside double quotes is context, not a promise → exit 0
(run 5, `report_pointers_quoted` +1, `report_total` unchanged at 34). (b) Placeholder
tokens (`<lane>`) are excluded (the 8 pre-existing `pointer-excluded` sites). (c) A
dead **out-of-grammar** pointer — a path that does not end in `.md` (run 10, `.txt`) —
is invisible to **both** instruments (exit 0, `report_total` still 34). Only an
in-grammar `.md` token is a promise. (c) is the executably re-measured form of the
blind spot already recorded in `corpus/README.md:46` (visible only via the `equal`
count detector, and only as a class move, never as a named site).

**F6 — shape coverage is complete for the guarded grammar, and README is scanned.**
Runs 7-9: a dead pointer is named from `corpus/README.md` itself, from a `~/` pointer
(when resolved against an empty `HOME`), and for the bare and host-absolute shapes.
The index census is untouched by a prose-level pointer (`tracked=52 unindexed=0
stale=0 missing=0`, 65 FILE-column patterns) — the two families stay separable.

**F7 — commit citations are a second live zero-class.** Run 6: `commit `deadbee1``
(8 hex, unresolvable) → exit 1, `unresolvable=1` and `commit_total` 27→28, site
`corpus/lessons/round-19-recensus.md:41: deadbee1`.

**F8 — a tracked-but-absent corpus file takes the environment path, not the INDEX
path.** Run 11: the instrument aborts with a single `INCONCLUSIVE` line and exit 2,
suppressing all nine checks, the detail block, and the `--json` envelope (the JSON
mode still prints no JSON). The independent instrument crashes with a raw traceback
(exit 1, run 12). Both are loud (never a silent pass) but they destroy the observation
set — if this state coexists with a planted dead pointer, the dead pointer is masked.

**F9 — read-only holds.** Run 13: after all runs the mutated copy shows only my own
plant; no instrument creates or writes a file anywhere in the tree; the live tree at
HEAD `5a33c3e` is clean except for the untracked `.ufo/round-23/` scout area.

**F10 — round-23 integration reading (for the landing round, measured not guessed).**
The three `equal` classes move with any corpus edit: `report_total` 34→35 and
`commit_total` 27→28 in runs 1/3/6/9, `tracked_files` 52→53 for a new corpus file
(`corpus-baseline.json` `checks`). Until the baseline is re-recorded, the landing
commit reds the gate on the `equal` rows — the zeros stay green. The round-23 landing
therefore owes exactly one re-record, and the new corpus doc's pointer to the round-23
report must be an in-grammar, unquoted `.md` token (F5), resolvable from the citing
file's directory, or `after` is false.

## Defects named (each: path:line + evidence)

1. **`verifiers/verify_corpus_integrity.py:486`** —
   `raise Inconclusive(f"cannot read tracked file {rel_repo}: {exc}")`: a tracked
   corpus file missing from the working tree aborts the entire run (exit 2, one stdout
   line, no detail block, no JSON envelope) instead of classifying it under the
   `corpus.index.{missing_paths,stale_patterns}` family it is defined for. Evidence:
   run 11 — the deleted `corpus/lessons/round-19-recensus.md` (still in the index, so
   `git ls-files` counts it) yields `INCONCLUSIVE … No such file or directory` and
   nothing else; `--json` prints the same non-JSON line. Consequence: the run reports
   no verdicts at all, so a concurrently planted dead pointer is undetectable in that
   state. (The `missing_paths` machinery at `:325` never sees the token.)
2. **`verifiers/verify_corpus_independent.py:313`** — `open(path, encoding="utf-8")`
   inside `analyse_pointers` (called at `:391`, from `main` `:766`): on the same
   tracked-but-absent state the independent instrument dies with an uncaught
   `FileNotFoundError` traceback and exit **1** — an environment error wearing the
   drift exit code, contradicting its own docstring ladder ("2 environment
   unreadable"; the only `return 2` is `:769`). Evidence: run 12 — full traceback,
   exit 1.
3. **`verifiers/verify_corpus_integrity.py:134-136`** (`UFO_POINTER_RE`, the token
   must end in `\.md`) **+ `verifiers/verify_corpus_independent.py` pointer tokenizer**
   — a dead pointer whose target is not `.md` (e.g. `.txt`, a directory, any other
   extension) is invisible to both instruments: exit 0, `report_dead=0`, no counter
   move. Evidence: run 10 (`.txt` plant, `9/9 checks pass`, exit 0; independent also
   exit 0). Documented as the shared tokenizer blind spot at `corpus/README.md:46`;
   re-measured here executably. This bounds the slice sentence: "plant one dead
   pointer → expect exit 1" holds **iff** the planted token is `.md`-shaped, unquoted,
   and free of `<`/`>`/glob characters — a non-`.md` dead pointer, or one inside double
   quotes, is a green run.

No defect found in the two detectors' core purpose: the in-grammar, unquoted dead
pointer plant is caught with the exact site, in text and JSON, with and without a
baseline, by both instruments (runs 1-4).

## Limits (what I did NOT verify)

- **No git-index mutation probes** (no `git add` / `git rm --cached`): the
  `tracked_files` 52→53 move for a *new* corpus file is inferred from the `equal`
  class behaviour I did measure (runs 1/3/6/9 show equal-class drift reds the gate at
  exit 1 while zeros stay green), not from a staged-new-file run.
- Variants 1-4 mutate one line of one file at a time in separate copies; combinations
  (dead pointer + absent file, run-11 state + dead pointer) were reasoned, not run.
- Only the two corpus instruments and their `--self-test`s were run; the pin guard
  (round-23 claim P), the checklist, harness, surfaces and fault-injection Gates were
  not executed — sibling lanes own those. The `corpus.index.*` families were exercised
  only as controls and as the run-11 abort.
- Only `python3 3.14` on this host and its filesystem; no permission-denied (EACCES),
  symlinked corpus file, non-UTF-8 corpus file, or `HOME`-unset variant was probed
  (the tilde probe used an *empty* fake `HOME`).
- The exact assertion counts (`88`, `52`) and all exact verdict strings quoted here are
  pinned to the two file hashes above; any edit to either instrument voids them.
- Probe fidelity note for future lanes: host-absolute pointers in a `/tmp` copy resolve
  against the **live** tree's `.ufo/reports/` (they are rooted as-is), so a clone's
  POINTERS family measures the host tree, not the clone. This is why runs 1/4/9 use
  relative or bare shapes for the *plant* and run 8 uses `HOME` to kill the one tilde
  pointer; the 33 host-absolute pointers were never the mutation target.
- All scratch state lives under `/tmp/d23/m3/` (`repo`, `v1`-`v9`, `v1.json`,
  `fakehome/`) and is ephemeral; the authoritative record is this fragment.
