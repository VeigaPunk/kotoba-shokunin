### 2. Deviation list (draft vs family) with severity

S1 = blocker for the round claim, S2 = major, S3 = moderate, S4 = minor, S5 = info.

- **V10-D1 (S3) — instrument name.** `check_substrate_pins.py` vs the family's 5/5 `verify_*.py`
  (`verifiers/`: `verify_corpus_independent.py`, `verify_corpus_integrity.py`,
  `verify_harness_claims.py`, `verify_skill_checklist.py`, `verify_surfaces.py`; `ls -l`, all
  `-rwxr-xr-x`). The round-23 dispatch fixes this name, so it is a *recorded* deviation: the
  landing round should state the "guard ≠ verifier" rationale in the corpus doc (nothing
  in-tree uses `check_*` yet). Not blocking.
- **V10-D2 (S2) — OS-level baseline read error must be exit 2, not a traceback.** P3
  `/tmp/p3/check_substrate_pins.py:138-139` raises `EnvError` for a `chmod 000` baseline, but
  `main():464-471` catches `BaselineError` only → traceback, exit 1 (probe #12, text and
  `--json`) — while the same docstring `:47-52` promises "2 environment unreadable (… an
  OS-level baseline read error — never a pass)". **Closed in the V10 draft** by adding
  `except EnvError` after the load (`draft:499-505`) → `ERROR … Permission denied`, exit 2,
  JSON envelope (probe #20). Note the family has the *same latent bug* (§5).
- **V10-D3 (S1-for-claim) — silent shrink of the checked pin set.** P3's `check_declared`
  (`/tmp/p3/…:215-225`) only rejects *zero* pins; deleting any single sha pin leaves the
  remaining pin(s) checking PASS with exit 0 (probes #7/#8; only the mtime pin is protected,
  and then only because its check has its own zero-pin floor `:246-249`). This is exactly the
  P7 C9 class, and the round-23 claim requires red probe (f) "deleted single pin → exit 1
  PIN_ABSENT". **Closed in the V10 draft** by `EXPECTED_PIN_KEYS` (`draft:96-97`) +
  `pins.present` (`draft:222-231`) emitting `PIN_ABSENT <key>` in family wording; probes
  #15/#16/#17 now exit 1 naming the deleted key. This also preserves generic discovery
  (extra valid pins are still compared) without P1's hardcoded-only downside (P7 L3).
- **V10-D4 (S3, open) — exit-code tension for missing/null `measured_against`.** The round-23
  claim's red probe (e) says `missing/null → exit 1 (vacuity)`. The family convention
  (`verify_surfaces.py:107-109`) puts "3 baseline missing or unparseable (bad JSON, **missing
  keys**, …)" at exit 3, and the P1 spec agrees ("3 … no `measured_against` object"). The V10
  draft follows the family: absent/null block → exit 3 (probe #18), present-but-empty `{}` →
  exit 1 vacuity (probe #17), never a traceback in either case. The M6-D2 class (M6.md
  D-M6-2: block deleted → 28/28 pass) is closed either way; the landing round must re-word
  probe (e) or consciously diverge from the family ladder. Not blocking, but it is the one
  place where the claim text and the family convention disagree.
- **V10-D5 (S5) — self-test writes scratch files.** Family's self-test writes nothing; the
  pin guard must stage fake binaries + ns-exact mtimes into a `TemporaryDirectory`
  (`draft:320-337`) because git cannot store mtimes. Disclosed in the docstring (`:52`,
  `:56`); acceptable.
- **V10-D6 (S5) — `import os` inside `stage()`** (`draft:330`) instead of module top; style.
- **V10-D7 (S5) — mtime vacuity wording** (`draft:267`) lacks the `vacuity:` prefix used by
  `pins.declared`/`pins.binary_sha256`; makes the three vacuity messages inconsistent.
- **V10-D8 (S4, landing checklist) — file mode.** The prototype/draft is `-rw-r--r--`; all
  five family verifiers are `-rwxr-xr-x`. Landed copy must be chmod 755 (shebang is present).
