## Findings

### F1 — the deliverable: full docstring text (verbatim; to sit at `verifiers/check_substrate_pins.py:1`)

```python
#!/usr/bin/env python3
"""check_substrate_pins.py — machine check for the substrate identity pins.

The claim under test: the two substrate binaries this host runs — ``omp``
(``/home/vgpnk/.local/bin/omp``) and ``opencode``
(``/home/vgpnk/.opencode/bin/opencode``) — are still, byte for byte, the
builds recorded in ``verifiers/baseline.json`` under ``measured_against``,
and ``omp`` was last written at exactly the recorded nanosecond — so a
substrate move turns a gate red instead of passing unnoticed.  The pins were
inert prose until this script: round 21 re-pinned ``omp`` after the
2026-10-16 rebuild (``ff59fc1b`` → ``bf1e86a9``) and recorded, in the same
breath, "no check enforces this pin (named debt)"; round 22 demonstrated
executably that corrupting ``omp_binary_sha256`` — or deleting the whole
``measured_against`` block — left every verifier green.

Pins enforced (the declared set; all three are REQUIRED — the checked set
never shrinks to whatever the file happens to contain):

    omp_binary_sha256       sha256 of the ``omp`` binary, 64-hex, compared
                            case-insensitively
    omp_binary_mtime        ``os.stat(omp).st_mtime_ns`` compared EXACTLY to
                            the pin's integer nanoseconds (offset-aware)
    opencode_binary_sha256  sha256 of the ``opencode`` binary

The mtime pin is an ISO-8601 string with a 9-digit fraction; parse it by
taking the fractional digits as an integer (right-padded to 9) and doing
integer arithmetic — never ``datetime.fromisoformat`` (microsecond
truncation) and never ``.timestamp()`` float round-trips: both under-read
the live pin by 874 ns and would fabricate DRIFT against a faithful pin.
A pin recorded at lower precision (µs) reads as drift BY DESIGN; re-record
it from ``st_mtime_ns`` — never add a tolerance to silence it.

Usage:
    python3 verifiers/check_substrate_pins.py                # verify
    python3 verifiers/check_substrate_pins.py --json         # machine-readable
    python3 verifiers/check_substrate_pins.py --self-test    # fixtures only

    --repo PATH             repo root (default: the script's grandparent);
                            moves only the default baseline path
    --baseline PATH         pin source (default: <repo>/verifiers/baseline.json)
    --omp-binary PATH       override the measured omp path (fixture testing)
    --opencode-binary PATH  override the measured opencode path

Exit: 0 all three pins present, measured, and equal | 1 the measurement ran
and the record failed: a pin disagrees (DRIFT, naming the pin and both
values), a required pin key is missing (PIN_ABSENT — a shrunken enforcement
set is as loud as drift), or ``measured_against`` is absent/null/not a
mapping/empty of declared pins (vacuity: a block deleted or emptied is a
FAIL, never a pass — deleting it must not be silent, that is the point) |
2 the environment is unreadable: a pinned binary path is missing, is a
directory, is unreadable (EACCES), is a dangling symlink, or stat/hash
fails — the guard cannot measure; never a pass | 3 the baseline is
unusable: file absent/unreadable, not parseable as JSON, a declared pin's
value cannot be interpreted (not 64-hex, not an offset-aware ISO mtime), or
a pin-shaped key sits outside the declared set (misspelled key, unknown
subject, stray pin kind) — fail-closed and named: never silently skipped,
never silently enforced.  Precedence 3 > 2 > 1 > 0; no path prints a
traceback.  Text mode: PASS/FAIL lines on stdout; exits 2/3 diagnose on
stderr as one ERROR line.  ``--json`` emits one document on every path —
``{"checks": [{"pin", "kind", "binary", "expect", "observed", "verdict"}],
"pass": N, "fail": N, "exit_code": N}``, with an ``error`` field added on
error paths — and ``exit_code`` always equals the process exit code (the
harness gate's ``--json --no-baseline`` exit-0 divergence is deliberately
not replicated).  Output is deterministic: same tree + same binaries => a
byte-identical stdout in both modes; no wall-clock, pid, or duration field.

DOCUMENTED LIMITS:

1. Host-local pins, not hermetic.  The defaults are this host's absolute
   paths; on another machine, or after a legitimate local reinstall, exit 2
   or 1 is the correct answer, and green here attests nothing about any
   other host.  ``--baseline``/``--omp-binary``/``--opencode-binary`` are
   the seam every fixture run rides on.
2. opencode mtime is unpinnable and deliberately unpinned.  Its live mtime
   is a packer constant (``1985-10-26T05:15:00-03:00`` — epoch-class, not a
   build time) and carries no provenance, so opencode is pinned by sha
   only.  Adding an ``opencode_binary_mtime`` key is rejected at load
   (exit 3, rule above) — not silently blessed.
3. The pins are change detectors, not provenance.  A PASS attests
   "unchanged since recorded", not "legitimate" or "official": there is no
   signature or upstream manifest to consult, and anyone able to write the
   binary can also reset its mtime.  The two pin kinds witness different
   events: sha catches any content change down to one byte; the mtime pin
   catches a rewrite/reinstall/restore that leaves the bytes identical — an
   event sha alone cannot see.  A red pin is repaired only by the
   deliberate re-pin ritual: re-measure, write the new value, append a
   mechanism note beside the pin (the ``round18_move``/``omp_round21_note``
   idiom).  This script never re-pins anything itself; an auto-repin would
   recreate the inertness it exists to close.
4. Sample-once scope.  The pins are read once per run: a binary swapped
   concurrently is a move the next run sees, not a race this run resolves.
   Symlinked paths are followed (``os.stat``): the effective file is what
   is measured; a dangling link is exit 2.  ``measured_against`` prose keys
   (``command``, ``round18_move``, ``omp_round21_note``) are counted and
   reported, never interpreted or executed; the ``corpus-baseline.json``
   repo-head pin needs ancestry semantics and is out of scope.

Read-only; deterministic; stdlib only.  Read-only guarantee: the guard
opens the pinned binaries as bytes and streams sha256 in 1 MiB chunks (so
the ~460 MB pair never sits in memory), and opens nothing else besides the
baseline JSON and ``os.stat``.  It never executes a pinned binary or any
other process — an exec-based "version check" is not read-only: it writes
to surfaces other gates observe (``opencode --version`` appends ``cli
starting`` lines to the log the harness gate's ``oc.log.*`` checks read;
``omp --version`` touches dozens of files under ``~/.omp``).  And it writes
nothing anywhere: no re-pin, no cache, no state files; no imports beyond
the standard library, and the file is only ever run as ``__main__``, so
nothing new lands on disk.

``--self-test`` runs the CLI surface in-process (``run_capture(main)``)
against committed fixtures under ``verifiers/fixtures/pins/`` — a small
non-empty fake binary plus per-case pin files generated into a temporary
directory that is removed on exit; no host binary and no ``$HOME`` path is
read — and closes with ``N failure(s) over M assertions`` (exit 0/1; not
the ladder above).  The cases cover the whole ladder and the named defect
classes: sha drift, mtime-only drift (including a 1 ns delta and a
µs-truncated pin), PIN_ABSENT, vacuity (absent / null / empty
``measured_against``), missing binary, corrupt JSON, malformed pin value,
stray pin-shaped key, and the integer ns round-trip (the 874 ns trap) so
the cheap-but-wrong parser cannot pass the suite.
"""
```

### F3 — decisions recorded (so the landing round does not re-litigate)

1. **Vacuity vs baseline-error split (contract conflict resolved).** Missing/null/
   non-mapping/empty `measured_against` → **exit 1** vacuity, per claims probe (e);
   absent file or unparseable JSON → **exit 3**, per probe (d). This *supersedes*
   `P1.md:137` ("`3` baseline absent/unparseable/no `measured_against` object") for
   the null case — the round contract fixed the probe explicitly, and P3's
   `pins.declared` vacuity-FAIL (exit 1, `P3.md:97-99`, its run 6) is the compatible
   precedent; canonical's exit-2 VACUOUS (`P7.md:132-137`, C3) is rejected as both
   divergence from the family and from probe (e).
2. **Malformed pin value → exit 3, named, no traceback.** Closes P6-D1
   (`P6.md:41`, `/tmp/check_substrate_pins.py:78-80` TypeError) and P7-C1
   (`P7.md:122-125`, `:59` TypeError); replaces P1's PIN_ABSENT mislabel
   (P7-L2 `P7.md:233-236` — "the diagnosis lies"): PIN_ABSENT is reserved for a
   genuinely missing required key, malformed values get their own named exit-3
   diagnostic. Rejected: exit 1 (a config error wearing the drift code) and
   canonical exit 2 (C3 divergence).
3. **Stray/mistyped pin-shaped key → exit 3 at load (fail-closed grammar).**
   The two silent directions are both closed: missing → PIN_ABSENT (P7-C9,
   `P7.md:158-165`), stray → load rejection (P1-L3, `P7.md:238-243`). Rejects
   canonical's compare-blessing of a stray `opencode_binary_mtime`
   (`P7.md:162-165` probe `extra-oc-mtime.json` → exit 1): limit 2 says such a
   pin is meaningless, so it must be refused, not compared to green. Model:
   P3's load-rejection grammar (`P3.md:87-94`).
4. **mtime exact at ns, no tolerance.** Required by `P1.md:166-167` (ambiguity 5),
   `P3.md:151-165` (F3), `P8.md:132-133`; canonical's ±2000 ns tolerance
   (`P5.md:83-86`; P7 probes 1850 pass / 2850 fail) was a workaround for its
   µs-truncating parser — with the integer-fraction parser (F1, verified this
   lane) a tolerance would only mask up to 2 µs of real drift. A µs-truncated
   pin reds by design; remedy = re-record, never loosen.
5. **Fixed required set + generic shape scan ("both sides" per `P7.md:243`).**
   The three declared pins are required; any other pin-shaped key is refused.
   The checked set never shrinks silently and never grows silently.
6. **JSON envelope on every path; `exit_code` parity.** Closes P7-C4
   (`P7.md:138-142`); adopts `{"error", "exit_code"}` (`verify_skill_checklist.py:1733-1743`
   verified command 7) and the `checks/pass/fail/exit_code` shape
   (`verify_surfaces.py:975-984` verified command 6); keeps P1 cmd 18's
   text/JSON parity and refuses the harness's `--json --no-baseline` exit-0
   divergence (`P1.md:137-139`).
7. **Hash-never-exec stated with its evidence in the docstring itself** (P1-F4,
   `P1.md:74-85`) so a future editor cannot "improve" the guard with an exec-based
   version probe without contradicting the file's own contract; and the docstring
   carries **no live pin values / line numbers**, so re-pinning does not rot it.
8. **Name `check_substrate_pins.py` is fixed by `claims.json`** (`verifiers/check_substrate_pins.py`;
   P8 adopted it too). P1's `check_*`-vs-`verify_*` divergence note (`P1.md:104-106`)
   is recorded as a deliberate round choice, not harmonized.
