## Findings
- **Regression GREEN: the vacuity FAIL is intact at HEAD `5a33c3e`, and it was never at risk from rounds 22–23 in the first place** — the script sha is byte-identical to the one round-22 M2 probed at `b16300f` (`cfebbca9…`), so the two probes are the same instrument at two HEADs. Crafted (530 B) and real-derived (47 MB) non-empty dead dumps both return **exit 1** with the vacuity wording, in single-check isolation (R1/R2) and full gate (R1b/R2b), against both the live 8-row and the fixture 2-row `loader-group` declarations.
- **The round-22 "crafted, not a real dump" limit is now closed**: `omp-live-domainless.txt` is derived from the live binary's own `strings` output (244 real allowlist-callee call sites, 47 071 461 B) with every `.md` name uniformly renamed — machinery present, literals mostly present (non-`.md` ones), `.md` extraction 0 → vacuity. This is the closest available simulation of a substrate rebuild that keeps loaders but loses `.md` registrations, and it flips exactly as designed.
- **The trapdoor is not only closed but self-tested**: R6 shows removing the branch on a copy yields the exact silent-pass it exists to kill (`PASS … all 0 extracted loader class(es) declared`) and the committed `--self-test` catches it (1 failure / 75 assertions, exit 1). The b3 records are at `:796-798`; the b3 fixture `strings-empty.txt` is itself a non-empty dead dump (100 B: `"AGENTS.md"`/`"CLAUDE.md"` literals, 0 call shapes), not a 0-byte file — so the committed regression case already exercises the non-empty form.
- **opencode analog also closed**: a non-empty dead opencode dump trips `surfaces.opencode_extract`'s zero-extraction rule (`:649-654`) with all 5 declared ids and 6 unmatched rules named (R5); `no_uncovered_class` staying green there (R5b) matches the documented per-harness scoping.
- **Division of labour is sharp**: vacuity covers the 0-extraction case only. Partial vanish stays green *inside* `no_uncovered_class` (R8: 1 of 2 fixture pairs) and is caught by `literal_present`, which reports the lost shape by name with the "no call shape" reason (R8b). One-declared-drop and all-dead are different nets by design; the round-23 regression claim should cite both.
- **The guard is baseline-relative** (R7): with `baseline-empty.json` the dead dump greens `no_uncovered_class` because no `loader-group` rows are declared — protection against a *baseline* shrink lives in the sibling parity checks and in the full gate (R7b exit 1 via 4 checks). No false PASS observed anywhere: every configuration that should be red is red at the gate level.
