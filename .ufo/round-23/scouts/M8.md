## Findings

**F1 — VERDICT, CONFIRMED: the round-21 (b2) fixture block is a live detector at round-23
HEAD.** A callee rename on the fixture's gemini caller (`Co`) or claude caller (`Dl`) flips
`--self-test` to exit 1 with exactly the expected naming:
`self-test FAIL: new-callees: exit 0: got 1` plus
`FAIL surfaces.literal_present: 1 loader literal(s) not verifiable: omp:gemini/GEMINI.md (no
(Id|Cl|jD[ef]|Tl|dr|GW|Co|Dl|Hj)(<v>, <group>, "<file>.md") call shape …)` (resp.
`omp:claude-md/CLAUDE.md`). 2 failure(s) over 75 assertions. Both live and copy controls are
green (0/75), so the red is causally the corruption.

**F2 — Detection map (measured, single-variable mutations of the pristine fixture):**

| corruption | exit | what names it |
|---|---|---|
| `Co`→`Cp` line 5 alone / both Co sites | 1 | `literal_present`, `omp:gemini/GEMINI.md` |
| `Co`→`Cp` line 10 alone (decoy `= Co;`) | **0** | — undetected |
| `Dl`→`Dm` | 1 | `literal_present`, `omp:claude-md/CLAUDE.md` |
| group `"gemini"`→`"gemini2"` | 1 | `literal_present` (gemini missing) + `no_uncovered_class` (`omp:gemini2/GEMINI.md` undeclared) |
| literal `"GEMINI.md"`→`"GEMINI.txt"` | 1 | `literal_present`, gemini |

| all three renamed | 1 | both classes + vacuity branch |

The two exit-0 rows are coverage boundaries of the fixture (D1/D2 below), not detector
failures: M1's round-22 F2 result reproduces byte-for-byte at HEAD.

**F3 — Double corruption reaches the round-21 vacuity branch; a single break does not.**
With only `Co` broken, `no_uncovered_class` still PASSes (`all 1 extracted loader class(es)
declared` — the surviving `Dl(e, BWr, "CLAUDE.md")` path); with BOTH `.md` call shapes broken,
extraction is 0 and `no_uncovered_class` emits the vacuity FAIL (command 5/10), escalating the
same fixture corruption to a two-layer red (per-class literal presence + vacuity floor). So the
(b2) block is deliberately two-layered; a round planning the pin-guard's PIN_ABSENT/vacuity
behaviour (P7 C9 silent-shrink class) has this repo precedent directly measurable in-tree.

**F4 — Group rename is caught in both directions.** `"gemini"→"gemini2"` (command 11) yields 3
failures: forward (`omp:gemini/GEMINI.md` declared but not extracted) and backward
(`omp:gemini2/GEMINI.md` extracted but undeclared). The extractor's two-way parity claim
(`verify_surfaces.py:99-105`) holds on this fixture.

**F5 — Pre-landing state for claim P, measured at HEAD:** `measured_against` reads = 0 across
all six `verifiers/` scripts and `verifiers/check_substrate_pins.py` does not exist (commands
13/14). M8 adds the *idiom* evidence for the landround: the fixture-corruption red probe the
P-lanes designed (P4 fixture cases a–d; claim-P red probes (a)–(f)) follows an existing,
demonstrably live pattern — a committed fixture + `--self-test` that names the corrupted pin.

**F6 — Cross-round pinning:** fixture sha and `verify_surfaces.py` unchanged since `2ca8d01`

## Defects named (each: path:line + evidence)
1. **`verifiers/fixtures/surfaces/strings-omp-newcallees.txt:6` — the `Hj(e, "cursor",
   "rules")` line is a non-detection witness.** Renaming the callee (→`Hk`) leaves `--self-test`
   exit 0 / `0 failure(s) over 75 assertions` (command 9; sha `59bb04be…`). Why, in source:
   `OMP_CALL_RE` requires a `.md`-suffixed file (`verifiers/verify_surfaces.py:154-158`), and
   `omp:cursor/rules` is `loader-literal` (`verifiers/fixtures/surfaces/baseline-clean.json:20-23`),
   so only the string `"rules"` is checked and it survives the rename. Re-confirms M1 D1 at
   HEAD; fixture coverage limitation, documented at `verify_surfaces.py:784-785`.
2. **`verifiers/fixtures/surfaces/strings-omp-newcallees.txt:10` — the decoy reference
   `const xSomeId = Co;` is a second non-detection witness (new, M1 renamed both Co sites
   together).** Renaming only line 10 leaves exit 0 / 0 of 75 (command 7; sha `f1ad502c…`),
   while line 5 alone is fully load-bearing (command 6). If a future round regenerates this
   fixture, the comment at `verify_surfaces.py:784-785` should not claim line 10 as a
   callee-shape witness; only `.md` call shapes are.
3. **Boundary (not a defect) — a single-callee break cannot exercise the vacuity branch:**
   `verifiers/verify_surfaces.py:556-561` fires only at 0 extraction; evidence command 3
   (`no_uncovered_class` PASS) vs command 5 (vacuity FAIL). Recorded so the landing round does
   not build a red probe expecting vacuity from one broken callee.
