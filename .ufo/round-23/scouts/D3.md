## Findings

### F1 — The merged design, as implemented (what a landing round should copy)

`/tmp/d23/D3.py`, stdlib only, CLI: `--repo` (default script grandparent),
`--baseline` (default `<repo>/verifiers/baseline.json`), `--omp-binary`,
`--opencode-binary` (defaults = the host paths of
`verify_surfaces.py:126-129`), `--self-test`, `--json`.

* **Enforced set (two-way, closes P7 C9):** `REQUIRED_PINS` =
  `omp_binary_sha256` (sha), `omp_binary_mtime` (ns mtime), `opencode_binary_sha256`
  (sha) — exactly the three keys live in `verifiers/baseline.json:4-9`; opencode
  mtime is deliberately unpinned (its live mtime is the synthetic
  `1985-10-26T05:15:00-03:00` build constant, P8 finding 2d). A required key
  that vanished → `PIN_ABSENT` exit 1; any *other* pin-shaped key
  (`^[a-z0-9]+_binary_(sha256|mtime)$`) → `PIN_UNKNOWN` exit 1, so a third
  substrate pin (the P6 "silent coverage boundary") or a deleted pin can never
  shrink the checked set silently. Ordinary prose keys (`as_of`, `host`,
  `command`, `round18_move`, `omp_round21_note`) are listed in a `NOTE … ignored`
  line and in JSON `ignored_keys`.
* **Exit ladder (family ladder 0/1/2/3, precedence 3 > 2 > 1 > 0):** 0 all pins
  PASS; 1 DRIFT / PIN_ABSENT / PIN_UNKNOWN, every failing pin named on its own
  line and in the `DRIFT k/n pins failed: …` summary; 2 a binary that must be
  hashed is unreadable (ENOENT/EISDIR/not-regular; EACCES would land here on the
  same `OSError` path, untested); 3 baseline missing/unparseable/wrong-shaped
  (bad JSON, top-level not an object, no `measured_against` object, non-mapping
  `measured_against`, non-string pin value, unparseable mtime pin, sha pin that
  is not 64 hex). `--json` returns the same code as the text path on every path
  tested (no repetition of `verify_harness_claims.py:658`'s JSON-returns-0).
* **ns-exact mtime, no tolerance.** `parse_iso_ns` does digit arithmetic
  (`re` + `calendar.timegm`); the alternative — `datetime.fromisoformat().timestamp()`
  — reads the live pin **874 ns low** and would red a faithful pin (my own
  re-measurement, table row above). The design decision versus the canonical
  prototype's ±2000 ns tolerance is deliberate: with an exact parser the live pin
  is green at delta 0, and a µs-truncated pin is a *different pin* (battery row
  `b-mtime-us` → exit 1), so the re-pin ritual must write 9 fractional digits.
  Tolerance would silently accept the residue the round exists to detect.
* **Read-only / hash-never-exec.** Binaries are opened `rb` in 1 MiB chunks;
  `subprocess`/`os.system`/`popen`/`exec*` appear nowhere (grep exit 1); nothing
  is written, never re-pinned; run leaves `verifiers/baseline.json`
  byte-identical and adds no file in-repo.
* **Determinism.** JSON `indent=2, sort_keys=True`, no wall-clock/host/pid field,
  record order fixed by `REQUIRED_PINS` then sorted unknown keys; stdout
  byte-identical across runs in both modes.
* **`--self-test` (P4 idiom, defects fixed).** 54 assertions run the **CLI
  surface** (`run_capture(main)`, stdout+stderr captured) against worlds generated
  in `tempfile.mkdtemp`: match→0, sha drift→1, 1 ns mtime drift→1 (with a
  reality-check `delta_ns=+1`), missing binary→2, PIN_ABSENT→1, PIN_UNKNOWN→1,
  non-string mtime pin→3, non-string sha pin→3 in both modes, null block→3,
  deleted key→3, missing baseline→3, bad JSON→3, garbage mtime→3, ns round-trip
  (9-digit pin PASS / µs-truncated pin DRIFT), determinism + JSON parity, read-only.
  Worlds are `shutil.rmtree`'d and the last assertion proves zero leftovers
  (closes P7 F3's leak: 0 `/tmp/d3-selftest-*` after two self-test runs).

### F2 — The adversarial extra (this slice's named requirement): exit 3, no traceback

`battery/b-nonstring-mtime.json` = live baseline copy with
`measured_against.omp_binary_mtime = 12345`:

```
$ python3 /tmp/d23/D3.py --baseline /tmp/d23/battery/b-nonstring-mtime.json
ERROR omp_binary_mtime: pin value is int, not a string (12345)      [stderr]
exit=3, no traceback
$ … --json
{"checks": [], "error": "omp_binary_mtime: pin value is int, not a string (12345)",
 "exit_code": 3, "fail": 0, "pass": 0}
```

Both P6 D1 (`null`/`int` `measured_against` → TypeError traceback, exit 1) and
P7 C1 (`mtime-int` pin → `TypeError: expected string or bytes-like object`,
exit 1) are closed: types are validated in `declared_pins` before any comparison,
so a config error is never reported as drift and never escapes as a traceback.
The same exits 3 hold for `float`-like non-strings, `bool`, `list`, and for
non-registry pin keys.

### F3 — Live green is real, and red-before is free

The live baseline is green at the strict ns-exact setting, so round 21's prose
re-pin is accurate by measurement: omp sha `bf1e86a9…4974`, omp mtime
`1792138511226207850` (delta 0 ns), opencode sha `d9123b9b…18c9`. Red-before for
the landing round is a `/tmp` baseline copy with `omp_binary_sha256` set to the
round-18 pin `ff59fc1b…074e` → exit 1 `DRIFT omp_binary_sha256`, i.e. exactly the
state the 2026-10-16 rebuild created while every gate stayed green.

### F4 — Divergence table D3 vs the four round-22 prototypes (for the integrator)

Same input → different codes across prototypes, which is the integration hazard
worth naming: a *present but unparseable* mtime pin is exit **3** here (config
error), exit **1** PIN_ABSENT in P1 (P7 L2 "the diagnosis lies"), exit **1**
traceback in the canonical guard (P7 C1), exit **2** ENVIRONMENT in canonical's
non-traceback paths. A *deleted* pin key is exit 1 here and in P1, exit 0
`OK 2/2` in canonical (P7 C9 silent shrink). D3's ladder is the family-consistent
one: 1 = the pins and the substrate disagree; 2 = the guard cannot measure;
3 = the baseline cannot be read as pins at all.

## Defects named (each: path:line + evidence)

The draft closes, by construction and by probe, the two classes this slice was
required to close; both were live in round-22 artifacts:

1. **P6 TypeError class — closed.** `/tmp/check_substrate_pins.py:78-80`
   (`pins = baseline.get("measured_against", {})` then `for key in sorted(pins)`)
   and `:59` (`re.match` in `iso_to_epoch_us` with a `ValueError`-only catch at
   `:94-97`). Evidence from my battery: `b-nonstring-mtime.json` → exit 3,
   `ERROR … pin value is int, not a string (12345)`, no traceback; `b-null.json`
   / `b-int.json` → exit 3, no traceback. D3 validates at
   `/tmp/d23/D3.py:165-168` (inside `declared_pins`), before any comparison or
   `parse_iso_ns` call.
2. **P7 C9 silent shrink — closed.** Canonical vacuity guard fires only when *no*
   recognized pin remains (P7 probe: `one-pin-missing.json` → `OK 2/2 pins hold`,
   exit 0). D3's `REQUIRED_PINS` check at `/tmp/d23/D3.py:289-293` yields
   `PIN_ABSENT omp_binary_mtime …` + `DRIFT 1/3 pins failed` + exit 1 on the same
   shape (`b-absent-mtime.json`), and `PIN_UNKNOWN` (exit 1) for a stray pin
   (`b-stray.json`) instead of canonical's exit-0-for-P1-and-exit-1-for-canonical
   split.
3. **P7 F3 mkdtemp leak — closed.** P4's self-test never removes its worlds
   (`/tmp/round22-p4/check_substrate_pins.py:113`); D3's `self_test` cleans in
   `/tmp/d23/D3.py:563` and asserts zero leftovers; measured
   `ls -d /tmp/d3-selftest-*` → 0 after two runs.
4. **P7 C4 no JSON error envelope — closed.** D3's 3/2 paths print
   `{"checks": …, "error"/per-pin verdicts, "exit_code": N}` (`emit_json`,
   `/tmp/d23/D3.py:236`) instead of 0 B stdout.
5. **Re-pin tool hazard (new, named for the landing round's ritual):**
   `verifiers/baseline.json:6` is the only ns-precision pin in the repo; any tool
   that writes ISO time from `datetime.isoformat()` (µs) produces a pin that D3
   reds (battery `b-mtime-us.json` → exit 1, 850 ns residue). The re-pin recipe
   must emit `st_mtime_ns`-derived 9-digit fractions; P4.md F1 reached the same
   conclusion from the fixture side.
6. **Not a defect, a deliberate non-goal:** `measured_against.command`
   (`"python3 verifiers/verify_harness_claims.py --no-baseline --json"`) and
   `round18_move`/`omp_round21_note` prose are ignored by design — enforcing
   `command` as a reference would mean exec-ing a gate (the read-only rule) and
   parsing its JSON envelope; and the
   round-21 baseline's JSON-path exit-code defect (F1 D2) makes it an unsafe
   reference anyway.

## Limits (what I did NOT verify)

* **Not landed, not integrated.** `verifiers/check_substrate_pins.py` does not
  exist in the tree; the draft lives at `/tmp/d23/D3.py` only, and I made no
  change to SCORECARD/corpus/SKILL/corpus-baseline (the P1 F5 / P8 §3 integration
  costs — `corpus.index.tracked_files` 52→53, a `SKILL.md` instrument bullet
  against the ≤600 line budget — are still unmeasured by me).
* **EACCES unprobed.** Exit 2 is verified for ENOENT and EISDIR and for a
  non-regular file; a `chmod 000` binary was not exercised (single-user host, and
  creating the case would touch `$HOME` copies only — it was not run at all).
* **No real substrate move.** All drift evidence mutates `/tmp` baseline copies or
  fixture worlds; the claim "the guard catches an actual rebuild" is proven only
  for pin-content mutations. No live binary was replaced, hashed-then-exec'd, or
  otherwise touched.
* **Concurrency/TOCTOU:** a binary swapped between `os.stat` and `open` (sha
  path reads bytes first, then `st` was taken before — mtime and bytes are not
  taken atomically) is unprobed; the fleet's concurrent omp lanes make a race
  theoretically reachable, though the guard's read is one stat + one open.
* **No Python <3.11 run** (host 3.14.7); no exotic-baseline fuzzing beyond the
  listed mutations (huge files, EIO mid-hash, unicode keys, symlink loops).
* **Fleet/idle assumption:** the "opencode log unchanged (3327→3327)" observation
  is bounded to my run window; it is corroborating, not proof, and the primary
  no-exec evidence is the static grep plus the fact that only `open("rb")`/`stat`
  appear in the code.
