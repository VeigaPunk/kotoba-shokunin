## Findings

### F1 — the family ladder, cited exactly (and it is not uniform in slot 3)

- `verifiers/verify_harness_claims.py:28-30` — "0 all checks agree with the baseline; 1 drift;
  2 the environment is unreadable (missing binary / db / log); 3 no baseline found
  (observations printed)".
- `verifiers/verify_surfaces.py:107-109` — "0 all checks pass | 1 any FAIL | 2 environment
  unreadable (binary, dump file, strings tool, inventory file, or an OS-level baseline read
  error — never a pass) | 3 baseline missing or unparseable (bad JSON, missing keys, malformed
  class id)".
- `verifiers/verify_corpus_integrity.py:82-87` — mirrors harness; adds "`--no-baseline`
  suppresses the comparison … but a `zero` violation is baseline-independent and still exits 1".
- `verifiers/verify_corpus_independent.py:29` — "0 every violation class empty, 1 any violation,
  2 environment unreadable" — **no exit 3** (it consumes no baseline).
- `verifiers/verify_skill_checklist.py:242-245` — 0 (with ≥1 subject evaluated) | 1 "any FAIL,
  or a run in which the executed checks together produce no subject" | 2 usage or environment |
  3 "THE BOX MAP is missing, unparseable, or unbound to the target — a gate failure class, not
  merely 'environment unreadable'".

So the 0/1/2 core is universal, slot 3 exists only in the baseline-consuming members, and
checklist repurposes 3 as a *gate-failure* class ("not merely environment unreadable"). The pin
guard is a baseline-consuming member, so the harness/surfaces/corpus_integrity sense of 3 is the
right precedent — and checklist:48 supplies the second half of my slot-1 rule: a run whose
executed checks evaluate *no subject* exits 1 (exactly the vacuity rung the round-21 lesson
demands).

### F3 — divergences, each justified (the slice's deliverable)

1. **VACUOUS (absent/null/empty/non-mapping block) sits on 1, not 3 and not 2.** P1's spec put
   "no `measured_against` object" on 3 (P1 §Ambiguities 7) and P6's D1 hardening suggested 2;
   `claims.json` probe (e) fixes it at 1 ("missing/null measured_against -> exit 1 (vacuity, the
   M6-D2 defect class)"). Justification beyond the claim: 3 means the baseline *document* cannot
   be read as a pin set (IO/JSON/shape at the root); a readable document that declares no pins is
   a policy verdict — the same class as a deleted pin, and `checklist:48` sets the family
   precedent that "no subject evaluated" is 1. P1's F3 rationale ("deleting a pin must be as loud
   as drift, or the guard re-inherits the inert-pin failure it exists to close") is the reason.
2. **PIN_ABSENT on 1 although surfaces maps "missing keys" to 3.** `claims.json` probe (f) fixes
   it at 1; the same rationale as (1): a pin the contract requires but the baseline omits is an
   *unenforced pin* — the exact defect class this guard exists to close — not a parse failure.
3. **BAD_PIN (a malformed pin value) on 3.** P1's prototype mapped an unparseable mtime pin to
   `PIN_ABSENT`/1 (its own L2 critic: "the diagnosis lies") and canonical crashed (P6-D1). Chose
   3 because `verify_surfaces.py:108-109` files "malformed class id" under 3, and because exit 1
   here would label a baseline-config error as substrate drift (P7-C1's objection). The value is
   present but uninterpretable: the document needs repair before any comparison is meaningful.
4. **UNSUPPORTED on 2 (my addition, no predecessor has it).** Canonical and P1 both discover only
   `^(omp|opencode)_binary_…` and silently ignore anything else — P6 recorded that as a
   silent-coverage boundary, P7-L3 as a docstring/behaviour mismatch. `verify_surfaces.py:107`
   puts a missing *tool* (`strings`) on 2, so "a pinned substrate this guard has no path for" is
   the same class: cannot measure. Chose loud (exit 2) over silent-skip because a skipped pin is
   an inert pin, the round's whole subject. Cost: a future `cursor_binary_sha256` pin lands red
   with a named remedy instead of invisible.
5. **Slot 2 is genuinely double-booked: argparse usage errors also exit 2** (`G --nope` → 2).
   That is argparse's convention and every one of the five family verifiers inherits it, so the
   guard does not deviate — but the landing docstring should say it, since "2 = environment" is
   not the only way to reach 2.
6. **Slot 3 has two sub-classes with different output shapes**: NO_BASELINE yields an empty
   `checks` list plus an `error` string in `--json` (family shape: `emit_json([], 3, str(exc))`,
   `verify_surfaces.py:1002-1005`), while BAD_PIN yields records. Text mode prints `ERROR …` on
   stderr for both. Verified: an exit-3 run has empty stdout (see D3 below for why that sentence
   is a defect record, not a tautology).
7. **JSON mode returns the identical code as text mode in all 27 dual-mode rows**, i.e. the
   harness's F1-D2 bug (`verify_harness_claims.py:658` returns 0 in `--json` where the text path
   returns 3) is not replicated — P8-2b's explicit instruction.
