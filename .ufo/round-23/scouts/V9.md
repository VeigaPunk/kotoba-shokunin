## Findings

**Verdict.** The D1-D3 self-tests are green, deterministic, host-binary-free, and export-safe, and they close the round-22 vacuity classes the prototypes had (CLI-surface cases, null/shrink/stray cases, fixture-sha pinning, no-exec assertion). Four honesty gaps survive into the drafts, all demonstrated, none blocking: **no assertion floor in any of the three** (a deleted case is invisible), **D1's committed fixture identity is unpinned** (flip/truncate → 84/84 green; deletion is caught cleanly), **D3's self-test never reads the committed fixture tree** (missing/mutated fixtures → 54/54 green, so the tree the landing plan commits is dead weight for D3's evidence), and **D1's JSON cases parse unguarded** (a broken `--json` path surfaces as a `JSONDecodeError` traceback instead of FAIL lines). The hermeticity rule holds by construction for all three (verified externally), but only D1 asserts its own no-exec property in-suite.

**Vacuous / insensitive assertions (the (a) question).**
1. **No assertion floor (all three; the P4/P1 class survives).** Deleting a whole case block leaves exit 0 with a smaller count: D1 84 → 80, D2 94 → 90, D3 54 → 51 (cmd 9). `--self-test` prints the count but nothing compares it to a constant, so the landing claim's "assertion count recorded" is again a hand-recorded number — a gate cannot see the shrink. Fix is one line per draft (`if total < 84: failures.append(...)`) and is precedent-compatible (cmd 18).
2. **D1: committed fixture identity unpinned.** `FIXTURE_BIN` (`D1.py:69`) is read and the payload's sha is derived (`D1.py:403-406`); no constant is asserted. Flip one byte or truncate to 1 byte → `0 failure(s) over 84 assertions`, exit 0 (cmd 8). The file is the *seed of every case's world*, so a corrupted or transport-mangled fixture silently redefines the test domain. (P4's V9-D4 class, unfixed in D1.)
3. **D3: the committed fixture tree is never read.** `D3.py:261` ("generated fixtures only") and `:334` are exact: payloads are in-code constants, worlds are `mkdtemp` (`D3.py:361`). Removing `fixtures/` entirely or mutating its files leaves 54/54 green (cmd 8). So D3's suite cannot witness the transport of `verifiers/fixtures/pins/` — the very condition P8.md:160-161 makes a landing requirement, and the round-21 lesson (an artifact that cannot survive git). D2, by contrast, reds 11/11 without the tree.
4. **D1: JSON cases crash instead of reporting.** `json.loads(jout)` unguarded at `D1.py:460` (also `:486`, `:520`, `:542`); with `main` patched to return 0 the suite dies with a `JSONDecodeError` traceback, exit 1, no `self-test FAIL:` line (cmd 10). The regression is detected but the evidence is a traceback — the same shape as P4's fixture-missing failure and p3's `/tmp/p3:307`. D2 (`parsed()`, `D2.py:403-406`) and D3 do it right (50 and 36 clean FAIL lines on the same mutation).
5. **No in-suite no-exec assertion in D2/D3.** D1 scans its own source for exec tokens (`D1.py:95`, `:621-624`, assertion K) — the only draft whose self-test asserts the hash-never-exec rule. D2/D3 rely on behaviour; my external audit/strace probes (cmds 5-6) find nothing, but a future `subprocess.run([bin, "--version"])` added to D2/D3 would ship with its self-test green.
6. **D2's missing-fixture run collapses the count** (`11 failure(s) over 11 assertions`, cmd 8) — red, but a floor would make "the suite aborted early" legible instead of a count that looks like a partial run.
