## Findings

- **Reproduction confirmed at round-23 HEAD (slice answer).** Deleting one tracked corpus
  file — a normal mid-round state; `git ls-files` still lists it — makes the independent
  instrument die with an uncaught `FileNotFoundError` whose frame is exactly `:313`
  (command #5), exit **1**. The primary instrument classifies the identical state as
  `Inconclusive` (`verify_corpus_integrity.py:485-486` → handler `:979-981` → **return 2**)
  and prints one structured line (#7). The two instruments disagree on both channel and code.
- **Crash is not a verdict.** The independent's own contract (`:29`: `Exit: 0 every violation
  class empty, 1 any violation, 2 environment unreadable`) and its `exit_code()` (`:431-432`,
  `0 if violations(observed) == 0 else 1`) mean a traceback exit **1** is byte-for-byte
  indistinguishable from a real drift verdict to any caller keying on the exit code — and in
  `--json` mode there is no JSON at all (stdout 0 bytes, #6). M8 named this conflation; it is
  still live.
- **Two crash sites, one iteration order.** The unguarded pattern exists at `:313`
  (`analyse_pointers`) and `:346` (`analyse_commits`); because `analyse()` builds `pointers`
  before `commits` (`:391`), `:313` shadows `:346` in the normal path. #8 proves `:346` is
  live by calling `analyse_commits` directly; a fix that patches only `:313` (e.g. a
  line-targeted patch) leaves the twin armed.
- **A third, distinct crash class: lazy decode.** Text-mode `open()` without `errors=`
  in the independent vs `errors="replace"` at `verify_corpus_integrity.py:484`.
  A tracked file with one invalid UTF-8 byte crashes the independent with
  `UnicodeDecodeError` at `:314` (raised during iteration, not at `open`) while the primary
  stays green (#11 vs #12). Measured trap: widening only the `open()` except-clause to
  `(OSError, UnicodeDecodeError)` does **not** fix it — draft B still crashes (#14). Any fix
  that claims to close this class must read inside the guarded block (draft D) or replace
  decode errors (draft C).
- **Guard asymmetry, for contrast.** `analyse_index` survives the same deletion because it
  tests with `os.path.exists` (`:275`), and the README gate is checked (`:385-386`); the
  crash therefore surfaces in the pointers pass first — matching M8's note.
- **Fix sketch (recommended, measured as draft D — 2 hunks).** Message payload matches the
  primary verbatim (`cannot read tracked file <repo-relative rel>: <exc>`), so cross-instrument
  greps work; the independent's own prefix stays `environment unreadable:` (`:768`). Exit
  parity with the primary is restored for both probed states (missing file, permission
  denied), and for the decode class it classifies (exit 2) where the primary silently
  replaces.

## Defects named (each: path:line + evidence)

1. **D1 — uncaught `OSError` on an unreadable tracked file.**
   `verifiers/verify_corpus_independent.py:313` (`with open(path, encoding="utf-8") as fh:`
   in `analyse_pointers`), reached from `:391` inside `analyse()`. Evidence: #5 — deleted
   tracked file → traceback, exit 1, no verdict output; #9 — `chmod 000` →
   `PermissionError`, exit 1. Contrast: primary `verify_corpus_integrity.py:485-486` →
   `:979-981` exits 2 with `INCONCLUSIVE: cannot read tracked file …` (#7, #10).
2. **D2 — shadowed twin site.** `verifiers/verify_corpus_independent.py:346` (same unguarded
   `open` in `analyse_commits`). Evidence: #8 — direct call raises `FileNotFoundError` with
   frame at `:346`. Shadowed by D1 only because `analyse()` runs pointers first (`:391`).
3. **D3 — uncaught `UnicodeDecodeError` (lazy decode, distinct class).**
   `verifiers/verify_corpus_independent.py:313`/`:314` — decode happens during iteration
   (`for lineno, line in enumerate(fh, 1)`), so it is not `OSError` and not caught by an
   `open()`-scoped OSError guard. Evidence: #11 (exit 1, `UnicodeDecodeError` at `:314`);
   primary immune via `errors="replace"` at `verify_corpus_integrity.py:484` (#12, exit 0);
   #14 proves the naive except-tuple widening is a dead end.
4. **D4 — crash/verdict conflation and broken machine contract.** Exit 1 is both "any
   violation" (`:29` docstring; `exit_code()` `:431-432`) and the interpreter's traceback
   exit; `--json` on the crash state emits 0 bytes of stdout (#5, #6). A caller cannot
   distinguish crash from drift; M8 named the same conflation.

Count: 4 (D1–D4; D2 is the shadowed twin of D1, D3 the lazy-decode sibling).
