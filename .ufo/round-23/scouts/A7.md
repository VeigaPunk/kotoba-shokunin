## Findings

**F1 — The exit-0 defect reproduces live, byte-for-byte.** kasegi HEAD is still `94aace2`
(the commit round-21's A6 pinned), the worktree file equals the committed blob
(`c2a9e6c6…`), and a file with `3 bad` citations plus a `PIN-BROKEN` returns **rc 0**
(Command 1). A fixture in which every recognised cite is bad also returns **rc 0**
(Command 2). Round-21 D1 stands unchanged at round 23: the instrument cannot signal failure.

**F2 — Static cause proven by AST, not grep (Command 11).** `main` (`:130`) contains
**zero `Return` nodes**; its only exits are implicit falls-off-the-end at `:279`.
`sys.exit(main(sys.argv[1:]))` at `:283` therefore calls `sys.exit(None)` → status 0.
There is no verdict-bearing exit path anywhere in the file, and no flag grammar
(`--help` is read as a filename, Command 7).

**F3 — Precision fix to the round-21/22 wording.** "Always exits 0" is true for every
verdict but not for every invocation: rc 1 is reachable three ways, all via an *uncaught
traceback* rather than an assertion — no args (`IndexError`, `:131`), unreadable input
(`FileNotFoundError`/`IsADirectoryError`, `:135`). The exact, quotable form for the route
evidence is: **no verdict-bearing exit path; rc 0 for every input that can be opened,
regardless of the `bad` count; rc 1 only for usage/IO crashes with a traceback (no
fail-closed `2`/`3` ladder and no diagnostics-without-traceback behaviour).**
This is what makes it a *counterexample* for claim P's ladder (0 match / 1 drift-or-absent
/ 2 environment / 3 baseline): the sibling prior art has a 3-class verdict vocabulary
(`BAD`-family / `BASE-ABSENT` / `LOST-RECORDED`, docstring `:9-19`) collapsed onto a
2-state *accidental* channel (0 = ran, 1 = crashed), i.e. the verdict is carried by stdout
text alone and the exit code carries no verdict information at all.

**F4 — Latent, not live-breaking, but kasegi's own record reads the empty channel as a
verdict.** No fleet script invokes `anchorcheck.py` (Command 12), so nothing consumes the
status today. The consumer that does exist is prose: `corpus/lessons/round-20-recensus.md:8`
records `` `python3 corpus/instruments/anchorcheck.py SKILL.md` → exit 0, `7 in-range / 0 bad
/ LOST-RECORDED=306 …` `` — the "exit 0" there reads as corroboration of a clean run, but the
same command returns rc 0 with any `bad` count (Commands 1/2) and with 306 LOST-RECORDED
(Command 9). Under r18's own matcher the lane has been at `bad=0`, so no false green is
claimed today; the channel is simply non-discriminating.

**F5 — Round-22's two records of this defect were static only; the executed evidence is new
here.** `.ufo/round-22/scouts/G1.md:83,170` (D7) greps for `return`/`sys.exit` and concludes
"always 0"; `.ufo/round-22/scouts/G4.md:128` explicitly flags the gap — "I did not prove that
cited content *supports* each claim (e.g. that `anchorcheck.py` always exits 0 — only that
its `:283` anchor is real)". This fragment closes that gap with Commands 1, 2, 8, 11.

**F6 — Provenance counterexample: file mtime here is *edit*-time, not commit/checkout time.**
The worktree file's mtime is `2026-10-15 01:50:29.664114220 -0300`, yet its bytes were
introduced by `94aace2`, authored and committed `2026-10-17T00:28:15-03:00` (`%aI == %cI`).
Cause, recorded by kasegi itself: `corpus/lessons/round-21-routing-blocked.md:23-24` — "The
pre-existing two-line `anchorcheck.py` root-join edit and cache are left unchanged and
excluded", and `:91` — the round-21 measurements were "exported with `git archive --format=tar`,
not the dirty anchorcheck". The edit sat dirty in the worktree from 2026-10-15 01:50 and was
committed on 2026-10-17; `git commit` does not touch mtime. Consequence for this lane: **an
instrument's mtime is not a provenance or freshness signal — a worktree can carry bytes that
predate their own commit by ~2 days, and a sibling's measurements can be taken against
dirty (uncommitted) bytes.** That is a live, cited argument for claim P's design choice of
sha256 as the primary pin with mtime ns-exact only as a secondary signal (and for documenting
opencode's mtime as unpinnable rather than inferring anything from it). The stray "cache"
named in the same lesson is gone at HEAD (`corpus/instruments/` holds only the 8 expected
files; no `__pycache__`).
