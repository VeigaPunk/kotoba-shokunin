## Findings

### F1 — Deliverable: the proposed committed tree (3 files, 228 bytes total)

```
verifiers/fixtures/pins/
  mini.bin      93 B  mode 0644  sha256 d3b4640ed5eb408197d7922ca1f2984d93fe7d7cbeb60c831f43f65c3952705c
                b"#!kotoba-pin-fixture-mini-v1\n" + bytes(range(0, 64))          # NUL + high bytes
  mini2.bin     94 B  mode 0644  sha256 b315d4899113a08818dc471b60bd495425dba8ae7f0063f963939efa0fe3166d
                b"#!kotoba-pin-fixture-mini2-v1\n" + bytes(range(64, 128))      # 64 distinct high bytes
  tripwire.bin  41 B  mode 0755  sha256 2b30a88038c24f1a5587d1010b2fb0aae46d90033e47c90b493717abea075e99
                b'#!/bin/sh\n: > "$(dirname "$0")/EXECUTED"\n'                   # fires only if exec'd
```

Per-file rationale: **mini.bin** is byte-identical to round-22 P4's payload (its recipe reproduces
P4's recorded literal `d3b4640e…705c`), so round 23 is continuous with the round-22 prototype and
the drift mutation `mini.bin + b"\x00"` reproduces P4's recorded observed digest `79684a93…084d`
(cmd 3). **mini2.bin** gives a second subject so multi-pin, multi-subject ordering and a
first-subject-only bug are covered. **tripwire.bin** converts the claim's "no execution of the
guarded binaries" clause into a behavioural assertion: it is a valid shell script that writes a
sentinel next to itself; any draft that stats+hashes it stays silent, any draft that execs it
leaves `EXECUTED` in the tmp world.

Rules the tree obeys:

- **No pin JSON is committed.** Only payload bytes. A committed pin file would either freeze a
  timestamp (red in every clone) or carry sha-only pins (asymmetric, and it would lose the
  discriminating mutations), so all pin documents are generated per case in tmp (F2).
- **sha256 anchors live as literals in the self-test**, not in a manifest and not re-derived at
  run time; the case set first asserts `sha256(payload) == literal` and `payload == recipe()`. This
  is not ceremony: on this slice's first run the same assertion caught a mistyped 64-hex literal in
  my own driver (`…b6129e884e4f…` vs the true `…b6129e8834e4f…`), which would otherwise have
  surfaced as a phantom the-guard-is-wrong failure (F6).
- **No timestamp, path or host in the tree**; no gate enumerates `verifiers/fixtures/`, and no
  baseline counts files under `verifiers/` (cmd 14). Fixtures alone therefore move **no** baseline
  counter; the corpus doc + its README row are the only `corpus.index.tracked_files` movers
  (52→53, P1 F5 / P8).

### F2 — Deliverable: per-case generation (why mtime forces it, and how)

Per-case world (one `tempfile.TemporaryDirectory(prefix="pins-selftest-<case>-")`):

```
<tmp>/home/.local/bin/omp            <- copyfile(mini.bin | tripwire.bin) + chmod + utime(STAGED_NS)
<tmp>/home/.opencode/bin/opencode    <- copyfile(mini2.bin)               + chmod + utime(STAGED_NS)
<tmp>/baseline.json                  <- GENERATED per case (never committed)
```

- `STAGED_NS = 1767333845123456789` = `2026-01-02T03:04:05.123456789-03:00` (P3's literal; 9
  fraction digits with a non-zero last digit, so a µs-truncating parse is 789 ns low — the
  canonical prototype prints exactly `delta 789 ns` on this fixture, cmd 10).
- After `os.utime` the case **re-stats and asserts** `st_mtime_ns == STAGED_NS` before launching
  the guard: a filesystem that truncates ns fails loudly instead of silently passing (P4's idiom).
- **Home-layout staging doubles as dual transport**: `HOME=<tmp>/home` drives a guard that resolves
  paths from `$HOME` (the round-22 canonical, cmd 10), while the same world drives
  `--omp-binary/--opencode-binary` drafts (cmds 5-9). One world, two transports, no second layout.
- **Generated pin document** (the native baseline shape, so the fixture path is the live path):
  `{"measured_against": {"omp_binary_sha256": <mini.bin literal>, "omp_binary_mtime":
  "2026-01-02T03:04:05.123456789-03:00", "opencode_binary_sha256": <mini2.bin literal>,
  "command": "fixture-only: generated per case in tmp"}}`; each case then mutates its own document
  (drop a key / `null` / `5` / `{}` / typo'd key / truncated JSON / stray pin / int pin value) or
  its own staged copy (append a byte and restore mtime, or `utime` by ±1 s / ±1 ns).
- Checkout-stability proved by execution, not argument (cmd 11): the whole matrix was re-run from a
  copy of the tree with every mtime rewritten to 2001-01-01 → `0 failure(s) over 98 assertions`.

### F4 — Both mandated defect classes have cases that catch them, demonstrated on an independent artifact

- **P7 silent-shrink**: `pin-deleted-omp-mtime` and `pin-deleted-opencode-sha` (one pin key removed
  from an otherwise-matching block). Canonical: exit **0**, `OK 2/2 pins hold` (it discovers pins

- **P6 TypeError**: `ma-null` / `ma-int`. Canonical: `TypeError: 'NoneType'/'int' object is not

- **Vacuity (P2 V1)**: `ma-empty` (`{"measured_against": {}}`). Canonical exit 2, all drafts exit 1.
  No draft passes vacuously on any of the four empty/absurd shapes.

### F5 — The mtime-precision frontier is now explicit; a precision-derived tolerance resolves it

The fixture pair `mtime-drift-1ns` (must be 1) and `mtime-pin-us-truncated` (accept vs reject) is
the whole design space in two cases. Canonical's fixed **2000 ns tolerance** exists to absorb the
789 ns parse artifact of `datetime.fromisoformat`-based µs parsing (its own PASS line on my fixture
reads `delta 789 ns` — the identical trap P1 F2 measured as 874 ns on the live pin) and therefore
**cannot see a 1 ns rewrite** (`mtime-drift-1ns` → exit 0). D2/D3 instead reject a µs-truncated pin
outright (exit 1), v7 rejects it as a schema error (exit 3). Recommendation for the merge:
parse the fraction ns-exactly (P1 cmd 6 / P3 F3) and derive the tolerance from the pin's own written
precision, `10**(9 - fraction_digits) - 1` — 9-digit pins become exact (1 ns reds), and a legacy
µs pin tolerates only its own truncation residue. That rule is what this slice's reference stub
implements, and it is the only rule under which both cases pass; adopting it turns
`mtime-pin-us-truncated` from spec-open into a hard case.

### F6 — The tripwire works, and the integrity assertions are load-bearing

`tripwire-control` executes the payload once and observes the sentinel (proving the tripwire is
live, not a dead file — the round-21 vacuity lesson applied to the fixture set); `hash-never-exec`
stages it as the `omp` subject and asserts exit 0 **and** no sentinel: all six guards pass, i.e.
none of them execs its subject. Separately, `pin-typo-key` catches the canonical ignoring a typo'd
pin key (`omp_binary_sha25`) with exit 0 while all five drafts refuse to pass.

### F7 — Conflicts the fixture set surfaced (decisions the merge must settle, not fixture bugs)

(a) **absent/null `measured_against`**: the round-23 claim says exit 1 (`P` claim, probe (e));
D3 returns 3. (b) **non-mapping value** (`5`): claim text silent; 4 of 5 drafts choose 3, one
chooses 1 — encoded as spec-open. (c) **µs-truncated mtime pin**: accept (canonical, v5, and any
pre-round-21 pin) vs reject-as-drift (D2/D3) vs reject-as-schema (v7) — encoded as spec-open with
F5's recommendation. (d) **typo'd pin key**: 1, 2 or 3 — all acceptable, since the case only
asserts "not a silent pass".

## Limits (what I did NOT verify)

- **Nothing is landed.** `verifiers/check_substrate_pins.py`, `verifiers/fixtures/pins/` and the
  self-test body do not exist in the repo; the artifacts live at
  `/tmp/d23/fixtures-proposal/` (`build_fixtures.py` sha256 `c6f29363…`,
  `selftest_driver.py` sha256 `cc5efdc8…`, `ref_guard.py` sha256 `f78b7989…`, payload hashes in F1).
- **Sibling drafts are moving targets.** `/tmp/d23/check_substrate_pins.py` changed sha twice while
  I worked (`502aa2c5…` → `09560e4a…` → `fafe88d8…`); D2/D3/v5/v7 were sampled once each. The
  matrix is a point sample keyed to those shas — re-run before quoting it in the merge.
- I ran **six** guards (`ref_guard`, four sibling drafts + v7, the canonical). D1/D5-lane artifacts
  elsewhere under `/tmp` (e.g. `/tmp/m9/D5proto.py`) were not run.
- **Exec-bit caveat**: the tripwire needs its 0755 bit; git stores it, but an export path that drops
  it degrades the case to "no sentinel + non-zero exit", which the driver's `exit 0` assertion still
  fails loudly. Verified on this host's tmpfs only (ns staging and the tripwire were not tested on
  another filesystem).
- The tripwire proves non-execution only for a guard that terminates; a guard that exec'd the
  tripwire and hung would be caught by the driver's 120 s timeout, which was not exercised.
- No live binary was touched, and no live-baseline run was performed (by design — the fixtures are
  the subject). Consequently the fixtures' ability to describe the *real* substrate is untested;
  that remains the landing round's live run.
- I ran **no existing gate** (`verify_*`), so F1's "fixtures move no baseline counter" rests on
  reading the gates' scoping (cmd 14, `verify_corpus_integrity.py:6,457`) rather than on a gate run.
- The µs/ns grid below 1 s drift, DST/zone-crossing pins, and symlinked pinned paths are not
  covered by the case set (one UTC-offset pin case exists; the rest assumes this host's `-03:00`).
