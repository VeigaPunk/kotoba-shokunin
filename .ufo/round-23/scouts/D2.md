### 2. My own draft's defect, found by my probe and fixed in-round

v1 (`89` assertions) ran `stat()` first and hashed second, so a **directory** at
a pinned path produced `UNREADABLE` for the sha pin and a *fabricated*
`DRIFT omp_binary_mtime` from the directory's own mtime (exit 2 only because
the env class outranks drift). Fixed by rejecting non-regular files
(`D2.py:170-171`); the class is now pinned by five self-test assertions
(`D2.py:492-506`) and externally probed (cmd 15). The chmod-000 case still
reports the mtime pin (its `stat` succeeds and the value genuinely differs) —
intended: exit stays 2 via the sha pin's `UNREADABLE`.

  round-trip is asserted at self-test time, but a filesystem with coarse
  timestamps would fail the self-test rather than be accommodated; no Python

- **No TOCTOU/race analysis** (a binary swapped between `stat` and hash would
  still be hashed); no EIO-mid-hash, no huge-file, no NFS/permission-matrix
  beyond the single EACCES probe (cmd 16).
- **Not verified under a read-only mount or a fresh clone**: the guard's defaults
  are host-absolute, so a clone's run is meaningful only on this host (the
  host-anchored caveat is declared in the docstring).
- **D1 comparison is text/CLI-level** (one sibling's artifact at one revision,
  hash unchecked by me). I did not read all of D1's body, so an unobserved
  design difference may exist beyond the seven named rows.
