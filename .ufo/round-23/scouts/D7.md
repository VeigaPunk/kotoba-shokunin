### 3. Wording style of the sibling verifier bullets (verbatim templates)

Two registers, both `` `path`[ + `path2`] — <register> (<counts; exit ladder; `--self-test`>);
<closing consequence clause> ``:

- Executable-form register (harness, corpus): "the round-N executable form of the
  *<class>* (N checks …, exit 0/1/2/3, `--self-test`). <Consequence: "the authority for
  every harness number in this file" / "Run it before shipping an artifact set …">".
- Instrument-noun register (fault injection): "the planted-fault harness, in-repo so the
  '<claim>' stops depending on `/tmp` scratch; … **Mutating — not a smoke check**
  (round-N precedent): <operational warning>; `--self-test` exercises the assertion
  machinery on fixture worlds …".

Style elements to copy for the pin guard: backticked `verifiers/` path(s) up front joined by
`+` when a dependency rides along; em dash; the class noun ("guard" is the round's word —
siblings say "verifier"/"harness"); a parenthetical carrying check count + exit ladder +
`--self-test`; one closing clause saying what a reader must do with it. The mutating warning
does **not** apply (the pin guard is read-only, hash-never-exec) — instead it needs the
inverse one-line clause ("read-only; hashes, never executes the guarded binaries"), which is
exactly claim P's falsifier surface.

Recommended 2-line bullet (as probed, 4-space wrap matching the file's ~78–84 char rows):

```

  guard enforcing `verifiers/baseline.json` `measured_against` (3 pins, hash-never-exec; exit 0/1/2/3, `--self-test`).
```

A 1-line variant exists (drop the fixtures token, run past 150 chars: `… — the round-23
read-only pin guard for `verifiers/baseline.json` `measured_against` (exit 0/1/2/3,
