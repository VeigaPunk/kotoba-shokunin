# Scout V3

## Task

Round-23 claim-P red probe (slice V3): (1) point `--omp-binary` at a nonexistent path —
expect exit 2 **naming the path**; (2) plant a fake `omp` shell script in /tmp that appends
a line to a canary file **if executed**, point the guard at it, and confirm the canary stays
empty while the guard still hashes it. Record both.

Artifacts under test are the two /tmp prototypes that actually expose `--omp-binary` (the
round-23 landing candidate set; a third, `/tmp/check_substrate_pins.py`, and `/tmp/p2/…`
have no such flag and are out of this slice — P7 covers them):

- **p3** = `/tmp/p3/check_substrate_pins.py`, 506 lines / 21 808 B, sha256
  `f2400d6e69340897e091d0134d7792ed18b3500786a8de39614cc20127c2b624`, mtime
  2026-10-19 01:32 -0300 (pre-dispatch; not written by this lane). Generic pin discovery
  (`<subject>_binary_(sha256|mtime)`), fail-closed pin-shaped keys, exit ladder 0/1/2/3,
  fixtures + `--self-test`, `--check` selection, `--json` error envelope.
- **P1** = `/tmp/P1/check_substrate_pins.py`, 226 lines / 8 993 B, sha256
  `54f44d4e009cc4c0e949dc881f85e41528ef658f7fe3a97d9e19f3d5ba9cb5b9` (matches the hash P7
  recorded in round 22). Fixed three-pin table (`omp_binary_sha256`, `omp_binary_mtime`,
  `opencode_binary_sha256`), per-pin verdict lines, exit 0/1/2/3, no `--check`.

Interpreter python3 3.14.7. All mutation under `/tmp/v3`; live tree read-only (mandate).

## Findings

### F1 — probe 1 passes on both artifacts, with two reporting conventions
Every nonexistent/dir/EACCES `--omp-binary` yields exit 2 with the path echoed verbatim
(commands 1–9). p3 uses stderr + a JSON `error` envelope; P1 uses per-pin stdout lines and
JSON `binary`/`detail`. Neither tracebacks. The landing design should record which
convention it adopts (p3's `error` field matches the family's `verify_surfaces.py:980-983` /
`verify_skill_checklist.py:1739-1742` envelope convention; P1 has no `error` key).

### F2 — probe 2 passes on both artifacts, mechanically
Exit-0 runs against a fakes-pinned baseline (10–13) cannot happen without reading the fake
bytes; the drift runs (14–15) report the fakes' true content hashes; strace (18–20) shows no
exec and no write-mode open; the PATH-poison runs (16–17) leave the canary empty. The
hash-never-exec property is confirmed *behaviourally*, not just by static import scan.

### F3 — EnvError fail-fast (p3) vs per-pin continuation (P1)
On a missing omp binary, p3 aborts at the first `EnvError`: its `--json` `checks` array
carries only `pins.declared` (the sha check raised before `pins.binary_mtime` ran), stdout is
0 B in text mode. P1 continues per pin and reports 2× UNREADABLE + opencode PASS — more
observability in one run, same exit code. A merge must choose consciously; both are
exit-code-correct.

### F4 — the mtime measurement path is the seam (see defects V3-D1/D2)
p3's `sha256_of` guards with `path.is_file()` (`:188-190`) but `mtime_ns_of` (`:201-208`)
only `stat()`s; P1's `observe` (`:65-70`) `os.stat`s for the mtime kind. Consequence: the
mtime half can return a verdict for a path that is not a readable file — V3-D2 below. Full
runs stay exit-code-correct (the sha check fires first, exit 2), so the exposure is (i) p3's
`--check pins.binary_mtime` selection surface and (ii) the per-pin verdict text in both.

### F5 — merge implication (for the landing round)
Port p3's `sha256_of`/`mtime_ns_of` structure, but give `mtime_ns_of` the same
`is_file()`/readability guard as `sha256_of` (raise `EnvError` → exit 2 before comparing), so
non-regular or unreadable subjects can never print a mtime verdict. That single guard closes
V3-D1 and V3-D2 in the merged design and keeps p3's own docstring contract
(`:47-49` "2 environment unreadable (a pinned path missing/unreadable … never a pass)")
true for the mtime kind.

## Defects named (each: path:line + evidence)

1. **V3-D1 (P1, S3 major-for-that-artifact) — mtime-kind reads mtime of a path it cannot
   measure, and can report `PASS` on an unreadable binary.**
   `/tmp/P1/check_substrate_pins.py:65-70` `observe()` calls `os.stat(path)` (`:67`) for the
   mtime kind (only `sha256_file` opens the file). Evidence: cmd 7/8 — with a directory or a
   chmod-000 path as `--omp-binary`, the `omp_binary_mtime` verdict is `DRIFT` (mtime of a
   directory compared against a binary pin), i.e. "cannot measure" is narrated as drift; and
   cmd 9 — with a chmod-000 omp whose mtime matches the pin, the line reads
   `omp_binary_mtime PASS 1792386108868714474` while the file cannot be opened. Exit codes
   are saved by the sha pin's UNREADABLE (precedence 2>1, `:121-126`), so this is a
   verdict-text/measurement honesty defect, not a false-green at run level for P1 (which has
   no check-selection flag).
2. **V3-D2 (p3, S3, contract-vs-behaviour) — `mtime_ns_of` lacks the `is_file()` guard its
   sibling has; `--check pins.binary_mtime` can PASS an unreadable binary or DRIFT a
   directory.** `/tmp/p3/check_substrate_pins.py:201-208` (`mtime_ns_of`) vs `:188-198`
   (`sha256_of`, guard at `:189`). Evidence (two adjudication probes, not in the tables
   above): with the fake chmod 000,
   `python3 /tmp/p3/check_substrate_pins.py --repo <repo> --check pins.binary_mtime
   --baseline /tmp/v3/baseline-fake.json --omp-binary /tmp/v3/fake/omp
   --opencode-binary /tmp/v3/fake/opencode` → **exit 0**
   `PASS pins.binary_mtime: 2 mtime pin(s) match at ns precision (omp, opencode)`, on a path
   this script's docstring (`:47-49`) promises yields "2 … unreadable … never a pass"; and the
   same argv with `--omp-binary /tmp/v3/fake` (a directory) → **exit 1**
   `FAIL pins.binary_mtime: 1 mtime pin(s) drifted: omp (… live 1792386070975517049 ns …)`
   — a directory's mtime compared to a binary pin. Full-run invocations are exit-code-safe
   (cmd 1/3 exit 2 via the sha check; see F3), so the false-green is confined to the `--check`
   surface (unique to p3). Fix in F5.
3. **V3-D3 (P1, S5 info) — dead import.** `/tmp/P1/check_substrate_pins.py:20` `import time`
   is never used (`grep 'time\.'` hits only docstring text at `:51` and `datetime` calls at
   `:58`, `:186`). Cosmetic; do not port into the merged design.
4. **V3-D4 (both, S5 info, divergence to record, not a behaviour bug) — JSON error envelope
   differs.** p3's exit-2 `--json` carries `"error"` + `exit_code` (family shape,
   `emit_json` `:441-450`); P1's exit-2 `--json` (`emit`, `:130-139`) carries no `error` key —
   the path appears only inside `binary`/`detail`. The landing copy should adopt p3's shape.

## Limits (what I did NOT verify)

- Only the two `--omp-binary`-capable artifacts were probed (p3 sha `f2400d6e…`, P1 sha
  `54f44d4e…`, hashes recorded at probe time). `/tmp/check_substrate_pins.py` (canonical, sha
  `92627710…`) and `/tmp/p2/…` (sha `b4f5517f…`) have no such flag; their probe coverage is
  P7's and was not re-run here. Any later edit to p3/P1 invalidates these hashes and every
  observation above.
- "Never exec" is proven for the planted tripwire and PATH-poison vectors and by strace
  (`execve,execveat`) on this host; no LD_PRELOAD/audit-level hook was attempted, and an
  exec through a mechanism invisible to strace is not excluded by construction.
- The unreadable-file probes use owner-mode `chmod 000` as the same user — no ACL, no
  setuid/root semantics, no FIFO/device/symlinked-retarget cases beyond directory + EACCES.
- The fakes are tiny `/bin/sh` scripts, so the mtime pins could be written with 9 fractional
  digits exactly; the nanosecond round-trip on another filesystem (ns-truncating) is not
  exercised — the fake-pinned PASS only proves this host's /tmp filesystem preserves ns.
- I did not run either artifact's `--self-test` in this slice (p3's fixture suite, P1's
  in-process cases) — other lanes' coverage; nor did I exercise p3's fixture path resolution
  from a `verifiers/`-relative install location (`FIXTURES = <script parent>/fixtures/pins`),
  which is a landing-round fact to re-check.
- No omp/opencode binary was executed anywhere in this lane (no side effects outside /tmp);
  the live tree was only read, and `git status`/baseline hashes before/after are identical
  (only `.ufo/` additions by round-23 lanes appear). Artifacts written by this lane:
  `/tmp/v3/**` scratch only.
