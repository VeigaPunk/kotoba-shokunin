## Findings

1. **M4 probe green: sha corruption is loud and named.** One-hex-char pin
   corruption in a copy drives exit **1** with the pin named in the FAIL line
   and the `DRIFT 1/3 pins failed:` summary (cmd 7), identically in `--json`
   where `exit_code` agrees with the process code (cmd 8). Both sha pins bite
   (cmds 7, 9), so the probe is not pin-specific. The same copy through the
   round-22 canonical artifact also exits 1 (cmd 13) — the probe behaviour the
   claim asserts is *design-independent for sha*, which removes the risk that
   landing a different merge changes the probe's verdict.
2. **Live green is real and ns-exact on this substrate.** Commands 4/5: 3/3
   PASS, omp mtime `delta 0 ns, tolerance 0 ns` — i.e. the round-21 pin
   `2026-10-16T05:15:11.226207850-03:00` parses to exactly
   `st_mtime_ns=1792138511226207850` (P1's F2 ns-exact recipe confirmed
   independently). Round 21's prose re-pin was accurate.
3. **The canonical artifact cannot satisfy the claim's "mtime ns-exact".**
   Canonical truncates the pin to µs (`iso_to_epoch_us`, `/tmp/check_substrate_pins.py:55-58`) and
   tolerates 2000 ns (`:42`, `:106`), so a pin moved by 1 ns passes (cmd 12:
   exit **0**, `delta 850 ns`) while the merged candidate reds it (cmd 11,
   exit 1). This is *not* a defect of canonical for its own spec — its
   tolerance exists to absorb the very 850 ns residue it prints — but it is a
   hard constraint on the merge: the landed guard must compare the 9-digit pin
   at ns precision, or red probe (b) must mutate by ≥µs and the claim's
   "ns-exact" wording must be dropped. The merged candidate resolves it with a
   precision-aware tolerance: exact when the pin carries 9 digits, resolution-
   scoped otherwise (so a µs-form pin is not falsely red — L1 closed — and a
   ns-form pin is bit-exact).
4. **Exit ladder and verdict hygiene behave under malformed input** (cmd 14):
   non-string/malformed pins return `BAD_PIN` exit 3 with **no traceback** on
   the merged candidate (P6/C1 class closed by construction: `parse_mtime_pin`
   type-checks before `re.match`, and `OSError`/`BadPin` are caught per pin),
   and canonical's `ENVIRONMENT … unparseable pin` path also survives (its
   TypeError case needs an *int* pin, which P6 probed; my splices produced
   strings).
5. **Read-only and determinism invariants hold** (cmds 15-18): no tracked file
   written, baseline hash unchanged, `--json` stdout byte-identical across
   runs, and the check path contains exactly one file access —
   `path.open("rb")` — with no subprocess/exec anywhere. Cost 0.223 s live,
   cheaper than the harness gate (~3 s).
6. **Self-inflicted harness bug found and fixed before finalizing** — recorded
   because it is evidence that the self-test idiom is load-bearing, not
   decoration: my first self-test helper appended the default
   `--omp-binary/--opencode-binary` *after* caller overrides; argparse keeps the
   last occurrence, so the override was silently discarded and 3 assertions
   failed (missing-binary and chmod-000 cases ran against the readable
   fixture). Fixed by ordering defaults first; `0 failure(s) over 29
   assertions` only after the fix. A landed self-test that builds argv the
   careless way would assert nothing about its overrides.
