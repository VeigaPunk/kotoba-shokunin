# Substrate-pin guard (round 23)

Round 23 landed `verifiers/check_substrate_pins.py`, the first instrument that
reads the substrate pins in `verifiers/baseline.json` `measured_against`. Those
pins are the record of *which binaries this workspace's measurements were taken
against*; before this round no code read them, so an unannounced substrate
rebuild was invisible to every gate.

## What the guard enforces

`measured_against` records three binary-identity pins (see § Pin inventory).
The guard re-derives each live value and diffs it against the pin:

- sha256 of the pinned binary file (streamed, 1 MiB chunks — 464 MB total);
- the omp binary's `st_mtime_ns` against the pin parsed to integer nanoseconds
  (§ ns-exact mtime caveat).

It does **not** execute the pinned binaries: the check opens each file as bytes
only. Executing them is not read-only here — a `opencode --version` probe
appends `cli starting …` lines to `~/.local/share/opencode/log/opencode.log`,
the exact file the harness gate's `oc.log.*` counters read (round-22 scout
`.ufo/round-22/scouts/P1.md` F4; D5 re-measured: log line count 3327 → 3327
across the full live run plus all red probes). The guard writes nothing anywhere
and is deterministic: the same tree and binaries yield byte-identical `--json`
output between runs.

The debt it closes was previously *named* but never enforced. Executable proof
(round-22 scout `.ufo/round-22/scouts/M6.md` RUN A/D): corrupting
`measured_against.omp_binary_sha256` in a `/tmp` copy left
`python3 verifiers/verify_harness_claims.py` at `28/28 checks pass`, exit 0; so
did deleting the block entirely. The same corruption now exits 1, naming the pin
(probe (a), § Six red probes).

**ns-exact mtime caveat.** The pin is nanosecond-precise and is compared as an
integer `st_mtime_ns`, not through float seconds or microsecond fields. Two
obvious implementations are wrong on this very pin (both measured in round 22,
`.ufo/round-22/scouts/P1.md` commands 5–6, `.ufo/round-22/scouts/P3.md` F3):
`datetime.fromisoformat(...).timestamp()` loses 874 ns (float round-trip), and
`fromisoformat` alone truncates the 9-digit fraction to microseconds. The
ns-exact recipe is: take the fractional digits as an integer
(`ljust(9,'0')[:9]`), strip them, and add them to `calendar.timegm(dt) * 10**9`.
Corollary for the writer: a re-pin must be derived from `os.stat().st_mtime_ns`
and carry 9 fractional digits; a microsecond-truncated pin reds by construction
(P1 command 12) — fix it by re-recording, never by loosening the comparison. No
tolerance is applied: the ±2000 ns tolerance in round-22's canonical `/tmp`
prototype existed only because its parser went through the truncating path
(`.ufo/round-22/scouts/P7.md` finding 1).

**opencode has no mtime pin, deliberately.** Its live mtime is
`1985-10-26 05:15:00.000000000 -0300` — a packer/build-epoch constant, not a
build time (`.ufo/round-22/scouts/P2.md` F3, `P8.md` 2d). An mtime pin there
would pin an artifact of the packer, not provenance; the guard must not "fix"
the asymmetry.

**Path constants are duplicated.** The guard's default paths are a third copy
of the constants in `verifiers/verify_harness_claims.py:52,55` and
`verifiers/verify_surfaces.py:126-129` (`.ufo/round-22/scouts/P2.md` D-P2-1).
The guard opens the absolute default and never resolves through `PATH`; a
`which`-based resolution could select the npx shim at
`/home/vgpnk/.local/bin/opencode` instead of the pinned file
(`.ufo/round-22/scouts/P2.md` D-P2-2).

## Exit-code ladder

| code | class | trigger |
|---|---|---|
| 0 | all pins hold | every declared pin PASS |
| 1 | drift or absence | `DRIFT` (pinned value moved; the pin is named) · `PIN_ABSENT` (one of the three declared pins is missing from the block — deleting a pin is as loud as drift) · `VACUOUS` (`measured_against` missing, null, not an object, or carrying no recognized pins — a block that pins nothing is not a pass) |
| 2 | environment | a pinned binary missing or unreadable (ENOENT/EISDIR/EACCES) — the run cannot measure, which is not the same as measuring drift |
| 3 | baseline | baseline file missing or unparseable (I/O error or JSON syntax error) |

Precedence when classes combine: 3 > 2 > 1 > 0. The same code is returned in
`--json` mode as in text mode; the harness gate's `--no-baseline --json` → exit
0 contradiction (round-22 `P1.md` F1/D2, defects of that file) is not
replicated. Malformed pin *values* never traceback: a non-string pin or a
non-dict `measured_against` is classified, not crashed on (the P6 D1 / P7 C1
`TypeError` class). Recorded divergence: round-22 `P1.md`'s spec placed "no
`measured_against` object" at exit 3; round 23's claim binds it to exit 1
(vacuity, the M6-D2 class) and the probes below follow the claim.

## Honest ceiling — what pin-matching does NOT prove

1. **Not provenance.** A sha256 match proves the file is byte-identical to the
   recorded digest; nothing here authenticates that digest. There is no
   signature and no upstream source to compare against; a tampered binary
   substituted before the pin was recorded would pass forever.
2. **Not that the pins are current.** Green means "matches what was recorded",
   never "the record is current". A legitimate rebuild plus a stale pin stays
   red until the re-pin ritual runs — that red is the design, not noise.
3. **Not behaviour.** The guard never executes the substrate; it cannot see the
   version string, whether the binary runs, or whether that path is the one a
   session actually used (a PATH-shadowing shim is invisible to it).
4. **Not hermetic.** Defaults are absolute host paths, so a clone's green
   measures the *host*; the same residue the corpus instruments already record
   (`corpus/README.md` § Known gaps, "pointer resolution is host-anchored").
5. **Not tamper-evident.** The guard reads the same repo file it enforces and
   nothing hashes the baseline or the guard; anyone who can write the repo can
   move the binary and the pin (or the guard) together.
6. **mtime is not content.** A byte-identical rewrite (reinstall, restore, plain
   `cp`) reds by design (`.ufo/round-22/scouts/P1.md` command 22); the mtime pin
   is a change detector, not an integrity proof.
7. **Only the three declared pins.** Version strings are unpinned; library,
   database, log and session artifacts are unpinned; other harnesses (cursor,
   codex) are unpinned; `corpus-baseline.json`'s `measured_against.head` is a
   separate, already-decayed provenance class left explicitly out of scope
   (`.ufo/round-22/scouts/P8.md` defect 2).
8. **Silent-coverage edges.** Unknown key families are ignored; and deleting a
   pin is loud (PIN_ABSENT) while *adding* a stray pin-shaped key is not
   enforced — the enforced set is the fixed trio. A future third substrate pin
   must extend the table, and the extension must be recorded, not assumed.
9. **Green today is not an audit of the past.** Nothing here says the binary was
   untampered between the measurement that produced the pin and now.

## Re-pin ritual

When the guard reds because a substrate legitimately moved: (1) confirm the new
value is the intended binary; (2) re-record the pin in
`verifiers/baseline.json` `measured_against`, deriving the mtime from
`os.stat().st_mtime_ns` with 9 fractional digits; (3) name the mechanism in the
file's own prose (`round18_move`, `omp_round21_note` are the precedent, e.g.
"omp rebuilt 2026-10-16 (ff59fc1b->bf1e86a9 …)"). Deleting a pin, weakening it
to existence-only, or adding a tolerance are the three failure modes this
round exists to make impossible.
