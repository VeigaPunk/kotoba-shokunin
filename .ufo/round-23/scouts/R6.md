## Findings

1. **Green at HEAD, and byte-identical to the round-22 evidence base.** Runs 1–2:
   `--self-test` 0; full run 0, `ALL PASS`, 11 worlds (9 planters + 2 controls),
   `instrument_sha256=a32da4a4224e…` (same value round 22 recorded). Harness sha
   `9db6c692c752…` equals the live file and the round-22 citation, so every
   line number in round-22 R6's D1–D3 still identifies the same code — the
   re-derivation is a re-measurement, not a re-reading.
2. **D1 (the fault-f gate) is a self-read tautology, proven executably in both
   directions.** The gate at `:290-298` computes `blind_total` from `out.json`
   (`:290`), runs the baseline mode into `out-baseline.txt` (`:291`), then
   computes `base_total` with *the same expression on the same file* (`:293`
   via `json_field`, `:125`). Nothing between `:290` and `:293` writes
   `out.json` (run 3: `:141` is the only writer), and run 4 shows the world's
   `out.json` hash is unchanged across the baseline run. M1 (run 6) makes it
   falsifiable: change only the redirect target of the baseline run and the
   gate immediately goes red — the second operand really is a re-read of
   `out.json`, so `[ "$blind_total" = "$base_total" ]` (`:296`) cannot fail
   except when the read itself returns empty (which `[ -n "$blind_total" ]`
   also excludes).
3. **D1's live clause is "baseline mode exited non-zero", and a crash
   satisfies it.** M2 (runs 7–8): with every world's `corpus-baseline.json`
   corrupt-but-present, the harness exits 0 `ALL PASS`, and fault-f's row
   claims `PASS(blind-spot documented: … baseline-mode exit 1)` while the
   baseline-mode run in that very world dies with a `JSONDecodeError`
   traceback. The stated justification — "the equal-mode count detector
   notices report_total moving 1 down" (`:275-279`) — was not met: no detector
   ran, no class was attributed, and no `DRIFT corpus.pointers.report_total`
   line exists in that world. Round 22 recorded the tautology; this run shows
   the acceptance also fires on a *crash* caused by a plausible real state (a
   half-written baseline file).
4. **The real detector is computed on disk and thrown away.** In a clean
   fault-f world the decisive line `DRIFT corpus.pointers.report_total:
   observed=33 expected=34` sits in `out-baseline.txt:13`; run 3 shows that
   file has no reader anywhere in the script. The one-line repair is available
   (`grep -q` for the class on `out-baseline.txt`, or parse the baseline-mode
   `--json` and assert the DRIFT id) but is **not landed** — out of claim P's
   scope, recorded as debt.
5. **D2 re-confirmed: (h) is a one-instrument row.** `fault_h_context`
   (`:307-326`) never calls `run_independent` (run 10) and the harness prints
   no fault-h independent row, while the doc's "fired class (both
   instruments)" column covers (h). The hand-run (run 10) shows the
   independent would have been green on that world (`quoted=1, dead=0`, exit
   0), so this is missing coverage, not a masked failure.
6. **D3 re-confirmed mechanically: the independent's class attribution is
   computed, correct, and discarded.** `run_independent` (`:145-150`) writes
   `indep.out`; run 3 shows nothing reads it; rows record only the exit code
   with class `-`. Run 11 re-derived the class table from the independent's
   own `--json` and found 11/11 agreement with the author's instrument —
   exactly the information the harness would need to substantiate "both
   instruments" rows.
7. **Documentary debt → the three inert-gate classes to keep out of
   `check_substrate_pins.py`.** (A) an assertion whose operands are two reads
   of the same artifact (D1): it cannot fail; every gate must have a probe in
   which *only its own input* moves. (B) a "both instruments/both paths gate"
   claim with the second path never invoked (D2): claims need one row per
   path, and the fixture self-test needs a case where the row goes red.
   (C) evidence computed into a side channel and never read (D3): either the
   assertion parses that channel or the channel should not exist. The P7 merge
   recipe (canonical body + P1 exit ladder + P4 CLI-surface self-test idiom +
   committed fixtures) is orthogonal — these three classes are what the
   self-test must exercise *negatively*, one red case per gate, or the new
   guard can be green-by-construction in exactly the same way (cf. round-22
   P6 D1 TypeError path and P7 C9 silent-shrink path, neither reachable from a
   green-only fixture set).
8. **Cross-check for the same failure mode at HEAD (side note, not my slice).**
   Run 12: `--self-test` (`:365-389`) reaches only `new_world`, `plant_a`,
   `run_integrity`, `drift_ids` — none of the five verdict functions
   (`fault_must_fire`, `fault_known_blind_f`, `fault_h_context`,
   `fault_must_not_fire`, `control_clean`). So D1/D2/D3's predicates are
   unreachable from the harness's own self-test: the three inert gates are not
   merely untriggered, they are unexercised by design.
