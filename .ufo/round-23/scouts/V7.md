## Findings

### F1 — Determinism (V7 core) holds on this host, in both modes, across seeds and time

Text stdout sha256 `3fc7acf1…96a235` for runs 3–6 (four runs: two identical-env,
one `PYTHONHASHSEED=0 LC_ALL=C`, one a minute later); JSON stdout sha256
`605ff814…7c520` for three runs; stderr byte-identical (empty on green). Red and
error paths are byte-identical too for their repeated runs (#13–20). Nothing in
the output carries wall-clock, pid, hostname, duration, or temp paths; pin order
is table order + sorted extras; the JSON dump is `indent=2, sort_keys=True` (the
family `emit_json`, in contrast to the canonical prototype's unsorted
`indent`-less dump).

### F2 — JSON contract

(a) **Validated schema, green run**: 4 check entries —
`measured_against` (kind `declared`, reports the 3 declared pins and the 3
ignored prose keys `command, omp_round21_note, round18_move`), then
`omp_binary_sha256`, `omp_binary_mtime`, `opencode_binary_sha256`; every entry
has exactly `{pin, harness, kind, binary, expect, observed, verdict, detail}`;
top-level `{checks, pass, fail, exit_code}`, optional `error` on exit ≥2;
`pass+fail == len(checks)`; the `exit_code` field equals the process exit code
on every path probed (0/1/2/3). Verdict vocabulary: `PASS, DRIFT, PIN_ABSENT,
VACUOUS, BAD_PIN, UNREADABLE`.

(b) **The canonical prototype's JSON is a different contract** (defect 2 below):
`/tmp/check_substrate_pins.py` (sha `92627710…`) emits
`{baseline, pins:[{pin,expect,live,delta_ns,ok}], verdict}` with no `exit_code`,
no `pass`/`fail`, no `checks` — and no error envelope at all (P7 C4: empty-pins
`--json` → 0 B stdout). The landing round must not inherit that shape; the
family shape (`verifiers/verify_surfaces.py:981-990`,
`verify_skill_checklist.py:1730-1737`) is what this draft validates.

### F3 — ns-exact compare removes the reason the canonical prototype needed a tolerance

Live, my draft reports the omp mtime pin as exactly equal
(`observed == expect == 1792138511226207850`). The canonical prototype instead
prints `"delta_ns": 850, "ok": true` — that 850 ns is produced by **its own**
parser (`iso_to_epoch_us`, line 59, truncates the fraction to 6 digits; line 95
multiplies by 1000) and then excused by `MTIME_TOLERANCE_NS = 2000` (line 42).
Net effect: the guarded machine's genuine sub-2 µs mtime drift is
indistinguishable from the parser artifact and passes. My draft: ns-exact
textual parse, integer compare, and a present-but-coarser-than-9-digit mtime pin
is rejected at load (`BAD_PIN`, exit 3, message names the pin) — so P7 L1's
µs-pin false-positive class is closed without silently tolerating drift
(self-test scenarios s4/s5: −1 s and +1 ns → DRIFT exit 1; `.123456` → BAD_PIN
exit 3).

### F5 — Consumer notes for the landing round

- `error` is present only on exit ≥2 (family convention); a JSON consumer must
  treat it as optional, and for file-level baseline failure `checks` is `[]`
  (payload still parseable — the C4 closure).
- The first check entry is the declaration check, not a pin: a consumer that
  wants "pins only" filters `pin != "measured_against"` (or `kind != "declared"`).
- The guard is host-anchored by default (`--omp-binary`/`--opencode-binary`
  default to `/home/vgpnk/...`); the `binary` field records the path as given,
  so a run with fixture overrides is not byte-comparable to a default run.
- The self-test (71 assertions) generates its fixture world in a
  `TemporaryDirectory` and cleans it up; the payload constant mirrors P4's
  committed fixture (`mini.bin` bytes, sha
  `d3b4640ed5eb408197d7922ca1f2984d93fe7d7cbeb60c831f43f65c3952705c`) and the draft asserts that
  hash, so the landing round can commit the same bytes as
  `verifiers/fixtures/pins/mini.bin` without changing the self-test's meaning.
- The claim's six designed red probes all reproduce on this draft with the
  specified codes: (a) sha drift → 1 naming the pin, (b) mtime-only drift → 1
  naming `omp_binary_mtime`, (c) missing binary → 2, (d) corrupt JSON → 3 no
  traceback, (e) missing/null `measured_against` → 1 vacuity, (f) deleted single
  pin → 1 `PIN_ABSENT`.
