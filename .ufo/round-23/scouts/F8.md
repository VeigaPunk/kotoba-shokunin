## Findings

1. **Reproduced, exact.** Round-22's number holds unchanged at HEAD `5a33c3e`:
   108 failures / 1504 assertions, exit 1, in a fresh `git archive` export; live tree
   0/1504 exit 0. Assertion **total is identical (1504) in both layouts**, so this is
   not a fixture-set difference — the same 1504 assertions are being evaluated against
   a different resolution base.

2. **One root cause, causally closed.** Chain:
   - `verifiers/verify_skill_checklist.py:386-392` `find_repo_root()` returns the nearest
     ancestor carrying `.git`; with no `.git` anywhere above, it returns the **target's own
     directory** (`return cur`).
   - the self-test's fixture argv (`:1341-1348` in `run()`, plus the direct
     `run_capture` site at `:1555-1556`) passes `--skill <fixture>/SKILL.md` and **no
     `--repo`** → `main()`'s `:1752-1753` calls `find_repo_root` → `repo` := the fixture dir.
   - `:1756` `governance_enabled = skill_path.resolve() == (repo / "SKILL.md").resolve()`
     is then **True** (the target *is* that directory's SKILL.md) → the `:1838` N/A branch
     is skipped and `:1833` runs `check_governance_citations(repo)` against
     `<fixture>/LOG.md` / `<fixture>/SCORECARD.md` → `OSError` → `FAIL … unreadable
     governance file(s)` (`:1258-1260`).
   - the same shifted base breaks every repo-rooted subject: `corpus/…` and
     `verifiers/…` operands now resolve relative to the fixture directory (`:1281`,
     `:1265`).
   Causal controls: injecting **one empty `.git` dir** into the export flips 108→0
   (command 5); a patched script in the same export is green without any `.git`
   (commands 8, 10); a plain `tar` copy (no `.git`) reproduces the same 108 (command 6).

3. **The 108 decompose into exactly three assertion classes, all one cause** (command 7
   tally of the failure log; 70 distinct fixture cases):
   - **69** × per-case `N/A-allowed governance.citation_resolves` — expected `N/A`, got
     `FAIL … unreadable governance file(s): LOG.md (… '<case>/LOG.md')`.
   - **28** × per-case `exit 0: got 1` — the exit ladder flips because one FAIL exists.
   - **11** × target-specific extras that embed the same flip (`PASS
     trigger.command_binary_resolves: got …FAIL…` ×4, `PASS trigger.citation_resolves:
     got …FAIL…` ×4, `command-output-flag: exit 0, 2 subjects` ×1,
     `command-heredoc-tilde: body opaque…` ×1, `command-heredoc-tilde-misterm: bare EOF…` ×1).
   No needle assertion, no map/box assertion, and no `delegated-*` assertion fails:
   round-21's `probe-dir/.gitkeep` repair is intact in the archive layout.

4. **Fix A (recommended): pin the anchor in the self-test argv.** The failure mechanism
   above is the self-test's alone: for its *default* target (`--skill` unset) the CLI
   already resolves the same base with or without `.git` (`<script>/../SKILL.md`, and the
   `find_repo_root` walk starts at `DEFAULT_REPO` and returns it), and the default run's
   output is **byte-identical with and without a `.git` dir** in the export (command 16) —
   so `.git` absence is *not* what moves the default run. (The default run is nevertheless
   not portable: it needs the tree to be named `kotoba-shokunin` — command 17, the
   `name_directory` assertion — and needs the fleet root above it for its `../PROTOCOL.md`
   / `../.ufo/…` tokens — command 18. Both are relocation sensitivities, independent of
   `.git` and out of this slice's scope; recorded so no design claims "layout-invariant"
   more broadly than that.) So the minimal fix is to state the anchor explicitly at every
   fixture invocation:
   ```diff
   --- a/verifiers/verify_skill_checklist.py
   +++ b/verifiers/verify_skill_checklist.py
   @@ -1339,7 +1339,8 @@
        def run(case: str, *extra: str) -> tuple[int, str]:
   -        argv = ["--skill", os.path.join(fx, case, "SKILL.md"),
   +        argv = ["--repo", str(DEFAULT_REPO),
   +                "--skill", os.path.join(fx, case, "SKILL.md"),
                    "--map", os.path.join(fx, case, "map.json")]
   @@ -1553,7 +1554,8 @@
        # foreign target, no map pinned -> N/A, not exit 3
        code, out = run_capture(
   -        ["--skill", os.path.join(fx, "missing-map", "SKILL.md")])
   +        ["--repo", str(DEFAULT_REPO),
   +         "--skill", os.path.join(fx, "missing-map", "SKILL.md")])
   ```
   **Both hunks are required** — this is the trap in the design: patching only `run()`
   (`:1341`) leaves exactly **1** failure, `self-test FAIL: foreign-no-map: exit 0: got 1`,
   because `:1555` bypasses `run()`. Verified: 0/1504 rc 0 in the `.git`-less export
   (command 8), 0/1504 rc 0 with a `.git` present (command 9), and the export's full
   output is **byte-identical** to the live tree's (command 11) — i.e. the fix is a
   provable no-op inside a checkout, and the assertion total stays 1504 (no silent shrink,
   the P7 class). No traceback in any patched run (the P6 class). `:1685-1687`'s relative
   `--repo .` probe is already layout-invariant (explicit `--repo` + `os.chdir`) and needs
   no change.

5. **Fix B (alternative, broader, behaviour-changing): change the fallback.**
   ```diff
   -    """Nearest ancestor carrying a .git marker, else the file's directory."""
   +    """Nearest ancestor carrying a .git marker, else the script's repo root."""
   …
   -    return cur
   +    return DEFAULT_REPO
   ```
   Also 0/1504 rc 0 in both layouts (command 10), and it additionally repairs the
   *foreign-target* CLI path (command 13: a `.git`-less foreign skill dir currently
   reports `FAIL governance.citation_resolves … '<foreign>/LOG.md'` and resolves its
   `corpus/…` citations against `<foreign>/` → under B, `N/A governance` + citation PASS).
   Cost: it contradicts three pieces of documentation that state the `.git`-else-**target's
   directory** rule — `:142-143` (docstring resolution base), `:179-185` (ceiling text),
   `:1707-1708` (`--repo` help) — so B must land *with* those three edits or it creates a
   doc-drift defect. A2 is strictly smaller and touches no semantics, so the sketch
   recommends **A (2 hunks) + the behavioural guard below**, with B recorded as the
   optional CLI-scope follow-up.

6. **Residual, separate (self-test does not cover it): the CLI in a `.git`-less tree is
   still layout-sensitive by design.** Running a fixture SKILL.md directly without
   `--repo` from the export (my classifier, 71 cases) differs from the live tree on each
   of the 25 exit-0 cases (rc 0→1) and 82 output lines, for exactly the same mechanism.
   The self-test fix does not change this; the documented fallback does what it says.
   It only matters for whoever measures a `.git`-less tree by CLI, which is why the
   fix's claim note should say "self-test is layout-invariant" and not the stronger
   "the checker is layout-invariant".

## Defects named (each: path:line + evidence)

1. **`verifiers/verify_skill_checklist.py:1341-1348` + `:1555-1556` (fixture argv without
   `--repo`) × `:386-392` (`find_repo_root` `.git`-else-dir fallback) × `:1756`/`:1833`
   (governance gate) — `--self-test` is not layout-invariant.** Evidence: commands 2, 3,
   6 (108/1504 rc 1 in `git archive` and in a plain `tar` copy vs 0/1504 rc 0 live,
   command 4), causal flip by a single empty `.git` dir (command 5), 69 of the 108 are
   `N/A-allowed governance.citation_resolves` FAILs whose text embeds
   `'…/fixtures/checklist/<case>/LOG.md'` (finding 3). Consequence: every recorded
   "`--self-test` → 0/1504" from a non-git export is in fact 108/1504; the round-21/22
   records are valid only inside a checkout.
2. **`verifiers/verify_skill_checklist.py:1341-1348` — partial repairs are silently
   incomplete.** The self-test has one fixture invocation outside `run()` (`:1555`), so a
   fix applied to `run()` alone leaves 1 failure and looks "nearly fixed". Evidence:
   command 8 was preceded by an intermediate build whose result was exactly
   `self-test FAIL: foreign-no-map: exit 0: got 1`, 1 failure / 1504. The fix must either
   patch both sites or (better) route all fixture invocations through one argv builder.
3. **Coverage record defect (documentation):** the self-test help/`--self-test`
   description (`:1725-1727`) and the checker docstring do not disclose that the mode
   presupposes a `.git` ancestor for its fixture targets (`:142` documents the fallback
   for `--repo`, nothing documents the self-test's dependence on it). Evidence: the mode
   is green only with a `.git` ancestor (commands 3/5/9) — a reader of `--help` cannot
   predict that.

## Fix sketch + fixture/guard implications

**Land (claim P and the checklist alike):**

1. Fix A's two hunks (above), or the refactor form: one helper
   `def case_argv(case, *extra)` that always emits
   `["--repo", str(DEFAULT_REPO), "--skill", …]`, used by `run()` **and** the
   `foreign-no-map` site at `:1555`.
2. **Structural guard (in-self-test, ~0 cost):** with every fixture invocation routed
   through `case_argv`, add one assertion that the anchor is explicit, e.g.
   `rec("fixture argv pins an explicit repo anchor", argv[0] == "--repo" and argv[1] == str(DEFAULT_REPO), argv)`.
   It is the cheap tripwire against a future call site that bypasses the helper — the
   exact shape of defect 2.
3. **Behavioural guard (out of tree — the only honest one):** in the harness/probe layer
   (not inside `self_test()`), add a row
   `T=$(mktemp -d); git archive HEAD | tar -x -C "$T"; (cd "$T" && python3 verifiers/verify_skill_checklist.py --self-test)`
   asserting rc 0 **and** the literal `0 failure(s) over 1504 assertions` (the assertion
   total is the anti-shrink check — the P7 class: a guard that goes green by dropping
   assertions must fail this row). Cost measured: 612K fixture tree, 0.082 s per
   self-test. A `tar --exclude=.git` copy (command 6) is an equally valid twin row and
   covers the non-git-archive export path.
   *In-self-test variant, if the round insists the guard live inside `--self-test`:*
   `copytree` the two dirs (`verifiers/verify_skill_checklist.py` + `verifiers/fixtures/`
   + `verifiers/checklist-*.json`) into a `TemporaryDirectory`, run it as a subprocess
   with an env marker (`KOTOBA_SELFTEST_NESTED=1`) that makes the nested run skip the
   guard (recursion breaker), and assert rc 0 + the 1504 total + `"Traceback" not in out`
   in the parent. Note the `.git`-free property comes for free: the nested script's
   `DEFAULT_REPO` is the temp root, which has no `.git`.
4. **For the P-claim's `check_substrate_pins.py`:** derive the baseline path and every
   fixture path from `Path(__file__).resolve().parent.parent` (never from a `.git`
   walk), keep `--self-test` free of any `.git` requirement, and make sure the six red
   probes mutate `/tmp` copies (they are file-level, hence layout-independent by
   construction). Mirror the two checks of point 3 in its own self-test: the printed
   assertion total (anti-shrink, P7) and `"Traceback" not in out` on the
   malformed-baseline probe (anti-crash, P6 — the same discipline as `:1612`'s
   `"not an instrument"` / `"Traceback" not in out` assertion).

**Do not** take Fix B without editing `:142-143`, `:179-185`, `:1707-1708` in the same
change (defect-free only if the documentation moves with it).
