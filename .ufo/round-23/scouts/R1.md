**4. R1 semantics finding A — box-first-integer (`trigger.line_budget`).** The
binding guard `LINE_BOUND_BOX_RE` (`:362-363`) selects *which* box states the
bound, but the threshold is `INT_RE.search(b["text"])` (`:1078`) — the **first
`\d+` anywhere in that box's text**, not the integer the line-bound regex matched.
Any integer before the word `File` wins. Proven both directions on `/tmp` copies:

- false-FAIL: `Rule 2: File ≤ 20 lines` → `budget 2`, rc 1 on a 48-line fixture
  (#6) — a numbered/ordinal prefix in ordinary checklist prose misbinds;
- false-PASS: `Rule 999: File ≤ 20 lines` → `budget 999`, rc 0 on the same file
  (#7) — an over-budget file passes under a box that says ≤20.

The docstring (`:1074-1075`) states "first integer" — code and docstring agree; the
defect is that the fixture `line-budget-box-binding` (box text
`File ≤ 20 lines; the box states the bound.`, line 46) only proves the positive
binding (box 20 beats default 600) and never carries a prefix integer, so this
hazard class is unprobed. `--max-lines` is correctly the fallback only
(`:1081`).

**5. R1 semantics finding B — literal-trigger quoting (`trigger.literal_trigger_string`).**
`check_literal_trigger` (`:1031-1049`) accepts three disjoint shapes:

- a non-empty frontmatter `triggers:`/`trigger:` key (case-insensitive key name,
  `:1035-1037`);
- the literal substring `"Triggers:"` in the description — **case-sensitive**
  (`:1041`; #11 vs #12: lowercase `triggers:` FAILs, capital `Triggers:` PASSes);
- else any quoted span of **≥2 chars** in five quote classes
  (`QUOTED_SPAN_RE`, `:356-358`: straight double, backtick, straight single,
  curly double, curly single; `:1043-1047`).

Consequences measured: `"ab"`, `` `js` ``, `“ok”` each PASS with `evaluated 1`
(#8-#10) — a 2-char quote with no trigger semantics earns the box ("shape test,
not semantics" is disclosed only on the FAIL line, `:1048-1049`, not on PASS).
The live file's PASS is the case-sensitive `Triggers:` token path (detail:
`description carries literal 'Triggers:'`), not a quoted trigger.

**6. Cross-check asymmetry (same quoting semantics, `trigger.anti_trigger_clause`).**
`check_anti_trigger` strips **all** quoted spans before matching
(`ALL_QUOTED_SPANS_RE`, `:1059`). A description whose only exclusion marker is
quoted — `Fixture "Anti-triggers: never".` — PASSes `literal_trigger_string` on
that exact span and FAILs `anti_trigger_clause` (#13). Fixture-covered intent is
visible (`negation-respected`, `anti-quoted-negation`), but the interaction is a
named semantics property worth carrying: one check reads quoted spans as
evidence, the other treats them as invisible.
