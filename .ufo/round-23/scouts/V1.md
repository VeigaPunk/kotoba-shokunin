## Limits (what I did NOT verify)

- **Only probe (a) of the claim's six red probes is mine.** mtime-only drift
  (b), missing binary (c), and the self-test runs are sibling slices; I did not
  run `--self-test` on any artifact and make no claim about it.
- **No real substrate movement was tested.** All drift was induced by editing
  /tmp baseline copies; the sha probe cannot distinguish a rebuild from a
  corrupted binary, and "guard catches a real rebuild" is only shown for the
  baseline-copy form (F8 replay). Replacing `~/.local/bin/omp` is out of scope
  and destructive.
- **Revision-pinned evidence.** Draft A and D3 changed under me (F6); my
  verdicts are pinned to the frozen snapshot hashes in the artifacts table.
  Any later edit to those drafts invalidates the mapping of my outputs to the
  live files (the snapshots remain replayable in `/tmp/d23/V1/`).
- **EACCES / directory / symlink binary cases not probed here** (the missing-path
  and unreadable-binary classes belong to probe (c)'s sibling slice).
- **The omp-side write surface was not checked** — `~/.omp` is shared with the
  fleet's concurrent lanes, so log-mtime movement there is unattributable (P1's
  round-22 limit applies); the opencode log (the gate-read surface) was checked
  and did not move.
- **`mut-ma-empty.json`** (empty dict `{}`) was run only on my port (exit 1,
  3× PIN_ABSENT); not run on the drafts.
- **Determinism** was checked by stdout `cmp` (port ×3, A ×2, D3 ×2); stderr
  byte-equality was not separately diffed (all stderr empties were 0 bytes).
- My port's own `--self-test` does not exist (probe vehicle); its BAD_PIN exit
  code (1) is my design choice, not a verified family convention.
