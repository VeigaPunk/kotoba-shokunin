## Findings

- **F1 — the claim holds for every single-point tamper.** Delete, add, reword,
  executed-reword, and section-move each exit 1 with
  `checklist.box_map_complete` FAIL, and each detail names the parity
  direction(s) as designed: `verify_skill_checklist.py:947` emits
  `map entry … has no live box` (map→file), `:955` emits
  `unmapped box at line N …` (file→map, line + section + sha12). A
  landing round that edits SKILL.md box text without re-recording
  `checklist-baseline.json` is caught, with `evaluated` moving 40/41/42 exactly
  as the tamper changes the box count.
- **F2 — executed boxes get a third message.** Rewording trigger.01 adds
  `line 190 annotation claims 'trigger.frontmatter_parses' but the map records
  '<no entry>'` (`:962-975` annotation branch) — the executed half of the map
  cannot be silently reworded either.
- **F3 — section identity is part of the key.** vF's orphan and unmapped
  messages carry the *two different* section names, so a box moved between
  sections is distinguishable in the detail from a text change.
- **F4 — whitespace-only rewrap is invisible by design.** vE stays exit 0 /
  PASS: `text` is `re.sub(r"\s+", " ", …)` normalised (`:581`) and only the
  normalised sha is mapped (`:582`). Consequence for the landing round:
  box-map green is not byte-identity — a reflow edit of SKILL.md text keeps
  the map valid (line numbers and `line_budget`'s "from box at line N" still
  shift).
- **F5 — past 6 problems the detail stops naming some violations** (the
  defect below): vI's run only ever mentions direction A; a reader of the
  FAIL line alone cannot see that an unmapped box exists.
- **F6 — fixture parity.** The committed self-test already asserts the same
  needle pairs at `:1416-1423` (`map-box-reworded` → `["unmapped box",
  "has no live box"]`, `map-extra-entry` → `has no live box`,
  `map-missing-entry` → `unmapped box`), green at 0/1504. This probe is the
  live-target end-to-end analogue on a full repo copy: both directions'
  observed live behavior matches the fixture expectations exactly.
- **F7 — mirror recipe note.** A fleet-shaped copy needs the dotfile entries
  too (`.[!.]*`); round-22 M5's phrasing "link every live fleet entry" read
  with a plain `*` glob leaves 2 citation FAILs that are copy artifacts, not
  tamper signal. Contrast with claim 3's harness: `name_directory` requires
  the copy directory to keep the name `kotoba-shokunin`.

## Defects named (each: path:line + evidence)

1. `verifiers/verify_skill_checklist.py:987-988` — the FAIL detail is
   `"; ".join(problems[:6]) + " … (+N more)"`, so direction names can be
   truncated away. Evidence: vI (`498811f2…`, 7 deletions + 1 added box,
   exit 1) names six `has no live box` entries and ` (+2 more)`; the string
   `unmapped box` never appears, although a live box is unmatched. vH (8
   problems) similarly drops the two injected boxes' line numbers. Impact for
   round 23: the requirement "box_map FAIL naming both directions" is
   guaranteed only for ≤6-problem states; detection is unaffected (exit/message
   still FAIL), so this is a presentation defect, not an escape. Fix shape if
   wanted: summarise by direction (counts + first offender each) instead of a
   flat slice.

No other defect found: direction A (`:947`), B (`:955`), annotation
(`:962-975`), and the executed floor all behaved as documented in the
module docstring (`:50-58`).

  slice — this probe only certifies the checklist regression surface a
