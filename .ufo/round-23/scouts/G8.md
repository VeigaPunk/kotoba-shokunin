## Findings
- **F1 — identity on the three round-22 commits is uniform and correct.** `5a33c3e`:
  author=committer=`kotoba-shokunin <kotoba@shokunin.local>`, `Mon Oct 19 01:52:31 2026 -0300`,
  parent `2e8eb64`; `2e8eb64`: same identity, `01:52:07 -0300`, parent `4b50d8d`;
  `4b50d8d`: same identity, `01:50:24 -0300`, parent `b16300f`. Author == committer on all
  three, all timestamps `-0300`, all three single-parent (linear, no merges). Repo-local
  `user.name/user.email` = the same pair, so the identity is configuration-backed, not ad hoc.
  Across the whole history (59 commits) there are 5 identity tuples:
  `kotoba-shokunin|kotoba@shokunin.local` ×41, `Joao Pedro Veiga|jpveigao10@gmail.com` ×8,
  `aggregator-shokunin|aggregator@shokunin.local` ×6, `shokunin|shokunin@local` ×2, `ci|ci@local` ×2.
  No commit in history mismatches author vs committer. All 59 commits are unsigned (`%G?` = `N`).
- **F2 — the true remote is 2 commits AHEAD of the local merge-base; the local repo does not
  know them.** `git ls-remote origin refs/heads/master` = `74fc0f12…`; that object is **absent
  locally** (`git cat-file -t` exit 128), so `ls-remote` alone cannot compute ahead/behind —
  it only proves the remote tip is not in local history. `git ls-remote origin` (14 refs) shows
  the remote also carries 8 `cursor/*` README branches, `refs/heads/devin/wiki-link` = `24feb3c`,
  and `refs/pull/1/{head,merge}`, `refs/pull/2/head`.
- **F3 — "ahead 6" is measured against a stale tracking ref, and the true relation is
  *diverged* (6 local-only / 2 remote-only).** `refs/remotes/origin/master` (and `origin/HEAD`)
  is frozen at `c8b53ac` (mtime `2026-10-17 00:29:06 -0300`; `.git/FETCH_HEAD` even older,
  `2026-10-16 23:31:26`). `git status`/`git branch -vv` therefore report `ahead 6` with no
  `behind` term; in the copy, `git fetch` moved `origin/master` to `74fc0f1` and
  `git rev-list --left-right --count FETCH_HEAD...HEAD` returned `2	6` with merge-base
  `c8b53ac`. Local-only 6: `5a33c3e 2e8eb64 4b50d8d b16300f 2ca8d01 4e92f36`. Remote-only 2:
  `24feb3c kotoba: README header Devin wiki link + LOG entry` (identity `kotoba-shokunin`,
  `2026-10-17 15:52:05 +0000`) and `74fc0f1 Merge pull request #2 from VeigaPunk/devin/wiki-link`

   `…/verify_surfaces.cpython-314.pyc` **as tracked by the remote tip `74fc0f12`**, with

   **published bytecode + published ignore-rule regression**, locally repaired but never pushed.
   Evidence: `git ls-tree -r --name-only FETCH_HEAD | grep -E 'pyc|pycache'` → 2 blobs;

## Limits (what you did NOT verify)
- No `git fetch`/`push`/`merge` in the live tree (forbidden); divergence was derived from
  `ls-remote` (read-only) plus a `cp -a` copy — so the 2-remote-only/6-local-only split is
  reproducible but was not exercised as an actual merge or push, and the rejection of a
  non-fast-forward push is inferred, not observed.
- `ls-remote` is a snapshot at ~02:00 -0300; concurrent pushes by other lanes would move
  `74fc0f12` and are not covered.
- GitHub-side state beyond refs was not read: no PR bodies, comments, branch protection,
  or CI status; the 2 remote-only commits were inspected by message/identity/path list/stat
  only, not by full content review.
- `git ls-remote origin` shows 8 `cursor/*` branches and `refs/pull/*`; none of those refs
  were diffed against local history, so further unpublished/unknown-to-local commits on those
  branches are unmeasured.
- Sibling-path check is regex/line-based over diffs (F4) and covers only the three round-22
  commits for content, plus the whole index for tracked paths; it is not a semantic review,
  and it does not prove no lane *wrote* outside the repo during round 23 (only that nothing
  outside the repo is committed).
- Whether round-22's A2 L0 append line actually exists in `../.ufo/l0-questions.md` was not
  checked (fleet root out of scope, would require reading a sibling-adjacent path).
- `git fsck` ran `--connectivity-only` (not `--full --strict`); object *content* integrity and
  the 6 dangling blobs' provenance are unverified. Pyc byte comparison covered 2 blobs only.
- `.git/config` was read for `user.*`/remote/refspec; global/system git config, hooks,
  `core.fsmonitor`, and credentials/credential-helper state were not inspected.
