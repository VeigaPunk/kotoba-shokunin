## Findings

### F1. Reference→existence audit: every referenced fixture exists and is tracked

- **checklist side.** 71 case directories on disk, and the AST-harvested `CASES` table
  (`verifiers/verify_skill_checklist.py:1351`) holds exactly those 71 names — both
  directions empty (cmd 4). Every case dir has `SKILL.md`; `map.json` is absent only in
  `missing-map/`, which is that case's *subject* (the run `--map …/missing-map/map.json`,
  `verify_skill_checklist.py:1341-1348`, asserts the box-map error path) — so
  "every case dir carries SKILL.md+map.json" must NOT be promoted into a fixture-integrity
  rule. Three dirs carry extra artifacts (`delegated-directory/probe-dir/.gitkeep`,
  `delegated-elf/probe-elf`, `delegated-py-suffix/probe.py`) and only
  `unresolvable-command/` carries `vocab.json` (discovered dynamically by the harness at
  `:1344-1346` when the file exists). No flat files under `fixtures/checklist/` (0).
- **surfaces side.** 26 files. 19 are referenced directly by `fx + "/<name>"`
  (`verifiers/verify_surfaces.py:748` defines `fx`), 6 more are referenced inside the
  drop-one loop `for fixture, named in (… "strings-opencode-drop-oc1.txt" …)`
  (`:888-897`) via `fx + "/" + fixture` — a naive `fx + "/name"` grep reports these as
  dead, they are not. The remaining 1 (see D1) is genuinely unreferenced.
- Corpus instruments and the harness/fault instruments need no fixture tree: the corpus
  self-tests build their fixture worlds in code (`FIXTURE_README`/`FIXTURE_TRACKED`
  literals, `verify_corpus_integrity.py:561-610`; `verify_corpus_independent.py`
  "its own fixtures" in-process) and `fault_injection_corpus.sh` builds worlds at runtime
  under `$WORLDS` (cmd 19: zero `fixtures` matches in both).
- **Tracked-ness holds**: 171 tracked = 171 on disk, both diffs empty (cmd 4). The
  round-21 `probe-dir` class (an untrackable empty dir making a self-test false in any
  clone) is closed today: fresh clone self-test is `0/1504` exit 0 (cmd 12) and the live
  gates are green (cmds 8-11).

### F2. `NO-SUCH.*` are intentional error-path probes, not missing fixtures

`verify_surfaces.py:882` (missing omp dump → exit 2), `:929` (missing inventory → exit 2),
`:936` (missing baseline → exit 3) reference filenames that must NOT exist. Any future
"every referenced fixture exists" checker must whitelist exactly these three literals or
it will fail the surfaces self-test case set by construction. This is the one place where
the audit's two directions are not simply complements.

### F3. `.git`-less export: 108/1504 reproduced, mechanism named (already-recorded debt)

A `.git`-less export of the *full* tree (cmd 14) yields `108 failure(s) over 1504
assertions`, over 70 distinct case names, every one a `governance.citation_resolves` FAIL
reading `<case dir>/LOG.md`. Mechanism: `find_repo_root` (`verify_skill_checklist.py:386-392`)
is "Nearest ancestor carrying a `.git` marker, **else the file's directory**" — with no
`.git` anywhere on the ancestor chain the self-test's per-case `repo` becomes the fixture
case directory, so `check_governance_citations` (`:1235-1245`) tries `<case>/LOG.md` and
`<case>/SCORECARD.md`. A clone (cmd 12) and the live tree (cmd 6) are both green, so
`108/1504` is export-only. Recorded already at `LOG.md:1223` ("`.git`-less export
self-test is 108/1504 (carried)") → this is **confirming evidence with the mechanism
attached, not a new defect**. Consequence for the pins guard: P4's design (committed
payload + tmp scratch, no repo-root discovery) is immune to this class by construction —
a positive property of the D4 layout worth preserving in the merge.

### F4. The fixture tree has no integrity checker; dead fixtures are reviewer-only

No instrument enumerates `verifiers/fixtures/**` — the only `fixtures` references in
instrument code are the two `FIXTURES` constants and the `--self-test` usages
(`verify_skill_checklist.py:271,1339`; `verify_surfaces.py:124,758`). Nothing fails when a
fixture is orphaned. Consequence measured: `inventory-kind-drift.md` has been tracked and
unreferenced since `29c17be` (round 14), through the round-15/16/17/21 fixture-set churn —
see D1. Practically, "fixture-tree audit" is a reviewer slice, not an instrument; the
cheap executable proxy is `git ls-files verifiers/fixtures` vs the reference extractor
(cmd 4).

### F5. Naming: the D4 fixture *directory* conforms, the instrument name does not

- Existing fixture dirs are one per instrument subject: `fixtures/checklist/` (for
  `verify_skill_checklist.py`), `fixtures/surfaces/` (for `verify_surfaces.py`).
  `fixtures/pins/` for a pin guard matches that convention (P1.md:156-157 states it too).
- Inside `surfaces/`, every name encodes role+variant: `strings-omp-clean.txt`,
  `strings-opencode-drop-oc3.txt`, `baseline-excluded-noreason.json`,
  `inventory-missing-row.md`. Inside `checklist/`, a directory name *is* the behaviour
  under test (`map-annotation-mismatch`, `citation-boundary-dirslash`). P4's
  `fixtures/pins/mini.bin` (P4.md:21-25) has no role/variant prefix and `mini` is a size
  adjective — the one name in the tree that does not say what it tests. A convention-shaped
  name would be e.g. `payload-mini.bin` (or P3's `fake-omp.bin` family, below).
- The instrument name is a live contradiction: P1 resolved it ("*Naming* — `check_*` breaks
  the 5/5 `verify_*` convention → recommend `verify_substrate_pins.py`", P1.md:105,165), yet
  the round-23 claim (`.ufo/round-23/claims.json` observable/after/`counting_command`/
  falsifier) and every drop-in draft in D6 (`.ufo/round-23/scouts/D6.md:49,68,102,109,118,126`)
  hard-code `check_substrate_pins.py`. P8's landing plan (P8.md:189) does too. Whichever is
  chosen, the *other* set must be rewritten in the same round or the landing's own
  counting command and README/SCORECARD rows name a file that does not exist.

### F6. Self-test discovery: the committed set P4 designs makes 3 of 4 cases invisible

- P4.md:26 — "No pin JSON is committed" — leaves the committed tree with exactly one
  positive payload; the sha-drift, mtime-drift and missing-binary cases exist only as
  in-process mutations inside `self_test()`. A reader running `ls verifiers/fixtures/pins/`
  cannot enumerate the designed failure modes, and no committed artifact pins the pin-file
  schema the self-test generates.
- The convention is the opposite where it can be: `fixtures/surfaces/` commits every
  negative input its loop consumes (`strings-empty.txt` for the vacuity class,
  `inventory-extra-row.md`, `baseline-oc-empty.json`, …), and `fixtures/checklist/` commits
  a whole SKILL.md per case. Only genuinely un-committable state (an empty dir) is handled
  by an in-tree trick (`probe-dir/.gitkeep`).
- P4's justification ("`mtime_ns` is not checkout-stable", P4.md:26) is sound only for
  fixtures whose *pin values* must equal the payload's live mtime. The competing P3 design
  (P3.md:117-131) commits `fake-omp.bin` / `fake-opencode.bin` + 8
  `baseline-pins-*.json` fixtures (`clean`, `sha-drift`, `mtime-drift`, `empty`, `badkey`,
  `badsubject`, `badsha`, `badjson`) and reaches ns-exactness by `os.utime`-ing the tmp copy
  to the pinned nanosecond value — i.e. commit the *pin*, set the *clock*. That is
  committable, checkout-stable, and matches the round-23 claim's own wording "a committed
  self-test fixture set" (`claims.json` claim text). So the two P-fragments propose
  **incompatible fixture layouts** (1 file vs 10 files, and pins as generated ns-ints vs
  committed ISO strings) and the merged canonical body must pick one explicitly. P7's
  22-defect review names the missing self-test (C2, P7.md) but not the layout conflict —
  the merge has no guidance for which fixture tree lands.

### F8. The D6 README row's directory token is convention-legal but needs a tracked file

`corpus/README.md:44` already indexes brace-expanded *directory* tokens
(`../verifiers/fixtures/checklist/command-heredoc-tilde{,-dead,-misterm}/`) and the live
corpus gate is 9/9 exit 0 (cmd 10) — so the D6 draft's `../verifiers/fixtures/pins/` token
(`D6.md:49`) will resolve as a directory. But git cannot track an empty directory: the row's
token only survives a fresh clone if the dir lands with ≥1 tracked file. This is the exact
round-21 failure shape (`probe-dir/.gitkeep`, SCORECARD.md:32); a "land the dir, commit
files later" order would leave the corpus gate's MISSING check red on the clone. `mini.bin`
is not gitignored (cmd 18), so one committed file is sufficient.
