## Findings

1. **The probe behaves exactly as designed.** One unquoted dead repo-rooted path planted in
   the copy's SCORECARD.md: `FAIL governance.citation_resolves … SCORECARD.md:155:
   'verifiers/m6-dead-probe.md' does not resolve from /tmp/d23/m6/plant/kotoba-shokunin`,
   exit 1; `--json` reports `status FAIL, exit_code 1`; the full suite is 9 PASS + this
   single FAIL (trigger.citation_resolves stays PASS at 35 — SCORECARD is outside that
   check's scope, so the red is specific to the governance variant). The detail names file,
   line, token and resolution base — the copy path is the read-identity proof.
2. **Regression pair (red -> green -> still red under a fresh plant).** Pre-fix
   `4b50d8d:SCORECARD.md` FAILs naming the two tokens (`SCORECARD.md:40`
   `verifiers/check_substrate_pins.py`; `SCORECARD.md:75`
   `.ufo/round-22/scouts/{S04,S05,S07,S08,S10}.md`) that the round-22 fix `2e8eb64`
   rewrote; HEAD is green (182); a new unquoted plant is caught again (183, named, exit 1).
   The fix removed the dead tokens from the file, not the gate's sensitivity.
3. **The two exclusion classes remain absorb-and-count, by design.** A dead token fully
   enclosed in one quote pair (`C1`) is excluded, counted (`9 quoted meta-finding(s)`), and
   the run stays green; schematics (ellipsis / literal `round-N`) likewise. This is the
   documented round-17 contract, bounded and counted in the detail string.
4. **Quote handling is parity-at-token-start, not enclosure** (S1/S2): adding a second
   enclosing pair *un-excludes* a previously quoted token. Direction measured here is
   fail-closed (resurrected dead meta-findings -> loud FAILs: S1 names 1, S2 names 7 total
   via `(+3 more)`), but the check's own documentation says the opposite of what it
   implements for even pair counts (see D-M6-1).
5. **The silent-shrink class (the round's P7) is alive on this check** (S3): mechanical
   quoting of live subjects removed 60 subjects from the evaluated population
   (182 -> 122, `69 quoted` counted only in prose) with **exit 0**. The only floor is
   `evaluated == 0 -> FAIL` (`verifiers/verify_skill_checklist.py:1261-1262`); any collapse
   down to 1 subject is exit-code-invisible.
6. **Unreadable governance file is a loud FAIL, not an environment exit** (C4): exit 1,
   detail names the file and the OSError, `evaluated` falls back to the surviving file's
   population (107).
7. **Committed self-test coverage of this class** (`verify_skill_checklist.py:1632-1670`,
   run green at HEAD: `0 failure(s) over 1504 assertions`, exit 0):
   `governance: quoted/schematic exclusions pass non-vacuously` (:1648),
   `governance: unquoted dead path fails and is named` (:1657),
   `governance: cross-line quotes do not suppress a subject` (:1667). No fixture covers
   even-pair enclosure (D-M6-1) or a subject-count floor above zero (D-M6-2); the fixtures
   use synthetic temp repos — this lane's probe is the live-tree instance.

## Defects named (each: path:line + evidence)

- **D-M6-1 — quoted-exclusion is implemented as quote parity at token start while
  documented as enclosure; even-pair enclosure silently fails to exclude.**
  `verifiers/verify_skill_checklist.py:1183` (`quoted = at_start and not at_line_end`,
  with `at_start` seeded from `advance_quote_state(line, 0, start, False)` at :1179)
  versus the documented contract at `verifiers/verify_skill_checklist.py:181-183` ("A token
  fully enclosed by double quotes on its own line is a historical/meta finding, not a live
  promise") and the limits text at :216-221. Evidence (S1): SCORECARD.md:50 wrapped to
  `""`corpus/QUALITY.md`""` — fully enclosed, on its own line — is evaluated and FAILs
  (`SCORECARD.md:50: 'corpus/QUALITY.md' does not resolve`, exit 1), while the single-pair
  live form is excluded (C1: 9 quoted). Severity: fail-closed in this direction (extra
  FAILs, no bypass); practical impact is a repair lane that requotes an already-quoted dead
  meta-finding (or writes any even number of enclosing pairs) resurrecting it as a spurious
  red. Fixture gap: `:1632-1670` covers only the odd-pair form.
- **D-M6-2 — the governance check has no subject-count floor above zero; the P7
  silent-shrink class is exit-code-invisible here.**
  `verifiers/verify_skill_checklist.py:1255-1262` (FAIL only when `evaluated == 0`;
  `evaluated` is post-exclusion). Evidence (S3): wrapping live subjects in quotes drops
  `evaluated` 182 -> 122 (60 absorbed, `69 quoted meta-finding(s)` prose-only) with
  `PASS … exit 0`; a collapse to any value >= 1 passes the same way. Round-23's claim makes
  closing the P7 class a merge requirement for `check_substrate_pins.py`; this measurement
  shows the same unguarded shrink is live on the existing governance instrument and gives
  the guard design a concrete sibling to assert against (a minimum evaluated count, not a
  zero test). Not a false-pass of a *dead* token by itself — it is a false-pass of
  population collapse.
