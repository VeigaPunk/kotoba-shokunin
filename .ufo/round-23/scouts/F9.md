## Findings

### F1 — One `opencode --version` = exactly **1 line, 156 bytes**; P1's "two lines" is two invocations

Three independent invocations, three appends of exactly one line each (rows 1/4/16):
probe #1 (+1, inferred: line #3326 is the only `04:59` line and followed P1's #3325),
probe #2 (+1, sha/size delta measured), isolated XDG run (+1 in a fresh log). P1's
`P1.md` Finding 4 quotes `04:25:59.932Z` **and** `04:26:14.259Z` — 14 s apart with distinct
run ids, i.e. P1's cmd 3 and cmd 4, two invocations (row 6). The per-exec budget is
therefore **1 line / 156 B**, not 2. This matters because the landed spec/docs will carry a
number, and the round-23 falsifier is itself a line-count claim ("opencode.log must not
gain lines") — the honest budget is 1 line per exec, and it is exceeded by any exec at all.

### F2 — The append is grammar-inert **today**, and that is luck of grammar, not a property

Row 19: none of the 113 `--version` lines in the log matches a counted grammar, so
`oc_observations` (`verify_harness_claims.py:457-516`) is completely unmoved by my two
appends — row 12 (my exact line, replayed against the real gate) → `DRIFT=[]`. Also
structural: the gate reads the **whole file** (`text = log.read_text(errors="replace")`,
`verify_harness_claims.py:461`), so there is **no tail window** for an append to shift —
the P7 "silent-shrink by window eviction" mechanism cannot arise from appends here.
Contamination verdict: **gate still passes, 28/28, exit 0** (rows 8/10), observed values
byte-identical to the pre-probe record. Documented as "clean, with the vector named".

### F3 — The real vector: **9 of 28 checks (32%) derive from that log**, and a heavier exec moves them

Log-derived checks (all in `verifiers/verify_harness_claims.py:537-552`; extractors at
`:457-516`): `oc.log.skills_rescan_max`, `oc.log.init_count_max`,
`oc.log.available_skills_hits`, `oc.log.skills_tag_hits`, `oc.log.init_count_monotone`,
`oc.dup.roots_both_sided`, `oc.dup.onesided_roots`, `oc.permission.skill_lines`,
`oc.permission.skill_allow` = **9/28**. `--version` is too shallow to touch any of them,
but rows 13/14 show the gate's own machinery flipping on one synthetic line: a single
`skills rescanned` line with 5 names → **exit 1**, `oc.log.skills_rescan_max` DRIFT 5≠3; one
line containing `<available_skills>` → **exit 1**. The live log already contains 1172
`spawning` / 1041 `event` / 825 `watcher` lines (row 17 census) — i.e. real session-shaped
invocations emit thousands of lines and 13 real `skills rescanned` lines. An exec-based pin
check couples the pin guard to an unrelated gate's observation surface by construction.

### F4 — `opencode.log` is a **reinstall-scoped** surface: it has already silently shrunk 90%, and the pinned counter would go red on a reset (F9's instance of P7's silent-shrink class)

Round-8's record (`corpus/knowledge/opencode-offer-trace-round8.md:70`, sourced 2026-09-28):
**9.49 MB**, 1918 `duplicate skill name`, 471 `evaluated permission=skill`, 190
`init count=` lines. Live today: **921 360 B / 3327 lines / 0 / 0 / 0** (rows 2/17) — a 90%
shrink, and the log's first line is `2026-10-11T15:50:24.055Z` matching `~/.opencode/`'s
mtime `2026-10-11 12:50`, the v2.0.26 replacement recorded in `baseline.json`
`round18_move`. So the surface was reset by a substrate upgrade (and its grammar with it),
not by anything this round did. Consequence, proved executably: the `equal` pin
`oc.log.skills_rescan_max: 3` does **not** survive a reset — row 15 (empty log) → **exit 1**,
DRIFT 0≠3. The two directions together are the defect shape: the same file that an exec can
*grow* with counted lines is also a file that a substrate upgrade can *empty*, and the pin
cannot tell the two apart. This is why the guard's own rule must be independence from the
log, and why the harness gate's log pins are worth a named durability caveat (not this
round's fix).

### F5 — opencode retains/trims the log itself (`Logging.trim`), so the ceiling is substrate-owned

Row 21: the shipped code opens the log with `flag:"a"` and pipes it through
`c("Logging.trim")(function*(e,r={}){let p=r.max??He,u=r.keep??Ke,…})`, writing a
`${e}.trim` scratch dir first. `He`/`Ke` (max/keep constants) are minified and I did not
resolve them (Limits). No external rotation siblings exist (row 22). Concretely for this
round: the file a gate pins is retentions-managed by the substrate; the pass/fail durability
of `oc.*` pins is therefore not in this repo's control.

### F6 — **hash-never-exec rule (explicit)** — the guard must open bytes and never spawn

State it verbatim in the landed spec, as a normative rule with the evidence behind it:

> **RULE (hash-never-exec).** `check_substrate_pins.py` MUST determine a binary's identity by
> opening it read-only and hashing the bytes (`open(path,"rb")` / `hashlib.file_digest`;
> P1's 0.22 s for both binaries). It MUST NOT execute the pinned binaries, spawn any
> subprocess, or read `~/.local/share/opencode/log/opencode.log`. Rationale, measured:
> every `opencode` exec appends exactly 1 line / 156 bytes
> (`message="cli starting" … args="[\"--version\"]" role=cli`) to a file that is the input of
> **9 of the 28** checks in `verify_harness_claims.py:537-552`, and round-23
> `claims.json`'s falsifier for claim P reads *"any execution of omp/opencode binaries
> (opencode.log must not gain lines)"*; every `omp --version` exec touches ~64 files under
> `~/.omp` (P1 cmd 4). Hashing writes nothing and needs no isolation.

Corollaries for the landing round:

- The guard needs **no version string**: the sha256 *is* the identity. If a human-readable
  version is ever wanted, take it from the fixture/doc side, not by exec.
- Exec is avoidable even if it ever became unavoidable (`XDG_DATA_HOME=<tmp> opencode
  --version` → live log Δ 0, row 16) — but that is a fallback, not a design.
- **Make the falsifier executable in the self-test**: snapshot `opencode.log` (line count +
  sha256) before and after the full live run and assert byte-identity; optionally stub
  `subprocess.run`/`os.exec*` with a raising sentinel. That converts claim P's prose
  falsifier into a green self-test assertion — the P4 idiom (`run_capture(main)`) extended
  with an environment-diff assertion. Cheap, and it is the only way the "no execution" rule
  is enforced rather than stated.
- Do **not** fold a fix to the harness gate's log pins into this round (F4/F5): re-pinning
  or re-scoping `oc.log.*` is its own change with its own evidence.
