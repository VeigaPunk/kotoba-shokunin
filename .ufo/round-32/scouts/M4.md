## Defects
1. **Whitespace-edged pin key silently skipped (the M4 red).** `DISCOVER_RE` is `^…$`; `re.match` anchors at 0 so a leading space fails the match and the key is never added to `keys`. Exit 0, no line mentions the key.
2. **`$` accepts a trailing newline -> mis-tiered + broken output.** `"omp_binary_sha256\n"` IS discovered but emits `DRIFT` (exit 1, the "pin moved" tier) for what is a malformed key, and the `FAIL` line carries a raw newline, so the summary renders as `…FAIL omp_binary_sha256\n: sha256 drift…`. Padded keys should be `UNSUPPORTED` (exit 2), not DRIFT.
3. **The obvious one-line fix crashes.** Strip in discovery only -> `AttributeError: 'NoneType' object has no attribute 'group'` traceback (`m` is None at the `known.get` site), exit 1. The prefix/kind `DISCOVER_RE.match(key)` must strip too and the padded case needs its own explicit verdict.
4. **Residual never-silent gap (same class, not whitespace-edged).** `"omp_binary_ sha256"`, `" omp_binary_ sha256"`, `"omp_binary_sha256_v2"`, `"omp-binary-sha256"` skip at both HEAD and the fix — exit 0 with a bogus value. Also a padded *stray* pin (`" cursor_binary_sha256"`) and a padded *mtime* pin (`" omp_binary_mtime"` = 2000-01-01) are invisible at HEAD; the fix catches both (`exit 2`).
5. **Floors coupling for the landed fix.** The 3-hunk fix adds no assertions, so `check_assertion_floors.py` `pins: 51` stays valid. Any landed variant that adds self-test cases must bump `EXPECTED_INSTRUMENTS["pins"]` and `INSTRUMENTS["pins"]` in the same commit (round-31 G lesson: a lowered/undrifted floor must fail loudly).
6. **Scope note for claim W's "six round-28 variants still behave":** all six re-verified `exit 2`; the claim's counting command (`padded -> non-zero`, `live -> exit 0`) is satisfiable by the 3-hunk fix — but the `_v2`/internal-space class (defect 4) is out of the whitespace-edged claim and should be named as carried debt, not silently claimed closed.
