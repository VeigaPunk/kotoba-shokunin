## Task
Substrate: pins guard + binaries vs pins. Verify claim W (freshness: whitespace-padded pin key silently skipped) and confirm the live pin set actually matches the live binaries.

## Findings
- Live pins hold exactly: omp sha `bf1e86a935b1…` (pin == live), opencode sha `d9123b9bcdb0…` (pin == live), omp mtime `2026-10-16T05:15:11.226207850-03:00` → `delta 0 ns (tolerance 0 ns)`. No drift, no host mismatch.
- **W reproduced.** Six whitespace key shapes silently skip at exit 0 `OK 3/3`: leading space, trailing space, tab, embedded newline, NBSP (U+00A0). `DISCOVER_RE` is anchored `^…$` and `$` matches before a trailing newline, so `omp_binary_sha256\n` is even *discovered and compared* while `' omp…'` is not.
- **The hole is cosmetic for deletion, real for value inspection.** Padded key alone + real pin deleted → still exit 1 `PIN_ABSENT` (the contract pin is always checked). But a padded key holding a *stale* or *malformed* value with the real pin present → exit 0, value never read. An operator editing only the padded key after a re-pin typo gets a green guard (probe `repin_bad`: padded key `0*64`, exit 0).
- Value-side whitespace is already safe: `sha+' '` and `mtime+' '` → exit 3 `BAD_PIN`, loud.
- **Patch validated on /tmp copy** (`pins_patched.py`): strip-aware discovery (`DISCOVER_RE.match(key) or DISCOVER_RE.match(key.strip())`) + an explicit `UNSUPPORTED` arm. Every whitespace shape now exits 2 naming the key (`whitespace-padded pin key: ' omp_binary_sha256' matches omp_binary_sha256 only after strip`), text and `--json` agree (`exit_code=2`), the three real pins still PASS 3/3, self-test unchanged at 51/0, live output byte-identical to unpatched, two runs byte-identical.
- Near-shape keys `omp_binary_sha256_x`, `omp_binary_mtime_ns`, `ompbinary_sha256` stay silent (exit 0) — outside the contract regex by design; noted, not a regression.
- Zero-width space (U+200B) is **not** Python whitespace (`' omp'.strip()` unchanged), so it survives both the old and the patch — a distinct residual shape, not a whitespace case.

## Defects
1. (W) Whitespace-padded pin key silently skipped, exit 0 — six shapes: leading/trailing space, tab, newline, NBSP; padded key's value never inspected.
2. (W, same root) A padded duplicate key can carry a wrong value while the guard reads green — masks a botched re-pin.
3. (S2 residual, not whitespace) U+200B / any zero-width or format-category key char is neither discovered nor flagged; `DISCOVER_RE` anchored match is blind to it.

## Limits
- All probes ran on `/tmp/s2` copies; no repo file touched, no git mutation. Floors table (`verifiers/check_assertion_floors.py:32,47`) pins `pins=51`; the patch does not move the self-test count, so **no floor bump is needed** — but a landing patch must still re-run the floors gate.
- Patch is a /tmp prototype only; not applied to the repo (out of S2's write scope).
- /tmp hit a transient tmpfs quota (Errno 122) mid-run; probes were re-run after cleanup, results reproduced.
- Did not exercise the binaries themselves beyond sha256/mtime; hash-never-exec property inherited from the guard, not re-tested here.
