## Findings

1. **The one value that could never have been guessed was derived, and it
   matches.** `omp.elf.template_bytes` = 273 and its sha256 `c1f03c8e…` were
   obtained by my own delimitation rule (the NUL-terminated UTF-8 run starting
   at `Compress into one routing hint` and ending at
   `Description: {{description}}\n`), and agree with the harness's live values
   exactly (`drafts/p1/comparison-live-v2.txt`).

2. **The cache-key rule is substrate-documented and independently reproduced.**
   `skill-descriptions.ts` (embedded, unminified): `key = sha256(TEMPLATE \0
   name \0 description)`. With the catalogue's captured description vintage my
   rule reproduces **7/7** db keys; with today's live files, **1/7** — and the
   captured strings equal the live strings **+ "\n"** for 6 of 7
   (`drafts/p1/adjudication.txt`), i.e. YAML *clip* chomping.

3. **My first pass was wrong, and the error was mine, not the harness's.** The
   frozen v1 table derived `keys_reproduced=1 / misses=6 / unmodelled=6 /
   verified_skills=1` and disagreed with the harness on those four rows
   (`drafts/p1/comparison-live.txt`). Cause: my frontmatter reader dropped the
   block-scalar trailing newline. After implementing clip/strip/keep chomping
   the same rule yields 7/0/0/7 and agrees. Both passes are preserved; the
   corrected one is `derived-live-v2.json` / `comparison-live-v2.txt`.

4. **Residual disagreements are definitional, and they are reported, not
   smoothed.** (a) `oc.log.skills_tag_hits`: I count `skills="` occurrences in
   the log (13); the harness counts a `skills` tag (0). (b) `oc.dup.roots_both_sided`:
   I count skill *names* seen in more than one rescan array (3); the harness
   counts duplicate *roots* (0) — the check name favours the harness's reading.
   (c) `omp.catalogue.*`: I declare them UNLANDED because the catalogue surface
   is a captured omp session file the harness selects by its own rule; a blind
   re-derivation would have to guess that rule, and guessing is what the claim
   forbids. Adjudication for a third seat: the catalogue path in the harness's
   stdout (`…/sessions/-Projects-shokunin-kumitate-shokunin/…/CoverageCritic.jsonl`,
   captured 2026-10-15T05:02:56Z) is *substrate*, so a future seat can derive
   `found/total/matched` from it without reading the harness.

5. **Representation differences were normalized explicitly, not silently.**
   `compare()` treats a list on one side vs a count on the other as the same
   quantity (`names.mismatches`, `descriptions.missing`, `dup.onesided_roots`);
   `init_count_monotone` was re-shaped from a boolean to a violation count so the
   two instruments compare in the same direction. Both are declared in code and
   here.

6. **Mutant sensitivity is real.** A planted mutation in a *copy* of the agents
   root (reverse-engineer-anything's description edited; tower's `name:` changed
   to `tower-mutant`) flips exit 1 and moves exactly the rows that should move
   (delta in `drafts/p1/comparison-delta-v2.txt`).

7. **A different seat's driver consumes this instrument.** P4's
   `compare_harness_independent.py` joins the live harness and my `--json` output
   with no expectations embedded; it reports 17/28 strict equality, 6 adjudicated
   and the same losers as my own comparator (`drafts/p1/p4-driver-join.txt`).
   I aligned `--json` to that driver's declared interface (`results[]` with
   `re_derived`).
