## Hermeticity discriminator

I built a two-file carrier under this seat's drafts directory: two JSONL files with 2 and 5 skill entries. The frozen payload `inputs/independent-fake-carrier.json` points all 12 published probe blocks at that carrier and declares its recomputed census (`session_files=2`, `candidate_blocks=2`, distinct totals `[2, 5]`). Its SHA-256 is `599e120060fe7468a1d74da4a060425a0bb83f7744cb86be849351beebf9756f`.

For each driver, the first run with this exact payload exited 0 at 24/24 and its receipt's input digests matched the files. I then removed only the carrier's two JSONL files—no JSON input, comparator, or scope bytes changed—and reran with the same frozen payload SHA. It exited 2 with `false blocker … probe target carries no candidate block`. The frozen and live runs both reproduce the flip; see `runs/{frozen,live}-same-input-carrier-{before,after}/`. The failing run has no receipt because `build_meta` rejects the probe before receipt rendering; the before/after input SHA is recorded by the runner and is identical.

This is an explicit external dependency, not merely a changed-payload test: `recompute_probe` reads the payload's `target` and walks its current `*.jsonl` files (`verifiers/compare_harness_independent.py:652-737`; invoked by `build_meta` at `:1925-1936`). The receipt records the two JSON inputs, instrument-file hashes, and scope-file hash (`:1157-1172`, `:1185-1220`) but no probe-target content digest. The receipt's scope digest is present and accurate; it does not make the probe substrate immutable. This is the payload-chosen target residual (R1 F-4), now confirmed as a hermeticity limit for frozen-inputs mode.

The separate `independent-probe-target-mutated.json` arm points the probes at an empty directory and also fails named exit 2. It is a rejection control, not the same-input hermeticity proof above.
