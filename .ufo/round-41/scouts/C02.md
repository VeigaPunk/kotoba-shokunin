# C02 | C1 exploitability rank — round 41

## Ruling

Ranked by access required first, then by effect on the result. The first tier is the best next depth target: an attacker needs only to supply the independent JSON, makes no committed-file edit, and can pass a 28/28 headline without the normal four scope-outs. The V10 draft matrix is a useful bounded census, not an exhaustive one; H04 and R02/Y02 report additional accepted payload forms not in its 46 arms.

## Ranked open doors

1. **Payload-only, direct scope/value laundering — highest priority.** V10's `heldout-flat-dotted-map`, `heldout-nested-checks-map`, `heldout-nested-expected-wrapper`, `heldout-nested-observations-wrapper`, and `heldout-wrapper-precedence-expected-over-observations` each exit 0 with 28/28. These record-free maps omit the ordinary scoped-out representation and let payload-provided values stand in for all 28 checks, including the four normally excluded rows. No carrier, committed-file edit, or special invocation is needed. C02 independently reproduced the expected-map, observations-map, and flat-map variants at 28/28, each beside a 24/24 honest control (`drafts/c02/door-probe-output/run-current.txt:6-14`).

   Also high: `heldout-expected-only-full-copy` exits 0 at 24/24 using harvested values in `expected` only, with no derivation fields. It is distinct from the **closed** F-2 arm that pairs `expected` with `re_derived="NOT DERIVED"`; that explicit contradiction now exits 2. H04's raw-JSON duplicate top-level `results` and duplicate per-record `re_derived` members (divergent copy first, honest copy last) are additional payload-only, 24/24 acceptance paths outside V10's matrix (`scouts/H04.md:28-46`). If callers can supply raw JSON bytes, treat those decoder last-key-wins shapes as co-priority with the expected-only copy.

2. **Payload-only, contradictory selected-field aliases — accepted, usually not a changed primary join.** V10's `heldout-expected-value-secondary-shadow`, `heldout-rederived-vs-value-shadow`, and `heldout-observed-key-shadow` pass at 24/24 while a secondary value field disagrees with the field the parser selects. `heldout-id-alias-conflict` likewise passes with a forged `id`/`name` beside the canonical `check`. These are low-cost, but show that a green join does not establish agreement among the payload's own value/identity claims.

3. **Payload-only, status/scope/report contradictions — accepted, but generally do not add or remove joined rows.** The accepted V10 arms are `heldout-duplicate-id-status-shadow`, `x2-state-shadow`, `status-nonstring-hides-state`, `top-level-status-and-alternatives`, `scoped-out-reason-and-evidence-drift`, and `w1-scoped-row-carries-value`. They permit an `UNLANDED` status to be hidden by duplicate ordering or the `status`/`state` alias, let top-level landed/unlanded/alternatives claims contradict the records, alter the scope-out explanation/evidence, or retain a value on a scoped-out row. Treat these as evidence/status integrity defects rather than 24-row value-join bypasses. X02 separately shows payload-controlled values can move adjudicated membership 4→5 or 4→3 while the protocol join remains 24/24 (`scouts/X02.md:24-38`). H02 also measured `secondary_agree` rising to 28 against a 24-row denominator; this is a payload-only reporting counter defect (`scouts/H02.md:26-37`).

4. **Payload-only probe-channel splits and unused probe fields — accepted evidence substitution.** V10's `record-probe-shadowed-by-top-level-map`, `record-probe-fallback-reads-results-only`, and `unmatched-extra-scoped-out-probe` pass at 24/24. C02 re-ran both split directions on fresh inputs at 16:47:25Z: an honest top-level map beside fabricated record probes exits 0 (independent input SHA `56ccb119…`), and with the top-level map removed a fabricated `rows[].probe` beside the honest results fallback also exits 0 (SHA `881cb100…`). Both controls exit 0 at 24/24; see `drafts/c02/door-probe-output/run-current.txt:29-32`. These cases require no planted carrier because the contradictory record-level probe is the channel being ignored. The separate `r1-f4` target-repointing case below is the one that needs a carrier.

5. **Caller-supplied live JSON plus independent JSON — invocation/input control, not an independent-payload-only attack.** V10's `live-mode-positive-masks-independent-drift`, `live-mode-split-across-row-channels`, `live-top-level-observed-summary-divergence`, and `live-verdict-shadow-in-row-channel` all exit 0 at 24/24, but they mutate the comparator's live-side JSON as well as (or instead of) the independent side. They are reachable only if the caller can substitute/control `--live-json` or the live producer's output; do not attribute them to an independent-payload attacker. H02 independently found that a conflicting live `rows` mode can alter adjudication (`scouts/H02.md:24-25`).

6. **Payload plus a planted carrier — F-4, moderate reachability; probe evidence only.** `r1-f4-payload-chosen-probe-target` exits 0 at 24/24 after the payload redirects the scoped probes to a small, locally created two-file carrier and supplies its recomputed observable. No committed file or invocation change is needed, but a writable carrier is. This does **not** add/remove joined IDs or defeat the committed scope set; it means “recomputed probe” does not establish that the real carrier was probed. V10's command/result is pinned in `drafts/v10/probe-results.json`; the mechanism is also summarized in `scouts/N07.md:28-35` and `scouts/Y02.md:43-48`.

7. **Driver-invocation control plus a planted scope file — hardest prerequisite, highest impact in this tier.** Two accepted variants exist: V10 `scope-file-caller-selected-absolute` supplies an absolute attacker-selected `--scope-file`; `r1-f3-prime-scope-file-cwd` instead keeps the relative scope argument and runs from a planted process CWD while `--cwd` remains the repository. Both exit 0 at 23/23 with five rows scoped out, including `omp.offered.skills`; neither edits the committed scope file. C02's fresh CWD run recorded receipt scope SHA `fbcdc8d2…` (the honest repository file) while the enforced planted file is SHA `f1886af4…`; the receipt says 23 joined / 5 scoped out (`drafts/c02/door-probe-output/cwd-planted-scope/receipt.json`). The same C02 payload from repository CWD exits 2 with the named “committed scope file does not list” rejection (`run-current.txt:40-44`). This is the strongest invocation-dependent integrity failure: membership expands beyond the committed four-row scope and the receipt attests a different file from the one enforced. Prioritize it highly when the runner's CWD or `--scope-file` argument is not trusted.
