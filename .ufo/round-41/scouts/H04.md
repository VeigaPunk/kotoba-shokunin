## Mechanism and residual scope

1. **Duplicate JSON object members — open.** The driver reaches Python `json.loads` in `extract_json` (`verifiers/compare_harness_independent.py:207-212`) before `_channel_maps` validates channels. A raw payload can put a divergent `results` array under the first duplicate key and the clean array under the second; Python retains the latter, so the former never reaches channel reconciliation. A duplicate `re_derived` member works the same way before the new within-record consistency guard. Reversing the top-level pair makes the divergent copy effective and correctly fails; this confirms last-wins, not a malformed/no-op arm. Reject duplicate names at decode time (for example, an `object_pairs_hook` that raises) before joining. The current JSON is syntactically accepted but semantically ambiguous.

2. **Nested shadow channels — conditionally open.** `_channel_maps` iterates the fixed top-level `CHANNEL_KEYS` (`results`, `rows`, `checks`) on the parsed object (`compare_harness_independent.py:246-257, 272-358`); it neither recursively searches unknown fields nor rejects the `extensions` subtree. I inserted a second set of conflicting channel-shaped copies under three nested keys on either input side. Both still returned exit 0. These fields are not part of the currently declared root-channel schema, so this is not a bypass of a *defined* direct channel. But if C1's completeness requirement includes every channel a payload can carry, either forbid/validate unknown nested channel structures or explicitly bound the claim to the three direct fields.

3. **Record shape — closed for the tested list form.** A record that is a JSON array is rejected at `_channel_maps`'s object check, with a named exit 2 on both input sides. No evidence of an acceptance or traceback in this shape.

4. **Unicode IDs — mismatch fails closed; format policy is loose.** NFKC aliases are not normalized into the ASCII ID: differing channels fail membership reconciliation, and an independent-only alias produces an uncovered and unknown row with exit 2. A matching Unicode ID in both list payloads joins because the driver has no committed ID inventory and accepts any string record ID. If the intended ID grammar is the documented ASCII dotted form, apply the same validator to list records. Do not describe the current behavior as Unicode alias normalization or as a demonstrated one-sided laundering path.
