# X05 | xcheck-live-side — round 41

**Question:** can the live side of the join hide a contradictory value in an unread channel, or change a row’s comparison semantics so a forged live value still joins green?

**Verdict: OPEN.** The live verifier’s ordinary output and self-test remain green, but the comparator trusts payload-provided `mode` and does not cross-check the live `results` rows against the verifier’s top-level raw `observed` map. A crafted live payload changed `omp.offered.skills` from 7 to 6 and switched its mode from `equal` to `positive`; the comparator returned **24/24, exit 0**, despite the independent value and the live row’s own `expected` both being 7. A value-only control with `mode=equal` fails as expected. This is a payload/parser trust gap, not a claim that the unmodified live process currently emits the forged row.

## Mechanism and boundary

`verify_harness_claims.py:638-660` emits both the nested raw `observed` object and the flattened `results` list. In the comparator, `_channel_maps()` (`compare_harness_independent.py:272-358`) reconciles list/map channels on value and `status`/`state`; it does not reconcile `mode`, `verdict`, or `expected`. `parse_live()` (`:469-495`) then takes the first row channel and copies `observed`, `verdict`, and `mode` from it. `predicate_agree()` (`:184-194`) accepts `positive` when independent value is at least the live value. The IND does not derive or attest the live mode.

The raw-summary arm alone is an **audit-consistency gap**: it is ignored and does not change the join’s chosen row value. The mode/shadow arm is the direct laundering result: the checked value remains `results[].observed`, but the payload selects a looser comparison predicate and makes contradictory sibling metadata invisible. `--strict-headline` names the mismatch, but the honest current capture already has four protocol-adjudicated strict differences, so its nonzero exit is not a clean proof by itself; the mutant adds this target as a fifth strict disagreement.

This re-verifies X2’s live-side `x5-live-observed-divergent` class on the current tracked bytes and adds a mode/verdict metadata discriminator. The existing live process is not shown to emit these contradictions; the accepted `--live-json` payload path is the tested surface. Do not describe the live-side payload class as closed. A follow-up depth fix should bind each live row’s mode/verdict to an independently trusted contract and cross-check the raw observation projection (or stop publishing it as a second authoritative value channel).
