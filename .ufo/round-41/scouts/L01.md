## Confirmed uncovered behavior

1. **Duplicate independent status is last-record-wins.** `verifiers/compare_harness_independent.py:309-345` rejects repeated IDs only when their values differ; otherwise the status slot is overwritten. `parse_independent` then copies the collapsed status at `:439-452`. The self-test covers an `UNLANDED` row becoming provisional at `:1392-1424`, but not duplicate records for that ID.

   - `live-zero.json` + `independent-duplicate-status.json` (`UNLANDED` then same-value `DERIVED`) → exit 0, agreement 1/1, zero provisional rows.
   - Same command with `independent-duplicate-status-reversed.json` → exit 1, provisional row `probe.value (status=UNLANDED)`.

   Thus a duplicate order change alone can turn an unlanded derivation from rejected to green. This is a direct gap in the guard that prevents unlanded-based agreement from passing.

2. **Live metadata conflicts are not reconciled.** `_reconcile` compares canonical values and status/state only (`:361-411`); `parse_live` subsequently takes the first record channel and overwrites a repeated ID's verdict/mode as it iterates (`:469-495`). The self-test's payload battery at `:1083-1146` has a true control and F-2/F-3 value/shape arms, but no same-valued live mode/verdict conflict arm.

   - `live-mode-shadow.json` publishes one ID/value in both `results` and `rows`, with `results` saying `mode=positive, verdict=PASS` and shadowed `rows` saying `mode=equal, verdict=DRIFT`. With observed 7 and independent expected 8, the CLI exits 0 at 1/1 by trusting `results`; it does not name the contradictory channel.
   - `live-duplicate-id.json` has two same-ID/same-observed rows but conflicting mode/verdict; the positive/PASS row last gives exit 0. Reversing the rows gives exit 1. This is the same last-record-wins weakness within one channel.

3. **The final `--json` smoke call is not actually asserted.** At `:1829-1852`, the self-test discards the `subprocess.run` result and checks only the Markdown report body. A regression in JSON stdout shape or that invocation's exit code could therefore ride green.
