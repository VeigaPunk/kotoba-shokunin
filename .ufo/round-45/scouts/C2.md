# C2 — R45 severity-ranked open doors

## Scope and meaning of “open”

This seat ranks the surviving exit-0 cases; it does not patch the comparator. “Open” below means an adversarial arm returned exit 0 when run against the frozen comparator bytes. It does **not** mean the normal producer emitted the malicious form, nor that a remote attacker can reach the CLI. Exploitability is conditional on control of the file(s) supplied to the comparator; the additional prerequisite for each class is stated below. The expected/value-alias and status cases are metadata-integrity failures in these probes, not evidence that the primary live/independent value comparison itself was changed.

## Exploitability ranking

Ranks order conditional decision effect and access prerequisites; they are not CVSS scores. All accepted JSON-arm outcomes require a caller to supply or alter the corresponding input file. The live-input class additionally requires control of the explicit `--live-json` input/invocation. No result here shows that the ordinary live producer itself is forgeable.

### H1 — Highest conditional risk: caller-selected `--live-json` can carry a contradictory decision

Four R41 arms accept inconsistencies in caller-provided live data. `live-mode-positive-masks-independent-drift` is the strongest false-green: the live value is 7 and the independent value is 999, yet the join returns 0 because the supplied live mode makes the row green. `live-mode-split-across-row-channels` accepts conflicting modes between live record channels; `live-verdict-shadow-in-row-channel` accepts a conflicting verdict shadow; `live-top-level-observed-summary-divergence` ignores a divergent top-level summary while the row channels return 0. The first is direct value disagreement; the latter three show live-channel/verdict/summary consistency gaps. This ranking is conditional on a caller selecting or tampering with the live JSON file, not the normal producer path (the fresh producer join above is green without such a mutation).

### H2 — Scope-out evidence/probe selection is payload-controlled; one case also needs a planted writable carrier

`r1-f4-payload-chosen-probe-target` redirects the probe target for already-committed scoped-out records to `.ufo/round-41/evidence/builder-carrier`; the replay reused this pre-existing planted carrier. Reproduction in another workspace requires a matching carrier readable at the chosen path and, to plant one, local write access. `stat -c '%A %U:%G %n' .ufo/round-41/evidence/builder-carrier` at `2026-10-19T18:47:31Z` returned `drwxr-xr-x vgpnk:vgpnk`. `record-probe-fallback-reads-results-only` and `record-probe-shadowed-by-top-level-map` accept a probe supplied in only one chosen representation/channel or let the top-level map take precedence over record probes. These weaken proof-channel binding for existing scope-outs. The separate `scope-uncommitted-extra-row` and planted-CWD scope-file arms reject with exit 2, so these cases did **not** demonstrate adding arbitrary scope-outs or a relative scope-file bypass.

### M1 — Ordinary independent JSON can create status/identity/alias ambiguity, but the probes preserve the primary values

`heldout-duplicate-id-status-shadow` and fresh `duplicate_id_status_precedence` accept duplicate check IDs with an earlier `UNLANDED` and later `DERIVED` status. `heldout-expected-value-secondary-shadow` accepts `value=7` beside conflicting `expected_value=999`; fresh `expected_expected_value_conflict` accepts a contradictory `expected`/`expected_value` pair. Fresh `status_lone_nonstring` accepts `status=["UNLANDED"]`, and `nonstring_check_alias` accepts a non-string `check` alongside a usable `name` alias. This includes both registered X2 residuals: on frozen `13b6d791` both still return exit 0. Their demonstrated effect is malformed status/identity/alias metadata being tolerated, not a change to the selected primary comparison value.

### L1 — Low decision effect: scoped-out explanation and unmatched-probe metadata

`scoped-out-reason-and-evidence-drift` changes scoped-out reason/evidence without changing the committed scope membership; `unmatched-extra-scoped-out-probe` adds an unused extra probe (`forged.extra`) while the join remains green. These can make audit metadata misleading or non-canonical, but the replay did not show a changed joined value or an added committed scope-out.

### L2 — Lowest within this comparator: raw duplicate JSON members

Fresh `duplicate_record_rederived_member` and `duplicate_top_level_results_member` contain raw duplicate object members with contradictory earlier values, both exit 0. They require raw JSON byte construction rather than ordinary serializer-produced JSON. Under this Python comparator's JSON parser, the later (honest) member wins, so the effective decoded value remains honest; this is a parser-differential/non-canonical-input risk, not a demonstrated false-green in this comparator's decoded object. Both remain exit-0 arms under the stated behavioral definition of open.
