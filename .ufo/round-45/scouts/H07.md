## H07 identity/value/status alias hunt

The fresh channel hunt ran **19** one-row CLI payload variants against the same two frozen comparator snapshots (`--expect-n 1`; live value `1`; equality mode). Every arm’s input payload is embedded and SHA-pinned in `H07-hunt.json`.

- **Expected aliases — still open:** `expected=1, expected_value=999, re_derived=1` exits 0 on both snapshots, with protocol/strict 1/1. Reversing the pair (`expected=999, expected_value=1, re_derived=1`) fails closed with exit 2. This is an order-sensitive gap: the landed parser checks the first foreign alias against derived aliases but does not reconcile `expected` against `expected_value`. It is the same expected-alias residual recorded by the census, not a second distinct census door.
- **String identity aliases — closed on landed bytes:** each conflicting pair (`check`/`id`, `check`/`name`, `id`/`name`) and all three string aliases disagreeing fail with named exit 2 `record id conflict`. The agreeing all-string control exits 0. These conflict arms were exit 0 on the `6881ce3` bytes.
- **New identity type edge — still open:** `check=[]` with matching string `id="alias.row"` and `name="alias.row"` exits 0. `_record_id` filters to string aliases, so it silently ignores the present non-string `check`. This is a malformed-alias acceptance, not a mismatched joined identity.
- **Derived value aliases — tested conflicts closed:** `re_derived`/`value`, `re_derived`/`observed`, `value`/`observed`, and all three derived aliases disagreeing fail with named exit 2 `record value alias conflict` on landed bytes; each corresponding focused arm was exit 0 on `6881ce3`. Agreeing derived aliases remain green. A payload with all five value fields (`expected`, `expected_value`, `re_derived`, `value`, `observed`) disagreeing also fails closed; the before and after runs both rejected that multi-conflict payload.
- **Status aliases — string split closed, lone malformed value still open:** `status="DERIVED", state="UNLANDED"` and `status=null, state="UNLANDED"` fail with named exit 2 `status/state split`; matching strings remain green. A lone non-string `status=["UNLANDED"]` with no `state` exits 0 because the non-string is dropped from the captured status map. This is an extra H07 residual beyond the 46-arm census, and distinct from the census’s `status-nonstring-hides-state` input (which also supplies a disagreeing `state` and is rejected).
- The composite record carrying all identity, value, and status aliases in disagreement fails closed, first as `record id conflict`. The independent per-family arms above are the evidence for the later value/status checks; the first composite error alone would not prove those checks.

Across the fresh alias matrix, **3 contradictory/malformed variants remain green**: the expected-value conflict, non-string `check`, and lone non-string `status`; three agreeing controls also exit 0. The other 13 variants return named exit 2. Thus H07 adds **two** distinct open cases beyond the 11 census survivors; the expected-value conflict overlaps the census survivor.
