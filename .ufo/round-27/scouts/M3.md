# Scout M3
## Task
Red probe: corpus dead pointer planted in a /tmp clone of HEAD 7a9c50c; measure whether
the corpus instruments catch it, and whether the clone is a usable probe environment.

## Commands run
- `git clone --no-hardlinks <repo> /tmp/m3-redprobe` (clone untouched repo; kept for re-run)
- baseline + per-mutation: `python3 verifiers/verify_corpus_integrity.py --repo .` and
  `python3 verifiers/verify_corpus_independent.py --repo .` (both `--json`-capable)
- mutations via `sed`/`rm` on the clone only; `git checkout --` between runs
- `bash verifiers/fault_injection_corpus.sh --self-test` (clone)
- reachability: `git cat-file -t <hash>`, `git rev-list --all --count`, `merge-base --is-ancestor`

## Findings
- F1 ORIGIN GREEN: integrity in the main repo = `9/9 checks pass`, exit 0 (read-only run).
- F2 CLONE RED AT BASELINE: both instruments exit 1 on the untouched clone —
  `corpus.pointers.commit_unresolvable observed=24 expected=0` in each. Root cause: the
  27 `commit` citations cite ~11 hashes (3b029b8, 4002b9f, a614927, 1d93182, 229b687,
  397b29c, 8c300ad, e997d45, abef8aa, 4dd7753, 683d147) that are unreachable from HEAD —
  reflog-only objects (origin 47 reachable commits, clone 45; `3b029b8` not an ancestor).
  Exit codes are saturated at 1 in a clone; only per-check DRIFT deltas carry signal there.
- F3 RED PROBE (report pointer): retarget README:57 round-23→round-99 report pointer →
  `report_dead 0→1` in BOTH instruments, DRIFT names `corpus/README.md:57:
  ../.ufo/reports/round-99/kotoba.md`. Detection works, site-precise.
- F4 RED PROBE (knowledge path): retarget README:20 `render-mechanism-round7.md`→`-GONE`
  → caught, but by the INDEX class: `unindexed=1 stale_patterns=1 missing_paths=1` in
  both instruments, sites named at README:20; `report_dead` stays 0. The pointer class
  only covers report pointers; coverage-map paths are index territory.
- F5 RED PROBE (deleted tracked file): `rm corpus/knowledge/fleet-skill-audit-round5.md`
  → both instruments fail CLOSED: INCONCLUSIVE exit 2, naming the unreadable path. No silent pass.
- F6 FAULT HARNESS BROKEN IN CLONE: `fault_injection_corpus.sh --self-test` →
  `T1 PASS / T2 FAIL (exit=1) / T4 PASS / T3 FAIL / self-test: BROKEN`, real exit 1.
  T2 asserts an unmutated fixture world reads clean (exit 0); the fixture world is a
  clone, so it inherits F2's `commit_unresolvable=24` and reads dirty. Same root as F2,
  not harness logic. Presumably green at its round-12 landing (d49dfa5) pre-rewrite.

## Defects named
- D1 (hermeticity): corpus-integrity green verdict is not clone-reproducible — any clone
  runs red with `commit_unresolvable=24` because cited landing commits were orphaned from
  HEAD history. Extends the round-12 "clone verdict not hermetic" caveat with a second,
  distinct mechanism (reflog-only objects, not host-anchored paths).
- D2 (regression, masked): fault-harness `--self-test` is BROKEN in any clone at HEAD
  (exit 1); unobservable in-origin green runs, so it passes silently in-repo.
- D3 (minor, classification): "dead pointer" prose in corpus-integrity row (README:35)
  maps to two different check classes (report_dead vs index missing_paths); detection is
  complete but the naming could mislead a reader expecting one class.
