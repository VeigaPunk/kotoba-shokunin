## Findings
- **No drift at HEAD.** Live run: exit 0, `OK 3/3 pins hold`. omp sha256
  `bf1e86a9…c754974` and opencode sha256 `d9123b9b…1813218c9` match the pins;
  independent `sha256sum` agrees with the guard byte-for-byte. omp mtime pin
  `2026-10-16T05:15:11.226207850-03:00` vs live ns: delta 0 ns, tolerance 0.
- **Guard red side alive.** Tampered-sha baseline → exit 1,
  `DRIFT 1/3 pins failed: omp_binary_sha256`, pin named on the FAIL line.
  Fake binary → DRIFT on both omp pins (sha256 + mtime), opencode PASS untouched.
- Self-test on the /tmp copy: `0 failure(s) over 46 assertions`.
- opencode mtime is the 1985 packer constant (`499162500` s epoch) — sha-only pin
  is by design, matches corpus/README.md:57.
- Gate wiring confirmed: guard is referenced by SCORECARD.md:128,
  corpus/knowledge/substrate-pin-guard-round23.md, LOG.md:1231; only repo commit
  touching it is dc4c0c0 (round 23).

## Defects named
- **D1 (minor, coverage boundary):** a pin-shaped key the discovery regex misses is
  silently ignored, contradicting the docstring's "never a silent skip" coverage
  lesson. `DISCOVER_RE` = `^[a-z0-9_]+_binary_[A-Za-z0-9]+$`, so
  `OMP_binary_sha256` (valid 64-hex value) → exit 0, `OK 3/3 pins hold`, key never
  mentioned. Same class: `omp_binary_sha256_v2` (kind regex stops at `_`).
  Impact low — it cannot displace a real pin (deleting the real key still fires
  `PIN_ABSENT` exit 1); the block's noise floor just swallows case-variant or
  suffixed pin records. Fix shape: case-insensitive discovery, or UNSUPPORTED for
  any `*_binary_*`-shaped key.
