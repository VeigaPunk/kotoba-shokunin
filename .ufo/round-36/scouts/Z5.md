# Scout Z5

## Task
Claim Z on the picked fix: the full 28-pin corruption matrix (one pin corrupted at a time) must flip every pin (exit 1 naming it); the live green run must be byte-identical to HEAD's output.

## Commands
- Candidate located: `/dev/shm/z6/verifiers/verify_harness_claims.py` (sha `c003965e7a2115…`), byte-equal to `/dev/shm/r36/repo/verifiers/…`; `baseline.json` identical to HEAD's. Copies: `/dev/shm/z5/{head,fixed}` (HEAD harness sha `f87f0d3802338c…` @ `754197e`).
- Patch = `evaluate()` drops the `zero`/`positive` early arms so the baseline arm sees them (HEAD `:560-566`).
- `TMPDIR=/dev/shm python3 /dev/shm/z5/matrix.py` — per-pin: deep-copy `verifiers/baseline.json`, corrupt only that pin's `expect`, run head + fixed, record exit and DRIFT lines.
- Live: `python3 <tree>/verify_harness_claims.py --cwd <repo>` and `--json`; `--no-baseline`; `--self-test`.

## Findings
- **28/28 flip on the fixed tree** — each corruption gives `exit 1` with exactly one `DRIFT` line naming that pin (`27/28 checks pass; DRIFT: <pin>`). Per-mode: zero 10/10, positive 1/1, equal 15/15, at_least 2/2.
- **HEAD is 17/28**: blind (exit 0, zero DRIFT lines) on exactly the 11 zero/positive pins — `omp.cache.misses`, `omp.descriptions.over_cliff`, `omp.names.mismatches`, `omp.descriptions.missing`, `omp.descriptions.unmodelled`, `omp.catalogue.missing_names`, `oc.log.available_skills_hits`, `oc.log.skills_tag_hits`, `oc.dup.onesided_roots`, `oc.log.init_count_monotone`, `oc.roots.plugins_cache`. Round-35 M8/N09 reproduced verbatim.
- **No regression**: all 17 equal/at_least pins flip identically head vs fixed. Combined 2-pin and all-28 corruption: head 0→17 drift, fixed 2→28 drift.
- **Live green run**: both exit 0, `28/28 checks pass`; stdout text **byte-identical** (sha `2b0bfc4c125a86…` both; stable across reruns; stderr empty both). `--self-test` identical, `0 failure(s) over 10 assertions`.
- **`--json` live run is NOT byte-identical** — 11 result rows differ only in `expected` (`"0 / empty"`/`"> 0"` → the baseline value, e.g. `0`, `7`, `[]`); `observed` equal, all verdicts still PASS, exit 0 both. `--no-baseline` text also changes: fixed prints 11 extra `OBSERVE … expected=baseline` lines (head prints none for these) — but both still exit 3.

## Defects
- **Z5-D1 (claim wording)**: "live 28/28 byte-invariant" holds for the default text mode only. In `--json` — which `verifiers/baseline.json:9` records as the canonical command — 11 rows change. Not a behavior break, but the invariance claim must be scoped to text mode.
- **Z5-D2 (pre-existing, not caused by the fix)**: `positive`/`at_least` pins with baseline `expect == 0` still pass vacuously — `omp.descriptions.over_cliff.expect=0` and `oc.permission.skill_lines.expect=0` both exit 0 on head AND fixed. The fix closes zero/positive dispatch but leaves this adjacent vacuity class open.
- **Z5-D3 (pre-existing metadata)**: `baseline.json` declares `mode: "at_least"` for `oc.permission.skill_lines`/`skill_allow` while `CHECKS` says `equal`; the baseline `mode` field is dead (documented round-19). `--json` echoes the CHECKS mode, so the two sources disagree in output.
- **Z5-D4 (minor, fail-closed)**: a missing baseline row for a zero pin now DRIFTs with `expected=None` (head silently passed). Correct direction, weak message.

## Limits
- One host, one live state (omp `c1f03c8e…`, 7 skills, catalogue 2026-10-15). Live invariance measured twice per tree, not under load.
- Corruption is `expect`-only (value/mode/type mutations, missing rows, empty `checks` block probed ad hoc, not per-pin). No mutation of the shipped `verifiers/baseline.json` — all baselines are /dev/shm copies.
- Repo untouched: only this fragment written; no git mutation.
