## Findings
Trace, verbatim (`want=NEVER-READ` means `baseline` is never even dereferenced):
- `omp.cache.misses mode=zero     L560 zero-arm     value=0  want=NEVER-READ`
- `omp.descriptions.over_cliff mode=positive L563 positive-arm value=7  want=NEVER-READ`
- every `equal` pin: `L569 baseline-arm value=… want=…`

The bug is branch order, not the r29 condition. `value` is captured at `:558` (before any dispatch — fine), but the mode dispatch at `:560`/`:563` sets `ok` from the *live* value and writes a literal `"0 / empty"`/`"> 0"` into `row["expected"]`, so `:566 elif baseline is None` / `:569 else` are unreachable for those modes — and `:571`'s r29 `mode == "zero"` / `:573`'s `positive` are dead code. `want` is read only at `:569`, i.e. *after* the arm that needed it has already returned.

- Zero corruption: exit **0**, row `expected: "0 / empty"`, `PASS`; plain mode `28/28 checks pass`.
- Positive corruption: exit **0**, row `expected: "> 0"`, `PASS`; plain mode `28/28 checks pass`.
- Matrix: orig **17/28 flip, 11 silent** — the silent set is exactly the 10 `zero` + 1 `positive` ids.
- Reorder fix: matrix **28/28 flip** (`DRIFT <id>` named, exit 1); live stdout byte-identical (`1239f387d7c1c7e7a6a7cd9ebcd3fc84`), `--no-baseline` identical, self-test 0/10, floors 6/6.

## Defects
1. **Claim Z reproduced:** 11/11 zero/positive corruptions exit 0 (`verify_harness_claims.py:560-575`). r29 `b0b0410` changed no observable behavior.
2. **`baseline` is unconsulted for those 11 ids**, so a deleted row (`b_del`) or `expect: null` (`b_null`) also exits 0 — the class is broader than "wrong expect".
3. **`expect: false` on a zero pin still exits 0** (`False == 0`) under both orig and the reorder fix.
4. **`--self-test` cannot see this class:** it exercises `preview`/`parse_frontmatter` only, never `evaluate` — 0/10 on the dead-code tree.
