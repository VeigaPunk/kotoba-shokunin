## 1. Method (and why it is not `git diff`)

The tree moves under every seat, and the parent integrates later; a diff has to
be pinned to a frozen base and be reproducible after the fact. Three layers,
each read-only:

- `drafts/n1/narrate.py` — pins the base by commit sha, hashes every working-tree
  file **as a git blob** (so the comparison is blob-identity, not mtime), and
  self-verifies against `git ls-tree` before reporting.
- `drafts/n1/semantic.py` — for each moved file: top-level def/class/const
  movement by AST-segment hash, unified diffs of changed function bodies,
  regex-literal movement, and the self-test fixture-string set diff.
- `drafts/n1/scope_check.py` — turns each claim's own wording into a declared
  surface set and classifies every moved path as in-scope / bookkeeping /
  **out-of-scope**.

**Calibration against ground truth** (the r38→r39 delta, where `git diff` *is*
authoritative) — the engine must reproduce it exactly or it is not trustworthy:

```
$ python3 .ufo/round-40/drafts/n1/narrate.py --base 1d027f2 --json out/calib-r38-to-r39.json
base 1d027f2  head 1c32b43521598ba37de6460222f63e06449de624  at 2026-10-19T15:04:14Z
tracked(base)=969 worktree=1222 unchanged=959 modified=10 added=253 deleted=0
fast hasher verified against git on 41 sampled blobs: 0 mismatches

$ git diff --name-status 1d027f2 HEAD | grep '^M' | wc -l
10
```

The engine's 10 modified paths are **exactly** git's 10 `M` paths (LOG.md,
SCORECARD.md, the corpus doc, the 6 instruments, the oc-log fixture) — 0 false
positives, 0 misses — and it correctly split git's 27 tracked additions from the
226 scratch files the r39 seats left behind. A second calibration at the r40
base reproduces the r39 scope-lock additions verbatim (`load_scope_file`,
`recompute_probe`, `check_scope_probes`, `DEFAULT_SCOPE`, `SCOPE_KINDS`,
`_PROBE_CACHE`) and names the 4 changed functions with unified diffs.

### N1-F3 (LOW, measurement) — the lane's "live stdout byte-invariant" idiom is not comparable across commits for one gate

`verify_corpus_independent.py` prints its own HEAD and absolute repo path
(`corpus independent derivation: <path> (HEAD 1c32b43)`), so its stdout hash is a
function of the commit, not only of the instrument. Proof:

```
$ python3 verifiers/verify_corpus_independent.py | sha256sum     # 4d911061e2dfb1a2
# same bytes with the HEAD token substituted:
  HEAD 1d027f2 -> ff1da3836ff6979c      <- r39's quoted "byte-invariant" value
  HEAD 1c32b43 -> 4d911061e2dfb1a2
```

r39's `ff1da383…` was **correct at its own HEAD** (seats do not commit, so HEAD
stayed at `1d027f2` all round) — this does not falsify r39's C3 verdict. But the
number is HEAD-dependent: it can be used to prove run-to-run stability *within* a
commit, never instrument identity *across* commits. The other six gates embed
neither HEAD nor an absolute path and are clean
(`out/head-token-probe.txt`).

## 6. Own defects (disclosed, not smoothed)

1. **My first floors reading measured the wrong process.** I ran
   `python3 verifiers/check_assertion_floors.py | tail -4; echo $?` and the exit
   code was `tail`'s, not python's — it read `EXIT=0` beside a `FAIL` line. This
   is verbatim the defect seat V3 disclosed in r39. Caught it in the same
   command's output, re-measured without the pipe (`FLOORS_RC=1`, recorded in
   `out/floors-midland.txt`), and every later floors number in this report is
   from an unpiped run.
2. **My first `sample-watch.sh` wrote into the wrong directory.** `dirname $0` is
   `drafts/n1`, and I climbed three levels instead of four, so it resolved to
   `.ufo/` and would have created `.ufo/.ufo/...` — the same doubled-`.ufo`
   shape as N1-F2. Caught immediately (the log file did not appear where I looked
   for it), fixed to four levels, and verified: no file was written outside
   `drafts/n1/`. No stray tree was produced by me.
3. **I killed my own shell once** with `pkill -f "sample-watch.sh"`: the pattern
   matched the parent `bash -c` wrapper, not just the watcher. No damage (no
   writes in flight, tree verified clean afterwards); the watcher was then
   restarted as a managed background task.
4. **A false alarm I did not report as a finding.** My scope checker first
   flagged `corpus/knowledge/harness-independent-round37.md` as OUT-OF-SCOPE,
   because the *claims* do not name it. Reading W1's brief showed it is that
   seat's declared deliverable, so I widened the declared set rather than filing
   it — the classification was mine to get right, not the seat's to defend.
5. **The engine cannot see inside JSON fixture *content*.** For the 13 new
   fixture files it reports "added", not what they assert; the semantic layer
   reads `.py`/`.md`/JSON-leaves only for *changed* files. The fixture arms'
   meaning is verified by the seats' own batteries and by the comparator's
   self-test, not by me.
6. **My report is a snapshot of a live tree.** I froze the base, but the round
   had not finished when I wrote: `compare_harness_independent.py` was still
   moving (11 revisions observed) and F-2 was still open. Section 2's shas are
   true at 16:01:46Z and must be re-measured at the landing commit if the tree
   moves again.
