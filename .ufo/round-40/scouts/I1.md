### 2.1 The decisive arm, and why the reconciler cannot see it

`F2-clean-all-channels-harvested` is the form that satisfies the new lock exactly:
**every published channel carries the same value** (the harvested one), so
`_reconcile` has nothing to disagree with; only the foreign key in `results`
supplies it, and the derived fields are dead.

```json
results: {"check": "omp.offered.skills", "expected": 7,
          "re_derived": "NOT DERIVED", "status": "DERIVED", "value": "NOT DERIVED"}
rows:    {"check": "omp.offered.skills", "status": "DERIVED", "value": 7}
checks:  7
```

```
$ python3 verifiers/compare_harness_independent.py \
    --live-json probes/live-2daeee7a.json \
    --independent-json arms-clean/CLEAN-f2-all-channels-harvested.json --cwd . --no-stamp
agreement: 28/28 … secondary 28/24 … verdict: exit 0 — all checks agree, both instruments green
```

**The foreign key is one the independent instrument never emits** —
`grep -c '"expected"' verifiers/verify_harness_independent.py` → **0**. So
`expected` is a key only the payload under test can supply, and it is consumed
first:

```
IND_VALUE_KEYS order: ('expected', 'expected_value', 're_derived', 'value', 'observed')
first key present in the record: expected -> 7
the derived field says: NOT DERIVED | but the join scores: 7
```

This is R1's r39 F-2, unchanged by the r40 closure, and it also inflates the
comparator's own secondary column (28/24 against a control 20/24) — the same
self-corroboration symptom B1 filed.
