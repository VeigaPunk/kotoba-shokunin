## FINDINGS

### X1-1 HIGH (mine) — a scoped flag silently discards a derived value the driver is holding

`compare` (`:346-347`) skips any row in `scoped_out` *before* reading its value:

```python
for cid in sorted(live):
    if cid not in independent or cid in scoped_out:
        continue
```

The landed IND emits `re_derived`/`value` on **every** record, including scoped
ones. Nothing rejects a non-null value beside a `SCOPED_OUT` status, and nothing
compares it to live. So a row whose builder derived a **wrong** value keeps it in
the payload, and the flag makes the driver drop it on the floor.

Matched pair, identical except for the flag (`final-battery`, base `bb8dcecd`):

```
A1-999-flag-removed  exit=1  24/25  disagreements: omp.catalogue.total (mode=equal: expected 999, observed 7)
A2-999-flag-kept     exit=0  24/24  all checks agree, both instruments green
```

`A2`'s record is `{"check":"omp.catalogue.total","re_derived":999,"value":999,"status":"SCOPED_OUT"}`.
**The driver holds `999` and reports agreement.** `D3` is the same shape across
all four committed rows → exit 0. This is F-2's class (a value the payload
carries is not reconciled) one level down: F-2 launders through the *key
priority*, this launders through the *flag*.

### X1-2 HIGH (mine) — the scoped row's probe `target` is payload-chosen; the committed file pins only `kind`

`recompute_probe` reads `target` from the payload (`:490`), requires only that
it be an absolute path to a directory with a `<skills>` block (`:491-531`). The
committed scope file pins `probe_contract.kind` (`:607`) and nothing else — the
four `scope_out` entries carry only `kind` and `reason` (verified: `['kind',
'reason']` for all four), and `probe_contract.census_rule` is **never read by any
code** (`grep -n census_rule verifiers/*.py` → no hits). The driver's own
docstring calls a redirected probe exit 2 (`:69`) and `load_scope_file`'s
docstring says the census runs "from the substrate root **the committed file
pins**" (`:472-474`) — but no such pin exists.

Measured, the same disagreeing payload pointed at trees I built:

```

B2-fabricated-under-tmp exit=0  24/24   target=/tmp/.../fake-outside          (totals [3,7])
B3-flat-tree            exit=2  false blocker: ... every blind-plausible rule agrees on one total [2]
```

`B3` is the control that shows the spread test *does* work — it just tests
whatever tree the payload nominated. A payload that cannot derive the row
selects a spread tree of its own and the scope-out stands. A symlinked target
behaves identically (pass-5 arm A4 → exit 0).

### X1-4 MED (mine) — the status channel is read-first and absence-tolerant

`annotate_statuses` (`:649`) fires the provisional guard only when the status is
a truthy string outside `("DERIVED", "OK")`:

```python

if status and status.upper() not in ("DERIVED", "OK") and row["protocol"] is True:
```

`C1`/`C2` are the same row: the honest `UNLANDED` fails closed; deleting the

### X1-5 LOW (mine) — the docstring's "lock 3" has no implementation

`:70-72` claims "**The blocker's falsifier is checked**: the strings whose
presence would put the rule back inside the substrate set are swept for; any

absent". `recompute_probe` returns `"present_tokens": []` hardcoded (`:550`) and

the claim.

### X1-6 The two inert candidates, and why they are still worth stating

`landed` (D1) and `n`/`total`/`headline` (D2) are **never read** by the driver

contradict the payload's own 28 records leaves exit 0. These are not laundering
channels — the driver simply does not trust the self-report, which is the right
design — but the brief asked, and the honest verdict is *inert, not closed*: a
reader who trusts the payload's headline is reading a field no code validates.
The live IND does publish `landed: 24` beside `unlanded: []` and `checks`/`rows`/`results`.

## VERDICT INPUT

**For the integrator — this slice's answer to "is there a fourth channel": yes,
three, and the C1 seat's fix as it stands today does not close any of them.**
The committed-file lock is real and defeats r38 R1-D1, but it is a lock on *which
rows* may leave the join, not on *what they may carry* (X1-1), not on *what tree
corroborates them* (X1-2), and the census it recomputes already contradicts two
of the four rows' scope-out claim (X1-3). The cheapest closures, in the order I
would take them:

- reject a scoped record carrying a non-null value in any `IND_VALUE_KEYS` field
  (or join it) — one predicate, closes X1-1;
- pin the probe `target` in the committed scope file (or derive it from the
  committed `census_rule`), so the recomputation runs against a nominated tree —
  closes X1-2;
- pass `live` into `check_scope_probes` and require that no blind-plausible rule
  reproduces the live value — closes X1-3 and is the only one of the three that
  makes the scope-out itself evidence;
- treat an absent status as not-landed rather than landed, and read `state` when
  `status` is absent — closes X1-4;
- either implement the falsifier sweep or delete locks 3 from both docstrings —
  closes X1-5.

X1-4 is the one I would flag hardest for the depth axis: it is the same
read-first/absence-tolerant shape as F-3, it sits in the same function family,
and unlike X1-1/X1-2 it needs no fabricated artifact at all — a builder that
merely omits a field it is not required to emit reads landed.
