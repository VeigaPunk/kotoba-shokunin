# Seat E2 | edge-guard — adversarial edges of the C2 fix (round 40)

**Question:** does the C2 fix (V3's copy-variant + path-confinement residuals) close the
*edge* shapes — a `--repo` at a subdirectory, a `--script` resolving to a real instrument
that is **not** the row's, and a relative `--script` with `..`?
**Answer:** **as scoped, no.** The two residuals named in the claim are real, but they are
the *symptoms* of one property: the guard classifies overrides by **path spelling**, not by
**what the target is**. Four edge shapes stay silent-green, one of them is a new HIGH that
neither V3 nor R1 named.

## 1. Method and why it is trustworthy

44 arms (`.ufo/round-40/drafts/e2/arms.py`), each in a **hermetic world**: the guard under
test is a byte copy, and every row's instrument is a **distinct stub** whose printed count
encodes which row it is (`harness` prints 1010, `surfaces` 1087, …). A green reading
therefore proves *which binary ran*, not merely that some stub printed a number — this is
what caught the symlink arm below. No live instrument is executed by any arm; nothing is
written outside the world directories under `drafts/e2/work/`.

```
$ python3 .ufo/round-40/drafts/e2/arms.py --guard .ufo/round-40/drafts/e2/frozen/guard-HEAD-1c32b43.py --tag HEAD-1c32b43-FINAL
44 arms · 25 GREEN · 18 exit2 · 1 exit1      (out/ARMS-HEAD-1c32b43-FINAL.{txt,json})
```

## 2. E2-b — `--script` resolving to a real instrument, but a different one

**The canonical-path repoint is closed; every other spelling of the same attack is open.**

| arm | shape | verdict |
|---|---|---|
| A3/A4 | another row's canonical path (relative / absolute) | **exit 2** `override repoint` ✔ |
| A4b | reverse direction | **exit 2** `override repoint` ✔ |
| A5 | **byte copy**, *relative* argv | **exit 0 GREEN** ✘ |
| A6/A31 | **byte copy**, absolute argv | **exit 0 GREEN** ✘ |
| A7 | byte copy at the world root | **exit 0 GREEN** ✘ |
| A8 | byte copy **outside `--repo`** | **exit 0 GREEN** ✘ |
| A9/A32 | copy with a one-line tweak | **exit 0 GREEN** ✘ |
| A10 | **symlink**, *relative* argv | **exit 2** `override repoint` ✔ |
| A11 | **symlink**, *absolute* argv | **exit 0 GREEN** ✘ |
| A12 | **hardlink**, absolute argv | **exit 0 GREEN** ✘ |

A5 vs A10 is the whole finding in one line: **the same target, reached as a copy and as a
symlink, is classified differently** — and the symlink is only caught because a *relative*
argv is `.resolve()`d while an *absolute* one is kept raw (`:344`). The predicate compares
`path == canonical[other]` (`:291`), i.e. it compares **path strings**, so it can only ever
see a target that was named by its canonical spelling. V3 filed this as "copy-variant
silent-green, documented in the trust boundary". I dispute the *documented* part, not the
*measured* part: the docstring's claim is "an override **aimed AT another pinned
instrument's canonical path** … fails loudly" — literally true, and useless, since the
attacker's cheapest move is to not use the canonical path. The registry comment's "a probe
may point a row at a stub or a temporary copy" is a deliberate affordance; it is precisely
that affordance that makes a **copy** of another instrument indistinguishable from a stub.

Measured proof that the wrong instrument really ran (A31, the sharpest form):

```
$ # world: harness row's canonical is a stub printing 1010; a byte copy of the
$ # surfaces stub (1087) is named verifiers/copy-of-surfaces.py
PASS harness observed=1087 floor=10      <- the surfaces stub ran under the harness row
```

## 3. NEW HIGH — a row whose *declared* path is a symlink to another instrument

This is a **tree shape, not an argv shape**: no `--script` is passed at all, so neither
`override_drift` nor any argv normalisation is even reached. The row path in
`INSTRUMENTS` / `floors-registry.json` is `verifiers/verify_surfaces.py`; make that path a
symlink to `verifiers/verify_harness_claims.py` and the guard **reruns the harness
instrument while printing the surfaces row's line**.

```
$ python3 .ufo/round-40/drafts/e2/symlink-row-probe.py --guard <frozen> --tag HEAD-1c32b43
-- S1: linked count 987 >= floor 87 (silent)
   rc=0
   PASS surfaces observed=987 floor=87        <- the harness stub's count, under the surfaces row
-- S2: linked count 7 < floor 87 (misattributed)
   rc=1
   FAIL harness observed=7 floor=10           <- same binary, two rows
   FAIL surfaces observed=7 floor=87          <- the surfaces instrument never ran
```

Two distinct harms: **S1 is silent green** (the row's real instrument never executes and
nothing is printed that a reader could tell apart from a normal PASS — the count 987 is
simply above the floor), and **S2 misattributes** the shortfall to a row that never ran.
This defeats the guard's core claim ("this guard reruns every self-test") for the price of
one `ln -s`, with **no argv involved**. My arm A24 shows the guard's own battery does not
notice either (`PASS surfaces observed=1010`).

Live incidence: **zero** — all 8 live row paths are regular files, no duplicates, no `..`.
A fix must therefore not redden the live tree; §5 shows it does not.

## 4. E2-c — relative `--script` with `..`

| arm | shape | verdict |

| A14 | `verifiers/../verifiers/<other>` — lands on another canonical | **exit 2** `override repoint` ✔ |
| A16 | `../w1/verifiers/<other>` — escapes then re-enters | **exit 2** `override repoint` ✔ |
| A17/A18 | `./` and `//` normalisation, another canonical | **exit 2** `override repoint` ✔ |
| A15 | `../<outside-file>` — escapes `--repo` | **exit 0 GREEN** ✘ |
| A16b | escapes then re-enters, own canonical | exit 0 GREEN ✔ (correct) |

So `..` **is** normalised on the relative branch and the in-repo forms are classified
correctly — the `..` shape is *not* an independent hole. The only green is A15, which is
the confinement residual (an out-of-repo target) reached by a relative spelling rather than
an absolute one. **Answer to the seat question: relative-`..`-that-stays-in-repo is
already handled; the escape is the same confinement hole as V3's.**

## 5. E2-a — `--repo` at a subdirectory of the repo

| arm | shape | verdict |
|---|---|---|
| A19 | `<lane>/verifiers` (no registry there) | exit 2 `absent` ✔ |
| A23b/A23c | `<lane>/verifiers`, `<lane>/corpus` | exit 2 `absent` ✔ |
| A21 | one level up from a world | exit 2 `absent` ✔ |
| A23 | `/tmp` | exit 2 `absent` ✔ |
| A37 | the monorepo root (`shokunin/`) | exit 2 `absent` ✔ |
| A20 | a subdir that **itself carries a registry** | **exit 0 GREEN** |
| A22 | `--repo` spelled with `..`, resolving to a full world | **exit 0 GREEN** |

**The registry, not the repo, is the trust root.** The guard never asks "is `--repo` the
repo?" — it asks "does `<repo>/verifiers/floors-registry.json` parse and agree with the
in-file tables?". So `--repo` at a subdirectory is fail-closed *only* because a subdirectory
has no registry; give it one and the guard happily validates an entirely different world.
That is arguably the intended design (the guard is hermetic and fixture-testable), and it is
what makes the F1–F20 fixtures possible — but the docstring at `:33-34` ("each declared path
must resolve to a non-empty file **under `--repo`**") reads as a confinement guarantee it
does not provide. **Verdict for E2-a: `--repo` at a subdirectory is in-bounds and correct by
design; the docstring wording is the defect.** Note this is the *same* property that makes
A8/A15 (confinement) unenforced — the guard trusts whatever world you hand it.

## 6. What a closure must do — and the fix-shape matrix

Six candidate shapes were patched onto the frozen guard (`.ufo/round-40/drafts/e2/variants.py`,
count-checked anchors, scratch copies only) and re-run through all 44 arms:

```
$ python3 .ufo/round-40/drafts/e2/variants.py --guard <frozen> --tag HEAD-1c32b43
                     base        resolve     resolve+dig  full        full+nosym
A5  copy, relative   GREEN       GREEN       exit2 dig    exit2 dig   exit2 dig
A6  copy, absolute   GREEN       GREEN       exit2 dig    exit2 dig   exit2 dig
A8  copy out-of-repo GREEN       GREEN       exit2 dig    exit2 conf  exit2 conf
A9  tweaked copy     GREEN       GREEN       GREEN        GREEN       GREEN     <- residual
A11 symlink, absolute GREEN      exit2 rep   exit2 rep    exit2 rep   exit2 rep
A12 hardlink         GREEN       GREEN       exit2 same   exit2 same  exit2 same
A15 `..` escape      GREEN       GREEN       exit2 dig    exit2 conf  exit2 conf
A24/A30 symlinked row GREEN      GREEN       GREEN        GREEN       exit2 sym
A25b both-declared .. GREEN      GREEN       GREEN        exit2 conf  exit2 conf
A29 out-of-repo file exit1       exit1       exit1        exit2 conf  exit2 conf
A33-A36 own-target   GREEN       GREEN       GREEN        GREEN       GREEN     <- affordance holds
```

`full` = resolve + `samefile` + **content digest** + confinement; `full+nosym` adds "a
declared row path must not be a symlink". Findings for the integrator:

1. **`resolve` alone is nearly worthless** (A5/A6/A8/A12/A31 unchanged). V3's diagnosis
   ("absolute argv kept raw") is correct but insufficient — canonicalising fixes only the
   *symlink* spelling (A11).
2. **Content digest is the load-bearing predicate** for E2-b: it is what closes the byte
   copies (A5/A6/A7/A8/A31) that `samefile` cannot see. `samefile` alone closes only the
   hardlink (A12).
3. **Confinement is load-bearing for a different arm** — A8/A15 (out-of-repo target) and
   A25b (both guard tables *and* the registry declare a `..` path, so no string comparison
   can see it; the guard then reads a file outside `--repo` and passes).
4. **The symlink row path (A24/A30) needs its own clause** — no argv predicate can reach a
   tree shape. This is the one arm the claimed C2 scope misses entirely.
5. **A32 (tweaked copy) survives every shape I built.** It is not byte-identical, so
   `samefile` and digest both miss it; only a positive content allow-list (e.g. "the row's
   path must be the file whose digest the registry pins") closes it, and that trades away
   the documented stub-copy affordance. **I recommend declaring this residual explicitly**
   rather than silently leaving it — it is the honest boundary of any digest-based closure.
6. The documented affordance survives all shapes: A33–A36 (copies/links of the row's **own**
   target) stay green, and A12b (a rogue summary-printing file) is the guard's declared
   trust boundary (self-test output is trusted), unchanged by any candidate.

## 7. Verdict for my slice

- **E2-b — NOT CLOSED by the claimed scope.** The claim names "an absolute-argv
  symlink/hardlink/copy override aimed at another row's target". Measured: *only the
  symlink-with-absolute-argv* spelling is reachable by argv canonicalisation; the **copies**
  (A5/A6/A7/A8/A31) and the **hardlink** (A12) need identity-by-content, not identity-by-path.
  A closure that only resolves paths will land green and leave A5/A6/A8/A12 green too.
- **E2-c — `..` in-repo is already correct** (A13/A14/A16/A17/A18); only the escape form
  (A15) is open, and that is confinement, not traversal.
- **E2-a — `--repo` at a subdirectory is in-bounds and correct by design**; the docstring's
  "under `--repo`" phrase overstates what the guard enforces, and that same gap is what A8/A15
  exploit.
- **NEW HIGH (mine, not in V3/R1): the symlinked row path.** Silent green with zero argv
  involvement; S1/S2 reproduced on frozen bytes; the guard's own battery does not see it.
  I recommend the claim's after-text name it, or it is declared in the trust boundary with
  the reason — but a declaration here is weaker than for V3's residuals, because this shape
  needs no operator intent (a stray `ln -s` in the tree is enough).
- **No live incidence** for any of the three (8/8 row paths regular files, no duplicate
  digests, no `..`), so all of this is latent, and both candidate closures are no-harm on
  the live tree (8/8 EXACT exit 0).

## 8. My own defects (disclosed, not smoothed)

1. **Run 1 of the matrix was invalid**: my toggle anchor `"INSTRUMENTS = {"` also matched
   inside `"EXPECTED_INSTRUMENTS = {"`, so every patched variant died with a `NameError`.
   The capture was pruned with the rest of the scratch; the control arm (A1 green) is what
   exposed it, and the defect is reproducible by reverting the anchor to the bare string.
   Fixed by anchoring on the line start, with a count assertion.
2. **Run 2 of the matrix was invalid**: my appended predicate block landed *after* the
   `if __name__ == "__main__":` dispatch, so `e2_extras` was undefined at call time. Fixed by
   inserting before the entry anchor; the corrected matrix is `MATRIX-HEAD-1c32b43.json`.
3. **My first `resolve` variant was a wrong fix**, not a measurement: I replaced the shipped
   line with `path = path.resolve()`, which dropped the `repo /` join for relative argv, so
   every relative-argv arm (including the clean-world control A1/A2b) read red. That is what
   produced the misleading "A1 red under confine" row in run 2 — it was my bug, not a
   property of confinement. The corrected patch keeps both branches and A1/A13 stay green.
4. **The w3/w6 worlds were off by one level** on the first run (`../outside-surfaces.py`
   from a world whose parent is another world), so A25b read exit 2 `path absent` instead of
   the green it now shows; regenerated.
5. `A29` (an existing non-instrument file outside the lane repo) is exit 1
   `summary=missing` on the baseline, not a named classification — that is the guard
   correctly refusing to parse a shell script's output, and I record it as an observation,
   not a defect. It is *not* the same as A8/A15 (which are silent green).
6. `--self-test` on a bare scratch copy reddens 6/109 for a `DEFAULT_REPO` artifact; I
   disclose that my first parity run used exactly that and was discarded in favour of the
   revworld harness (`out/SELFTEST-REVWORLD-HEAD-1c32b43.txt`).
7. **The w6 world's mutation was not count-checked** (my own idiom violation, caught on
   self-audit): `"verifiers/verify_surfaces.py"` occurs **twice** in the guard — the
   INSTRUMENTS row *and* the F2 fixture literal at `:494` — so my `str.replace` silently
   rewrote both. A25b's reading was not affected in direction (the extra edit sits inside a
   self-test fixture string and no arm runs `--self-test` on w6), but the world was not the
   clean single-edit I described. Rebuilt with an exact-row anchor and a count assertion;
   **all 44 arms re-measured and every matrix row reproduced identically**
   (`MATRIX-HEAD-1c32b43.json` regenerated).
