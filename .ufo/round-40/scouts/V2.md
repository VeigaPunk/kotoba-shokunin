## 1. Method

**Battery:** `.ufo/round-40/drafts/v2/f3-battery.py` — **56 arms defined; 51 run
in `--joined-only` mode** (the 5 arms whose subject is a scoped row are skipped
there and measured in the untrimmed run), each a mutation of the REAL captured
IND payload (`.ufo/round-40/drafts/v2/ind-r40.json`, 28 results / 28 rows / 28
checks, exit 0), driven through the comparator as a real CLI run with **both
sides byte-pinned** (`--live-json` / `--independent-json`):

```
python3 f3-battery.py --comparator <driver.py> --base ind-r40.json \
  --live-json live-r40.json --live-vals live-vals.json \
  --scope-file <scope.json> --cwd REPO --expect head|landed --joined-only
```

Every arm prints its exit code, the verdict line, and the class line; the runner
compares against a pre-registered expectation table (at-HEAD exit + landed
requirement) and exits 1 on any mismatch.

**Two measurement modes, and why.** The scoped rows' blind probe is *recomputed
live* from the session tree, which grows — a captured payload's probe observables
age within minutes and late runs then fail with `false blocker` for a reason
unrelated to the arm. That contaminated my first late run (disclosed in §6).
`--joined-only` trims the payload and the live side to the 24 joined ids and
drops the scope channel entirely, so those arms are stable across time; the
untrimmed run is kept for the arms whose subject *is* the scope machinery.

**Expectation classes.** `"2"` = must exit 2 class-named (claim counting);
`"0"` = control, must stay 0; `"nonzero"` = must fail closed, code free;
`None` = report-only hunt arm (observed behaviour is the evidence).

5. **Duplicate ids inside one channel** (A7/A8/A25): fail closed; first-vs-last
