## 6. MY OWN DEFECTS (disclosed, not smoothed)

1. **The snapshot script's `cd` was wrong on first run** — `../../..` from
   `.ufo/round-40/drafts/m1` lands in `.ufo/`, not the repo root, so it created
   a stray `.ufo/.ufo/round-40/drafts/m1/` tree and completed in 0.15s doing

   The 47s re-run is the one I report. Nothing was written outside the lane
   repo at any point.
2. **`f2f3-probes.py` m2 first read exit 2 for the wrong reason.** My harvest
   blanked every record including the four scoped-out ones, tripping the r39
   lock: `independent: scoped_out names omp.catalogue.found but its status is
   'DERIVED', not 'SCOPED_OUT'`. That is my probe's bug, not a driver property.
   Fixed to skip scoped-out rows; **both runs kept**. This is the same hazard
   R1 filed as its own F-10.4 (a probe that fails for an unrelated reason
   reading as a "closed" signal).
3. **`c2-residual-probes.py` b2b–b2d first invoked the LIVE guard** (`GUARD`)
   against a foreign repo, so the exit 2 came from a table/registry mismatch
   (10 `row vanish`/`extra row` lines), not from enforcement. Corrected to run
   the *foreign* world's own guard script. **Both runs kept** — and the wrong
   run is instructive: it shows a foreign repo with a *differently-shaped*
   anchor fails loudly, which is why the decisive arm needs the foreign world's
   own self-consistent guard.
4. **`c3-indent-probes.py` cmark parser was wrong** — it tested for `b</p>` and
   reported "in code" for every shape including the control. Fixed to read
   `"<p>b</p>" not in stdout`; the corrected run is the one quoted in §5.3.
5. **`c3-gate-arm.py` v1 used the wrong shape** — a 3-backtick pseudo-closer
   under a 4-backtick opener, which r39's length clause already rejects. All
   four shapes read identically, i.e. the probe could not discriminate. Rewritten
   to V4's same-length vector; the discriminating run is the one quoted.
6. **The first e2e arm exited 2 for an unrelated reason** — a bare tempdir is
   not a git repo, and the gates need one. Then exit 3 for a missing baseline.
   Fixed with `git init` + a seeded baseline; only then did the arm reach the
   `exit 0 unindexed=0` state the claim is about.

None of these changed a conclusion; four of them produced a *false* reading
