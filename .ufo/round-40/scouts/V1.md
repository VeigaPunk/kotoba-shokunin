## 1. Method

**Battery:** `.ufo/round-40/drafts/v1/attack-battery.py` — 28 attack arms + 4
legitimate controls. Each arm is a full payload built from the live IND capture with
exactly one mutation, written to `variants-<label>/<arm>.json`, and driven through
the comparator as a real CLI run with **both sides byte-pinned**:

```
python3 verifiers/compare_harness_independent.py \
  --live-json .ufo/round-40/drafts/v1/live-capture.json \
  --independent-json .ufo/round-40/drafts/v1/variants-<label>/<arm>.json --json
```

Expected verdicts are declared per arm: attacks must fail closed **exit 2**
class-named; controls (`F*`) must stay exit 0. A control turning red is a regression
in the driver *or* in my control — both are reported, never smoothed (§7).

**Residual probe:** `.ufo/round-40/drafts/v1/residual-probe.py` — imports the
comparator as a module and calls `parse_independent` / `_record_list` directly on
synthetic shapes, answering "does any residual path still accept the never-emitted
keys" at function level rather than through a payload.

**Captures:** `.ufo/round-40/drafts/v1/{ind,live}-capture.json` from the live
instruments at each run (re-captured per run — see §6, the scope probe is
time-varying). Frozen byte copies of every measured comparator instant are under
`.ufo/round-40/drafts/v1/frozen/` (`cmp-<sha16>.py`).

## 7. My own defects (disclosed, not smoothed)

1. **Controls rewritten on one channel only.** The first version of `F2`/`F3`/`F4`
   rewrote `results` and left `rows`/`checks` stale, so the cross-check candidate
   rightly rejected them (3/4 controls red at `b268a5eb`). The control was wrong,
   not the driver. Fixed to rewrite all three channels consistently.
2. **Controls published the live observed value as the derivation.** Even with all
   channels rewritten, writing `live_observed` into `re_derived` creates an
   intra-record disagreement on the 4 adjudicated rows (`[]` vs `0`), turning all
   controls red. Fixed to publish the instrument's own honest derivation.
3. **Inverted guard in my cross-check candidate.** `map_channel = … if not channels
   else None` skipped the `checks`-map reconciliation exactly when a list channel
   was present — so `C2` stayed open at my own candidate. Caught by running the
   candidate against the battery, fixed; that is how `C2` got closed at `d6acabfe`.
4. **Frozen captures have a short shelf life — I measured a false red because of
   it.** At `2daeee7a` all 4 controls went red with `false blocker: … declares
   observable … but recomputation gives …`. Cause: the scoped-row census probe is
   recomputed live and the substrate moved — `session_files` **763 → 764** (a new
   session file appeared on the host). The comparison prints only truncated
   observables, so the mismatch is invisible in the error line; I found it by
   diffing `declared` vs `recomputed_probe()` field by field. Re-capturing fixed it
   (`2daeee7a-fresh` = 13/28, controls 4/4). **Every battery run must re-capture
   both payloads first** — the arm files are built from them. This is fail-safe
   behaviour in the driver (a frozen payload whose probe no longer recomputes must
   not pass) but it makes frozen-input batteries time-sensitive; a reader re-running
   my arms should re-capture or expect the probe class, not a channel class.
5. **`E2` is filed as an attack but reads exit 1**, not the declared exit 2. It is a
   nested map with one divergent value: the driver names the disagreement but
   through the protocol column, not the class-named rejection. Reported as `OTHER`
   rather than counted closed.
