# Seat A1 — adjudication: which channel is authoritative when they disagree (round 40)

**Seat:** A1 `adjudicate-laundering`. **Question given to me:** *if the F-2/F-3 fix
needs a ruling on which channel is authoritative (`results` vs `rows` vs `checks`),
write the adjudication — which channel the comparator should trust when they
disagree and why, citing the instrument's own emission contract.*

**Ruling (one line).** **No channel is authoritative over another, because the
instrument never emits a disagreement between them.** `results`, `rows` and
`checks` are three *projections of one derivation*, built from a single row list
in one expression. A disagreement between them is therefore not a semantic
question to be adjudicated — it is **positive evidence that the bytes are not
this instrument's output**. The comparator must **reject, exit 2, class-named
`channel divergence`**, naming both channels and the check id. It must not read
the first channel and ignore the rest (today's `_record_list`), and it must not
pick a winner.

This ruling is substrate-backed, not a preference: it follows from the emission
contract at `verifiers/verify_harness_independent.py:1346-1356`, and it is
*implementable and measured* — I built a reference implementation and ran the
before/after battery (below).

## 1. The emission contract (the citation the ruling rests on)

`verifiers/verify_harness_independent.py:1341-1356` (frozen `872993f8`):

```python
    # `results` is the join shape the round's agreement driver
    # (verifiers/compare_harness_independent.py, seat P4) reads; `checks` is the
    # flat name -> value map.  Both carry this instrument's own numbers only.
    table = {"results": [{"check": r["check"], "re_derived": r["value"],
                          "value": r["value"], "status": r["status"], ...}
                         for r in rows],
             "checks": {r["check"]: r["value"] for r in rows},
             "rows": rows, ...}
```

Three facts, each measured, and together they settle the question:

1. **One derivation, three projections.** All three channels are built from the
   same local `rows` list in a single dict literal. `results` copies
   `r["value"]` into both `re_derived` and `value`; `checks` maps the same
   `r["value"]`; `rows` *is* the list. The instrument therefore **cannot**
   produce a cross-channel disagreement — not "should not", *cannot*: there is
   no code path that writes one channel without the others.
2. **Live confirmation.** Over the frozen capture: 28 records in each channel,
   **0 value divergences, 0 status divergences, 0 id-set divergences**
   (`drafts/a1/measure-channels.txt`). `results` carries
   `{check, re_derived, value, status, probe}`; `rows` carries
   `{check, evidence, value, status, probe}`; `checks` is `{id: value}`.
3. **The vocabulary is disjoint from the live side's.** `expected`,
   `expected_value` and `observed` are **never emitted by IND** — `grep -c
   '"expected"' verifiers/verify_harness_independent.py` → **0**, and
   `'"observed"'` appears only inside the `--observed` *comparison* reader, never
   in the emitted table. Those keys are the **live** instrument's vocabulary:
   `verify_harness_claims.py:659` emits
   `{"observed": …, "results": [{"check", …, "observed", "expected", "verdict",
   "mode"}]}` and nothing else.

**Corollary 1 (the authority rule).** `results`, `rows`, `checks` are peers: any
two of them that disagree prove the payload is not the instrument's output.
There is no "primary" channel to trust, and no tie to break. The comparator's
job is to *verify the projection identity*, and to fail closed when it breaks.

**Corollary 2 (the vocabulary rule).** A value key the instrument does not emit
is not "another channel to reconcile" — it is **foreign input**. Accepting a
harvested reading through `expected`/`expected_value` is not a priority-order
question (today's `IND_VALUE_KEYS` ranks `expected` *first*, `:119`); it is a
contract violation, because the independent column is defined as the
*re-derived* reading. The live-side vocabulary must be rejected by name.

**Corollary 3 (what the live side gets).** The live contract names exactly one
record list, `results` (`verify_harness_claims.py:659`; the driver's own
`parse_live` requires `observed` per record, `:294-311`). A live payload
publishing a sibling `rows`/`checks` list is likewise outside its contract, and
today's read-first hole reaches the live side too (§4, arm `LIVE-rows-shadow`).

## 2. Why "trust `results`" and "trust `rows`" are both wrong

The tempting rulings, and why each fails on the evidence:

- **"Trust `results` (the declared join shape)."** `results` *is* named as the
  join shape in the instrument's comment — but that names where the driver
  *reads*, not what it may *ignore*. Under this rule arm `F3-checks-shadow`
  (divergence hidden in `checks`) stays silent-green, and so does `F3-rows-shadow`
  if the reader prefers `rows` for another reason. R1's F-3 and V1's A7 are
  exactly this shape.
- **"Trust `rows` (the full records with evidence)."** Symmetric failure, and
  worse: `rows` is the *least* constrained channel (free-text `evidence`), so a
  builder that wants to hide a divergence in the channel the driver reads would
  choose `rows`. My arm `COPY-rows-only` shows the whole payload can be
  published through `rows` alone and is accepted today.
- **"Reconcile, but only lists."** Insufficient: `checks` is a **map**, not a
  list, so list-only reconciliation (my `patched-recon-only`) leaves
  `checks-shadow` at exit 0. Measured, §5.
- **"Prefer the derived vocabulary, ignore the rest."** Insufficient: it closes
  `expected` but leaves every divergence shape open (my `patched-vocab-only`
  closes `expected-launder` only). Measured, §5.

So the claim's own "**Either** drop `expected`/`expected_value` **or** cross-check
the value channels" is **false as written**: the two locks are *independent
necessities*, not alternatives. Dropping the vocabulary does not close F-3;
reconciling channels does not close F-2. The matrix in §5 shows it arm by arm.

## 3. The ruling, stated for the landing seat

**R1 (authority).** When any two published record-list channels of the
independent payload disagree on any check id (value, or status, or id set), the
comparator exits **2** with a `channel divergence` message naming **both
channels and the id**. No channel is preferred; the disagreement itself is the
failure. Same rule for the `checks` map against the list channels.

**R2 (vocabulary).** A record whose value is carried by `expected`,
`expected_value` or `observed` is exit **2**, named `harvested-vocabulary value
key(s)`. The independent value vocabulary is exactly the instrument's own:
`re_derived` | `value`. The nested-map fallbacks `expected` / `re_derived` /
`observations` (`:279`) go too: only `checks` is an emitted map key.

**R3 (intra-record).** Two legal value keys inside one record that disagree
(`re_derived: 7` beside `value: 999`) is exit **2**, same class. The instrument
writes them from one variable, so they cannot differ.

**R4 (live side).** The live payload's contract is `results` (+ top-level
`observed`); a sibling `rows`/`checks` list is exit **2**, named as outside the
live contract. (This closes the live-side instance of the same hole that my
`LIVE-rows-shadow` arm demonstrates.)

**R5 (duplicate ids).** Two records with the same check id in one channel is
exit **2**. Today the driver silently keeps the last (`out[cid] = …` overwrite,
`:272`), so a duplicate-id payload can shadow a divergent first record — R1's
`B3-duplicate-id-first-dropped` reads exit 0 at `bb8dcecd` (§7). This is the
same class as R1: an id appearing twice in a channel the instrument cannot
produce twice (its `rows` is a list of unique checks).

**R5b (the read rule *inside* reconciliation — a design axis, measured).** The
reconciliation's own value-read rule decides whether it can see the F-2 shape at
all. R1's `expected-launder` fixture carries the harvest in `expected` **and** the
true reading in the sibling channels: under a reconciler whose read rule is
today's `IND_VALUE_KEYS` order (`expected` first), all channels "agree" on the
harvest and the arm stays green; under a read rule that prefers the instrument's
own vocabulary (`re_derived`|`value`) the divergence is visible and the arm
fails closed. Measured (§5b-ii). **So R1's reconciliation and R2's vocabulary
lock are not independent after all: the read rule must be the derived vocabulary
for the reconciliation to be sound.** A landing seat that splices in a
reconciler without also fixing the read order will pass F-3 and still miss F-2.

**R6 (the residue — explicitly NOT claimed).** A **consistent** copy — every
channel and every legal key carrying the harvested value, no foreign key
anywhere — is **not detectable by any read-time rule**, and my reference
implementation still reads it exit 0 (arm
`RESIDUE-consistent-copy-no-foreign-keys`). The driver's job is to check the
*payload's internal consistency*; it cannot check *provenance* from bytes that
are internally consistent. That hole is closed only by the freeze/provenance
mechanism (the round-37 protocol's §6 freeze-before-compare receipt, which r39
already exercised), and I say so plainly rather than implying R1-R5 close it.
**The after-text of C1 must not be read as "independence is now proven" — it is
not, and no read-time rule can prove it.**
