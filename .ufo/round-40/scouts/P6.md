Every world is a *modified copy* of the guard under test: the two in-file tables and
the registry are the world's, while the predicate / override / join machinery is
byte-identical to the guard under test (the tables are inserted immediately before the
`if __name__` guard, shadowing the originals). No world is a copy of the repo; no
symlink points at the live tree; nothing is written outside `drafts/p6/`.

**Design decisions that matter for the numbers.**

- *Counts are equalized at `max(floors)`* in the headline/extended/rel matrices, and the
  stub prints **all three summary shapes** at that count. So a cell that the guard does
  not name reads a fully satisfied row — the maximally favorable shape for the override,
  and the only one that isolates the residual from the floors guard's ordinary job.
- *`real` mode* is the honest attacker constraint: the copy is the source instrument's
  own file, so it prints the source's own count in the source's own format. Since the
  floors are EXACT at the pinned state, a cell is green iff `source_count >= target_floor`.
- The classifier distinguishes `silent-green` (rc=0, row PASSes, zero FAIL lines),
  `named-exit2` (rc=2 with a named FAIL), `loud-unnamed` (row FAILs, no named line), and
  `other`. Only the first is evidence about the residual.

## 5. THE REMEDY QUESTION — the claim's stated fix is insufficient (new finding)

Claim C2(a) prescribes: *"the override must resolve+canonicalize so a copy pointing at a
different row's instrument fails class-named"*. I built that remedy and measured it.

`remedy-probe.py` inserts a redefinition of `override_drift()` immediately before the
entry anchor of the frozen bytes (shadowing the original), then runs the headline copy
matrix against it:

| variant | cells | silent-green | named-exit2 |
|---|---|---|---|
| **frozen** (as-is) | 24 | 24 | 0 |
| **resolve-only** (the claim's stated remedy) | 24 | **16** | 8 |
| **content-hash** (resolve + byte-identity) | 24 | **0** | 24 |

**`resolve+canonicalize` is not sufficient, and cannot be.** A byte copy is a *different
inode at a different path*; `Path.resolve()` is documented not to resolve a copy to its
original — there is no filesystem link to follow. So the resolve-only remedy names only
the 8 `symlink` cells (where `resolve()` genuinely reaches the canonical path) and leaves
all 8 `copy` and all 8 `hardlink` cells silent-green. Hardlinks are a special case worth
naming: they share an inode, so `os.path.samefile`/`st_ino` **would** catch them, but
`resolve()` alone does not, and a byte copy evades both.

The sufficient predicate is **content identity**: compare the SHA-256 of the override
target against each canonical instrument's SHA-256. A copy, a hardlink and a symlink all
carry the canonical bytes; a legitimate stub does not.

### 5a. The content-hash remedy does not harm the documented affordances

The trust boundary says `--script NAME=PATH` "stays an explicit operator override by
design -- a probe may point a row at a stub or a temporary copy". So a remedy is only
admissible if it keeps those uses. `afford-probe.py`, 8 arms x 2 variants:

```
frozen        L1 copy of OWN instrument         allowed  OK
frozen        L2 fresh stub in-world            allowed  OK
frozen        L3 fresh stub OUTSIDE --repo      allowed  OK
frozen        L4 row's own canonical path       allowed  OK
frozen        L5 in-repo .. path                allowed  OK
frozen        R1 copy of OTHER row's instrument allowed  **HARM** (the residual)
frozen        R2 symlink to OTHER row's instruc allowed  **HARM** (the residual)
frozen        R3 non-file path                  rejected OK
content-hash  L1..L5                            allowed  OK (all five)
content-hash  R1 copy of OTHER row's instrument rejected OK
content-hash  R2 symlink to OTHER row's instruc rejected OK
content-hash  R3 non-file path                  rejected OK
arms=16 ok=14 harm=2   (the 2 harms are the frozen variant's residual)
```

**The content-hash remedy closes the residual on 24/24 cells and keeps all five
documented affordances green.** That is the one-command discriminator P3's landing should
be graded against — "resolve+canonicalize" alone would leave 16 of the 24 headline cells
open, so a landing that implements only the claim's literal wording will **not** satisfy
the claim's own "after" clause.

**Caveat on the claim's escape hatch.** The claim allows arm (a) to instead be "formally
declared inside the trust boundary with the reason recorded". That is admissible per the
claim text — but the declaration must name the shape that is actually open (a copy of
another row's instrument is accepted as that row's evidence), not the narrower
"an override aimed AT another pinned instrument's canonical path" the docstring already
carries, which is true of the path string only. §5 is offered to P3 and to the integrator
as the measurement that decision should be made against.

**The disposition space, with its measured cost.** No content-inspection predicate can
close arm (a) while keeping both documented affordances, because the attacker can always
make the bytes unique (B) while printing the same summary:

| option | closes arm (a)? | cost |
|---|---|---|
| S1 leave open, **declare** in the trust boundary | no (by choice) | the docstring must name the real shape |
| S2 `resolve+canonicalize` (the claim's literal wording) | **no — 16/24 cells survive** | none, and no benefit |
| S3 content identity (SHA-256) | against unchanged copies only — **evaded by +1 byte** | none, but it is a speed bump |
| S4 declared-only (override must be the row's own canonical path) | **yes** | loses the fresh-stub and temp-copy affordances |

So the claim's own escape hatch is not a soft option — for arm (a) it is the **only
sound** disposition short of S4's affordance loss or a declaration channel that does not
exist yet. What must change either way is the docstring's claim: "an override aimed AT
another pinned instrument's canonical path … fails loudly" is true of the path string
only, and the open shape is broader (a copy *of* the file, at any path, in any link
form).
