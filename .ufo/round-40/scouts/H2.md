## 3. THE TWO BYPASS PATHS (the answer to "does any path bypass it")

### Bypass 1 — the payload that is not a record list at all (independently found by A2 HIGH and P5; see §6 for attribution)

`parse_independent`'s dotted-map fallback (`:278-285`) accepts a payload that
carries **no record list whatsoever**. Because `parse_scoped_out` returns `{}`
for such a payload (`:392-394`: `raw = payload.get("scoped_out")` → `None`), and
`check_scope_probes` iterates only `scoped_out` (`:584`, `:593`), **the entire
r39 scope-out lock is never entered**:

```
$ python3 verifiers/compare_harness_independent.py \
    --live-json .ufo/round-40/drafts/h2/har-live.json \
    --independent-json .ufo/round-40/drafts/h2/payloads2/P-flat-dotted-map-28-harvested.json
agreement: 28/28 (mode-aware protocol headline; 28 live checks, 0 scoped out ...)
exit 0
```

The payload is `{harvested_id: harvested_value, ...}` for all 28 ids — a dict of
the harness's own `observed` values. **The 4 committed scope-out rows re-enter
the join with harvested values, the numerator grows from 24 to 28, and no
scope-out is declared or checked.** The receipt records it plainly:

```
join: {headline_column: mode-aware protocol, n: 28, joined_scope: 28,
       live_checks: 28, joined_rows: 28, n_scoped_out: 0}
scope_locks.committed_set: ['omp.catalogue.found', 'omp.catalogue.matched',
                            'omp.catalogue.missing_names', 'omp.catalogue.total']
scope_locks.probe_kind: None
join.scoped_out: {}
```

`scope_locks.committed_set` shows the committed set was read; `probe_kind: None`
and `n_scoped_out: 0` show **not one of the three locks was applied to anything**.
The same shape as a bare JSON **list** (BQ) also reads **28/28 exit 0**, and
there `scoped_out` cannot even be expressed.

The control that proves this is a bypass and not a mis-aimed arm: the *honest*
IND payload's own `results` list, fed as a bare list (BR), exits 2 —
`channel split: record omp.catalogue.found carries status SCOPED_OUT but the
payload's scoped_out map omits it`. The lock fires when the records are
present; it is skipped when they are not.

**The committed set is enforced as an upper bound only.** `committed` is
consulted at exactly two places, both inside `check_scope_probes`: `if cid not
in committed` → laundering (`:594-597`), and the same guard before the probe
check (`:599-600`). `committed - declared` is **never computed anywhere in the
driver** (verified by reading every `committed` occurrence at `bb8dcecd`:
lines 58, 60, 62, 66, 75, 430, 433, 556-597, 611, 940, 969, 1312, 1359-1364,
1495-1505, 1659-1672, 1718, 1751-1752 — and by instrumenting the module
in-process: `check_scope_probes({}, {}, committed, contract, {})` returns
`True`). So a payload may *shrink* the declared set to zero and the join simply
widens.

### Bypass 2 — the docstring's own rule is not implemented (mine; no sibling names it)

The module docstring (`:60-63`) states:

> The payload's own declaration must match the committed set **exactly**: a row
> declared scoped out that the file does not list is exit 2 (the laundering
> shape), and **a committed row the payload no longer declares is exit 2 (an
> undeclared deletion)**.

The second clause is not implemented. `check_scope_probes`'s own docstring
(`:575-579`) records the reversal: *"Deliberately NOT a failure: a committed row
the payload now derives … Failing it would punish a builder for succeeding."*
P1's r39 DEFECTS section confirms it was dropped in-round ("an over-strict
'undeclared deletion' rule that failed the legitimate no-scope-out tree").
**The module docstring was not updated with it** — so the file's advertised
contract and its behavior disagree, and the disagreement is exactly on the
bypass path.

Measured (arm AJ / AJ2), the fully-consistent form:

```
$ python3 ... --independent-json .ufo/round-40/drafts/h2/payloads6/AJ2-reentry-fully-consistent-all-channels.json
agreement: 28/28 ... 0 scoped out by the independent instrument
exit 0
```

Every one of the 4 committed rows is declared `DERIVED` with the harvested value
in `results.value`, `results.re_derived`, `rows.value` and `checks[id]` — all
four channels mutually consistent, no `scoped_out` key, no probe. **A
cross-channel reconciliation would not catch this** (the channels agree); only
a committed-set completeness check would. AJ3 (same shape, one value wrong)
exits 1 — so the re-entered row *is* joined and checked, it is just no longer
bounded by the committed set.

`--expect-n 28` does not help: it is satisfied exactly (28 live checks), and
`--expect-n 0` also leaves both shapes green (measured).

### The asymmetry that isolates the mechanism

The identical flat map on the **live** side is refused: `--live-json` with a
flat dotted map exits 2 (`live: payload is not a results list`) — `parse_live`
has no fallback (`:294-298`). The permissive fallback exists **only** on the
independent side, i.e. only on the side whose values are the ones under test.
That asymmetry is the whole of bypass 1.

## 4. WHAT P2 MUST RECONCILE

Concretely, at `bb8dcecd`, in the order I would land them:

1. **`_record_list` must return *all* record lists, not the first.** Currently
   `for key in ("results","rows","checks"): if isinstance(payload.get(key), list):
   return payload[key]`. All three are published by IND and all three are
   present in every live capture. Requiring them to agree (or failing named on
   divergence) closes arms B/C/D/S/AF.
2. **The value-key priority must be reconciled within a record**, or
   `expected`/`expected_value` must be dropped. This is R1's F-2 (HIGH) and it
   is *the same defect one level down*: `IND_VALUE_KEYS` (`:119`) picks one key
   per record, first match, and the live IND emits `re_derived`+`value` while
   never emitting `expected`. Arms M/AC/AD.
3. **The dotted-map fallback (`:278-285`) must not bypass the scope-out locks.**
   Either the fallback must be removed for payloads that carry no `scoped_out`
   declaration while the committed set is non-empty, or the committed set must
   be enforced as a **set equality** (both directions) rather than a one-way
   membership test. Bypass 1 + 2 die together on this one change.
4. **The status/probe twins must agree with their record-level fields**
   (`unlanded` list vs `status`; `landed` count vs the statuses; top-level
   `scoped_out_probes` vs per-record `probe`). Arms K/Z/BC/I.
5. **The live side's `observed` map should be checked against
   `results[].observed`**, or dropped as a channel. Arms U/W.

**Feasibility is measured, not assumed:** on the honest live payload every one
of these reconciliations is already satisfied — 0 channel disagreements across
`re_derived`/`value`/`rows.value`/`checks[id]`; 0 `results`-vs-`rows` status
disagreements; the top-level probe map is byte-identical to the per-record
probes for all 4 scoped rows; `committed - declared` is empty. **So a
cross-channel reconciliation rule cannot break the live comparator** — the live
join must stay 24/24 exit 0, and I re-confirmed it does:

```
$ python3 verifiers/compare_harness_independent.py --no-stamp

secondary (independent expected vs live expected): 20/24
verdict: exit 0 — all checks agree, both instruments green
```

**Two traps for the builder, both measured:**

- The live side has **no** `rows`/`checks` channel and its records legitimately

  `parse_live` would be wrong — the reconciliation belongs on the independent
  side, or must be side-aware.
- **`expected` is load-bearing on the live side**: the secondary join

  requires `observed` at `:304`); dropping it from the live parser would break
  the secondary join. The two parsers share the constant but not the semantics.
- Arm AM shows the secondary join **saturates under the F-2 launder**: with
  `expected` = harvested values it reads `secondary_agree: 28/28` against the
  honest payload's `20/28`. A second column that is meant to be an
  adjudication aid currently rises to a perfect score under exactly the shape
  the round is closing — worth a floor or a note when F-2 is fixed.
  **Attribution:** B1 filed this first (`B1.md:66,77`, arm `F2b-full`, same
  20/24 → 28/28 reading and the same `:1690-1696` mechanism, with an open
  question about whether the landed closure holds it at ≤20/24). My AM was run
