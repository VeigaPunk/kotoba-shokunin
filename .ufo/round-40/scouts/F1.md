Each `case.json` carries its own `expect` contract: `exit`, `named` (substrings
that must appear — the failing check id, so a closure cannot pass by rejecting
everything for an unrelated reason), `text` (the headline), `failure_named`
(the driver must say it failed, not exit non-zero via an unexplained traceback),
and `absent` (substrings that must NOT appear — `Traceback` and the class lines
the arm is not about).

Payloads are **synthetic on purpose**: every arm is driven through the driver's
`--live-json` / `--independent-json` entry points, so no host substrate (the
session tree, the omp binary, the skill db) is read and the arm cannot drift
when the host moves. Each arm differs from the control in exactly one channel.

**Wiring — `verifiers/compare_harness_independent.py`** (`bb8dcecd…` →
`727ec6760e0b07b3…`, +71 lines, one hunk): `FIXTURE_DIR`, a `fixture_battery(check)`
function, and one `fixture_battery(check)` call at the end of `self_test()`. The
battery globs `FIXTURE_DIR.iterdir()` for `case.json`, asserts the arm set is
exactly the four names, then drives each arm as a subprocess and applies its
`expect` contract.

## 6. My own defects (disclosed, not smoothed)

1. **Wrong path in the generator.** `mk-fixtures.py` first used
   `parents[3]`, which resolved to `.ufo/`, and wrote a whole stray
   `verifiers/fixtures/…` tree under `.ufo/`. Caught by the follow-up `find`
   (the expected path did not exist), removed with `rm -rf .ufo/verifiers`, and
   fixed to `parents[4]`. The generator now has a `--check` mode; the landed
   bytes verify at `0 drift(s)`.
2. **Invalid byte-invariance run.** My first live-vs-HEAD diff compared the
   frozen copy run *without* `--cwd`; the copy derived REPO from its own
   location and died on a missing instrument, so the "diff" showed an error line
   rather than invariance. Re-run correctly with `--cwd "$PWD"`; the discarded
   output is kept at `out/live-HEAD.stdout` history only in that first form and
   was overwritten — **the invariance claim rests on the second run only.**
3. **A disclosed interaction I introduced.** The battery resolves
   `FIXTURE_DIR` relative to `__file__`, so a comparator copy **without** the
   fixtures tree beside it now reports an extra failure
   (`fixtures: battery dir present: …`). Measured:

   ```
   $ python3 <copy>/verifiers/compare_harness_independent.py --self-test
   self-test: 2 failure(s) over 98 assertions
     FAILED: receipt: the committed scope file's digest is recorded
     FAILED: fixtures: battery dir present: <copy>/verifiers/fixtures/…
   ```

   This is **not** a regression in the guard's own self-test (green at 109) and
   not a regression on the live tree, but it does change the behaviour of the
   guard's `--script NAME=PATH` override when pointed at a fixtures-less copy
   (observed=98 vs the old 97). Whether to make the battery tolerate a missing
   directory — versus treating "the battery is absent" as a genuine failure of
   the anti-shrink contract — is a **judgement call for the integrator**, and I
   have deliberately left it failing closed. It is the one place my change
   alters a path a sibling seat (C2/V3's `--script` vector) owns.
4. **Scope honesty.** The `expected-launder` arm's derived keys carry
   `"NOT DERIVED"` while the sibling list channels carry the true value `"x"`.
   A closure that reconciles the three channels against **each other** but never
   compares foreign vs derived keys *within* a record will leave this arm green
   — that is by construction (the arm isolates the F-2 channel), but it means
   this arm alone does not prove the F-2 class closed; it must be read together
   with the record-local check. Measured: d2's v4 (record-local, no channel
   reconciliation) passes this arm but fails both F-3 arms; T1's (both) passes
   all four.

Nothing was committed; no git state was mutated; no installs; writes confined to
`kotoba-shokunin/` (the `verifiers/` fixtures + the three floor carriers +
`.ufo/round-40/`).
