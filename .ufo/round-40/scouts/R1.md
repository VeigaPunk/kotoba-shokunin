### F-3 (HIGH, **mine**, NEW) — the scope file is enforced against the *process cwd* but attested against `--cwd`

This is a third door, and it is the sharpest one: it lets a builder make a genuine
disagreement leave the join **while the receipt attests the honest file**.

`load_scope_file(args.scope_file)` (`:1661`) does `Path(path).read_text()` — a
**relative path resolved against the process cwd**. `render_receipt` (`:943`) resolves
the *same* `--scope-file` against `Path(args.cwd)`. The two agree only when the process
happens to be started in the repo.

```
$ python3 .ufo/round-40/drafts/r1/cwd-door.py      # planted dir carries a superset scope file
### A) from the planted dir ###
  exit 0 | all checks agree, both instruments green
  n_scoped_out 5  total 23   (honest repo set has 4 rows)
### B) the receipt it wrote ###
  receipt scope_file.path : verifiers/harness-independent-scope.json
  receipt scope_file.sha  : fbcdc8d247475a5f   == honest repo file: True
  receipt committed_set   : [... 5 rows including omp.offered.skills ...]
  honest set 4 rows; recorded set 5 rows
### C) control: same payload, driver run FROM the repo ###
  exit 2 | laundering: the payload scopes out omp.offered.skills, which the committed scope file does not list
```

The receipt's own two fields **cannot both describe one file**: its digest
(`fbcdc8d2…`, the repo's honest file) and its `committed_set` (5 rows, the planted one)
are inconsistent. The enforced file's sha is `0e9a3e9b75f126fb` — which appears
nowhere in the receipt. The receipt does not record the process cwd at all, so nothing
in the artifact can expose the divergence.

**Why this matters more than the raw exit 0.** C1's after-text names the freeze receipt
as the recording clause. A receipt that attests a file the run never enforced is
strictly worse than no receipt: it is a *false* record of what was enforced, and it is
exactly the shape the protocol's "record, don't smooth" rule exists to forbid. The
committed-set lock is real — but only when the driver is invoked from the repo root.
§6 of the corpus doc does `cd /home/vgpnk/Projects/shokunin/kotoba-shokunin` first, so
the documented path is safe; any other invocation is not.
