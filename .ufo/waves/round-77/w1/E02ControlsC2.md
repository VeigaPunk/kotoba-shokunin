## 2. How the worlds were built and scored

Every world is its own `git clone --shared` of the lane at the round-77 freeze commit
`6523aced1ee0ebe07dca996213bdc645a6acbd1e` (the item's pinned base for scratch clones). Per clone:
`user.name scratch-r77` / `user.email scratch@example.invalid` were set **before** any commit, the
toplevel was asserted equal to the clone dir before the first commit, and every git call names `-C`.
Scoring command form (one per world, own exit status captured, no pipeline):

```
python3 -B /home/vgpnk/Projects/shokunin/kotoba-shokunin/verifiers/check_r75_routed_repairs.py \
  --repo <scratch clone> --rev <scratch commit> --work <scratch work dir>
```

The receipt records each world's clone path, commit, full command, full stdout+stderr, and the
counter's own `exit=` line. Scratch commits in the receipt are ephemeral (the clones were removed);
rerunning the driver rebuilds the same content with new SHAs. The r75/r76 commit names and the gate
transcripts are stable.

The counter re-runs both corpus gates in its own sandbox clone at the revision the R2 receipt names.
The driver reproduced exactly that protocol (clone --shared, checkout, `--repo <clone> --json`,
`str(clone)` → `<repo>` normalization) to author the fixture transcripts, and observed:
