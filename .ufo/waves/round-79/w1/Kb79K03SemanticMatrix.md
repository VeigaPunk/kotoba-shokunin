## Cross-cutting patterns actionable for authors

1. **Write the interoperable representation as a scalar string, and describe it as advisory/experimental rather than a portable sandbox.** Open spec + Microsoft explicitly require a space-separated/delimited scalar; Claude documents the same scalar as a pre-approval grant. Factory accepts a YAML-list illustration but says it is display/review metadata and does not sandbox/add tools. Evidence: spec value/effect; Claude value/effect; Factory value/effect; Microsoft value/effect. This is not a claim that every client parses identically.
2. **Do not infer a universal permission boundary from this key.** Claude states a per-turn permission grant; Factory explicitly says its field does not add tools or sandbox; Microsoft describes pre-approval but also has a separate default approval middleware; the spec marks the field experimental; pi calls it experimental; Vibe gives an example without semantics. These statements are materially divergent, not reducible to one shared meaning.
3. **Separate loader tolerance from permission semantics.** Microsoft and Claude say unknown fields are ignored in specified contexts, while Microsoft rejects malformed recognized field shapes; pi warns for most invalid fields; none of those statements establishes how each runtime treats an unknown tool name. Author guidance: keep the key/value shape conservative, and test client-specific acceptance/approval rather than extrapolating from loader behavior.
4. **Trust is an independent control plane in the opened evidence.** Microsoft tool approval, Pi project trust, Vibe folder trust, and Claude managed settings/plugin trust are described, but only Claude explicitly ties `allowed-tools` to a skill turn permission grant. Avoid claiming those trust mechanisms either replace or reinforce that field absent a source statement.

## Disagreement / contradiction

Within these six pages, the sharpest divergence is semantic: Claude's per-turn permission grant conflicts with Factory's explicit “does not add tools or sandbox” metadata description for the same-named field. The format itself also diverges: Vibe's README example uses a YAML list, whereas the open specification and Microsoft specify a space-delimited/string form, and Claude documents a string. These are client-page divergences; neither should be smoothed into a universal behavior.

A separate same-vendor contradiction is already held in `corpus/knowledge/chinese-vendor-skill-surfaces-round73.md`: CodeBuddy IDE presents `name`/`description` as required while its CLI table marks them optional; Kimi Chinese and GitHub pages disagree on key vocabulary and roots. That entry's `allowed-tools` sweep records CodeBuddy as the lone documented allowlist among those four vendors; it is an adjacent divergence, not evidence for the six requested surfaces.
