## Counter-contract mismatch

`plans/round-81.md` § C1 / E6 says `LINE_CAP = 140`. The published `Kb81E05Erratum.patch` instead changes it to `900` and documents the larger post-measurement allowance. Every counter receipt above prints `cap 900`; the current scored tree reports `402 added / 29 deleted` lines. Under the frozen 140 bound the measured added count exceeds the limit by 262 (arithmetic from the counter's own reported count and guard formula; no separate 140-cap run was performed). Therefore the `6 of 6` readings above apply only to the out-of-contract published counter. Restore the frozen cap; do not narrow the plan after data. If the reviewed instruments cannot fit the declared budget, stop honestly rather than widen it.

## Smallest safe correction

1. Restore E6's exact `LINE_CAP=140`. Shrink only after a new reviewed design/measurement authorized by the plan; otherwise C1 stops, with no after-value.
2. Make the external-commit authority non-self-authenticating: require a frozen/reviewed allowlist binding the exact 40-hex hash, repository, receipt path and receipt digest, and parse the receipt's exact repo/ref/hash association. A committed manifest plus a digest supplied by that same mutable tree is not independent proof. E01 must reject a receipt without the hash; both witnesses must use the same binding rule.
3. Use one strict first-resolved report route in both gates (lane before fleet; an invalid lane object must not be rescued by a fleet object). Marker plus size is spoofable: bind report identity to independently reviewed content identity, rather than accepting any blob that can be padded to contain `## SHONEN`.
