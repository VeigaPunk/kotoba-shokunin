## Findings by severity

**F1 — defect, fix before land (E01): malformed-manifest crash class.**
`external_binding` guards `json.loads(...)["commits"]` with `except (ValueError, KeyError, TypeError)`,
but the `claims` set comprehension then iterates `entries` OUTSIDE that try. Measured (clean serial run):
manifest `{"commits": 5}` → `TypeError: 'int' object is not iterable` traceback, rc=1; `{"commits": null}`
→ `'NoneType' object is not iterable`. E02 handles the same five shapes (`commits: 5`, `null`, truncated,
top-level list, `{}`) fail-closed with zero tracebacks. Failure direction is safe — the tip battery counts
the exit-1 traceback as not-green, so no false `6 of 6` path exists — but the gate's contract routes
environment problems to exit 2 and content problems to counted classes; a traceback is neither. One-line
fix inside the try: `entries = json.loads(...)["commits"]; if not isinstance(entries, list): return False`.

**F2 — defect, fix before land (E01): binding does not require the hash in the receipt (diverges from E02 and from the plan sentence).**
E01's binding requires only `repository.encode() in proof`; E02 requires `sha in text and name.lower() in text`.
The plan's R2 wording is "the committed fetch/ls-remote receipt that proves the repo→hash association".
Measured (P5): a committed manifest row binding `ffff…(40f)` to `acme/widget` through a receipt whose
bytes name the repository but NEVER the hash (digest pin correct) → E01 classifies the fabricated token
`commit_external` (integrity unresolvable stays 2 at commit_total 47) while E02 keeps it
`commit_unresolvable` (3 / external 0). Two consequences: an adversarial manifest can launder an absent
hash through E01 with a hash-free receipt, and the two witnesses DISAGREE on that input — which is
exactly the disagreement the independent-gate design exists to surface. One-line fix: add
`hex_id.encode() in proof` to E01's return conjunction.

**F3 — consistency divergence, no live token today (E01 vs E02): `<rev>:<path>` where the lane object is a symlink blob.**
Probe (P7a): cite `HEAD:.ufo/reports/round-76/kotoba.md` where the lane tracks the round-76 symlink
(43 B link-text blob) and the fleet holds the real 8128 B report. E01: ALIVE — its object arm is
`any(report_content_ok(blob) for repo in [lane, fleet])`, so the fleet object's real content saves it.
E02: DEAD — `report_target` reads the LANE blob first and stops (`route="object"`), and 43 B of link
text carries no identity. No live corpus token has this shape (the only `HEAD:` token, round-77, does
not resolve in the lane, so both gates fall through to the fleet object and agree alive). Not narrowing;
must be aligned (E02 hopping to fleet on lane-identity failure, or E01 stopping at lane) before any
lesson cites a lane-symlinked report by revision.

binding) work; zero live narrowing; the r80 killing classes stay red under it. Fix F1 and F2 first — each
is one line — then re-cut the E6 pin to the new post-image blob (E15 §2.5's coupling: the pin hex is a
