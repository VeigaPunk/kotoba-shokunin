## 0. Harness notes (for the reader reproducing this)

- The clone is `git clone --shared` of the lane and is named **`kotoba-shokunin`** on purpose: the checklist's
  `trigger.name_directory` check compares the frontmatter `name` with the directory name, so a clone named `lane`
  fails it spuriously (observed: `FAIL name 'kotoba-shokunin' != directory 'lane'`).
- `verify_skill_checklist.py` resolves `../…` citation tokens against the clone's parent, so the parent was populated
  with symlinks to the fleet's `.ufo`, `*-shokunin` (only `kasegi-shokunin` is cited by `LOG.md`), `PROTOCOL.md`,
  `AXES.md`, `CORPUS.md`, `MISSION.md`, `SCORECARD.md`. With that shim the clone reproduces the lane's own numbers
  exactly at `4de12b6` (checked: same 11 pass, same subject counts).
- Exit codes: several of these counters break when stdout is redirected to a file in this environment; they were run
  through a pipe and `PIPESTATUS[0]`/direct invocation was read. The lane's own base-battery receipt shows the
  masking this produces — see §4.
- Nothing under `/tmp` is cited as evidence; all numbers below were reproduced in the clone or the lane itself.
