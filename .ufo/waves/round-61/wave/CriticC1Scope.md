## 1. Boundary answer: the alternatives are not opposites

**C1 is a measured successor to r60 by construction. The defensible reading is that it can be a legitimate, explicitly bounded successor—not that it is something other than a successor.** The r60 closure gates that successor on an actual redesign; it does not require the redesign and successor to occupy different numbered rounds.

The controlling local evidence is unusually direct:

- `corpus/lessons/round-60-verifier-spotcheck.md:79-83,134-139` requires the provenance-authenticating redesign, including semantic key/action arms rejecting the `sessions` class, **before any measured successor**. It does not say “no measured successor in round 61.”
- `plans/round-61.md:9-16,21-59` expressly takes that routed item as motivation, declares a redesigned v3 and freezes its arms, worlds, live-row conjunct and kill rule before implementation. This is an announced successor, not inherently an undisclosed re-score.
- However, `corpus/lessons/round-60-verifier-spotcheck.md:58-83` already closes r60 as exploratory `unprovable-but-better`, with depth held at 9. That historical ruling cannot be upgraded by later v3 results.

**Stronger interpretation:** conditional legitimacy as a new, bounded claim about the verifiability/discrimination of held scoped-rule knowledge. A categorical objection that “a successor is forbidden because redesign is required” reverses the closure's stated precondition. Conversely, “v3 exists, therefore the precondition is satisfied” is not a sound defense. The actual delivered discriminator and receipts decide that question; a version label does not.

## 2. Strongest case for legitimate depth

1. **Depth need not mean a previously unknown filename or another client.** The definition is verifiable technical detail and actionable decisions (`/home/vgpnk/Projects/kimi-shokunin/skills/shokunin/protocol/AXES.md:9-16`). Tightening the distinction between a genuine matching-path key and a prose colon, and between a documented loading action and an invented action, is directly about the correctness of this lane's scoped-rule authoring advice.
2. **The requested redesign is a real missing assurance, not an arbitrary additional metric.** The r60 counter admitted wrong keys and inadequately supported actions (`.ufo/waves/round-60/build/ExecKeyForms.md:66-149,151-192,194-241`). Preserving valid advice while rejecting those concrete false variants can deepen the evidentiary support for the existing technical decisions. This is strongest when the new entry/skill wording exposes those distinctions to the reader, not merely the existence of more Python assertions.
3. **Same-round design and implementation are not inherently circular.** A frozen specification can be implemented, attacked, frozen by digest, controlled, and then measured. `plans/round-61.md:55-59` proposes a final digest and controls before the live data measurement. Those promised steps must actually occur, and the chronology issue below remains separate.
4. **The A4 limitation was declared in advance.** `plans/round-61.md:34-39` limits the arm to internal consistency of committed bytes and disclaims wall-clock authentication against author-forged dates. Reporting exactly that bounded property is more honest than claiming an impossible proof of fresh acquisition. It is not permission to omit W1 rejection or any other frozen conjunct.
5. **One depth claim can contain the counter, reconstructed worlds, fixtures and explanatory entry.** These are components of the same claimed improvement, not independent depth achievements. Their existence must not be counted again as new client coverage, runtime capability, or repeated outside verification.

This defense does **not** depend on pretending r60 lacked the four scope-key decisions. It depends on a genuinely stronger, source-grounded means of distinguishing valid advice from the recorded counterexamples.
