## Finding 1 (KILL): the Q70 first-heading-block rule hard-fails the honest Microsoft Agent Framework row on the real snapshot

Mechanical, reproduced against the committed bytes.

Facts (receipt `Kb80C02C2-sweep.txt`, counter's own `text_view`/`quote_location` imported from the draft):

- The counter's text view for `.html` strips `script`/`style` and all tags, then `quote_location` treats any remaining line starting with `#` as a heading and bans quotes at `idx <= first_head + 1` (draft lines 885–897).
- The real `S229-msaf.html` text view has 1550 lines; its **sole** `allowed-tools` occurrence (confirmed by the pinned fetch record: "Contains exactly one occurrence of 'allowed-tools'") sits at **line 95**; the first line starting with `#` is at **line 168** — which is a YAML comment inside a code sample (`# Auto-approve load_skill and read_skill_resource, but not run_skill_script.`), one of 23 such `#` comment lines, none a heading. The page's real `<h1>` ("Agent Skills") is tag-stripped into an unmarked plain line.
- Any located quote for msaf must contain `allowed-tools` (conjunct d), must be 5–25 words, and is searched in `" ".join(lines)`, so its match starts at or before line 95. Since `95 <= 168 + 1`, `quote_location` returns `(False, "quote lies in the first-heading block (Q70)")` for **every** findable quote. Kill proof (`Kb80C02C2-killproof.txt`), exact text-view substrings:

  ```
  quote_location('allowed-tools No Space-delimited list of pre-approved tools the skill may use.')       -> ok=False why='quote lies in the first-heading block (Q70)'
  quote_location('allowed-tools No Space-delimited list of pre-approved tools the skill may use. Experimental') -> ok=False why='quote lies in the first-heading block (Q70)'
  ```

- The other five snapshots are unaffected (first `#` line is a real title at index 0–3, the field occurrences sit far later — sweep table in `Kb80C02C2-sweep.txt`).

Consequence: with the frozen predicate `exit 0 iff N == 6` (plan § C2 measured part), the honest round-80 world — real snapshots, honest entry — reads `allowed-tools surfaces documented 5 of 6`, exit 1. The plan's own kill rule fires: "any world making the exit predicate lie … is a counter defect and stops C2." The exit predicate as drafted lies about S229: it claims the quote is in a banner/first-heading block when the quote is in the page's field-definition table and the "heading" is a code comment.

Secondary defect in the same rule, opposite direction (`Kb80C02C2-evidence.txt` D1b): for an HTML page whose text view has **no** literal `#` lines, both the banner-line check and the first-heading-block check are structurally vacuous — a synthetic HTML whose only quote occurrence sits inside `<h1>Agent skills allowed-tools overview for practitioners</h1>` returns `ok=True`. So for HTML snapshots the Q70 conjunct can neither pass the honest row (S229) nor fail a banner row (generic). The rule is broken in both directions on exactly the one HTML surface.

**Smallest safe correction (pre-freeze, declare like E5):** in the counter's HTML branch, derive heading/banner lines from the `<h1>`–`<h6>` tag contents (synthesize `# `-prefixed markers before tag stripping; skip `<pre>`/`<code>` regions so YAML comments never become headings), and keep the Markdown branch as-is. This one amendment fixes both directions. Porting landmines to fix in the same pass: the draft's exit is `ok = n >= TARGET and m < TARGET and …` with `TARGET = 5` and a self-test margin doctrine ("a single broken surface is inside the declared margin", draft lines ~1680, 2284) — the round-80 predicate must be exactly `N == 6` with no margin, else the msaf failure exits 0 and the defect is hidden; and the `m < TARGET` conjunct must become print-only, because the plan states the claim "does not rest on beating" the generator (a generator reaching 6 is a reported counter defect, not an auto-fail). Also rebind `BASE_REV` from the r79 base `b10bcbc6…` to `398cbe1…`, and align the snapshot filename pins with the real files (`S226-spec.md`, not `S226-spec.html` as the draft's FIX table says; `S229-msaf.html`, not `.md`).
