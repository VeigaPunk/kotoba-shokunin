## Headline

omp's **loader imposes almost no frontmatter rules**. Name regex, 64/1024 caps, field allowlist and XML rules live in three *other* paths (agent-plugin validator, managed-skill writer, registry pack) that never run when an ordinary `SKILL.md` is discovered. **Angle brackets are validated nowhere** in the loader; the only `<`/`>` handling is a strip in the managed-skill writer and an XML escape in one render path (F6, F11). **Duplicate names are not rejected**: they are resolved — first-processed copy (provider priority) keeps the plain name, later copies are renamed `<namespace>/<name>` (F8) — except a skillshare-installed copy, which always loses the plain name, and a custom-directory copy, which always wins it.

## Findings (observed, with literal context)

F1. **Frontmatter parser** `packages/utils/src/frontmatter.ts` `parseFrontmatter(e, opts)` @147789099. Options `{location, source, fallback, normalize=true, level="warn", repair=true, rawKeys=false}`. YAML via `globalThis.Bun.YAML.parse`; keys kebab→camel (`disable-model-invocation` → `disableModelInvocation`) unless `rawKeys`; a non-map YAML document yields **empty** frontmatter (`if (typeof r !== "object" || Array.isArray(r)) return null;`); parse failure with `level: "fatal"` throws `FrontmatterError` ("Failed to parse YAML frontmatter"). Skill loaders call it with defaults (`tr(u, { source: S })`) — repair on, warnings only.

F2. **Runtime discovery rule** `packages/coding-agent/src/discovery/helpers.ts` `loadSkillsFromDir(dir, {dir, level, providerId, requireDescription=false, includeSelf, ...})` @154025204. Reads `<dir>/<child>/SKILL.md` (child a directory or symlink, name not starting with `.`), plus `<dir>/SKILL.md` when `includeSelf`. The only name rules: `const v = typeof k === "string" ? k.trim() || f : f;` (frontmatter name, else directory basename) and `if (/[\\/]/.test(v)) { r.push(\`Skill name "${v}" contains a path separator, skipping: ${S}\`); return; }`. No regex, no length cap, no lowercase rule, no match-with-directory rule. `enabled === false` skips. Description gate is truthiness only: `if (d && !p.description) return;` — a non-string truthy `description: 123` passes here and later renders as `""` (loaders coerce with `typeof ... === "string" ? ... : ""`).

F3. **Who requires a description** (`requireDescription: true`): native (`~/.omp/agent/skills` + `<walk-up>/.omp/skills`), managed-skills, github `.github/skills`, omp-plugins, `skills.customDirectories` entries (provider `custom`), and the exported `loadSkillsFromDir` (skillshare probe). **Not required** for `.claude/skills`, claude-plugins, `.agent`/`.agents`, `.codex/skills`, `~/.config/opencode` + `.opencode/skills`, and skillshare store copies (F10). Enablement defaults (`skills.*` settings @154002066): claude project true, claude user false, codex user false, agents user/project true, native user/project true; managed always on (`if (Ge === za) return true;` @158595308).

F3b. **Host state today (2026-10-22).** `~/.omp/agent/skills` and `~/.omp/skillshare` do **not** exist (round-7's `~/.omp/agent/skills/ufo/SKILL.md` is gone); live roots are `~/.agents/skills` (10 dirs: create-toolset, godspeed, omarchy, reverse-engineer-anything, shokunin, swarm, tower, ufo, unreal-mcp, unreal-skill), `~/.claude/skills` (3), `~/.codex/skills` (2) — i.e. the skills this session is offered come from providers where omp imposes **no** name/description rules at all.

F4. **Strict validator** `packages/coding-agent/src/discovery/agent-plugin-format.ts` `Ade(frontmatter, dirName)` @154919507 — used **only** by agent-plugin skills and `omp skill pack` (3 `Ade(` call sites in the binary). Field allowlist `var qY = { name: true, description: true, license: true, "allowed-tools": true, metadata: true, compatibility: true };` → any other key fails `unexpected frontmatter field "<key>"`. Name (`XY`): `missing required "name"`; `Array.from(R).length > 64` → `"name" exceeds 64 characters`; `R !== R.toLowerCase()` → `"name" must be lowercase`; leading/trailing `-`; `--`; then `var JY = /^[\p{L}\p{N}-]+$/u;` (Unicode letters allowed — `café` passes here); then `R !== p.normalize("NFKC")` → `"name" ... does not match directory ...`. Description: non-empty string, `T.length > 1024` → `"description" exceeds 1024 characters`. `compatibility` ≤500; `metadata` string map; `allowed-tools` string.

F5. **Loader vs validator conflict (live).** The loader honours `enabled`, `hide` and `disableModelInvocation` (`extensibility/skills.ts` @158598838: `hide: Ge.frontmatter?.hide === true || Ge.frontmatter?.disableModelInvocation === true`), but `Ade`'s allowlist has none of them — so those keys make a *plugin* skill invalid while remaining legal in every other root. Likewise the loader accepts `name:` ≠ directory name; `Ade` rejects it.

F6. **Managed-skill writer** `packages/coding-agent/src/autolearn/managed-skills.ts` @155025284: `var M$ = 64000;` `var A$ = /^[a-z0-9][a-z0-9-]{0,63}$/;` and `vj(name)` lowercases then tests it, else `Invalid skill name "<raw>". Use lowercase letters, digits, and hyphens (1-64 chars, starting with a letter or digit).` Description sanitizer `ob()`: `u.replace(/[\p{Cc}\p{Cf}]/gu, " ").replace(/[<>`]/g, "").replace(/~{2,}/g, "~").replace(/\s+/g, " ").trim();` — **the only place angle brackets are stripped**. Write path `Fpe` requires non-empty description and body and caps the whole file: `Managed skill is ${I} bytes; the limit is ${M$}. Trim the body or description.` (64000 bytes, UTF-8). Managed-skill creation refuses a name already held by an authored skill (`nO`, @161241498): `Cannot create managed skill "<name>": an authored skill of that name already exists, and managed skills cannot override authored ones. Choose a different name.`

F7. **Registry pack / wire limits.** `packages/coding-agent/src/skillshare/pack.ts` `D()` @165958476 throws `SKILL.md: <Ade message>`, then `registry names must be ASCII kebab-case (a-z, 0-9, single hyphens), at most ${TZ} characters; got ...` with `var Z0t = /^[a-z0-9]+(?:-[a-z0-9]+)*$/;` and `var TZ = 64;` (`packages/wire/src/skillshare.ts` @153998842), then `"description" exceeds ${up.descriptionLength} characters` with `var up = { tarballBytes: 5*1024*1024, unpackedBytes: 20*1024*1024, files: 1000, pathLength: 255, descriptionLength: 1024, keywords: 20, keywordLength: 50, deprecationLength: 500 };`, plus `metadata.version` semver required to publish. **No angle-bracket rule** in any of them.

F8. **Duplicate names are resolved, never rejected.** Two layers. (a) Capability merge (`discovery/…` `$e` @154006949): key is the name (`capability/skill.ts` @154915440 `key: (u) => u.name`), items arrive in provider-priority order, first wins; later same-key items get `_shadowed = true` and are dropped from `items` (kept in `all`). Current skill priorities in this binary: native 100, skillshare 95, omp-plugins 90, claude 80, agent-plugins 75, claude-plugins/agents/codex 70, opencode 55, github 30, managed 5. (b) `extensibility/skills.ts` `loadSkills` + `l0e` @158592408 run over `all` (shadowed copies included) and decide the id: identical body **and** deep-equal frontmatter duplicates are dropped silently (`dropped: re`); a skillshare copy never keeps the plain name (`name collision: installed "<name>" from <file> is overridden by <file>; available as "<ns>/<name>"`); a custom-directory copy always does; otherwise the later copy is renamed `<namespace>/<name>` (`~2`, `~3` … on further clashes) with `name collision: "<name>" from <file> differs from <file>; available as "<ns>/<name>"`. Namespace = plugin name, else the path segment before `skills` if it does not start with `.`, else the provider id (`O4` @158591965). Same-realpath duplicates are skipped (`ge.has(St)`). Skill URI resolution (`internal-urls/skill-protocol.ts` @158603478) matches `name` exactly, or `<host>/<first path segment>` for the namespaced form; unknown → `Unknown skill: <name>` + `Available: <list>`.

F9. **Render path caps the description, not the validator.** `extensibility/skill-descriptions.ts` @161581111 `var v = 100; var x = 160; var P = 12;` — `Bze(description)` = whitespace-collapse; ≤100 chars verbatim; else `slice(0, 99)`, first sentence if ≥40 chars, else last space + `U+2026`. LLM compressor validator `b()`: rejects empty, any `\r\n`, >160 chars, >12 words; model call uses `maxTokens: 1024, temperature: 0, disableReasoning, AbortSignal.timeout(30000)`; cache key `sha256(template \0 name \0 description)`; `wM.render` emits `cache.get(key) ?? Bze(description)`. The round-7 100-char cliff is unchanged in shape but re-anchored to `Bze`.

F10. **Skillshare store copies bypass description checks.** `discovery/skillshare.ts` `jne` @155141837 reads `SKILL.md`, honours only `enabled === false`, and takes `name: typeof oe === "string" && oe.trim() ? oe.trim() : B` (fallback: registry name) — no description requirement and no `Ade`.

F11. **Catalogue render: no escaping in the live system prompt.** `system-prompt.ts` @161658745 passes `skills: vt` with `vt = (t.skillDescriptions ?? new wM).render(he ? pe.filter((e) => e.hide !== true) : [])`, then `D = E(Tt, X)`, and `E` compiles templates with `{ noEscape: true, strict: false }` (@147757101) → `{{name}}`/`{{description}}` are inserted **raw** into the template `<skill name="{{name}}">{{description}}</skill>` inside `<skills>` (@252945817, replacing round-7's `- {{name}}: {{description}}` list). The legacy-pi catalogue (`Qt` @175478916, template `/$bunfs/root/legacy-pi-available-skills-*.md`) filters `!i.disableModelInvocation && !i.hide` and **does** XML-escape name/description/location via `Ps` (`&`, `<`, `>` → entities, @147862374).
