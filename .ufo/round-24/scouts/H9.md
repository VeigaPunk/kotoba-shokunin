## Findings

1. **The export reproduces F8's defect exactly, and the fix closes it — but only the
   self-test.** Pristine export self-test = `108/1504` rc 1 (cmd 5); patched export
   self-test = `0/1504` rc 0, **byte-identical to the live tree's** (cmds 9 vs 1). The
   causal control is a pair of `.git`-less exports differing only in the 2-hunk script
   fix and in nothing else (both named `kotoba-shokunin`, same content): 108 → 0.
   The assertion total is preserved at **1504** in both — no silent shrink (the P7 class).

2. **The corpus instruments cannot run export-side at all — by design, and not
   fixable by a flag.** Both exit **2** (the environment tier) with `not a git
   repository` (cmds 12/13), and `verify_corpus_integrity.py` still exits 2 under
   `--no-baseline`, because the git dependency is upstream of the baseline: it is
   `git ls-files` that enumerates the tracked corpus set
   (`verify_corpus_integrity.py:409-434`, `verify_corpus_independent.py:63-72`). A
   `git archive` export carries no index, so the corpus gates are structurally
   checkout-only. Their **self-tests** (pure model checks on fixtures) do run
   export-side and pass (88 / 52 assertions).

3. **`verify_harness_claims.py`, `verify_surfaces.py` and `check_substrate_pins.py`
   are fully export-portable and byte-invariant.** All three run live in the export
   at rc 0 with output **byte-identical** to the live tree's (28/28, 7/7, 3/3), and
   their self-tests pass with identical assertion totals (10 / 75 / 46). This is the
   strongest export-side evidence available: three of the seven gates reproduce the
   live verdict byte-for-byte with no `.git` and no fleet root.

4. **The remaining export gap is the fleet root, not `.git` — and it is a different
   defect from F8's.** In a plain export (`/tmp/<anything>/kotoba-shokunin`), the
   *patched* tree's live checklist run still fails 2 checks because 5 cited tokens
   point above the repo (`../PROTOCOL.md`, `../.ufo/l0-questions.md`,
   `../.ufo/reports/round-{7,9,11}/kotoba.md`); `--repo` does not help (cmd 11),
   because those paths simply are not in the export. Dropped into a full fleet-mirror
   layout, the **same bytes** go rc 0 with all 10 PASS, byte-identical to the live
   tree (cmd 18). So: `--self-test` is now genuinely layout-invariant (F8's claim,
   and only that claim); the *live* run is fleet-layout-invariant, i.e. it needs the
   sibling fleet present, which a `git archive` of this repo alone cannot supply.
   F8's finding 6 said exactly this and is confirmed here at full-gate scope.

5. **The `fault_injection_corpus.sh` harness is checkout-only too** (cmd 16): rc 2
   `env unreadable: not a git repo`, in both default and `--self-test` modes, because
   it clones the target (`file://$REPO`, `:76`) and runs the corpus instruments
   inside each clone. Its `--self-test` is green on the live tree (rc 0 `self-test: OK`).
   So the export can run **4 of 7 gates live** (checklist, harness-claims, surfaces,
   pins) and **6 of 7 self-tests** (all but the fault harness).

6. **Documentary errata are gate-inert, re-confirmed at export scope.** The
   docs-only copy (E errata, scripts pristine) passes all six gates rc 0 in the live
   tree (cmd 20), and the patched export's harness/surfaces/pins outputs are
   byte-identical to the *unpatched* live tree's (cmd 15) — the corrected counts are
   not read by any check, which is what claim E needs. The census patch specifically
   survives `verify_surfaces.py --inventory <patched census>` at 7/7.

7. **A caution for the H claim's wording.** The self-test green of cmd 9 holds for
   *any* directory name and *any* location once the 2-hunk fix is in (the fixture argv
   now pins `--repo DEFAULT_REPO` = the script's grandparent), so the honest claim is
   "the self-test is hermetic in a `.git`-less export", not "the checker is
   layout-invariant". The live run's portability is a separate property (finding 4).
