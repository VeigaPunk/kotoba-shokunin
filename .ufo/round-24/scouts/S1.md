## Findings

**F1 — the pre-state is fully green.** All six gates + the pins guard exit 0 live,
and all six self-tests are 0-failure. SKILL.md is 521 lines / 41 boxes
(15/9/9/8), sha `84257c62…`, worktree == HEAD. This is the E/H "before": any
correction must keep every one of these exits unchanged.

**F2 — the H defect is a single root cause, and it is `.git`-presence, not
fixture-absence.** The export carries every fixture file (174 = 174, #21), so
nothing is missing on disk. What is missing is a `.git` ancestor: with none,
`find_repo_root()` (`verify_skill_checklist.py:386-392`) falls back to the file's
own directory, so the fixture SKILL.md's "repo" becomes the fixture dir, and the
governance check then looks for `<fixture>/LOG.md` / `<fixture>/SCORECARD.md`
(absent) → 108 failures. Proof of the mechanism: adding an *empty* `git init .`
to the extract makes the same self-test `0/1504` exit 0 (#22) with zero content
change. So a fix that resolves fixtures relative to the script (per claims.json
H) is the right class; a "copy the missing files in" fix would be wrong — nothing
is missing.

**F3 — the E site list is wider than "seven counts".** The seven headline counts
(claims.json E items 1-4 plus SKILL.md `27/27` and SCORECARD `4 checks`) reproduce
as false at HEAD, but the sweep finds **companion sites in the same lines**: the
census rule-count error has a *second* occurrence at `:287` and a *third* inside
the round-22 byte-frozen window at `:337`; the harness `27` has a second site at
`harness-verifier-round10.md:186`; the round-12 `10/19` has three occurrences
(`:49/:73/:92`); the SHONEN anchor has two (`:7/:46`); the SKILL.md `27` has three
(`:109/:456/:461`); SCORECARD `4 checks` has two (`:30/:68`) plus the stale
`0/28` assertion count beside it; and `corpus/README.md:34` carries a 27 too.
Applying only the headline sites would leave the same falsified number standing
elsewhere — the "corrections sweep every mention" rule (PROTOCOL) is the risk to
name for the E lane.

**F4 — one E site is inside a hash-frozen window and cannot be edited in place.**
`census-round13.md:337` ("seven named rules") sits inside the round-22 byte-frozen
block (body sha `e046a025…`, census lines 332-422 per round-23 F3). Editing it
would break the pinned sha / contiguity gate. The correct handling is an addendum
*outside* the window (round-23 F3 F2 reached the same conclusion independently).
Flagging because the E lane's "minimal in-place erratum" phrasing does not fit
this one site.

**F5 — nothing on the E list is load-bearing for a gate.** Every corrected string
is prose in a doc; the live gates read `SKILL.md` (as the pinned target),
`LOG.md`/`SCORECARD.md` (governance citations), and `corpus/README.md`'s FILE
column. `SKILL.md:109/456/461` are prose, not the check ids; the `27/27` is not
re-derived by any check (the harness gate prints `28/28` regardless of what the
prose says). So the corrections are safe — but the E lane must still re-run all
seven instruments after landing (a governance-citation or corpus-pointer shift is
conceivable if a corrected line adds a token).

**F6 — the census's own sha is `a51d29ea…`.** `sha256sum
