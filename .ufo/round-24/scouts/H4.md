## Findings

**Root cause (independently re-derived).** The self-test drives each fixture
case through the public CLI via `run_capture` (i.e. `main(argv)`), supplying
only `--skill <fixture>/SKILL.md`, `--map <fixture>/map.json`, and optionally
`--vocabulary`. It never supplies `--repo`. In `main()` (`:1752-1753`) an
absent `--repo` resolves through `find_repo_root(skill_path)` (`:386-392`),
whose rule is *nearest ancestor carrying `.git`, else the file's directory*.
- Live tree / normal clone: `find_repo_root` walks up from the fixture dir to
  the real repo root (which has `.git`), so repo-rooted citations, commands,
  and the `LOG.md`/`SCORECARD.md` governance files all resolve → green.
- `.git`-less export: the walk finds no `.git` anywhere and returns the
  **fixture's own directory**, so every repo-rooted subject resolves against
  the fixture dir and fails. That is the 108.

Attribution of the 108 (from the pristine-export run): 79
`governance.citation_resolves` (`unreadable governance file(s): LOG.md …`),
29 `exit 0` case assertions, plus `trigger.citation_resolves` and
`trigger.command_binary_resolves` PASS-side assertions — exactly the cases
whose subjects are repo-rooted.

**Design C = explicit `--repo` threaded through the self-test only.** The fix
makes the self-test pass the repo it already knows by construction
(`DEFAULT_REPO = Path(__file__).resolve().parent.parent`, `:269`, correct in
any checkout because it is script-relative) rather than relying on the
`.git`-heuristic. Two hunks, **both inside `self_test()`**:

1. `:1341-1343` — the shared fixture runner `run()` gains
   `"--repo", str(DEFAULT_REPO)`.
2. `:1556` — the `foreign-no-map` targeted extra, which calls `run_capture`
   directly (bypassing `run()`), gains the same flag.

**Why hunk 2 is load-bearing (design independence).** Hunk 1 alone stalls at
`1 failure(s)` — the residual `foreign-no-map: exit 0: got 1`. Confirmed
mechanism: `foreign-no-map` builds argv with `--skill` only, so `--repo`
defaults to the fixture dir; the target then equals `<repo>/SKILL.md` and
`governance_enabled` flips true (`:1755`), running `check_governance_citations`
against the fixture dir where `LOG.md`/`SCORECARD.md` are absent → FAIL.
Adding `--repo <export root>` makes the target foreign again → governance N/A,
exit 0. This matches H10's "patch B" (hunk 1 only) reporting 1/1504; design C
adds hunk 2 to reach 0/1504. Direct probe on the pristine export:

```
cd export_pristine; python3 verifiers/verify_skill_checklist.py \
  --skill verifiers/fixtures/checklist/missing-map/SKILL.md
  -> FAIL governance.citation_resolves: … unreadable governance file(s): …/missing-map/LOG.md …
# same + --repo <export root>
  -> N/A governance.citation_resolves: evaluated 0 — governance files are checked only with the repo SKILL.md
```

**Live-behavior invariance.** Design C does not touch `find_repo_root`, `main`,
or any check. Byte-proof: the region outside `self_test()` (`:1-1328` and
`:1704-end`) is byte-identical between HEAD and patched. In the same-location
`.git`-less copy (C3), the full-gate stdout is **byte-identical** pristine vs
patched (both exit 1 there — an export is not a gate target), while the
self-test moves 108 → 0. On the live tree the self-test is byte-identical
(0/1504 both) and the live gate is unchanged at exit 0.

**Non-vacuity.** A fault-injected `clean` fixture (leading `---` removed) in
the patched export still flips: exit 1, 8 failures naming
`frontmatter_parses`/`name_directory`/`literal_trigger_string`/
`anti_trigger_clause`. The patch does not weaken red detection.

## Defects named

- `verifiers/verify_skill_checklist.py:1341-1343` — self-test fixture runner
  omits `--repo`, so fixture cases inherit the `.git`-heuristic repo root
  (defect F8). Evidence: pristine export, exit 1, 108/1504; patched export,
  exit 0, 0/1504.
- `verifiers/verify_skill_checklist.py:1556` — `foreign-no-map` targeted extra
  calls `run_capture` directly and also omits `--repo`; this is the residual
  1/1504 after the runner-only fix. Evidence: hunk-1-only run → `1 failure(s)`;
  `--repo` probe above (FAIL → N/A).
- `verifiers/verify_skill_checklist.py:386-392` (`find_repo_root`) — the
  cwd/`.git` heuristic itself is the shared surface; design C deliberately
  does **not** modify it (keeps the gate path byte-invariant). This is the
  same surface H2/H3/H5 patch directly, so designs differ at the seam:
  C changes the caller, not the helper.
- `verifiers/verify_skill_checklist.py:269` (`DEFAULT_REPO`) — the
  script-relative repo root that design C reuses as the correct value; no
  change needed, cited as the invariant the fix leans on.

## Limits (what I did NOT verify)

- **Fragment-dir clobbering.** The dispatched `/tmp/h24/H4/` and the sibling
  `H2/H3` dirs were deleted mid-run by concurrent scouts (the whole `/tmp/h24`
  was re-created several times). I rebuilt everything under an isolated
  `/tmp/h24-H4/` and re-ran the matrix once, cleanly; the numbers above are
  from that single run. Sibling designs H2/H3/H5 were not re-inspected beyond
  their fragments, so my "third independent design" claim rests on my own
  derivation, not on diffing their patches.
- **C6 is not a clean byte-invariance test.** Aiming the patched script at the
  live tree with `--skill <live>/SKILL.md` changes `DEFAULT_REPO` to the
  script's own dir, so the pinned-map path (`DEFAULT_REPO/verifiers/...`)
  points elsewhere and `box_map_complete` goes N/A — an artifact of the
  script's location, not of the patch. The valid invariance evidence is C3
  (same-location copy, byte-identical gate) plus the outside-`self_test`
  byte-diff.
- **Not run:** the export's own *full gate* as a landed target (an export has
  no pinned map, so `box_map_complete` is N/A by design; C3 recorded exit 1
  identically pristine vs patched). The claim's "0/1504 in a git-archive
  export" is the self-test, which is what R1/R3/R4 measure.
- **Not verified:** that the live repo's gate/self-test remain green after the
  patch is *landed* in the live tree — I did not mutate the live tree (hard
  rule). The landing step is the parent's; my evidence is the same-location
  copy equivalence (C3) and the outside-`self_test` byte-diff.
- **Unanimity condition.** H lands only if the `/tmp` simulations are
  unanimous. H4 is one of three independent designs; I did not adjudicate the
  others. Design C's own matrix is internally unanimous: four patched runs all
  0/1504 exit 0, controls red, gate byte-invariant.
- Assertion count is 1504 in every patched run and in the pristine export, so
  no case is silently skipped (matches H10's invariance concern).
