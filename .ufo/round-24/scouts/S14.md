## Findings

### F1 — the slice headline HOLDS: 53/53 indexed, every README row resolves
`git ls-files corpus` = 53, and the coverage-map section (lines 7-57, 50 data rows)
carries 67 FILE-column tokens covering all 52 non-README tracked files — every one,

`index_patterns=67` matches the gate exactly. The third instrument
(`verify_corpus_independent.py`, cmd 6) agrees again. Three independent readings, one
answer.

- 48/50 rows resolve on **every** token. The 2 exceptions are directory tokens ending
  in `/` — README:44 `../verifiers/fixtures/checklist/command-heredoc-tilde{,-dead,-misterm}/`
  and README:57 `../verifiers/fixtures/pins/` — excluded by the shipped rule
  (`token.endswith("/")`), and both **exist on disk** (cmd 7). So the rows are not
  broken; the rule just declines to check directory tokens.
- README.md itself is the only tracked corpus file with no row, which the gate excludes
  by design (`t in tracked if t != INDEX_NAME`). Correct, not a gap.
- All 11 README `commit `<hex>`` citations resolve as commits (cmd 8); all report
  pointers resolve from their citing file's own directory (cmd 9 after the base fix).
