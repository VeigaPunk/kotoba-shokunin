## Findings

**F1 — the H10 headline: no drift. The assertion count is exactly 1504 in every
mode that matters.** Rows 1, 3, 4, 5 all print `over 1504 assertions`. Patch A does
not change the count in either normal or export mode; the export red→green flip is
purely a *failure* delta (108 → 0) at a **fixed 1504**. There is no evidence of a
silently-skipped case in the landed fix, and no assertion count is conditional on
`.git` presence.

**F2 — the count is non-vacuous and the floor is real (V9 class confirmed live).**
Rows 7/9 show that deleting one CASES row (71 rows → 70) drops the total by exactly
21: `1504 → 1483`. Row 8 shows deleting one targeted `rec()` drops it by exactly 1:
`1504 → 1503`. So the "1504" figure is a genuine floor that a skipped case would
break, and the patched export mode still prints the full 1504 — the fix does not
reach green by skipping.

**F3 — the defect's exact mechanism (named, with coordinates).**
`verifiers/verify_skill_checklist.py:386-392`, `find_repo_root`:
```
cur = skill_path.resolve().parent
for cand in (cur, *cur.parents):
    if (cand / ".git").exists():
        return cand
return cur          # <- :392
```
In a `.git`-less export no ancestor carries `.git`, so the fallback returns the
**fixture directory itself** (`…/verifiers/fixtures/checklist/<case>`). `main()`
then computes `governance_enabled = skill_path.resolve() == (repo / "SKILL.md").resolve()`
(`:1756`) — trivially true, because `repo` *is* the fixture dir and `--skill` *is*
that dir's `SKILL.md`. Governance is thus enabled on 71 fixture dirs that carry no
`LOG.md`/`SCORECARD.md`; `check_governance_citations` (`:1235-1259`) returns
`FAIL … unreadable governance file(s)`, and because every fixture run now exits 1,
the 71 expected exit codes flip (28 of them are `exit 0` fixtures) → the
`exit 0`/`PASS` assertion classes in F-taxonomy. The 108 is exactly the class the
run log shows; the count of 1504 is unchanged because the failure replaces a
pass, not a case.

**F4 — patch A is sufficient; patch B is not.** Patch A = change `:392`'s fallback
to `return DEFAULT_REPO` (`:269`, `Path(__file__).resolve().parent.parent`).
Row 3: export self-test `0/1504`, exit 0. Row 5/12: identical full-gate stdout
sha256 to the live tree — live behaviour byte-invariant. Patch B (force
`--repo DEFAULT_REPO` into each self-test `run()` call at `:1340-1342`) leaves
`foreign-no-map: exit 0: got 1` (row 6) because that extra deliberately passes no
`--repo` (`:1553-1555`), so an explicit `--repo` breaks the very case it must
exercise. **Recommendation: land patch A only.** (A third option — making the
self-test set an explicit repo — is strictly worse: it also perturbs the
`foreign-no-map` and `relative --repo` extras.)

**F5 — live-behaviour invariance is proven against a *fleet-layout* control.**
Rows 11/12/13: patch-A export, patch-A clone, and *pristine* export all emit a
full-gate stdout byte-identical to the live tree (`eaf9f7ca…`), when placed in a
fleet layout (`/tmp/h10/fleet*` with sibling `PROTOCOL.md`, `AXES.md`, `CORPUS.md`,
`MISSION.md`, `SCORECARD.md`, `.ufo`, `kasegi-shokunin` symlinked read-only).
Note the control matters: run outside that layout, the live gate itself turns red
on 2 checks (`trigger.citation_resolves`, `governance.citation_resolves`) purely
because 22 `../…` cites (e.g. `LOG.md:177 ../.ufo/reports/round-9/kotoba.md`,
`LOG.md:311 ../PROTOCOL.md`, `SKILL.md:511 ../.ufo/reports/round-7/kotoba.md`)
escape to the fleet root — a *layout* sensitivity of the live gate, unrelated to
the self-test defect, but worth recording for the claim's "byte-invariant"
observable: it holds only for the fleet layout, not for an arbitrary `cp -a` into
an isolated dir. The same layout sensitivity does **not** affect `--self-test`,
which never touches those cites (its 1504 is layout-independent: rows 1/3/4/5).

**F6 — self-test stdout is byte-identical live vs patch-A export** (`diff` empty),
so the fix is observationally inert on the passing path.

## Defects named (each: path:line + evidence)

**D1 — `verifiers/verify_skill_checklist.py:392` — `.git`-less export makes the
self-test non-hermetic (the F8 defect; the thing claim H is about).**
`return cur` (fixture dir) → `governance_enabled` trivially true (`:1756`) →
108 failures / exit 1 on a `git archive HEAD` export (row 2), vs `0/1504` / exit 0
on the live tree (row 1). Fixtures are present in the export (174 tracked paths),
so the cause is the repo-root fallback, not missing fixtures.

**D2 — `verifiers/verify_skill_checklist.py:1553-1555` — `foreign-no-map` extra
hard-codes "no `--repo`", so any fix that injects an explicit repo into the
self-test `run()` helper breaks it.** Evidence: patch B row 6,
`self-test FAIL: foreign-no-map: exit 0: got 1`. Constrains the fix shape: patch A
(change the fallback), not patch B (change the call site).

**D3 — layout sensitivity of the *live gate* (not the self-test), for the claim's
record.** `verifiers/verify_skill_checklist.py:1756` + `check_citation_resolves`/
`check_governance_citations`: 22 `../…` cites resolve only when the repo sits in
the fleet root. A `cp -a` into an isolated dir turns the live gate red on
`trigger.citation_resolves` and `governance.citation_resolves`. Confirmed by
`/tmp/h10/norm_A` (exit 1) vs `/tmp/h10/fleetB` (exit 0, identical to live). This
is a pre-existing property, not introduced by any patch; it bounds how "byte-
invariant live behaviour" can be tested (fleet layout required).

**Non-defect (recorded to close the H10 question):** the assertion count itself is
**1504 everywhere** — rows 1, 3, 4, 5 — so claim H's falsifier clause
"assertion-count drift" does **not** fire, and the V9 no-floor class is not
present in the fix.
