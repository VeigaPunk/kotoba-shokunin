## Findings

**F1 — VERDICT (primary): corpus class (d) fires in BOTH instruments, with the documented class
split, and reproduces the harness's own table rows byte-for-byte.**
- **(d1)** (index row naming an absent file): integrity exit **1**, DRIFT set
  `corpus.index.stale_patterns,corpus.index.missing_paths` — the *two-class* firing round-21 F4
  observed (a missing-path row also matches the stale-pattern shape). Independent exit **1** with
  its own two DRIFT rows and the exact site. This is the harness row
  `fault-d1 | integrity | 1 | corpus.index.stale_patterns,corpus.index.missing_paths` (command 12).
- **(d2)** (index row naming an on-disk but untracked file): integrity exit **1**, DRIFT
  `corpus.index.stale_patterns` **only** — `missing_paths=0`, exactly as the doc predicts
  ("`stale_patterns` only", `independent-verification-round12.md:132`) and as the harness row shows.
  Independent exit **1**, `stale=1 missing=0`.
- Both worlds: `report_total`/`commit_total`/`report_dead` untouched — the (d) class lands entirely
  in the **index** family, never the pointer family. The two instruments agree check-for-check on
  both worlds (same counts, same sites, same exit codes).
- Both fire in **both modes**: `--no-baseline` (zero-mode DRIFT rows) and default/baseline mode
  (`7/9` resp. `8/9 checks pass`). Unlike the (f) blind spot, class (d) has no mode gap.
- Cross-round comparability: the live harness re-run at `b889e78` prints `ALL PASS` with
  `fault-h checked=36` (round-21 F4 measured `checked=32`, round-23 M7 `checked=34`; the growth is
  the recorded round-22/23 corpus additions, not drift).

**F2 — (d1) is the class whose *second* class is the load-bearing one.** The harness's own expected
class for `d1` is `corpus.index.missing_paths` (script:403), i.e. the class that (d1) shares with no
other fault; the round-12 doc's table lists `stale_patterns` first (`:131`). Both are true; a reader
comparing the doc table to the harness's `fault_must_fire d1 … missing_paths` line sees a
presentation-order difference, not a disagreement.

**F3 — the (d) plants are *section-scoped*, and the plant guards do not check the scope (D1).**
Commands 13-16: with one ordinary table appended below `## Known gaps`, the harness's
`insert_index_row` places the (d1)/(d2) row at the **last table row in the file** (line 103), i.e.
outside the coverage-map section that `file_column_tokens` reads
(`verify_corpus_integrity.py:281-282`, `SECTION_HEADING_RE`/`COVERAGE_HEADING_RE`). The row then
matches **no** check: `stale=0 missing=0`, exit 0 in both instruments and both modes. The plant's
self-verification (`grep -qF 'knowledge/gone-file-fault.md'`, script:191/199) still passes because it
tests token *presence*, not section membership — so the guard certifies a plant the detector cannot
see.

**F4 — pins "(i)" is measurable now, and its discovery predicate is the boundary (D2).** The landed
guard discovers a stray pin only when the key matches
`^(?P<prefix>[a-z0-9_]+)_binary_(?P<kind>[A-Za-z0-9]+)$` (`check_substrate_pins.py:70`). Lowercase
variants of a stray pin (`cursor_binary_sha256`, `grok_binary_sha256`) and an unregistered *kind*
(`omp_binary_sha`) all fire exit **2 UNSUPPORTED** as designed. A **case** variant
(`OMP_BINARY_SHA256`) or a **suffix** variant (`omp_binary_mtime_ns`) is not discovered at all and
the guard exits **0 `OK 3/3 pins hold`** — a declared pin silently unenforced, which the guard's own
docstring forbids (D2).

**F5 — non-vacuity of the (d) demo.** Every red above is causal: the clean controls (commands 2-3)
exit 0 with `stale=0 missing=0`, and each red is a single planted row; the d1late world (commands
13-16) shows the same row going green when moved out of the read section, so the firing is
attributable to *section membership*, not to the mere presence of the text.

## Defects named (each: path:line + evidence)

1. **`verifiers/fault_injection_corpus.sh:111-119` — `insert_index_row` targets the last table row
   in `corpus/README.md`, not the last coverage-map row; its plant guard cannot tell the
   difference.** Evidence: commands 13-16. After appending a table below `## Known gaps`, the row
   lands at `corpus/README.md:103`; both instruments exit 0 with `stale=0 missing=0` in both modes,
   while `plant_d1`/`plant_d2` still return 0 (their `grep -qF` guard at script:191/199 sees the
   token). Consequence at HEAD: **none** — no table exists below `## Known gaps` today
   (`awk 'NR>59 && /^\|/' corpus/README.md` → 0 rows), so `max(...)` picks the coverage-map's own
   last row and the demo is correct. Consequence after any future README table is added below that
   heading: the (d1)/(d2) plants become detector-invisible and the suite reports
   `MISS` → exit 1 (a mislabelled, noisy failure — *not* a false PASS, because `fault_must_fire`
   maps `ex=0` to `MISS`, script:256-258). Severity: low-to-medium, latent/robustness.
   Fix shape: scope the scan to the coverage-map section (stop at the next `^## `), or have the
   plant guard assert the inserted line number is inside the section.

2. **`verifiers/check_substrate_pins.py:62-63` (comment) vs `:70` (`DISCOVER_RE`) — a stray pin whose
   key is a case- or suffix-variant of the pin grammar is silently skipped, contradicting the
   stated contract "a pin the guard cannot resolve is UNSUPPORTED (exit 2), never a silent skip".**
   Evidence: command 19 — `measured_against` with an added `OMP_BINARY_SHA256: "a"*64` → exit **0**
   `OK 3/3 pins hold`; with an added `omp_binary_mtime_ns: "a"*64` → exit **0** `OK 3/3 pins hold`.
   Contrast `cursor_binary_sha256` → exit **2** `UNSUPPORTED`. `OMP_BINARY_SHA256` fails
   `DISCOVER_RE` on the `[a-z0-9_]+` prefix class; `omp_binary_mtime_ns` fails on the `$` anchor
   (`kind` = `mtime_ns`, not in `KINDS`). Impact: a hand-edited pin recorded in the "wrong case" is
   enforced by nothing and the guard still prints `OK 3/3 pins hold` — the exact
   silent-shrink/vacuity class the guard exists to close (P7-C9 / M6-D2). Severity: medium (silent,
   but requires an unusual key spelling). Fix shape: discover any key containing `binary`, or assert
   that every `measured_against` key is either a contract pin or an explicitly-ignored free-text key
   (the guard already classifies `command`, `omp_round21_note`, `round18_move` as non-pin).
   Note: the committed `--self-test` covers "stray pin from an **unregistered substrate**" (lowercase,
   `check_substrate_pins.py:378-383`) but has **no case/suffix-variant case**, so the hole is not
   caught by its own suite.

3. **Cosmetic (recorded, not a defect): the two instruments print the missing-path arrow target in
   different path forms.** Author `missing_paths_detail` →
   `corpus/README.md:58: knowledge/gone-file-fault.md -> knowledge/gone-file-fault.md`
   (corpus-relative, `verify_corpus_integrity.py:325`); independent →
   `… -> corpus/knowledge/gone-file-fault.md` (repo-relative, `verify_corpus_independent.py:276-277`).
   Same site, same token, same count — only the arrow's right-hand form differs. Round-12 §3.5 already
   adjudicated "same sites, richer text in the independent"; this is the one place where the text
   difference is a *path form*, so a byte-diff of the two detail lists is not empty.
