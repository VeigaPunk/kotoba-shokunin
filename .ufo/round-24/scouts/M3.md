## Findings

**F1 — the red direction is intact, and it is red in both instruments, for every
pointer shape.** Commands 15–22: a single planted dead pointer at HEAD moves the author's
`report_dead` 0→1 with the exact site named, flips the check to DRIFT, and exits 1 in
both the `--no-baseline` and default modes; the independent instrument names the identical
site and exits 1. The four-shape world (command 18/19) shows the regex admits relative,
absolute, tilde, bare, other-round and sub-path pointers, all six resolved-and-dead, and
both instruments agree on the shape vector. There is no shape the author's tokenizer
misses that the independent one catches, or vice versa, in this population.

**F2 — the `10/19` figure in the round-12 record is host-state, and its cause is
measured, not inferred.** Commands 12–14 reproduce `19/19`, not `10/19`, in both
instruments with identical site sets. The delta is exactly 9 pointers:
`/home/vgpnk/projects` (lowercase) **does not exist on this host** —
`test -e /home/vgpnk/projects` → absent; `test -e /home/vgpnk/Projects` → present —
so the tilde row (`~/projects/...` → `/home/vgpnk/projects/...`) and the eight
lowercase-absolute lesson rows that resolved when the record was written now dangle.
The doc's own shapes line (`absolute 8 + tilde 1` of 19 checked) was internally
consistent *on its host*; only the resolution of those 9 moved. Corollary: the record's
§3 masked-world figure "W0 from 10 to **19/19 dead**" now equals W0's *unmasked* reading
— the host has drifted into the state round 12 needed the private tmpfs to produce. This
independently corroborates round-23 scout F6 finding 2 (measured here in both
instruments, at the same revision, with the same six-site/19-site lists).

**F3 — the round-17 case correction is load-bearing, so its revert is a clean red
probe.** Command 20–22: reverting one lesson file's `Projects`→`projects` (the exact
defect `corpus-baseline.json`'s note records as fixed at round 17) turns the corpus gate
red with `report_dead=1`, `8/9`, exit 1, both instruments. So the gate is not merely
green-on-a-green-tree; it fires on the specific host-case defect the baseline note claims
to have cured.

**F4 — claim E's errata texts are provably non-load-bearing.** Commands 23–24 plus the
baseline/fixture greps: no baseline JSON and no fixture carries any of the seven target
strings, and patching the two drafted sites (`10/19`→`19/19`) and the whole harness
`27`→`28` family leaves corpus `9/9`, surfaces exit 0 and harness `28/28` — exit 0 in
every case. The claim's falsifier ("any gate flipping on the corrected text") cannot
fire on these sites. Note the harness gate prints `28/28` **already** at HEAD, which is
precisely why the `27` prose in `harness-verifier-round10.md:15,186`, `SKILL.md:109,456,461`
and `corpus/README.md:34` is stale, and why fixing it is text-only.

**F5 — F8 reproduces exactly, and the export boundary is a real portability defect.**
Command 25: a clean `git archive HEAD` export self-tests `108 failure(s) over 1504
assertions`, exit 1 — byte-identical in count to scout F8's measurement. The failing
families are fixture-rooted: `governance.citation_resolves` tries to read
`<fixture-dir>/LOG.md`/`SCORECARD.md` (fixtures carry none) and
`trigger.command_binary_resolves` tries to resolve `<fixture-dir>/corpus/...`. On a
clone the same gate is also red but for a different reason (host-anchored `../.ufo/...`
citations, command 30), and in a bare export the two corpus instruments correctly
refuse with exit 2 (commands 27–28) — so the `.git`-less boundary is fail-closed for the
corpus instruments and *not* for the checklist self-test. The `--self-test` green in
command 11 is therefore checkout-dependent, exactly as claim H's "before" states.

**F6 — the corpus instruments are git-dependent by construction, and their `--self-test`
does not cover that.** Commands 27–29: no-`.git` → exit 2 (`INCONCLUSIVE`, fail-closed,
good); `git init` + commit → `commit_unresolvable=27`, exit 1 (expected: a fresh repo
cannot resolve historical citations). Neither is a defect; recorded because claim E's
"full gate sweep exits 0" is a live-tree statement and does not hold in an export.
