## Findings

1. **Both documented behaviors re-derive.** `--self-test` → exit 0, `T1…T4 PASS`, `self-test: OK`
   (0.49 s). Full sweep → exit 0, `verdict: ALL PASS`, 10 classes `fault-0/a/b/c/d1/d2/e/f/g/h`,
   `fault-f` blind-spot row as documented, `fault-h` context row with `quoted=1` and the checked
   population unchanged (`checked=36` at this HEAD; round-21 F4 recorded 32, round-23 F1 recorded 34
   — the count tracks the tree, not a regression).
2. **The verdict layer is NOT inert.** Every gate I forced false flipped its row *and* the `verdict:`
   line *and* the process exit code (probes A, C, D, E, F, H, J). The slice's premise of "three inert
   internal gates" does not hold as stated; what is real is narrower and is filed as D1/D3 below.
3. **`row()`'s `*) FAIL=1 ;;` (`:243`) is the single exit carrier.** Probe G neutered only that
   branch: the `fault-f … FAIL` row still printed, yet the run said `verdict: ALL PASS` and exited 0.
   So the exit status is not derived from the table; probe I (A+G) shows a red row can coexist with a
   green suite. This is the structural reason D1 matters: `fault-f` is an `INFO*` row (`:242-243`),
   non-gating by design, so its evidence line is the only thing that carries the blind-spot claim.
4. **The `(f)` blind-spot gate cannot distinguish a crashed baseline run from a real DRIFT** (D1,
   measured by probe L2): `base_ex != 0` is satisfied by a stub that prints `boom` and exits 3, and
   the count clause is then satisfied by the `out.json` the baseline run never wrote.
5. **`--self-test` cannot see the `(f)` or `(h)` gates** (D3): with the `(f)` count clause forced
   permanently false — a state in which the full run exits 1 `FAILURES PRESENT` — `--self-test`
   still prints `self-test: OK` and exits 0.
6. **The harness refuses `.git-less` trees outright** (`env unreadable: not a git repo`, exit 2;
   probes 11, 12), by design: `new_world` clones, `plant_c` runs `git cat-file`, `plant_d2` runs
   `ls-files`, `plant_e` runs `git add` + `ls-files`. Claim H's "operability in .git-less exports"
   therefore does not extend to this harness — the git-archive work (F8/G6) is out of its scope, and
   any round-24 claim of export-mode coverage must not be read onto it.
7. **`--self-test` is cwd-hermetic but `--repo` is inert in self-test mode** (probe 9, 12): the
   self-test resolves `REPO` from `$SCRIPT_DIR/..` (`:37-38`) and never reads the parsed `REPO`, so
   `--self-test --repo <git-less extract>` fails on the *script's* repo, not the named one.
8. **`PYTHONOPTIMIZE=1` does not break the sweep** (probe 10): `replace_once`'s `assert n == 1`
   (`:95`) is stripped, but every planter greps its own marker afterwards, so a no-op plant surfaces
   as `INVALID-PLANT` (round-21 F4 D3 re-derived; still latent-only).
9. **Independent-absent mode is honestly labelled** (probe 13): `PASS(author-only; independent=absent)`
   (`:265`) + `SKIP`, exit 0 — matches the recorded intent at `:262-265`.
10. **Pin provenance corrected.** Round-23 scout F6's "HEAD blob `9db6c692…`" is a terminology slip:
    `9db6c692…` is the file's **content sha256** (and the value the harness itself prints as
    `instrument_sha256`), while the HEAD **git blob** is `add3460e65e2…`. F6's other half is real and
    belongs to claim E's scope, not to the harness: the record pin `9bc80ae61cea…` at
    `corpus/knowledge/independent-verification-round12.md:120` matches no reachable object
    (round-21 R6 proved this; `git rev-parse --disambiguate=9bc80ae61cea` → empty). My first reading
    placed that pin "in the harness `:120`" — that was my misread; harness `:120` sits in
    `insert_index_row`'s README surgery (`:115-121`), not a pin.

## Defects named (each: path:line + evidence)

**S8-D1 — the `(f)` blind-spot gate is satisfied by a crashed baseline-mode run**
`verifiers/fault_injection_corpus.sh:290-297`. `blind_total` (`:290`) and `base_total` (`:293`) are
both read from `$w/out.json` by `json_field`; `json_field` (`:124-135`, the swallow at `:133-134`)
treats every read failure as an empty value, and because `print("")` succeeds the command substitution
returns **status 0** with an empty string, so the failed read is unobservable at the call site (no
`set -e`, no status check — `set -u` is not tripped by a command substitution). Measured (probe L2): replacing
the instrument with a stub that prints `boom` and exits 3 before the baseline invocation yields
`DEBUG(L2): base_ex=3 baseline_out_bytes=4` and row
`fault-f | integrity | 0 | - | PASS(blind-spot documented: --no-baseline exit 0; baseline-mode exit 3)`,
`verdict: ALL PASS`, harness exit 0. The gate's `base_ex != 0` test is therefore satisfied by *any*
non-zero exit, and its count-equality clause is satisfied by a file the baseline run never wrote. The
true evidence at HEAD (probes 14–16) is `report_total=35` in both modes with
`DRIFT corpus.pointers.report_total: observed=35 expected=36` and exit 1 — i.e. the gate passes for
the right reason today, but cannot tell that reason from a crash. Because `fault-f` is an `INFO*` row
(`:242-243`) and the exit status comes solely from `:243` (probe G), this is the one place where the
harness's blind-spot *claim* rests on evidence that a broken baseline mode would also produce.

**S8-D2 — `plant_f` is host-pinned; on a foreign host the whole suite fails**
`verifiers/fault_injection_corpus.sh:212-214`:
`local old=/home/vgpnk/Projects/shokunin/.ufo/reports/round-4/kotoba.md` guarded by
`[ -e "$old" ] && [ ! -e "$new" ] || return 1`. Measured (probe K): with the anchor moved to a
nonexistent file the row reads `fault-f | f | - | - | INVALID-PLANT`, the `verdict:` line reads
`FAILURES PRESENT` and the harness exits **1** — a portability gap in one plant becomes a
whole-suite failure rather than a `SKIP`. Already filed by round-21 scout F4 as D1; re-derived here
as still live at HEAD `b889e78`, with the exit code now measured.

**S8-D3 — `--self-test` exercises no fault-class gate**
`verifiers/fault_injection_corpus.sh:365-390`. The body calls only `new_world`, `plant_a`,
`run_integrity`, `drift_ids` and one `grep`; it never calls `fault_must_fire`, `fault_known_blind_f`,
`fault_h_context`, `fault_must_not_fire` or `row()`. Measured: with the `(f)` count clause forced
permanently false (probe A — a state where the full run exits 1 `FAILURES PRESENT`), `--self-test`
still prints `self-test: OK` and exits 0. The header comment (`:25-26`) claims the self-test
"verify[s] the assertion machinery on deliberately broken fixture worlds"; the `(f)` and `(h)`
gates are outside that claim in fact. Adjacent: T2's comment at `:374` calls itself
"deliberately broken: NO mutation applied", but its assertion is byte-identical to T3's
(`:375-376` vs `:384-385`), so T2/T3 are one probe printed twice and T4 (`:379-381`) is what carries
T2's intended content.

**S8-D4 (latent, mechanism-read — not execution-proved) — the independent instrument is gated through
an unpinned in-world copy**
`verifiers/fault_injection_corpus.sh:145-149`: `run_independent` (`:145`) executes
`"$INDEPENDENT"` (`:148`), the **relative** path inside the world, while the harness itself is
normally invoked as `$SCRIPT_DIR/…`. `new_world` copies the live file over the clone
(`:83`; `INSTRUMENT` likewise at `:80`), so in the natural invocation the independent rows measure
the world's copy — i.e. the live tree's bytes, not HEAD's. Not manifested at HEAD (the file is
committed and unmodified), and I did not build the full shadow world; the mechanism is read from the
two sites. The same relative invocation for `INSTRUMENT` is intentional (the live instrument is the
object under test), so only the independent side is a shadowing hazard.
