## Findings
1. **The probe is real and non-vacuous.** The (b3) block at `verifiers/verify_surfaces.py:793-799` asserts, for `--omp-strings …/strings-empty.txt`: exit 1, `FAIL surfaces.no_uncovered_class:` present, and the substring `vacuity` present. Live self-test green (0/75), so the probe fires exactly as designed.
2. **The dump is genuinely non-empty (decoy-bearing), 100 bytes, three lines:**
   - `description:"Load context files"`
   - `for (const s of ["AGENTS.md","CLAUDE.md"])`
   - `nothing registered here`
   These lines carry md-suffixed-looking content but **no allowlisted registration call shape** (`(Id|Cl|jD[ef]|Tl|dr|GW|Co|Dl|Hj)(<v>, <group>, "<file>.md")`), so `extract_classes(dump,'omp') == set()` — a *dead* dump, not an empty file. This is the precise "non-empty dead dump" the slice names.
3. **The guard is load-bearing.** `check_no_uncovered_class` (`verifiers/verify_surfaces.py:556`) fires when a harness has `loader-group` classes declared but `pairs` is empty. `baseline-clean.json` declares 2 omp loader-group ids (`omp:gemini/GEMINI.md`, `omp:claude-md/CLAUDE.md`), so 0 extraction → FAIL. Neutralizing the condition (M2a) makes the same run print `PASS … all 0 extracted loader class(es) declared` — the 2026-10-16 silent-pass defect class — and the self-test catches it (1/75).
4. **The probe pins deadness, not the exact bytes.** Substituting the *clean* dump (M2b) breaks both vacuity cases (2 failures), proving the fixture's deadness is what the case depends on; truncating to 0 bytes (M2c) stays green, so the self-test does not itself assert the fixture's non-emptiness. That is the intended ceiling: the assertion is "0 extraction while classes are declared", not "the fixture is non-zero-byte".
5. **Both harness halves fire on the same 100-byte fixture.** The omp guard is `no_uncovered_class` (:556); the opencode zero-extraction guard is `opencode_extract` (`:649`, `if not extracted:`). The self-test pins both (`:795-799` for omp, `:918-924` for opencode).
