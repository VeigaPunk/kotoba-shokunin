## Findings

**F1 — Verdict: HOLDS. All three pins reproduce at HEAD `b889e78`, zero drift.**
`exit 0`, `OK 3/3 pins hold`, omp mtime `delta 0 ns` at `tolerance 0 ns` (a 9-digit pin ⇒ the
acceptance window is 0 ns, so this is an ns-exact integer equality, not a loose compare). The
independent sha256sum (row 6) equals the pins exactly for both binaries, and the raw
`st_mtime_ns` (row 7) equals the parsed pin exactly. This is the third consecutive round
(21 → 23 → 24) in which the opencode pin `d9123b9b…` holds byte-identically; the omp pin
`bf1e86a9…` has held since the round-21 re-pin. **No DRIFT to report.**

**F2 — The guard is deterministic and read-only in the live path.** Rows 5 and 9: two `--json`
runs are byte-identical, and a full guard run leaves `~/.local/share/opencode/log` mtime and
size untouched — the docstring's "never executes a pinned binary (an exec writes to another
gate's log input)" claim is confirmed at the observation surface it names.

**F3 — The measured baseline is the committed one.** Row 8: `verifiers/baseline.json` is clean
in the worktree and its blob hash equals `HEAD:verifiers/baseline.json`, so the 3/3 hold is a
statement about the landed artifact, not a dirty local edit.

**F4 — The guard is now the *sole* reader of `measured_against`, and it is tracked at HEAD.**
Row 19: `grep -c measured_against` is 18 in `check_substrate_pins.py` and 0 in all five other
instruments + the shell harness; `git cat-file -e HEAD:verifiers/check_substrate_pins.py`
succeeds. This directly falsifies the baseline's own note (D1 below).

**F5 — The full exit ladder still flips red as filed.** Rows 10–16 reproduce all six round-23
red probes on `/tmp` baseline copies: sha drift → 1, mtime-only drift → 1, missing binary → 2,
corrupt baseline → 3, null block → 1 `VACUOUS`, deleted pin → 1 `PIN_ABSENT`. The checked set
cannot silently shrink and the vacuity class cannot pass. `--self-test` is `0/46` (row 4),
matching the SCORECARD/LOG record.

**F6 — The self-test is hermetic (it does not depend on the committed fixtures).** Rows 17–18:
a `git archive HEAD` export (no `.git`) runs both the live gate and the self-test green, and —
stronger — deleting `verifiers/fixtures/pins/` entirely from a `cp -a` copy *still* yields
`0 failure(s) over 46 assertions`, `exit 0`. `self_test()` never references the fixture
directory (`grep -n fixtures verifiers/check_substrate_pins.py` → one hit, the `--self-test`
argparse help string at `:250`); it synthesizes its own `mini.bin` into a `TemporaryDirectory`
(`:311`), and that synthesized blob is byte-identical to the committed `mini.bin`
(`d3b4640e…`, row 20). So for *this* guard the portability that claim H is chasing for
`verify_skill_checklist.py` already holds — but the fixtures' recorded role in the docs is
false (D3).

## Defects named

**D1 — `verifiers/baseline.json:7` asserts a debt that was closed three rounds ago.**
The exact text: `"omp_round21_note": "omp rebuilt 2026-10-16 (ff59fc1b->bf1e86a9, v18.11.1,
unminified source chunks; registration callees now Co/Dl/Hj). Re-pinned by round 21; no check
enforces this pin (named debt)."` — the trailing clause `no check enforces this pin (named
debt)` is false at HEAD. Evidence: `verifiers/check_substrate_pins.py` is tracked at HEAD
(commit `dc4c0c0`, "round 23: substrate-pin-guard capability"), it reads `measured_against` 18×
(row 19), and it exits 0 while enforcing exactly this pin (row 2). This is a **freshness/claim-E
erratum** the round-23 landing missed: it re-pinned and guarded the value but left the value's
own inline annotation saying nothing guards it. The correction is minimal (drop or rewrite the
clause; the historical record of the rebuild itself is still true). Related: `SCORECARD.md:32`,
`corpus/README.md:57`, `corpus/knowledge/substrate-pin-guard-round23.md:3`, `LOG.md:1210` and
`.ufo/reports/round-21/kotoba.md:19` also carry the `named debt` phrase, but those are *dated
historical records* that correctly say the debt existed then — `baseline.json:7` is the only
live document whose present-tense clause is false.

**D2 — The `874 ns` figure at `verifiers/check_substrate_pins.py:105` (and
`corpus/knowledge/substrate-pin-guard-round23.md:14,57`) is host/route-dependent, not a
constant.** Measured on this host against the live omp pin
`2026-10-16T05:15:11.226207850-03:00` with `st_mtime_ns = 1792138511226207850`:
`datetime.fromisoformat(pin).timestamp() * 1e9` (float, as the docstring writes it) =
`1.792138511226207e18`, i.e. **768 ns low**; `int(…)` / `round(…)` of that same float =
`1792138511226206976`, i.e. **874 ns low**; the exact integer route the guard actually uses
(`calendar.timegm(dt.utctimetuple())*10**9 + frac_ns`) = `1792138511226207850`, **delta 0**.
So `874` and `768` are both artifacts of the same IEEE-754 conversion and both differ from the
true value; only the guard's own parse path is exact. The docstring's *conclusion* (use integer
ns, never `timestamp()*1e9`) is correct and is what the code does — but the *number* is
reported as if it were a property of the pin, when it depends on the float→int rounding step.
Worth an erratum that names the route (e.g. "`int(...timestamp()*1e9)` is 874 ns low; the
unrounded float is 768 ns low on this host") so a future reader re-deriving it on a different
libc doesn't conclude the doc is wrong.

**D3 — `verifiers/fixtures/pins/{mini,mini2,tripwire}.bin` are dead fixtures, yet five
documents record the self-test as running "over `verifiers/fixtures/pins/`".**
`SCORECARD.md:116`, `LOG.md:1231`, `corpus/README.md:57`,
`corpus/knowledge/substrate-pin-guard-round23.md:35` and `.ufo/reports/round-23/kotoba.md:13`
all describe the fixture directory as the self-test's substrate. At HEAD no code path opens it:
`grep -n fixtures verifiers/check_substrate_pins.py` returns only the argparse help text
(`:250`), and the self-test green survives deleting the whole directory (row 18, exit 0,
`0/46`). Two consequences: (a) the documentary claim is inaccurate — the self-test is
*tempdir-synthesized*, and the committed files are an unreferenced record; (b) more
importantly, **`tripwire.bin` — the 41-byte `#!/bin/sh; : > "$(dirname "$0")/EXECUTED"`
fixture whose whole purpose is to catch an accidental exec of a pinned binary — is never
executed by any assertion in the suite.** The read-only/hash-never-exec property is therefore
witnessed only by my out-of-band log-mtime check (row 9) and by round-23's strace note, not by
the committed self-test. This is a coverage gap in the round-23 capability, not a gate flip;
it is fixable by adding one assertion that runs the guard against `tripwire.bin` and asserts
`EXECUTED` was never created (and, if the fixtures are to stay, one that hashes them).

**D4 (minor, observation only) — `verifiers/baseline.json` `as_of` is `2026-10-14T09:58:47…`
while the omp pin inside it was re-recorded by round 21 (commit `2ca8d01`, `2026-10-19
01:21:10 -03:00`).** The pins are correct and enforce (F1); only the document's own timestamp
lags its content by five days. Round-22 scout R4 already named the head/repo pins as inert and
lagging, so this is a recurrence of a known class, listed for completeness — not a new finding
and not part of claim E's seven counts.

## Limits (what I did NOT verify)

- **Host scope.** Rows 2/6/7 are a statement about *this host's* installs (`~/.local/bin/omp`,

  other machine, so "the pins hold" is not a portable claim; the opencode 1985 mtime is a
  synthetic packer constant and is not pinned at all.
- **No rebuild probe.** I did not (and must not) rebuild or touch either binary, so the
  guard's *detection* of a fresh rebuild is evidenced only by the `/tmp` baseline-copy drift
  probes (rows 10–11), not by a live move.
- **No strace.** Row 9's read-only evidence is `stat` on the opencode log before/after a single
  guard run, not a syscall trace; I did not reproduce round-23 V3's strace.
- **D2 is inferred from this host only.** I measured `768`/`874`/`0` here; I did not test other
  libc/Python builds, so the exact dependence is stated as "route-dependent", evidenced
  locally.
- **Not claim H.** I confirmed the *pins* guard's self-test is export-hermetic (F6), but I did
  **not** run or patch `verify_skill_checklist.py`; the 108/1504 git-archive defect and its
  fix are outside this slice.
- **Not a full doc audit.** I checked the pins/`measured_against`/874/fixtures surfaces; the
