## Findings

**Root cause (same as scout F8, independently re-derived).**
`verifiers/verify_skill_checklist.py:386-392` — `find_repo_root()` returns the
nearest ancestor with a `.git` marker, **else the target file's own
directory**. The self-test's `run()` (`:1341-1348`) builds fixture argv with
`--skill`/`--map` but no `--repo`, so `main()` (`:1752-1753`) falls into that
else-branch. In a git-archive export no `.git` exists, so `repo` becomes
`verifiers/fixtures/checklist/<case>/` for every case. Two consequences:
`governance_enabled` (`:1756`, `skill_path == repo/"SKILL.md"`) flips **True**
for every fixture (the fixture SKILL.md now *is* the repo's SKILL.md), so
`check_governance_citations` (`:1235-1260`) hunts `LOG.md`/`SCORECARD.md`
inside the fixture dir → `unreadable` → FAIL; and every repo-rooted citation /
command token re-bases onto the fixture dir → FAIL. 108 assertions, exit 1.
A checkout masks it entirely because `.git` is found at the true root.

**Fix shape A (mine, proven):** after the `.git` walk, if the resolved target
lies inside `DEFAULT_REPO` (`:269`, `Path(__file__).resolve().parent.parent`),
return `DEFAULT_REPO`; otherwise keep returning the file's own dir. The patch
is script-relative by construction and is 10 lines (1 docstring, 1 code body).
It is behaviorally equivalent to sibling scout H1's implementation B (which
pins `--repo str(DEFAULT_REPO)` at the two self-test argv sites): both resolve
a fixture inside the repo to `DEFAULT_REPO` — verified directly, `A:
find_repo_root(fixture) == DEFAULT_REPO` is `True` and equals the value B
pins. A differs in *scope*: it is a `find_repo_root` change, so it also
repairs a bare `python3 verifiers/verify_skill_checklist.py --skill
verifiers/fixtures/.../SKILL.md` run in an export (not just `--self-test`),
whereas B only fixes the self-test's argv. Both leave a genuinely foreign
target on the old fallback (negative control above).

## Defects named (each: path:line + evidence)

- **D1 — self-test non-hermetic in `.git`-less exports (root cause).**
  `verifiers/verify_skill_checklist.py:386-392` (`find_repo_root` `.git`-else-
  dir fallback) combined with `:1341-1348` (self-test argv omits `--repo`).
  Evidence: `git archive HEAD` export at `b889e78` → `exit 1`,
  `108 failure(s) over 1504 assertions`; the 79 governance failures each name
  `unreadable governance file(s): LOG.md ([Errno 2] .../fixtures/checklist/
  <case>/LOG.md)`, i.e. the fixture dir was treated as the repo root.
- **D2 — `governance_enabled` flips on the mis-resolved root.**
  `verifiers/verify_skill_checklist.py:1756` —
  `governance_enabled = skill_path.resolve() == (repo / "SKILL.md").resolve()`
  is `True` whenever `repo` has been mis-resolved to the fixture dir, so the
  governance check runs (and fails) for a foreign fixture instead of returning
  N/A. Evidence: in the patched export the same invocation returns
  `N/A governance.citation_resolves: evaluated 0 — governance files are
  checked only with the repo SKILL.md` (probe re-run with explicit `--repo`).
- **D3 — fix shape A scope (recorded, not a defect).** A is a
  `find_repo_root` change, so it also alters bare fixture runs in an export
  (superset of H1-B's argv pinning). Both are inside the repo's own tree;
  behavior for a foreign target outside `DEFAULT_REPO` is unchanged
  (negative control). The integrator should pick one shape; they are not
  additive (applying both is harmless but redundant).
