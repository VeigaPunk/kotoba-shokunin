## Findings

**Root cause (single, mechanical).** `main()` computes

    repo = Path(args.repo).resolve() if args.repo else find_repo_root(skill_path)

and `find_repo_root` (:386-392) walks ancestors for a `.git` marker and, failing
that, returns **the skill file's own directory**. In a `.git`-less export there is
no marker anywhere, so *every* fixture run inside `self_test()` resolves the repo
root to `verifiers/fixtures/checklist/<case>/`. Three consequences, all visible in
the 108 failures:

1. `trigger.citation_resolves` resolves `corpus/README.md`-class tokens against the
   fixture dir -> FAIL (and the PASS-side fixtures like `citation-ok`,
   `citation-anchor-ok`, `citation-second-word-ok` flip to exit 1).
2. `governance.citation_resolves` enables itself, because
   `governance_enabled = skill_path.resolve() == (repo / "SKILL.md").resolve()` and
   with `repo == <fixture dir>` the fixture's own `SKILL.md` *is* `repo/SKILL.md`.
   It then reads `LOG.md`/`SCORECARD.md` from the fixture dir, finds neither, and
   returns `FAIL ... unreadable governance file(s)`. This is the bulk of the 108:
   79 of the emitted failure strings mention `governance.citation_resolves`.
3. `trigger.command_binary_resolves` resolves path-like operands
   (`corpus/README.md`, `verifiers/absent-round16-source.sh`, …) against the
   fixture dir -> FAIL.

`find_repo_root`'s docstring already describes exactly this contract
("nearest ancestor carrying `.git`, else the file's directory"); the defect is not
the fallback's existence but that `self_test()` **never states the repo it means**,
so it inherits a cwd/filesystem-dependent default. The live tree is green only
because the real repo happens to carry `.git`.

**Design B (this patch) — harness-side explicit repo pin.** Two hunks, both inside
`self_test()`; `find_repo_root` is NOT touched:

`DEFAULT_REPO = Path(__file__).resolve().parent.parent` (:270) is already the
script-anchored repo root, so this is the same rule the CLI's own `--repo` help
text promises — just made explicit instead of inferred. The self-test is the only
caller of `run_capture` with fixture paths; the two hunks cover all of them.

**Named decision that distinguishes B from H2's design (H2 unseen).** Design B
fixes the *harness*, not the *resolver*: it never changes `find_repo_root`, so the
live CLI's default-repo semantics for a foreign, `.git`-less target are **byte-
identical to today** (still "the target's own directory"). The alternative —
design A, patching `find_repo_root`'s fallback from `return cur` to
`return DEFAULT_REPO` — also reaches 0/1504 (verified: `altA` archive self-test
exit 0, 0/1504), but it is a **live-CLI behavior change**: with A, running the
checker on a foreign `.git`-less target silently starts resolving that target's
citations against *this* repo root. Measured divergence, same invocation on the
same `.git`-less export:

    --skill <exp>/.../citation-ok/SKILL.md --map <exp>/.../citation-ok/map.json \
      --check trigger.citation_resolves
    design A  -> PASS trigger.citation_resolves: evaluated 2 (resolves from this repo)
    design B  -> unchanged default (resolves from the fixture dir)

B was chosen because claim H's `after` requires "live tree byte-identical behavior
(live gate + self-test unchanged)"; A satisfies the letter of the export result but
not that clause. B's cost, stated plainly: it fixes the *self-test*, not the
*resolver*, so a user who invokes the CLI directly on a foreign `.git`-less target
still gets the cwd-dependent default (A's behavior change was judged out of scope
for H). B also leaves `find_repo_root`'s docstring accurate as written.

**Live byte-invariance (the load-bearing check).** Two independent comparisons,
both empty diffs:

- patched `livecopy` vs unpatched live tree — gate output `diff` EMPTY, self-test
  output `diff` EMPTY.
- same-basename `inv/kotoba-shokunin` copy, output captured before the patch was
  applied and after — gate `diff` EMPTY, self-test `diff` EMPTY.

A `cp -a` copy under a *different* directory name is NOT a valid invariance probe:
it flips `trigger.name_directory` (`name 'kotoba-shokunin' != directory 'livecopy'`)
and every `../`-prefixed fleet-root citation (`../.ufo/...`, `../PROTOCOL.md`),
which are pre-existing, unrelated to this patch, and identical pre/post. That
non-empty diff is the copy's basename, not the patch; recorded here so a reviewer
does not mistake it for a regression.

## Defects named (each: path:line + evidence)

D1. `verifiers/verify_skill_checklist.py:386-392` + `:1749` — `find_repo_root`'s
    fallback (`return cur`) combined with `self_test()`'s `run()` helper
    (`:1341-1347`) leaving `--repo` unset, makes the self-test's verdict a function
    of whether a `.git` marker is reachable. Evidence: git-archive export of HEAD
    -> `108 failure(s) over 1504 assertions`, exit 1; same export patched -> `0
    failure(s) over 1504 assertions`, exit 0. This is scout F8's defect, reproduced
    byte-for-byte (108/1504, exit 1).

D2. `verifiers/verify_skill_checklist.py:1752` — `governance_enabled =
    skill_path.resolve() == (repo / "SKILL.md").resolve()` is true for *any* fixture
    whose directory is used as the repo root, so `governance.citation_resolves`
    silently enables itself on fixture runs and then FAILs on unreadable
    `LOG.md`/`SCORECARD.md` (79 of the 108 failure strings). B suppresses this by
    making `repo` the real repo root; the latent coupling (governance-on-fixtures)
    is named but not otherwise addressed.

D3. `verifiers/verify_skill_checklist.py:249-250` — the docstring already scopes
    `--self-test` as "exercises fixtures only; its rc (0/1) is not comparable to a
    live run", but does not state the repo the fixture runs resolve against. The
    omission is what let D1 ship. B closes it behaviorally; the docstring is left
    unchanged (a wording fix would be claim E's territory, not H's).
