## Findings

**1. Derived check set == registry exactly (10/10, same order).** Frozen derivation
(`/tmp/h24/S3-derivation.md`), built from three independent sources with no source read:

- the baseline's executed disposition targets — 8 ids from
  `verifiers/checklist-baseline.json` (`trigger.01/02/03/04/09/11/14/15`);
- `SKILL.md:122-123` arithmetic: "**10 checks** (`checklist.box_map_complete` + the
  eight boxes marked `(executed: …)` + `governance.citation_resolves` over the two root
  governance files)" = 8 + 2;
- the round-15/16/17 record counts (8 → 9 → 10 checks) as a monotone cross-check.

The script's `CHECK_IDS` at `verifiers/verify_skill_checklist.py:282-293` is that same
set in that same order. No divergence; the registry is not over- or under-populated.
The `--check` argparse `choices=CHECK_IDS` (`:1731`) means the CLI cannot address an id
outside this set, so the derived set is also the full addressable surface.

**2. Assertion count 1504 confirmed, twice.** `--self-test` (cmd 6) and an in-process
`self_test()` call (cmd 18) both print `0 failure(s) over 1504 assertions`, rc 0. The
script sha (cmd 7) is byte-identical to the round-17 landed sha, so the round-17 doc
figure and the current count are the same instrument, not a coincidence. The count is the
harness's `rec()` counter (`self_test()` at `:1329-1337`): 39 static `rec(` call sites
in the `self_test` body plus per-case/per-id/per-subject loops over ~70 fixture CASES.
Independently confirmed that the *total* is layout-stable: R1/F8 both recorded 1504 in a
`.git`-less export too — so 1504 is a property of the fixture set, not of the checkout.

**3. Live counts at HEAD (cmd 5) differ from the round-17 doc, and the script is not the
cause.** Live: `box_map 41 (8/0/33)`, `line_budget evaluated 521 — within budget 600 (from
box at line 244)`, `no_placeholder 478`, `command_binary_resolves 13 — 9 segments`,
`citation_resolves 38`, `governance 198 — 8 quoted meta-findings, 3 schematics`. Round 17
reported 599 lines / box at 327 / 42 citations / 125 governance. Script sha is unchanged
(cmd 7), so all drift is target-side: SKILL.md shrank (599→521 lines, box line 327→244,
citations 42→38) across rounds 19-23, and `LOG.md`/`SCORECARD.md` grew (governance
125→198). Not a defect — recorded so the round report does not misquote round-17 numbers
as current. Note the box-map line is unchanged at 41 (8/0/33), so the *structural*
claim survived the edits.

**4. R1 semantics finding A reproduces — box-first-integer budget binding.** `box_line_budget`
(`:1073-1081`) picks *which* box states the bound via `LINE_BOUND_BOX_RE` (`:362-363`), but
takes the threshold as `INT_RE.search(b["text"])` — the **first `\d+` anywhere in that box's
text**, not the integer the bound regex matched. Both directions proven on `/tmp` copies of
the committed `line-budget-box-binding` fixture (whose box text is `File ≤ 20 lines; the box
states the bound.`, line 46):

- `Rule 2: File ≤ 20 lines` → `budget 2`, rc **1** on a 48-line file (cmd 10) — a numbered
  prefix in ordinary checklist prose misbinds into a false-FAIL;
- `Rule 999: File ≤ 20 lines` → `budget 999`, rc **0** on the same file (cmd 11) — an
  over-budget file PASSes under a box that states ≤20 (false-PASS).

The docstring at `:1073-1075` states "first integer", so code and docstring agree; the
defect is that no committed fixture carries a prefix integer, so this hazard class is
unprobed. `--max-lines` is correctly the fallback only (`:1081`). **Severity note for
round 24:** the live SKILL.md box at line 244 has no prefix integer, so the live gate is
not currently misbinding — this is a latent hazard, not an active false verdict.

**5. R1 semantics finding B reproduces — literal-trigger quoting.** `check_literal_trigger`
(`:1031-1049`) accepts three disjoint shapes: a non-empty frontmatter `triggers:`/`trigger:`
key (`:1035-1037`); the literal substring `"Triggers:"` in the description, **case-sensitive**
(`:1041`); else any quoted span of **≥2 chars** in five quote classes (`QUOTED_SPAN_RE`,
`:356-358`). Measured: `"ab"`, `` `js` ``, `“ok”` each PASS with `evaluated 1` (cmds 12-14) —
a 2-char quote with no trigger semantics earns the box. The case-sensitive token path is
confirmed by cmd 15 (lowercase `triggers:` → rc 1) vs cmd 16 (capital `Triggers:` → rc 0).
The live file's PASS is the `Triggers:` token path (`description carries literal 'Triggers:'`),
not a quoted trigger.

**6. Cross-check asymmetry confirmed.** `check_anti_trigger` strips **all** quoted spans
before matching (`ALL_QUOTED_SPANS_RE`, `:1059`). `Fixture "Anti-triggers: never".` PASSes
`literal_trigger_string` on that exact span (20 chars) and FAILs `anti_trigger_clause`
(cmd 17). One check reads quoted spans as evidence, the other treats them as invisible.
