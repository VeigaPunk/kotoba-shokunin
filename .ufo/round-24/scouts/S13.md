## Findings

**F1 — The pins self-test is hermetic; it clears the bar H sets for its sibling.**
`--self-test` returns `0 failure(s) over 46 assertions`, exit 0, in five distinct environments:
live tree, foreign cwd (`/`), `git archive HEAD` export (no `.git`), `cp -a` copy with `.git`
deleted, and a foreign `TMPDIR`. stdout is byte-identical across all of them
(sha256 `34e75cee…`). Unlike its sibling, the pins guard needs no git metadata: its fixtures are
built with `tempfile.TemporaryDirectory(prefix="pins-selftest-")` at
`verifiers/check_substrate_pins.py:299-332` and its baseline JSONs are generated in tmp by
`world()` (:322-328), because mtimes are not checkout-stable (scout D4's design note).

**F2 — F8's root cause, isolated to one line.** `verify_skill_checklist.py:386-392`
`find_repo_root()` walks ancestors for a `.git` marker and, finding none, returns the *file's own
directory* — so `governance.citation_resolves` looks for `LOG.md`/`SCORECARD.md` inside
`verifiers/fixtures/checklist/<case>/` and fails 108 assertions. Proof: `mkdir -p /tmp/s13d/.git`
on a copy of the archive export (nothing else changed) restores `0 failure(s) over 1504
assertions`, exit 0. The failure set is dominated by `governance.*` plus citation/command cases
whose subjects resolve relative to the mis-located root. This is *not* archive-specific — a
`.git`-less `cp -a` copy fails identically — so H's `counting_command` (`git archive` export) and a
plain git-less clone are the same defect surface.

**F3 — The self-test's assertion count (46) and text reproduce at HEAD**, so no erratum is owed
on that count. `grep -o "0 failure(s) over 46 assertions"` hits exactly once each in
`SKILL.md`, `SCORECARD.md`, `LOG.md`, `corpus/README.md`,
`corpus/knowledge/substrate-pin-guard-round23.md` — all five match the live measurement. Likewise
the three live pin values in `SCORECARD.md:116` reproduce verbatim (`OK 3/3 pins hold`, omp mtime
`delta 0 ns`).

**F4 — The whole fixture tree is tracked and clean.** 174 files tracked, 174 on disk, no
untracked/ignored strays, no symlinks, one intentionally empty file
(`verifiers/fixtures/checklist/empty-file/SKILL.md`), one executable (`pins/tripwire.bin`), and
`git archive` preserves the 0755 mode.

**F5 — No mutation, no leak.** A self-test run leaves every `.json`/`.bin` under `verifiers/`
byte-identical, does not touch `verifiers/baseline.json` or the live binaries' mtimes, and leaves
no new `/tmp/pins-selftest-*` directory. (86 pre-existing `/tmp/pins-selftest-*` dirs, oldest
01:29, are round-23 lane artifacts, not produced by the landed self-test.)

**F7 — two untracked stray files at the repo root, not mine.** `git status --porcelain` shows
`?? B-live-cli.txt` and `?? altA-live-cli.txt` (151 B each, both mtime `02:32:59`). Content is a
Python error from a sibling lane's aborted probe:
`python3: can't open file '<repo>/exp2/verifiers/verify_skill_checklist.py': [Errno 2] No such
file or directory` (and the `altA/` twin). They appeared during my lane's window but were not
created by me — my only write is this fragment. Flagged for the integrator: a sibling lane's
redirection landed outside `/tmp` and left repo-root pollution that a `git add -A` would commit.

**F6 — `--repo` is inert in `--self-test` mode** (`main()` returns at :253-254 before `--repo` is
consulted). Correct, but it means the pins self-test cannot be pointed at the committed tree even
by an operator who wants to.

## Defects named (each: path:line + evidence)

**D1 — `verifiers/fixtures/pins/mini2.bin` is tracked but unread.**
Path: `verifiers/fixtures/pins/mini2.bin` (100644, 94 B, sha256 `b315d489…`).
Evidence: `grep -rn "pins/" verifiers/*.py verifiers/*.sh` → rc 1 (no match);
`grep -rn "mini2" .` outside `.git`/`.ufo` finds the file itself and prose only. The self-test
never loads it — it writes its own `mini.bin` payload (`check_substrate_pins.py:302`). Deleting the
entire `verifiers/fixtures/pins/` tree still yields `0 failure(s) over 46 assertions`, exit 0
(`/tmp/s13b`). So a reader cannot tell, from the instrument, that this file exists, and the
"multi-subject ordering / first-subject-only bug" coverage scout D4 designed it for
(`.ufo/round-23/scouts/D4.md:51-52`) is not exercised by the landed self-test.

**D2 — `verifiers/fixtures/pins/tripwire.bin` is tracked but unreachable; its documented role
cannot fire.**
Path: `verifiers/fixtures/pins/tripwire.bin` (100755, 41 B, sha256 `2b30a880…`); claim site
`corpus/knowledge/substrate-pin-guard-round23.md:36`.
The record says: "tripwire.bin is a 0755 sentinel that appears only if exec'd, turning
hash-never-exec into an assertion". The self-test never passes it to `--omp-binary` — every `run()`
call uses the tmp `mini` (`check_substrate_pins.py:330-332`). Evidence:
`grep -rn "EXECUTED"` over the repo → rc 1; `ls verifiers/fixtures/pins/EXECUTED` → rc 2. The
hash-never-exec property is real and independently measured (V3's strace, LOG.md:1231), but it is
not certified by this fixture; the sentinel is decorative.

**D3 — Five documentary sites overstate the self-test's relation to the committed fixture tree.**
Sites: `SKILL.md:465` ("`--self-test` over `verifiers/fixtures/pins/`"),
`SCORECARD.md:116` ("`0 failure(s) over 46 assertions` over `verifiers/fixtures/pins/`"),
`LOG.md:1231` (same phrase), `corpus/README.md:57` ("exits 0/1/2/3 with `--self-test` over
committed fixtures"), `corpus/knowledge/substrate-pin-guard-round23.md:34-35` (same phrase).
Evidence: the measured self-test runs over `tempfile` payloads, not the committed tree — removing
`verifiers/fixtures/pins/` entirely leaves the result at `0 failure(s) over 46 assertions`, exit 0
(`/tmp/s13b`, command above). The "over `<dir>`" clause is false as written at all five sites. The
assertion *count* (46) is correct; only the location clause is wrong. This is an erratum of the
same species as E's seven, and it sits in files E already touches (`SKILL.md`, `SCORECARD.md`,
`LOG.md`, `corpus/README.md`) — but it was **not** in the seven-site errata list, so it is a
freshly measured miss rather than a duplicate of another scout's finding.

**D4 (minor) — an operator cannot drive the committed pins fixtures through the documented CLI.**
Path: `verifiers/check_substrate_pins.py:253-254`.
Evidence: `python3 verifiers/check_substrate_pins.py --omp-binary verifiers/fixtures/pins/mini.bin
--opencode-binary verifiers/fixtures/pins/mini2.bin` → `DRIFT 3/3 pins failed` (the tmp-fixture
`--self-test` is the only mode that uses them, and it ignores them). The fixtures are unreachable
both from `--self-test` and from a normal run.

**Net: 4 defects, 3 of them one class (tracked-but-unread pins artifacts + the "over
`verifiers/fixtures/pins/`" claim that they exist).**
