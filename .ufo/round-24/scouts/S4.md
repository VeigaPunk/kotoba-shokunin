## Findings

**F1 — the 7-check set and the 75 assertions both re-derive exactly.**
`CHECK_IDS` (`:173-181`) holds 7 ids; `--check` choices agree; the live run emits
7 PASS lines and exit 0. The self-test total is **75**: `self_test()` has **52
static `rec(...)` call sites** (command 6), three of which sit inside loops that
run more than once. AST walk of the loop bodies gives the exact multipliers: the
`CHECK_IDS` loop at `:774` (1 `rec` × 7 ids = +6 over static), the opencode
drop-one loop at `:888` (3 `rec` × 6 fixtures = +15), the oc-empty-baseline id
loop at `:913` (1 `rec` × 3 ids = +2). **52 + 6 + 15 + 2 = 75**, matching the
observed `0 failure(s) over 75 assertions`, exit 0 (command 2) exactly — so the
total is fully re-derived and no assertion silently vanished. No drift from the
round-21 `70→75` record (`SCORECARD.md:75`).

**F2 — every count behind every check independently reproduces.** My own parser
(commands 7–10) — not the verifier's — found 38 inventory rows carrying a
first-cell id, 38 distinct backticked ids, an exact id-set match with the
baseline, and zero literal/kind cell mismatches. The baseline tallies
(29 governed / 9 excluded; 8 loader-group / 7 loader-config / 23 loader-literal;
omp 33 / opencode 5) match the six detail strings that quote them
(`literal_present` 38, `no_uncovered_class` 8, `table_parity` 38,
`literal_parity` 38, `kind_parity` 38, `excluded_reason` 9). Blind agreement is
check-for-check.

**F3 — the vacuity guard is real and fires in four independent places.**
`check_no_uncovered_class` (`:537-570`) FAILs when a harness dump yields 0 pairs
while the baseline declares loader-group classes for it (G1, command 12 — names
"2 loader-group class(es)"). `check_opencode_extract` (`:641-675`) FAILs on a
0-class extraction with declared opencode ids, and additionally names every
unmatched rule and every unproduced id (G2, command 13). `table_parity`,
`literal_parity` and `kind_parity` each refuse the 0-vs-0 pass with an explicit
`vacuous … is not a pass (census not landed)` detail (G3/G4/G5, commands 14–16).
The guard is not decorative: the `strings-empty.txt` fixture drives G1/G2 and the
`baseline-empty.json` + `inventory-empty.md` pair drives G3–G5, all committed.
The docstring's claim (`:96-99`, `:651-655`) that an unlanded census is red, not
green, holds.

**F4 — the verifier is hermetic in a `.git`-less export (round-24 H-axis
environment).** `git archive HEAD | tar -x` (no `.git`) then `--self-test` →
`0 failure(s) over 75 assertions`, exit 0, **stdout byte-identical** to the live

differs only in the absolute path prefix of the three `NO-SUCH` diagnostic lines
(the export lives at `/tmp/h24/s4/export`), which is expected and not a
resolution change. Unlike `verify_skill_checklist.py` (scout F8/G6: 108/1504 in

resolves its fixtures from `Path(__file__)` (`:123-124`) and the self-test passes
explicit `--repo`/`--*-strings`/`--baseline`/`--inventory` argv, so it never
touches a repo-root heuristic. This is a *positive* portability property worth
preserving; it also means the H-axis claim's export-fix work need not touch this
file.
