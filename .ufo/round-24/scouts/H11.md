## Findings

**F1 — the H patch is verifier-only, and specifically `self_test`-only.** The
live→patched diff is exactly two `argv` edits inside `self_test()`
(`/tmp/h1-r24/patched/verifiers/verify_skill_checklist.py`):

- line 1343 (was live 1343): `run()` gains `"--repo", str(DEFAULT_REPO)`
  alongside the existing `--skill` / `--map` / `--vocabulary` argv;
- line 1556 (was live 1556): the `foreign-no-map` case gains
  `"--repo", str(DEFAULT_REPO)`.

`self_test` spans 1329–1699 (AST). Neither changed line is in
`extract_boxes`, `check_box_map`, `box_line_budget` or `check_line_budget`.
Function-level AST hashing shows 37/38 top-level definitions identical and the
module docstring identical, so no check semantics, no extraction rule and no
documented contract text moved. No file other than
`verifiers/verify_skill_checklist.py` differs between the pristine and patched
trees (command 6, `diff -q` silent on `SKILL.md` and
`verifiers/checklist-baseline.json`).

**F2 — box-map invariance.** Box extraction is a pure function of the target
file plus the extraction model, and the extraction model is untouched (F1).
Measured directly: `extract_boxes` output on the live `SKILL.md` is
byte-identical under the pristine and the patched verifier (command 9) — 41
boxes, same sections, same `sha256` per box. The instrumented check agrees:
`checklist.box_map_complete PASS evaluated 41 — 41 boxes mapped (8 executed,
0 delegated, 33 unexecuted)` on both sides of every paired run (commands 10,
11, 12, 14). The map file itself is byte-identical to HEAD (command 6), so
multiset parity between live boxes and map entries cannot move.

**F3 — line-budget invariance.** The budget is bound by the checklist box at
`SKILL.md:244` (`File ≤ 600 lines …`), which lies inside the box span
**(244,246)** (command 16); that box is hashed in the map and unchanged.
`trigger.line_budget PASS evaluated 521 — 521 lines within budget 600 (from
box at line 244)` on every paired run (commands 10, 11, 12, 14), and the file
has 521 lines on both sides. The patch cannot alter the counted line set: the
only edited statements are argv construction inside `self_test`, which the
live path (`main`) never calls (`main` returns at
`verifiers/verify_skill_checklist.py:1749` when `--self-test` is set, before any
target file is read).

**F4 — end-to-end byte-invariance of live behaviour.** The strongest control is
command 10: a clone at a fixed absolute path, run three ways, then the *same
path* with only the verifier replaced. Gate stdout, `--json` stdout and
`--self-test` stdout are all byte-identical. Command 14 reproduces this for the
alternative patch shape (`fixB`). Command 12 removes the last confound — the
earlier apparent `+47 more` vs `+49 more` split between `/tmp/h11/EA` and
`/tmp/h11/EB` was a stray sibling `/tmp/h11/EA/.ufo` directory created by my own
`mv`, which changed how `../.ufo/...` governance tokens resolve; with the
pristine verifier restored in EA at the same path, both sides print `+47 more`
and the gate is byte-identical. **Environment, not patch.**

**F5 — assertion-count and non-vacuity preservation.** 1504 assertions on both
sides in every environment (commands 10–14): clone pristine 0 failures,
clone patched 0 failures, export pristine `108 failure(s) over 1504`, export
patched `0 failure(s) over 1504`. The red probe (command 15) rewords one
fixture box and both verifiers report exactly `1 failure(s) over 1504` with
byte-identical stdout — the patch does not blunt the self-test's ability to
fail.

**F6 — the H patch and the E edit cannot interact.** The E erratum site
`SKILL.md:456` (`27/27 checks`) is inside **no** box span and inside no fence
(command 16), and it is prose scanned only by `no_placeholder` /
`citation_resolves` classes that read different predicates. Simulating the E
edit (command 17) leaves line count at 521 and both
`checklist.box_map_complete` (41) and `trigger.line_budget` (521, budget 600,
box at line 244) unchanged. So landing E after H (or H after E) does not move
either H11 quantity.

## Defects named (each: path:line + evidence)

Neither defect is introduced by the H patch; both are pre-existing and bear
only on how H may be *verified*.

1. `verifiers/verify_skill_checklist.py:1755` (live) — `pinned` compares
   `skill_path.resolve()` to `DEFAULT_REPO / "SKILL.md"`, while `--repo` only
   feeds command/citation bases. Evidence: `python3 /tmp/h11/B/kotoba-shokunin/verifiers/verify_skill_checklist.py
   --repo /home/vgpnk/Projects/shokunin/kotoba-shokunin --skill …/SKILL.md`
   → `N/A checklist.box_map_complete: evaluated 0 — no map pinned … (map
   unreadable: …/map.json)` where the un-overridden live run prints
   `PASS … evaluated 41`. Any future H-adjacent change that adds `--repo`
   without `--map` silently degrades box-map coverage from 41 to N/A, so the
   `--repo`-only form must not be used to argue box-map invariance. (The patch
   itself is safe: `run()` always passes `--map`, and the `foreign-no-map`
   case passes neither, asserting N/A.) For H11 the invariance claim is
   therefore argued at a fixed path with no flag override (F4), not through
   `--repo`.
2. `verifiers/verify_skill_checklist.py:1235-1277` —
   `governance.citation_resolves` resolves `../`-prefixed tokens against the
   *parent* of the repo, so a stray sibling directory outside the tree changes
   the reported failure count (`+47 more` vs `+49 more` between two otherwise
   identical archive extracts; evidence command 12). Environmental, and the
   reason all H11 paired runs are same-path controls.

  gate flips" is asserted only for `verify_skill_checklist.py` itself.
- I did not verify that the H patch preserves `--repo` semantics for *live*
  invocations with a non-default repo root (e.g. a sibling skill directory as
  `--skill`); only the default-root live path (command 10) and the fixture
  paths (self-test) were exercised.
- Line-budget invariance was measured at the 600-line bound only; a target file
  near the bound was not constructed, so "no threshold-adjacent behaviour
  change" rests on the structural argument (untouched `check_line_budget` /
  `box_line_budget` ASTs) rather than on a boundary probe.
