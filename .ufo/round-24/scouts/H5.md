## Findings

1. **Non-vacuity HOLDS, for both patch shapes.** In live and in the patched
   `.git`-less export: `delegated-directory` and `delegated-noninstrument` still
   FAIL `checklist.box_map_complete` with `not an instrument` (rc=1), and both
   box-tamper forms still FAIL `checklist.box_map_complete` (rc=1). The five
   self-test non-vacuity assertions on the instrument-ness rule are intact
   (`grep -c "not an instrument"` = 5). Neither fix silences a red probe.
2. **Both shapes are effective and minimal.** Export `--self-test` goes
   108/1504 rc=1 → 0/1504 rc=0; assertion count stays 1504; live stdout
   byte-identical (empty `diff`) for `--self-test` and the default run.
3. **F8 root cause is `find_repo_root`'s `.git`-only heuristic (:386).** Fixtures
   already resolve via `__file__` (`FIXTURES = VERIFIERS_DIR/"fixtures"/"checklist"`,
   :271). With no `.git` ancestor, `find_repo_root` returns the skill's own
   directory (a fixture dir under `--self-test`), so repo-root resolution of
   `LOG.md`/`SCORECARD.md`/`corpus/…` fails. Failure taxonomy of the 108:
   79× `FAIL governance.citation_resolves`, 18× `FAIL checklist.box_map_complete`,
   10× `FAIL trigger.citation_resolves`, plus paired `N/A-allowed` assertions;
   even the `clean` fixture FAILs in the export on `governance.citation_resolves`
   alone.
4. **The two shapes are equivalent under every probe here**, which is useful for
   the H lane: `--repo` in the self-test argv and the `find_repo_root` fallback
   both reach 0/1504 with identical live output. Choice between them is a
   scope/style decision, not a correctness one (H1 argues `--repo` keeps the
   fallback correct for foreign targets; the FR fallback is guarded by
   `FIXTURES in …parents`, so it also leaves foreign targets untouched).

## Defects named

- `verifiers/verify_skill_checklist.py:386` (`find_repo_root`) — the `.git`-only
  heuristic is not export-safe: with no `.git` ancestor it returns the skill's
  own directory (a fixture dir in `--self-test`), collapsing repo-root
  resolution. Evidence: `/tmp/h5-r24/export0` `--self-test` = 108/1504 rc=1
  (`FAIL governance.citation_resolves … unreadable … fixtures/checklist/clean/LOG.md`);
  live = 0/1504 rc=0. This is the H-claim target (F8).
- (scope note, not a defect) `verifiers/verify_skill_checklist.py:1340-1343` —
  the self-test fixture argv omits `--repo`, so the self-test's greenness depends
  on the checkout carrying `.git`. The claim's stated locus ":386-392
  fixture-resolution fallback" is imprecise: fixture *paths* are already
  `__file__`-relative; the two candidate fix sites are :386 (`find_repo_root`)
  and :1340/:1553 (self-test argv).
