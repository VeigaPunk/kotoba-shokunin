## Findings

**F1 — The class is live at HEAD and wider than M8 recorded.** M8 (round 21) and G1 D1
(round 22) named one trigger: a deleted-but-still-tracked corpus file. It is really **four
crash classes** — deleted/absent path, dangling symlink, directory in the file's place, and
unreadable permission — each tracebacking at `verifiers/verify_corpus_independent.py:313`
(pointer pass) where the primary exits 2 with `INCONCLUSIVE`. The pointer pass runs before the
commit pass, so line 346 is unreached in these worlds but is identically unguarded.

**F2 — A fifth crash site the prior scouts did not name: `README.md` as a directory.**
`analyse()` gates on `os.path.exists()` (`:385`), which is true for a directory, so the guard
passes and `coverage_cells` dies at `:205` with `IsADirectoryError`. The primary catches this
(`index not readable`). The `:203` guard is also shadowed — `analyse()`'s `:385` check fires
first in every reachable path — so it is dead code today and only becomes load-bearing after
the `:385` fix.

**F3 — The invalid-UTF-8 class is not only the independent script's problem; the primary
silently mis-measures.** For byte corruption *appended* to a corpus file the primary exits
**0** (its reader uses `errors="replace"` at `verify_corpus_integrity.py:455,484`), i.e. it
reports a green verdict on a corrupted corpus file. For a wholly binary file the primary
exits **1** but prints a **false `8/9 checks pass`** and a spurious
`DRIFT corpus.pointers.report_total: observed=32 expected=36` — it decoded 52 of 53 files
because the corrupted file raised before being counted, so its own numbers are a 1/53
measurement shortfall presented as a verdict. This is the sharper finding of the two: the
primary's `errors="replace"` is a *verdict-altering* choice, not just a robustness gap, and
`errors="replace"` never fails closed.

**F4 — The fix is one helper plus one predicate, and it is fully verifiable.** See sketch
below. All five exit-1 crash classes become exit 2 with `INCONCLUSIVE` (matching the
docstring's exit contract at `:29` and the primary); the clean-tree observation is
byte-identical; `--self-test` stays 52/0; the fault harness output is byte-identical.

**F5 — `errors="replace"` must NOT be copied from the primary.** Variant A
(`errors="replace"` on the independent reader) turns both byte-corruption worlds green:
`--self-test` then passes on a corrupted corpus tree, and a corruption that kills a pointer
citation would silently drop the promise instead of failing. The primary's own false green
(F3) is the proof that this idiom trades a crash for a wrong answer.

**F6 — Only full-fidelity decoding closes the byte-corruption class, and it belongs in a
separate move.** Variant C (`errors="surrogateescape"`) is byte-exact on round trip and makes
both byte-corruption worlds exit 0 — it would let a corrupted file be *ignored* rather than
reported. The honest fix for that class is a guard that decodes strictly and converts failure
to `EnvError` (fail closed, exit 2), which is a behavior change to a currently-crash-only path
and therefore a distinct claim from F4; it should not be smuggled into this one.

**F7 — The class is invisible to every gate that exists.** No repo gate executes the
independent instrument on a mutated corpus: `fault_injection_corpus.sh` plants a–h, all of
which are *readable* worlds (the planters only append/replace text or `git add`), so
`run_independent` never meets an unreadable file. Nothing else invokes the script except
advisory re-runs recorded in `SCORECARD.md:29` / `corpus/knowledge/*`. The crash class is
therefore reachable only by hand, exactly as M8 found.

## Fix sketch (drafted only; live script NOT patched)

Copy: `/tmp/h24-H8/fix/verify_corpus_independent.py`, sha256
`e3f53ef199282dab5d3496550dd82e034d1791d50e0d3af68943d4d0ee054b10`; diff
`/tmp/h24-H8/fix/sketch.diff` (56 lines, 4 hunks). Five edits, no new imports:

```diff
+def _open_text(path, label):
+    """Open a corpus file, or raise EnvError (exit 2) when it cannot be read."""
+    try:
+        return open(path, encoding="utf-8")
+    except OSError as exc:
+        raise EnvError("cannot read %s: %s" % (label, exc)) from exc
```
1. new `_open_text` helper next to `_git` (`:64`);
2. `coverage_cells` `:203-205`: drop the shadowed `os.path.exists` guard, open via
   `_open_text(readme, "corpus/README.md")`;
3. `analyse_pointers` `:313`: `with _open_text(path, rel) as fh:`;
4. `analyse_commits` `:346`: same;
5. `analyse` `:385`: `os.path.exists` → `os.path.isfile`.

Notes on the sketch:
- `OSError` also covers `UnicodeDecodeError`'s neighbours only partially — `UnicodeDecodeError`
  is a `ValueError`, not an `OSError`, so the byte-corruption class stays a traceback under
  this sketch (variant B: exit 1 on `badutf`/`content`). That is deliberate: F6.
- `rel` as the label makes the message repo-relative and greppable, matching the primary's
  `cannot read tracked file <rel_repo>` idiom; the full absolute path is still in the `OSError` text.
- Optional fifth-touch follow-up, only if the docstring is to stay exact: `:58`'s EnvError
  docstring ("not a git repo, corpus/ or corpus/README.md absent") would gain "or a tracked
  corpus file unreadable".

   exits 1 dying in `unread` with `FileNotFoundError`; `ft` (sketch + the same cases) exits 0

   four places and every one must be updated in the same move, or claim E's "every recorded

   `corpus/knowledge/independent-verification-round12.md:18` and `:281`;

   stays byte-identical under the sketch (command 4) — which is the property to preserve.
7. **Do not add an `errors="replace"` fixture** (F5): a case pinning "corrupted bytes are
   tolerated" would be pinning the wrong verdict.
