## Findings

- **ID aliases.** Frozen `6fbbff5` accepts a record with `check="alias.row", name="alias.other"`; paired with a clean second row, this produces exit 0 at 2/2. Candidate `a2bf6a2…` rejects the same split as `record id conflict` (and rejects differing string `check`/`id`/`name` aliases together); see comparator `_record_id`, `verifiers/compare_harness_independent.py:265-273`. NFC `unicode.café` vs NFD `unicode.café` in the two aliases is also rejected by the candidate's exact-string check. However, a present non-string `check` (`[]`) plus string `name="alias.row"` is silently ignored and accepted; the validator only reconciles string aliases.

- **Independent value aliases.** Frozen bytes accept `value=1, observed=999` and `re_derived=1, observed=2`; `value`/`observed` can produce exit 0 at 1/1 when the selected `value` matches live. Candidate rejects conflicts among `re_derived`/`value`/`observed`, including `value`/`observed` (see `verifiers/compare_harness_independent.py:335-345`). **Remaining door:** candidate accepts `expected=1, expected_value=999`, selects `expected`, and joins live `1` at exit 0, 1/1. The candidate only reconciles expected-side aliases against derived aliases, not against each other (`:337-362`). Add this pair to the C2 fixture battery.

- **Status/state.** Both frozen and candidate reject string `status="DERIVED", state="UNLANDED"`; agreeing strings parse. Candidate still accepts a lone non-string status (`status=["UNLANDED"]`), omits it from the captured status map, and joins equal values at exit 0, 1/1. This is a malformed-status silent-ignore case, not a string alias-precedence pass; whether it is in-contract depends on whether status fields must be type-checked. The relevant conversion is `verifiers/compare_harness_independent.py:277-285`.

- **Live `value`/`observed`.** Candidate `parse_live` accepts `value=1, observed=2` and uses `observed=2`. A live payload with `observed=1, value=999` can join at exit 0 when independent says `1`. This is not a false-green under the declared live contract, which reads only `observed` (`LIVE_VALUE_KEYS`); `value` is ignored, not treated as a competing live alias. If the builder intends to reject unexpected/contradictory value fields on live records, it needs a separate test.

- **Verdict/mode.** These are not synonyms: `mode` chooses the comparison predicate, while `verdict` is checked for non-PASS after joining. `verdict="FAIL", mode="equal"` with equal values exits 3; `verdict="PASS", mode="not-a-mode"` exits 1 as un-adjudicated. No green was observed; do not make them equal-value aliases.

- **Substring and Unicode-normalized IDs.** `probe.item` and `probe.item.extra` remain two exact keys, without substring collision. Record lists accept NFC and NFD spellings as distinct IDs (the dotted-map grammar rejects the non-ASCII spelling). If both live and independent records carry both spellings, candidate joins 2/2 at exit 0; if one side has NFC and the other NFD, it exits 2 with unknown/uncovered IDs. The mismatch fails closed, but the comparator does not normalize record IDs; decide whether Unicode canonical-equivalence is allowed before claiming this boundary closed. These are synthetic-only shapes, not incidences in the real harness payload.

The frozen→candidate improvement is confirmed for string ID aliases and independent derived aliases; operability is **improved, not complete**. The specific leftover independent alias (expected/expected_value) is a direct C2-builder miss. The self-test does not cover that pair or the single non-string status case.
