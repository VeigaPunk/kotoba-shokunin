## Why C1 remains open

The R1 payload has a record-bearing `results`/`rows` pair and a 28-key `checks` map. For each of the 24 non-scoped IDs, its record's only value field is `expected`, copied from the live observation; each of the four scoped-out rows has `expected: null` and retains its valid `SCOPED_OUT` status, committed reason and recomputable probe. The map repeats those same values and nulls, so channel value/membership reconciliation succeeds. Both the record-free map-key guard and the scope-value guard then miss the laundering:

- `check_independent_scope_maps` returns as soon as a record list exists (`verifiers/compare_harness_independent.py:684-709`), so it does not check the companion map's IDs against the committed derived set.
- `check_independent_scope_values` rejects a scoped-out value only when it is non-`None` (`:712-721`); the four `null` values pass.
- The record parser accepts `expected` as a value key, and the channels agree. Copying the live values into those expected-only records makes the 24 joined rows strict-agree and removes the honest payload's four adjudications.

The own map/list arm fails on channel membership because its list omits the added scoped ID; the `expected` wrapper arm fails on the explicit value-map-override contract. Those do not cover the fully aligned R1 record+map case. The existing 28-value fixture also rejects a different shape: its scoped IDs carry ordinary non-null values and do not reproduce the valid scoped-out/null-value composition.
