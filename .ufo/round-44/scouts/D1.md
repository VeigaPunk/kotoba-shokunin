# D1 | deep-record-channel — Round 44, loop A position 8

## Finding

The scope-derived key-set guard is **map-only in record-free payloads**. In the current comparator, a record list makes `check_independent_scope_maps()` return before it inspects *any* accompanying dotted maps. The later `check_independent_scope_values()` does inspect the parsed independent values from both record and map channels, but rejects only **non-`None` values** for committed scope-out IDs. Thus non-null scoped-out record values are caught; a null scope-out value/key in a record-bearing map/list composition is not rejected by either scope guard. `_reconcile()` makes the representations agree with each other, but does not bind their common ID set to the committed derived set. That is the composition seam.

This is a source-path finding on the current comparator bytes; I did not freshly replay R1's composed payload against those bytes. The historical green result below is specifically pinned to a prior candidate and must not be reported as a current end-to-end reproduction.

1. **Independent record and row-channel parse — `parse_independent()` → `_channel_maps()` / `_reconcile()` (`verifiers/compare_harness_independent.py:283-422,437-515`).** `_channel_maps()` visits every non-null `results`, `rows`, and `checks` channel. A list is read record-by-record: `_record_id()` selects the first string among `check`, `id`, `name` (`:265-269`); value selection takes the first present key from `IND_VALUE_KEYS` (`:315-319`; the record-only `expected` form is explicitly accepted at `:326-329`); status/state is attached to that row (`:350`).    `_reconcile()` checks every parsed channel for canonical value agreement, exact membership equality, and agreement where both channels have a status (`:372-422`). This catches a divergent record/map pair and mismatched row counts. It does **not** check that the shared IDs are a subset of `live IDs − committed scope-outs`. A consistent record list plus `checks` map can therefore pass channel reconciliation even when both contain committed scope-out keys.

2. **Map-only shape/fallback readers — `parse_independent()` and `check_independent_scope_maps()` (`:458-515,663-688`).** With no row channel, `parse_independent()` tries dotted maps in `checks` → `expected` → `re_derived` → `observations` order, then a bare top-level dotted-ID map (`:502-509`). These return the first valid map; they are not cross-reconciled as simultaneous wrappers. If `checks` is a dotted map *beside a record list*, it is instead a direct row channel handled by `_channel_maps()` and `_reconcile()` above.

   `build_meta()` calls `check_independent_scope_maps()` **before** `parse_independent()` (`:2057-2061`). The guard computes `derived_ids = set(live) - set(committed)` and rejects any collected map whose key-set exceeds that set (`:667-687`), including null-valued excluded keys. But its first branch, `if _record_list(payload) is not None: return True` (`:663-665`), bypasses all map inspection when any supported record-list exists. This is why the same map key-set is protected in a map-only payload but not a mixed record+map payload.

3. **Scope-out value check — `check_independent_scope_values()` (`:691-700`), after parsing.** This checks the flattened `independent` mapping, so it covers values that came from a record list as well as a map. For each ID in committed-scope ∩ live ∩ independent, it errors only when the value is not `None`. It is a value check, not a key-set check: `None` for a committed scope-out row passes here. On a record-free map the earlier map guard has already rejected the excluded key; on a record-bearing payload that guard skipped, making `None` the relevant gap.

4. **Scope declaration/probe validation — `parse_scoped_out()` and `check_scope_probes()` (`:613-660,830-910`; calls at `:2059-2072`).** The payload's optional `scoped_out` declaration is checked for IDs present in the parsed independent result, a record status exactly `SCOPED_OUT`, and a nonempty reason. `check_scope_probes()` checks status/declaration splits, rejects uncommitted declarations, and recomputes probes for declared exclusions. These checks validate the declared exclusion/probe channel; they do not impose the derived-ID key-set constraint on the record/map value channels. Note the separate read shape: `parse_scoped_out()` obtains statuses through `_record_list()` (the first list found), whereas `_channel_maps()` parses every row channel.

5. **Join and adjacent readers (`:564-610,518-544,2063-2098`).** `compare()` removes IDs declared in the validated `scoped_out` mapping from the join; it does not sanitize the independent map's key set. `parse_live()` reconciles live direct channels using the live `observed` value contract, then uses `_record_list()` for observed/verdict/mode records. `build_meta()` also uses `_record_list(live_payload)` to read live `expected` values for `secondary_agree`, whose numerator now iterates joined `res["rows"]` only. The independent `scoped_out_probes` map has precedence; record `probe` fields are fallback when that map is empty (`:2063-2072`). These are not substitutes for the independent-record scope-key check.
