## Ranked findings

### 1. HIGH — expected-only record payload still passes and erases adjudication

The `heldout-expected-only-full-copy` arm exits 0 on both frozen and candidate comparators with protocol 24/24, four rows scoped out, zero disagreements, and **zero adjudicated checks**. The honest control also exits 0 at 24/24, but has four adjudicated checks. Thus the payload changes adjudication from 4 to 0 without making the run red. Its payload SHA-256 is `c58694de3d21a51a1f6a8fc72edd36dab37bf4384b40a13bc56bf8f92022b3f7`.

This arm carries `results`/`rows` records whose 24 in-scope values use only `expected` rather than derived-value fields, plus a 28-key `checks` map. The four committed scope-out ids remain present in that map with `null` values. Candidate `check_independent_scope_maps` returns early as soon as a record list is present (`.ufo/round-43/drafts/r1/compare-worktree-snapshot.py:663-688`), so it never checks that map's key set against the 24-id derived set. `check_independent_scope_values` only rejects non-null scoped-row values (`:691-700`), so the nulls pass. This is precisely the record+map cross-channel boundary: map membership is bypassed by publishing records, and expected-only rows are accepted despite eliminating the baseline adjudication.

**Next closure:** validate every map channel even when record lists coexist (or reject the mixed shape), enforce the derived-set key boundary including null-valued scope-out keys, and ensure row values used for adjudication are actually derived rather than expected-only.

### 2. The plain full-map overflow guard works for tested non-null map forms

On the frozen comparator, the flat 28-value map and nested `checks`, `expected`, and `observations` maps each exit 0 at 28/28. The candidate rejects each with exit 2 and `derived-set overflow`, naming the offending map and keys outside the honest derived set. A conflicting `expected` + `observations` map pair is also rejected exit 2 as competing value-map aliases.

The direct extra-key controls also fail closed: `flat-plus-unconstrained-id` and `nested-checks-scored-plus-unconstrained-id` add `attacker.extra`; the candidate exits 2 with `derived-set overflow` naming that key. The latter is the isolated check that tests a non-scoped map with a key outside the derived set.

### 3. The scored-only map changes adjudication but does not produce a false-green

`nested-checks-scored-only-adjudication-mutant` changes one adjudicated check's map value to the live observation. Its candidate JSON reports `n_adjudicated=0` and `n_uncovered=4` (headline 24/28), but the comparator exits 2 because the four scoped rows are absent. The map therefore changes adjudication, as requested, while the coverage error prevents a green verdict. A payload-only `scoped_out` declaration cannot hide those missing rows: the companion arm exits 2 because the declaration names `omp.catalogue.found` absent from its records.

### 4. Deeper wrapper and precedence controls reject

A two-level `expected.values` wrapper exits 2 as not keyed by check id. Competing `expected` and `observations` aliases exit 2 with `competing value-map aliases`. These controls did not reproduce the high finding; the surviving shape is the expected-only value placed in ordinary record channels alongside a map.
