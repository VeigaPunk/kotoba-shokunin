- **Absolute symlink to scope file:** exit `0`; the sole synthetic row was scoped out. Receipt kept the lexical symlink path and recorded SHA-256 `187729b814343c6d7060db4e6bb94e4f90b9058d2131dc33f9412aab6c8a250e`, matching the stable target bytes. No mismatch reproduced.
- **Scope file through symlinked directory:** exit `0`, same synthetic `0/0` result. Receipt scope-file SHA-256 `fdbd97e2adff8eed246fdbb5a3e3af76abdaffb36bc0772cd466b99768625d583` matched the stable target bytes. No mismatch reproduced.
- **Relative scope argument with different process CWD and `--cwd`:** exit `0`, headline `0/0`, but the path split reproduced. `load_scope_file` enforced the file found relative to the planted process CWD (SHA-256 `2e64fb2ea3464797fca20749afcc86b06ddf965bcf3169a636f18581e9de4be8`); receipt resolution used `--cwd` and attested a different file (SHA-256 `184e1e31b63dd5b22d997f7a27ee2ce0985fbb6d989d9894c9a141fb635e6cc7`). The receipt's committed set was `["a.b"]` although the file it hashed was the empty scope. This is the open F3' receipt/enforcement mismatch.
- **Absolute scope path outside the repository:** exit `0`, synthetic `0/0`; receipt hash `187729b814343c6d7060db4e6bb94e4f90b9058d2131dc33f9412aab6c8a250e` matched the selected external file's bytes. This shows the caller can explicitly choose an external scope file. It does not show a payload-only way to alter the scope trust input. If policy requires committed/repository-contained scope, path containment must be enforced separately.

In the frozen source, `load_scope_file` reads `Path(path).read_text()` at `verifiers/compare_harness_independent.py:793` (invoked with `args.scope_file` near `:2171`), while `render_receipt` resolves a relative scope path against `cwd` near `:1415-1421`. Recommendation: resolve the scope path against `--cwd` once, load/capture those exact bytes once, and derive the receipt path and digest from that same object. Receipt re-reading leaves an untested symlink-retarget/TOCTOU possibility; no retarget race was tested, so this report does not claim it is exploitable.
