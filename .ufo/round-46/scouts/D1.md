# D1 | Deep scope-file path map — Round 46

## Finding

On the frozen `055d3b9` comparator, the scope file is not resolved once. Enforcement opens a relative `--scope-file` under the driver's **process CWD**; receipt rendering independently opens that same relative string under resolved `--cwd`. Those paths can differ. The receipt records the original relative string, a digest from the `--cwd` path, and the committed ID set parsed from the process-CWD path; it does not record the resolved path or digest of the bytes actually parsed. The source locations below refer only to frozen comparator SHA-256 `1101213a7bed5410151564aeb5a4b49030a4821c86e7469286f046253fbc51e4` (`git show 055d3b9:verifiers/compare_harness_independent.py | sha256sum`).

These are separate from scope resolution. |
| Self-test scope paths | `fixture_battery()` at `:1285-1343`; inline scope test at `:1823-1854`; receipt assertion at `:2004-2011` | Fixture scopes are constructed from absolute `FIXTURE_DIR`/`case_dir` paths and passed as `--scope-file`; the inline probe uses an absolute temporary scope path. The receipt assertion checks the default path string and that a digest exists, not that the digest identifies the bytes `load_scope_file()` parsed. These tests do not exercise a relative scope argument with process CWD different from `--cwd`. |

The exact split is therefore:

```text
load/enforcement: Path(args.scope_file)                 -> process CWD / relative argument
receipt digest:   Path(meta["scope_file"]) -> cwd / relative argument
receipt path:     raw meta["scope_file"]                -> no resolved source path recorded
```

A relative argument is consistent only when process CWD and resolved `--cwd` are the same directory. An absolute scope path avoids this particular relative-path split. Even in the consistent-path case, this code parses the file during `build_meta()` and rereads it later for the receipt, so the digest is not bound to the exact parsed bytes if the file changes between those reads.
