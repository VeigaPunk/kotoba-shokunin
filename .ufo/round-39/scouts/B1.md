### F6 — Shape traps found while rebuilding the probes (recorded, not smoothed)

1. **Channel preference.** `compare_harness_independent.py`'s `parse_independent`
   / `_record_list` returns the **first** of `("results", "rows", "checks")`.
   IND publishes **both** `results` and `rows`, so a probe mutating only `rows`
   measures nothing — arm 5: `rc=0`, "all checks agree", while `rows` said 5 and
   live said 7. My first three D1 arms were silently invalid because of this.
2. **Corpus-gate world requirements.** The gates need a **git repo** and read only
   **backticked column-2 tokens inside the coverage section**; a throwaway world
   without them reads `unindexed=3` and a naive probe reports a false "fail-safe".
   My first C3 matrix reported `0 silent false-PASS` for exactly this reason —
   a false negative in my own instrument, caught by reading the gate output
   instead of trusting the exit code.
3. **Exit code is not the verdict.** `verify_corpus_integrity.py` returns **rc=3**
   when no baseline is present *while still naming the unindexed rows*, so
   `rc != 0` cannot be read as "the gate noticed".
4. **Byte-source mixing.** A world built from HEAD guard bytes plus a **live**
   registry produced an unrelated `floor drift` early-return that masked the crash
   being measured. Fixed by freezing guard and registry from the same source.
5. **Probe-location error (mine).** I first ran HEAD-byte copies of the corpus
   gates from `/tmp`, which made them report `not a git repository` and produced a
   spurious "stdout differs" byte-invariance result. Re-run from the repo root
   with `--repo .` → IDENTICAL.
