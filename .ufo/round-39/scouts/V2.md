### F-7 NEW DEFECT (HIGH, inherited): identical non-empty readings on a `zero` row are named a disagreement

The `zero` predicate is `is_empty(live) and is_empty(ind)`
(`compare_harness_independent.py:145-146`). An **identical non-empty** list
fails it, so `strict=True, protocol=False` — the driver reports a disagreement
between two instruments that measured exactly the same thing:

```
$ python3 - <<'PY'   # false-disagree-final.txt, both payloads planted identically
baseline : exit 0  all checks agree, both instruments green
identical non-empty on a zero-mode row: exit 1
   NAMED DISAGREEMENT: {"check": "oc.log.init_count_monotone",
                        "independent_expected": ["5->1"], "live_observed": ["5->1"],
                        "mode": "zero"}
```

Shape table (computed from the driver's own functions):

| live | ind | strict | protocol(zero) |
|---|---|---|---|
| `[]` | `0` | False | True (adjudicated) |
| `["3->1"]` | `["3->1"]` | **True** | **False** ← defect |
| `["3->1"]` | `["3->2"]` | False | False |

End-to-end through my matched-tree join: three of eight logs
(`log-e-two-runs`, `log-f-mixed`, `log-h-two-runs-incr`) read
`disagreements: oc.log.init_count_monotone (mode=zero: expected ["3->1"],
observed ["3->1"])` — identical on both sides. Receipts:
`join-FINAL/log-e-two-runs.cmp.txt`, `join-FINAL-table.txt`.

**Inherited, not introduced:** the same predicate at the r38 landing commit
gives `predicate_agree("zero", ["3->1"], ["3->1"]) == False`. It was invisible
because both sides were always empty (0/[]), which is precisely the zero-delta
agreement R1-D2 warned about — the fix that makes the row detect violations is
also what exposes this. The comparator's self-test has no arm for the shape
(`:996-1003` covers `[]`/`0`; `:1096-1107` covers `[]`-vs-`0` adjudication).
**Consequence for C1's counting:** the "mutant leg" cannot go green on a real
violation while this stands — a nonzero violation list on the row is always a
named disagreement, even when both instruments agree exactly.
