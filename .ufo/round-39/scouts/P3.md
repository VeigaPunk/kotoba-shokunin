## 2. The fix

One predicate, one message, and no derivation off a rejected row.

- `row_problem(name, spec)` — the single source of truth for row soundness: rejects a non-5-field
  tuple, a non-`str`/empty path, and a non-`int` floor with `bool` excluded. It returns the
  finished message, so callers append it verbatim and cannot re-introduce the contradiction by
  formatting a rejected row's own fields.
- `_row_parts()` returns `(None, None)` for a row failing the field tests too.
- `registry_drift()` checks BOTH tables' fields (the EXPECTED table's value is what the drift line
  prints as `expected`); `registry_anchor_drift()`'s round-38 `row_path is not None` suppressions
  are gone; `main()`'s `repo / spec[0]` join and `override_drift()`'s canonical map both consult
  the predicate, so no reordering can reach them with a bad row.
