# Scout T1

## Task

Design an assertion-floor guard against self-test blocks being deleted while their instrument still exits green. The specified `.ufo/round-27/scouts/X10.md` is absent; use the matching prior evidence in `.ufo/round-26/scouts/X10.md` and round-29 claim T.

## Commands

- `Read .ufo/round-27/scouts/X10.md` → missing. `.ufo/round-27/scouts/` contains no X10 fragment.
- `Read .ufo/round-26/scouts/X10.md` → X10 F3: deleting `verify_surfaces.py`'s (b2) block changes 75→72 assertions but returns 0; its printed count was not enforced.
- Ran `python3 -B <instrument> --self-test` for all six current instruments; all rc=0: harness 10, corpus_integrity 88, corpus_independent 52, surfaces 82, checklist 1504, pins 51 assertions. Corpus-independent reports `self-test: 52 assertions, 0 failures`; the others report `0 failure(s) over N assertions`.
- `git status --short` after probes showed only untracked `.ufo/round-29/` and `.ufo/reports/round-29/`; no verifier changes from these runs.

## Findings

- Add `verifiers/verify_assertion_floors.py`; CLI: `python3 verifiers/verify_assertion_floors.py [--repo ROOT] [--floors PATH] [--json] [--self-test]`. Defaults are this repo and `verifiers/assertion-floors.json`; paths in the table are repo-relative.
- Use a small `kotoba-assertion-floors-v1` JSON table of `{id, script, floor}` rows: `harness / verifiers/verify_harness_claims.py / 10`; `corpus_integrity / verifiers/verify_corpus_integrity.py / 88`; `corpus_independent / verifiers/verify_corpus_independent.py / 52`; `surfaces / verifiers/verify_surfaces.py / 82`; `checklist / verifiers/verify_skill_checklist.py / 1504`; `pins / verifiers/check_substrate_pins.py / 51`. Keep an exact required-ID→script registry in guard code; reject missing, duplicate, or extra rows so the table cannot silently omit an instrument. Floors are positive integers and mean minimums, not equality; raise them deliberately when assertions are added (the current corpus-independent count is 52; “+new” must become an explicit integer increase).
- Run each fixed `sys.executable <repo-relative-script> --self-test` (never shell-join), collect output/rc, parse exactly one anchored summary: `N failure(s) over M assertions` or `M assertions, N failures`. Pass an instrument only if rc=0, failures=0, and M≥floor. Emit stable instrument IDs and observed-vs-floor details; `--json` carries per-instrument results and `exit_code`.
- Exit ladder: 0 all six pass; 1 child self-test failure or M below floor; 2 missing/unlaunchable/timed-out instrument or absent/ambiguous summary (protocol/environment unreadable); 3 missing, malformed, or schema-invalid floor table. Precedence 3>2>1>0. Never rewrite floors or baselines.
- Read-only/hash-only: hash only each instrument script before/after its self-test; detect and report byte changes. Guard reads the floor table and output, invokes only `--self-test` (no live gate or installed binaries), and writes nothing in the repo. Existing self-tests that need scratch data use temporary directories.
- Guard `--self-test` should test both summary formats, floor validation and exit precedence, then make a `/tmp` copy with the surfaces (b2) self-test block removed and prove the guard reports `surfaces observed=72 < floor=82` / exits 1; never mutate the live tree.

## Defects

1. No assertion-floor enforcement exists; X10's deletion probe is a confirmed false-green (75→72, rc=0).
2. The specifically requested round-27 X10 artifact is missing; its same finding is substantiated by round-26 X10 and the round-29 claim.

## Limits

This is a design slice only; no guard/table implementation or `/tmp` deletion probe was created here. Floors are measured from current HEAD's self-test outputs and need intentional review when suites grow; assertion count is a quantity check, not proof that each assertion is meaningful.
