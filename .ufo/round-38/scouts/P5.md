**Defect found in V6's battery auditor (mine, fixed).** `verify_battery.py`'s
cmark classifier decided fenced-vs-indented by *absolute* columns
(`cols <= 3 and FENCE_RE.match(body)`), so it called the new four-column
container fences indented code and reported 2 spurious FAILs. Fixed to the
window-based classification (V6b's method): a block is fenced when the
`start+1..end-1` or `start+1..end` window reproduces the node text. This is an
audit-harness bug, not an instrument bug — but it is the same blind spot the
instrument had, which is why it did not catch the class at r37.
