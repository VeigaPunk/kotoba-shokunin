**A/B attribution (only the governance bytes differ, real repo elsewhere):**
```

$ git log --oneline -S'{P5,P6,V4,V5,I1,I2,S2}' -- SCORECARD.md -> c8e233d
```

**Mechanism:** the tokenizer skips tokens containing `*<>?$`
(`verify_skill_checklist.py:1361`). Every older brace-glob row wrote
`.ufo/round-2{1,3}/scouts/{F,M,R,S}*.md` — the `*` makes it a counted
*schematic* and it is skipped. r37's three rows dropped the `*`, so each brace
token is taken as a **literal path subject** that cannot resolve. Verified:
```
`.ufo/round-21/scouts/{F,M,R,S}*.md`   -> subjects=[]                 (skipped)
`.ufo/round-37/scouts/{P5,...}.md`     -> subjects=['...{P5,...}.md'] -> resolves=False
```
So r37's landing commit turned a previously green gate red, and r37's report did
not record it. **Every r38 claim's "pre-existing gates byte-invariant"
requirement is currently measured against a red baseline.** `--self-test` is
unaffected (`exit 0`), and the per-seat paths themselves are fine — all 7
`S2.md`-style files exist and are tracked (26 files in `.ufo/round-37/scouts/`).
