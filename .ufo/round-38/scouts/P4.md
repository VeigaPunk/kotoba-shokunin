## 2. The fix (3 edits, all in `verifiers/check_assertion_floors.py`)

1. `registry_drift()` — a pre-flight scan of both tables naming every non-str key
   (`non-string key: <TABLE> has <repr> (instrument names must be str)`) and returning
   before any `"…" + n` concatenation or `sorted()` can touch a key.
2. `main()` — fail-closed short-circuit: if `registry_drift()` reported a non-string key,
   print and return 2 **before** calling `registry_anchor_drift()`. This is load-bearing,
   not cosmetic: the anchor's own `sorted(set(INSTRUMENTS) - set(entries))` raises
   `TypeError: '<' not supported between instances of 'str' and 'NoneType'` against a
   mixed-type key — a **second crash site V4's report did not name** (my F12b fixture
   caught it; see §4).
3. `_row_parts(spec)` — returns `(path, floor)` only for a well-formed 5-field tuple,
   else `(None, None)`; the anchor's call site now guards both derivations on
   `row_path is not None`, so a malformed row is named once and nothing is derived
   from it.
