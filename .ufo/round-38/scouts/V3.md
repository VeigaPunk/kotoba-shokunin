## Method (rig: `drafts/v3/battery.py`)
Sandbox `HOME`-shaped mirror under `/dev/shm/v3-r38/base` so BOTH instruments
run against an arm (the harness resolves from `$HOME`; IND takes the same paths
as flags). Arms are `cp -al` clones (KB each; the 253 MB binary is one copy in
the base). Two hazards found and fixed while building, both mine:

1. **WAL leak (HIGH, found by self-check).** The live db is WAL-mode; copying it
   and then opening it read-only created `-wal`/`-shm` siblings, which `cp -al`
   then hardlinked into every arm — an arm's sqlite write reached the BASE
   through the shared log (base db 14→15 rows, one key corrupted). Fixed by
   converting the base copy to rollback-journal mode and unlinking
   `skill-descriptions.db-*` in each arm. The base-integrity receipt
   (`out-final/base-receipt.json`) now asserts mirror == live; `base` arm
   `sandbox harness == live harness` passes with `differing ids: none`.
2. **Non-genuine mutation arms (MEDIUM, mine).** Two of my arms mutated a
   surface only IND reads (a `"init count"` quoted form the harness's regex
   misses; a `skills="x"` attribute). Fixed to the adjudicated/shared grammars.
   Every F arm now also records the harness's own moved ids
   (`arm-<name>-harness-moved.json`), so "genuine substrate mutation" is
   measured, not asserted.
