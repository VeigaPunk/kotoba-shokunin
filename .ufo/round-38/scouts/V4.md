## 4. NEW bypass hunt — **the fix introduces a regression** (headline finding)

`pins` row path set to `None` (still a 5-field tuple):

| bytes | rc | output |
|---|---|---|
| HEAD `162006498182` | **2** | `FAIL registry path drift: pins registry=verifiers/check_substrate_pins.py row=None` (named) |
| in-flight `3ee2b34d` | **1** | **Traceback**: `TypeError: unsupported operand type(s) for /: 'PosixPath' and 'NoneType'` at `paths = {name: repo / spec[0] for …}` |
| at-report `d63443a1` | **1** | same traceback (`out/FINAL-P-nonstr-path.txt`) |

Mechanism: the new suppression guards at `:185`/`:187` —
`if row_path is not None and row_path != entry["path"]` — mean a `None` path appends **no**
drift line, so `main()` never returns early and falls through to the `repo / spec[0]` join.
**A named exit 2 was turned into an uncaught TypeError**, i.e. the exact defect C2a exists to
close, reintroduced on an adjacent shape. Bounded by value (`out/PATH-VALUE-BOUND.txt`):
`int`/`bool`/nested-tuple paths still name correctly (rc=2); only `None` crashes — but `None`
is precisely the value `_row_parts()` itself manufactures for a malformed row, so the two
paths interact. The fix's own `--self-test` is green (`0 failure(s) over 68 assertions`) on
the very bytes my probe crashes on: F12 covers non-str **keys**, F13 a short row; neither
covers a non-str row **value**.
