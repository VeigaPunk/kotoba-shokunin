### F-2 LAUNDERING HOLE (HIGH) — a self-consistent scope-out absorbs a real disagreement

The scope-out trusts the builder's self-declaration. A builder that *failed* to
derive a row can declare it `SCOPED_OUT` in **both** payload channels plus the
map, and the row leaves the join with no failure:

```
# 1. genuine disagreement, no scope-out:                exit 1
   reason: disagreements: omp.offered.skills (mode=equal: expected 5, observed 7)
# 2. same payload, row ALSO declared SCOPED_OUT:        exit 0
   exit 0 | headline {'joined_scope':23,'n':23,'total':23} | all checks agree
```
(`drafts/r1/{disagree-ind,disagree-scoped-ind}.json` + `cmp-disagree*.json`.)

The driver docstring claims "a scope-out set that the live side does not know
about cannot hide a check: `--expect-n` still covers the live check set" — true
only of the **live** count. Nothing in the exit-0 path distinguishes "cannot
derive the row blind" from "did not derive the row." This is protocol §11
failure mode 1 (smoothing) through a new door, and the same class r37's R1-F1
opened. §5 says a definitional ruling needs both scopes' probe blocks; the
scope-out needs **no probe at all** — one line of free text suffices.
Minimum fix: require a machine-checkable discriminator per scoped row (probe
command + output), or have the driver read the scope-out set from a committed
corpus file rather than the payload under test.
