## Findings
- The red class is live and gating at HEAD: one dead pointer → integrity **1** (class `corpus.pointers.report_dead`) and independent **1** (same class), both naming `corpus/lessons/round-3.md:38`; the untouched clone is **0/0**, so the flip is caused by the plant.
- Two independent DRIFTs fire on the red world (dead-pointer zero-rule + `report_total` equal-rule 37 vs 36); under `--no-baseline` only the zero-rule remains and exit is still 1 — the probe does not depend on the baseline.
- Exclusions are unchanged: a double-quoted pointer (v2) still exits 0 in both instruments with the checked population held at 36, so the round-12 context rule has not leaked into the checked class.
- `fault-a` in the harness is non-vacuous end to end (plant self-verifies, integrity exits 1 with the intended class id, independent also exits 1); the harness is green at HEAD (`ALL PASS`, self-test OK).
- Resolution semantics worth recording: bare/relative pointer tokens are resolved from the citing file's directory, so a lesson that says `../.ufo/reports/...` only resolves from `corpus/lessons/`; the same token copied into `corpus/knowledge/` silently becomes dead (v3/v5/v6 evidence, integrity exit 1).
- Sub-class where the instruments part company: a dead pointer whose target exists on disk but is untracked (v4) is *not* counted in `report_dead`; integrity still exits 1 via the equal-mode `report_total` count, but the independent instrument returns 0. The harness records that row `INFO(non-gating)`, so the class's "independent must also exit non-zero" promise does not cover this shape.
- The independent-verifier crash class (claim I) is reproduced unpatched at HEAD: deleting one tracked corpus file yields a `FileNotFoundError` traceback at `:313` (exit 1) where the primary classifies it (exit 2).

## Defects named
1. `verifiers/verify_corpus_integrity.py` (`corpus.pointers.report_dead`) — a pointer whose target exists on disk but is untracked is classified by the equal-mode `report_total` count only, never by the zero-rule; the independent verifier returns 0 for the same world, so this sub-class is gated by one instrument alone (harness row `INFO(non-gating)`).
2. `verifiers/verify_corpus_independent.py:313` — `analyse_pointers` opens a tracked path without guarding absence; a deleted tracked corpus file raises `FileNotFoundError` (exit 1, traceback) where the primary exits 2. Same class as claim I / scout M8; still open at HEAD.
3. Corpus lesson idiom `corpus/lessons/round-3.md` (bare `../.ufo/reports/...` tokens) — resolution is relative to the citing file's directory, so the token's meaning is depth-dependent and silently breaks when copied between `corpus/lessons/` and `corpus/knowledge/`; both instruments then exit 1 with no diagnostic naming the depth as the cause.
4. No defect found in the exclusion paths themselves: double-quoted (v2), angle-bracket/glob, and depth-correct resolving (v6) tokens all behave as documented; v6's exit 1 is the legitimate `report_total` equal-rule.
