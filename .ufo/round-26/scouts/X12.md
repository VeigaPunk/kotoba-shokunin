## Findings
- **Probe confirmed.** Deleting the opening catalogue anchor at `verifiers/verify_harness_claims.py:384`
  (`block_re = re.compile(r"<skills>(.*?)</skills>", re.S)`) makes `omp_newest_catalogue()`
  return `catalogue_found=False`, `total=0`, `matched=0`; exactly three `equal`-mode checks
  DRIFT (`CHECKS` at `:536-539`) and the gate exits **1**. Reproduced twice: isolated
  synthetic baseline, and against the real host state + shipped `baseline.json`.
- **Not vacuous.** The unmutated control observes the catalogue (found, `1/1` matched) and
  exits 0 in the same environment; the two copies differ in exactly one line, and their
  binary/db/log/session inputs are byte-identical.
- **Sensitivity is on the catalogue, not on the anchor.** Only five observation keys differ
  between control and probe (`catalogue_found/total/matched/timestamp/path`); all other
  observations are identical, so the probe isolates the extraction path.
- `omp.catalogue.missing_names` (mode `zero`, `baseline.json:73`) is **PASS in both states** —
  `[]` when the catalogue is found and fully matched, and `[]` when none is found. It is not
  discriminating for this class; the class rests on the three `equal` checks.
- Exit 2/3 behaviour is intact and traceback-free (`INCONCLUSIVE: omp binary not found`,
  `no baseline — observations above only`).
- The `min(10, len(known))` floor at `:386` admits a 1-skill catalogue, which is what makes
  this probe cheap; the live host's floor is 7 (`baseline.json:65-71`).
- Live repo verified unchanged after all probes: `git status --porcelain` shows only
  `.ufo/round-26/` (+ `.ufo/reports/round-26/`); instrument and baseline shas are
  `2c4c6488…` / `80949255…`, unchanged.

## Defects named
1. `verifiers/verify_harness_claims.py:384` — **no anchor self-assertion (variant B).** An
   outright *deletion* of the opening anchor (`r"(.*?)</skills>"`) still extracts the block:
   `catalogue_found=True`, `total=1`, `matched=1`, 0 DRIFTs, **exit 0**. The gate detects
   anchor *corruption* (a still-present-but-wrong literal) but nothing asserts the `<skills>`
   literal exists in the extractor, so a mutation that removes the anchor passes green.
   Contrast `verify_surfaces.py`, which gained an extraction-vacuity guard at round 21.
   Severity low (a probe/robustness gap, not a live false-pass): the class needs the anchor
   to vanish *and* the catalogue to survive.
2. `verifiers/baseline.json:73` (`omp.catalogue.missing_names`, mode `zero`) — carries no
   discriminating power for the catalogue-anchor class: `[]` in both the found-and-matched
   and the not-found states, PASS either way. Informational.
3. `verifiers/verify_harness_claims.py:580-616` — `--self-test` covers only the `H7s` preview
   and block-scalar chomping models; the mutated copy reports `0 failure(s) over 10
   assertions`, byte-identical to the control. The self-test cannot detect this class by
   design; recorded so the 10-assertion count is not read as coverage of the catalogue path.

  host-shaped confirmation, but it was not repeated on other hosts.

  anchor — C also exits 1). Other `omp.*`/`oc.*` checks were not individually perturbed.
- `--self-test` green and exit 2/3 were observed; exit codes for every other argument
  combination were not swept.
- No repo file other than this fragment was written; all mutations live in `/tmp/kx12/`
