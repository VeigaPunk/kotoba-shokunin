## Task

Red probe: harness check-pin corruption -> DRIFT. Corrupt `verifiers/baseline.json` pin
entries on `/tmp` copies of HEAD `10bf6d3` and measure what each gate reports. The slice
wording forced a second reading: the harness gate reads a *different* block (`checks`)
from the pin guard (`measured_against`), so both were probed. Also reproduces claim R's
`instrument_drift`. Live tree read-only.

## Findings

- **R reproduced.** `sibling-citation-routing-round16.md:154` embeds `02ccf1b3…`; file
  and JSON `:9-10` pin `15d0aa16…`. One hex string → exit 0 at `226/14/14/0`. No gate
  reads this guard, so it can stay broken with every gate green.
- **The two pin blocks are disjoint.** `check_substrate_pins.py` reads only
  `measured_against` (18 refs; 0 in the other six instruments); the harness reads only
  `checks`. Corruption in one is invisible to the other's gate.
- **`expect` is unread for 11 of 28 harness ids.** `evaluate()` (:565) branches on mode
  *before* touching `baseline["checks"]`; `zero`/`positive` rows hard-code the expected
  text. The baseline `expect` for those ids is decorative — round-23's `PIN_ABSENT` class
  ("the checked set cannot silently shrink"), still open on the harness side.
- **Baseline `mode` is never read** and 2/28 ids contradict the source table
  (`oc.permission.skill_lines`/`skill_allow`: `at_least` in JSON, `equal` in `CHECKS`).
- **Traceback class where the docstring promises `3 = no baseline found`:** missing
  `checks`, `checks: null`, malformed JSON all exit 1 uncaught.

## Defects named

1. `sibling-citation-routing-round16.md:154` — guard sha `02ccf1b3…` stale vs the
   `15d0aa16…` pin; published `HEAD frozen` exits 1 `instrument_drift`. One-string fix
   re-measured green. **Claim R's target.** (`:136` *Before* command breaks the same way:
   guard is file-embedded, not revision-derived — dual-source pin.)
2. `verify_harness_claims.py:565` — `expect` unread for `zero`/`positive` modes: 11 ids
   (`omp.cache.misses`, `omp.descriptions.over_cliff`, `omp.names.mismatches`,
   `omp.descriptions.missing`, `omp.descriptions.unmodelled`, `omp.catalogue.missing_names`,
   `oc.log.available_skills_hits`, `oc.log.skills_tag_hits`, `oc.dup.onesided_roots`,
   `oc.log.init_count_monotone`, `oc.roots.plugins_cache`) can be deleted or
   value-corrupted with **no** DRIFT (28/28, exit 0) — the r23 `PIN_ABSENT` class, open.
3. `verify_harness_claims.py:650-654` — deleted `checks` key / `checks: null` / malformed
   baseline JSON each raise an uncaught traceback (exit 1), not the documented 3.
4. `verifiers/baseline.json` — `mode` field never read; `oc.permission.skill_lines` and
   `oc.permission.skill_allow` carry `at_least` against the source's `equal`.
5. Self-tests do not cover 2-4: `check_substrate_pins.py --self-test` stays 0/46 and
   `verify_harness_claims.py --self-test` 0/10 after the tamper.
6. **Visibility gap:** neither 1 nor 2 is observable from any gate's exit code — the
   live HEAD suite is 6/6 green while both hold.

## Limits

Repo and siblings read-only; only this fragment written; all mutations on `/tmp` clones.
`live` routing ran against symlinked siblings in `fleet/`, so it reports `source_drift`
(drifted kake/kengaku bytes) — the comparator's designed stop, not a measurement. Defect
2 is proven by tamper outcome, not by reading `evaluate()`'s intent; defect 4 is a byte
comparison of two tables, not a runtime divergence (nothing reads the field). No fix landed.
