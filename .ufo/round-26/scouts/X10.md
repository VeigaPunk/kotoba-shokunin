## Findings

**F1 — the probe flips, but only for a narrow corruption class.** P1/P2/P3 and M1 all
exit 1 with the expected named failure. The detector is real for extraction-bearing
callees (`Co`, `Dl`) and for vacuity/deletion.

**F2 — four corruption forms leave the suite green (exit 0).** P4 (old-name revert),
P5 (clean-fixture overwrite), M3 (`Hj` regex drop), M7 (`Tl|dr|GW` regex drop). The
claim's "new-callee fixture corruption -> exit 1" therefore holds only conditionally.

**F3 — the entire (b2) block is deletable with no signal (M11).** Removing the 4
`rec(...)` calls at `:786-791` yields `0 failure(s) over 72 assertions`, exit 0. The
count line (`:941`) is printed but read by nothing — `grep` for `assertions` across
`verifiers/` finds only other instruments' own prints; `fault_injection_corpus.sh` never
invokes the surfaces self-test. So the newcallees coverage is self-deletion-prone, and
the round-21/25 "75 assertions" records are not machine-enforced.

**F4 — only 5 of 11 allowlisted callees are load-bearing.** `Id`, `Cl`, `jDe` (clean,
drop-class, extra-class fixtures) and `Co`, `Dl` (newcallees). `Hj`, `Tl`, `dr`, `GW`
have zero detection power — M3/M7 show the regex can lose them silently.

**F5 — fixture bytes are unguarded.** No verifier hashes `verifiers/fixtures/**`
(`grep sha256|hashlib` x fixture -> empty); `check_substrate_pins.py` covers binaries and
`baseline.json` only. Hence P5's clean-fixture overwrite is invisible.

## Limits

Fixture-only self-test probing; the live gate was also run on the extract with the real
binaries (row 15, 7 x PASS, 38 classes) but was not mutation-tested. P4/P5/M11 mutate the
instrument itself as well as the fixture — they measure self-deletion and fixture-drift
tolerance, not a runtime fault. Not a seven-gate sweep.
