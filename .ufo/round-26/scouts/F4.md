## Findings
- **Minimality.** Both touch exactly one file and add no imports. F2 edits three read sites + one precondition (guards travel with the reads). F3 adds one upfront pass over `tracked + ["corpus/README.md"]` and one call. F3 is smaller (3 hunks vs 6); F2 is the one that is *complete*.
- **Agreement semantics preserved by both.** On the clean tree the nine numbers and the full output are byte-identical to HEAD; on W0 the independent's numbers are identical across HEAD/F2/F3; both red probes still flip. Neither changes any classification, only the unreadable-file path. So both are semantics-neutral for the agreement claim.
- **Self-test count exact in both:** `52 assertions, 0 failures`, exit 0. Neither adds assertions (F2 states the H8 fixture side is deferred; F3 also leaves it out).
- **Why F2 over F3.** F3's guard lives in `analyse()` (`:406`), but the self-test calls `analyse_index`/`analyse_pointers`/`analyse_commits` **directly** (`:605/:640/:681`), not through `analyse()`. So F3's guard is off the paths the self-test exercises and off any future direct caller: a direct call on a deleted-file tree still raises `FileNotFoundError` (proven above). F2's guard sits at the read site, so no caller can bypass it. F3 also leaves the `exists`→`isfile` README case to the upfront pass and leaves three raw `open()`s in place, which is a latent re-entry point.
- Neither patch addresses invalid UTF-8 (`UnicodeDecodeError` is `ValueError`, not `OSError`); both leave it tracebacking — correctly deferred as a separate move (round-24 H8/F6).
