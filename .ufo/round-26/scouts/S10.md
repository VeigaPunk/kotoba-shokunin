## Defects named
- **D1 — the row's fixtures citation is false (documentation, minor-but-real).** The row says `--self-test` runs "over `verifiers/fixtures/pins/`". It does not: the self-test **generates** its payload in `tempfile.TemporaryDirectory(prefix="pins-selftest-")` (`:299-302`, `b"#!kotoba-pin-fixture-mini-v1\n" + bytes(range(64))` — byte-identical to the committed `mini.bin`, sha-verified). No code reads that directory: `grep -rn 'fixtures/pins' verifiers/*.py` → the only hit is a *help string*; `tripwire`/`mini2`/`EXECUTED`/`fixtures/pins` are all absent from the guard. So `mini2.bin` and `tripwire.bin` are **unreferenced committed files**, and the corpus doc's claim that `tripwire.bin` "turns hash-never-exec into an assertion" (`corpus/knowledge/substrate-pin-guard-round23.md:36-37`) is **not true of the landed guard** — the never-exec property rests on a docstring (`:32`) and my grep, not on a behavioural assertion. Same wording propagated to `LOG.md:1231` and `corpus/README.md:57`.
- **D2 — the Capabilities table is unenforced prose (structural, the round-21/22 debt class).** Deleting the row from a clone's `SCORECARD.md` leaves every gate at its **prior** exit code (checklist 1→1, harness 0→0, surfaces 0→0). No gate reads the table, and `verify_skill_checklist.py` — the only gate that reads `SCORECARD.md` — has no `Capabilities` rule. This is the same zero-readers shape the round-23 guard closed for `measured_against` pins, still open for the table itself.
- **D3 — the guard is unguarded (minor).** Nothing pins or verifies `check_substrate_pins.py`'s own sha. A copy with `return 0` injected at the top of `main()` exits 0 and leaves `verify_harness_claims.py` and `verify_surfaces.py` green. Named only — no fix proposed here.
- **No-finding (recorded):** the row's numbers, exit ladder, probe matrix, read-only claim, and harness-blindness rationale all reproduce exactly; the row itself needs no correction beyond D1's fixtures clause.

## Limits
- Probes ran on `/tmp` copies (archive extract + `--no-hardlinks` clone); the repo was never written. `check_substrate_pins.py` reads host-absolute binaries, so a fresh clone elsewhere would exit 2 — untested here by design.
- The six-probe battery was reproduced with `/tmp` baseline copies and `--baseline`, not by the round-23 scripts (none are tracked); the probe *set* and exit codes match the row, the invocation differs.
- `tripwire.bin`'s non-execution was inferred from static absence of exec primitives plus the sentinel not appearing — no `strace` was run (scout V3's strace is cited by the row, not reproduced).
- D2/D3 were probed on clones whose corpus gates were already red for the environmental reasons above; the *delta* (no change in exit code when the row is deleted / the guard tampered) is the measurement, not the absolute codes.
