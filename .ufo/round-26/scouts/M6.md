## Task
Red probe for the substrate-pin guard at HEAD `10bf6d3`: confirm the
**mtime-only drift -> exit 1** class still flips — a moved timestamp with
byte-identical content is caught, while the sha256 pin on the same binary
still PASSes (independent pins). Probes on /tmp copies only.

## Findings
- **Probe flips as designed.** Byte-identical content (`t_omp` sha
  `bf1e86a935b1…` unchanged), mtime moved +1 ns -> exit **1**:
  `FAIL omp_binary_mtime: mtime drift (sha256 not compared): delta_ns=1
  tolerance_ns=0`, while `PASS omp_binary_sha256` and `PASS
  opencode_binary_sha256` stay green. The pins are independent: a
  timestamp-only move is caught by the mtime pin alone; a content-only move
  by the sha pin alone (reverse case -> exit 1 naming `omp_binary_sha256`).
- **Full ladder all exit 1**, each naming the pin: `-1 ns` (`delta_ns=-1`),
  `+999 ns`, `+1000 ns`, `+1 s` (`delta_ns=1000000000`), `-1 day`
  (`delta_ns=-86400000000000`). Tolerance is 0 ns on a 9-digit pin, so a
  single-nanosecond move is out of window in both directions — ns-exact, not
  a blob tolerance.
- `--json` on +1 ns: `exit_code 1`, `pass 2`, `fail 1`, mtime record carries
  `delta_ns 1`, `tolerance_ns 0`, `verdict DRIFT`. Text and json agree.
- **Determinism**: two consecutive runs byte-identical (`diff` empty); no
  `Traceback` in any output; the guard does not re-pin or repair.
- **Read-only**: live omp `mtime`+`size` identical before/after a run;
  `strace -f -e execve` = **1 execve** (the `python3` interpreter) — the
  pinned binaries are never executed. `git status --porcelain` after every
  probe: only the pre-existing `?? .ufo/round-26/`.
- Regression context re-confirmed: `--self-test` `0/46`, live `exit 0`
  `OK 3/3 pins hold` — the round-23 landing numbers still hold at round 26.

## Defects named
1. **The committed fixtures are dead weight.** `verifiers/fixtures/pins/`
   (`mini.bin` `d3b4640e…`, `mini2.bin` `b315d489…`, `tripwire.bin`
   `2b30a880…`) is named by SKILL.md:465 and corpus/README.md:57 as the
   `--self-test` substrate, but the script never reads it: `self_test()`
   builds `mini = tmp/"mini.bin"` inside a `tempfile.TemporaryDirectory`
   (line 301) and no path opens `verifiers/fixtures/pins/`. `grep -n
   "fixtures" check_substrate_pins.py` -> only the `--self-test` help string.
   A clone's self-test green is about the script's tmp world, not the
   committed fixtures; their quoted shas are unenforced decoration.
2. **No aggregate invokes the guard.** `grep -rln` over the other verifiers
   finds no runner; the guard is documented as one of "the seven gates"
   (SCORECARD.md:32,124; SKILL.md:463-465) but nothing in-tree calls it — the
   `measured_against` pins are enforced only when someone runs the command by
   hand. The round-21 named debt is closed at the tool level, not the sweep
   level; a lane that skips the command re-opens the silent-rebuild class.
3. **`--self-test` does not exercise the pinned real binaries** (by design —
   host-anchored constants), so a host with unreadable omp/opencode still
   shows a green self-test; only the live run (exit 2) reveals it. Scope
   limit, not a bug.

- Did not evaluate round-26 claims R (stale replay SHA guard) or I
