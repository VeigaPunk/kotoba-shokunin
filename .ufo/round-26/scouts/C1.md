## Findings
- **R reproduces and its repair works.** Published command fails at HEAD (exit 1 `instrument_drift`); the one-hex-string swap yields exit 0 at `226/14/14/0`, matching W05/R1. The literal is unique (`count==1`) and is not pinned by any gate: repaired copy leaves the primary at `9/9` exit 0 and the independent verifier at exit 0, and `HEAD frozen` runs in a bare clone with no sibling repos (frozen mode is sibling-independent, so the falsifier "touches sibling repos" is not met).
- **R's minimality is per-instance, not per-class — the hidden trade.** The stale value was introduced by round-24 commit `4c1c2cf` (verifier `02ccf1b3…`→`15d0aa16…`) and never propagated to the md; the md literal is a duplicate of `…round16.json:9` `instrument.sha256`. The verifier sha has now moved `c55a3f9f→02ccf1b3→15d0aa16`. R's counting command passes while the recurrence survives the next verifier edit. The class fix is available and free: binding the guard to `fixture["instrument"]["sha256"]` verified green (command 0, primary 9/9, independent 0), so a single-source guard is demonstrably collateral-free.
- **The `:136` "Before" command is unrunnable by construction, and R does not fix it.** The md was added at `292bbf8`; `581e293` predates it, so no checkout of that revision contains the file the command reads. R1's reading ("the historical replay only works from a checkout of that revision") understates the defect: it works from no checkout of that revision. It runs only from a `292bbf8`-era checkout with `581e293 frozen` as argv — and only because the file-embedded guard pins the sha that `581e293`'s verifier happened to have.
- **I reproduces exactly and every stated condition holds.** Deleted tracked file → `:313` raw `FileNotFoundError`, exit 1 (not a clean classification); primary → exit 2 `INCONCLUSIVE` naming the same file, so I's "exit 2/INCONCLUSIVE per the primary's semantics" is the primary's real behaviour, not an assumption. Patched: crash probe exit 2 clean, `--self-test` 52/52 unchanged, live agreement identical on all nine numbers, red probes still flip to exit 1 with `report_dead=1`/`commit_unresolvable=1`. Unanimous.
- **I's two-site patch is non-minimal; `:346` is unreachable for this class.** Every tracked md is opened by `analyse_pointers` (`:313`) before `analyse_commits` (`:346`), and pointers raise first, so `:313` alone suffices — verified (`/tmp/c1w/p4` → exit 2). Guarding both is defensible hardening, but it is not required by the stated class; the claim should not price it as necessary.
- **I lands un-gated.** `verifiers/fault_injection_corpus.sh` plants faults a, b, c, d1, d2, e, f, g, h only; there is no deleted-tracked-file fault, so the fix ships with no regression test and the class can be reintroduced silently. Adding one is not free: in that world the primary exits 2 with an empty `out.json`, and the harness's `drift_ids` reads that as `UNPARSEABLE`, so the assertion needs the exit-2-aware branch that only fault (f) has.
