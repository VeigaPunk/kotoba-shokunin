## Findings
- **The slice's expected red probe is green at HEAD.** `command-heredoc-tilde-dead` exits 1 for the right reason (dead tail named), the body line is never a subject, the live twin exits 0, and the flip is causal (path present → 0). No repair is needed for the probe itself; the round-17 `HEREDOC_RE` fix holds.
- **Two escape directions measured, both real divergences from bash** (each: checker 0 PASS, bash 1):
  1. *Operator in quoted text or a trailing comment*: the scanner opens a heredoc on `<<EOF` inside `"…"` or after `#`, then swallows every following line until a matching terminator. Any dead path after such a line is invisible. Same root cause for both rows; `:793` is the site.
  2. *Delimiter ending in `~`* (`<<EOF~`): `HEREDOC_RE` captures `EOF`, so the terminator line `EOF~` never matches, the body never ends, and the dead tail after it is swallowed.
- Neither direction is named in the round-17 ceiling table (`corpus/knowledge/checklist-execution-round17.md:317` names `<<~'EOF'`, `<<\~EOF`, and delimiters ending in `~` as **over**-catching); the measured behavior for `<<EOF~` is an **under**-catch, i.e. the ceiling's stated direction is wrong for that variant.
- `SCORECARD.md:45-55` carries both heredoc items as standing historical debt ("quoted/trailing-tilde heredocs and terminator whitespace"), so this is a re-confirmation of filed debt, not a new defect class.
- No live trigger: the four governance-scanned files contain no bash-fenced `<<` block, so the current tree's exit 0 is not resting on a swallow.

## Defects named
1. `verifiers/verify_skill_checklist.py:787-795` — heredoc detection is applied to quoted text and trailing comments; a phantom operator swallows the remainder of a shell-fenced block, hiding every later subject (checker 0 / bash 1). Escape direction: under-catch (false PASS).
2. `verifiers/verify_skill_checklist.py:311` — `HEREDOC_RE` captures `EOF` from `<<EOF~`, so the real terminator line never closes the body; same swallow, same false PASS.
3. `corpus/knowledge/checklist-execution-round17.md:317` — the named ceiling mis-states the direction for delimiters ending in `~` (says over-catch; measured under-catch). Documentation defect only; no instrument change proposed here.
